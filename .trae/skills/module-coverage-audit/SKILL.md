# 模块覆盖率与设计质量审计

**结论先行**：本仓库的自动化用例「存在且通过」≠「覆盖完整」。审计要回答的是「页面上每个元素/每条业务路径，是否有断言以正确的方式覆盖它」。

**必读**：[docs/模块深度检查清单.md](../../docs/模块深度检查清单.md)（九节，含十项实战坑位）。

## 何时用

- 用户问「这个模块覆盖是否完善/是否有没设计到的地方」
- 新模块上线、大版本迭代后需要复盘覆盖
- 准备宣称「某模块 100% 跑通」之前

## 执行顺序（九步，别跳）

1. **采集**：`wc -l` 文档与 spec → 统计表 vs 索引行数/优先级逐组对齐
2. **映射核对**：`npm run check:mapping`（0 失真才继续；失真分「行过宽/指错 spec/待实现挂账」三类）
3. **元素矩阵**：从 Vue 源码提 `FormItem/label/控件/v-if`，与 spec 断言指纹做「字段 × {默认值/显隐/校验/边界/提交体/回显/特殊行为}」矩阵，空列即缺口
4. **六维评价**：主路径 / 校验 / 一致性 / **状态语义（休眠保留）** / 权限（含后端探针）/ 跨模块
5. **场景补强**：主链闭环、换依赖、引用约束生命周期、增强层叠加、生命周期释放、审计反向核对
6. **盲区打勾**：异常注入 / 幂等 / 并发 / 时间边界 / 大数据量 / 安全 / 角色矩阵 /（组合=阻塞待产品）
7. **写发现表**：每条带证据（文件:行或命令输出）+ 优先级 + 处置；同时回写 `docs/覆盖缺口清单.md`
8. **修复**：新增用例守规范（页面封装、无裸 selector、API 造数 + track、快照还原、三件套同步）
9. **验证**：定向 → 受影响 spec 全量 →（必要时）模块全量 → 重跑 `check:mapping`

## 硬性判据

- **拒绝迁就实现**：实现与 02 文档冲突时，保留文档预期、登记「测试问题复盘」，等用户决策；禁止静默弱化断言
- **状态语义必须测**：条件渲染的「隐藏期间值休眠保留 + 提交不丢值」是最常见真 bug 区
- **契约要抓包**：提交体用 `postDataJSON()` 断言字段结构，而不是只看页面回显
- **长批次失败先判抖动**：>10 分钟批次出现会话类报错（session key）→ 定向复跑；不等于产品缺陷
- **组合/优先级类缺口**：产品未定义语义前**不得臆造预期**，登记为阻塞

## 输出模板

见 `docs/模块深度检查清单.md` §0（产出物）与 §7（优先级字典）。审计结束时清单里只允许三种状态：**已闭环（带证据）/ 明确不做（带决策人）/ 阻塞（带卡点）**——不允许「未开始」长期挂账。
