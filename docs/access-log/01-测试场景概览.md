# 访问日志（Access Log）模块 - 测试场景概览

## 模块概述

访问日志模块提供**访问日志 Header 白名单**的全局配置能力：按白名单采集指定请求头/响应头，写入访问日志的 `req_headers` / `res_headers` 字段，供下游按 Header 维度做流量分析与问题排查。单例全局配置（非集合资源），保存为**整组全量替换**。

对应接口端点：

- `GET /open-api/v1/access-log/config`（读取当前配置，从未配置时返回两段空数组）
- `PUT /open-api/v1/access-log/config`（整组全量替换请求头/响应头白名单）

对应接口文档：`design-docs/api-define/OpenAPI接口定义/access-log.md`；对应原型：`design-docs/prototype-design/pages/access-log.html`；UI 源码：`src/modules/AccessLog/index.vue`。

| 功能区域 | 说明 |
| --- | --- |
| 顶部提示区 | Alert 提示块：标题「访问日志 Header 白名单」+ 说明与采集语义合并段落；只读角色追加只读提示 |
| 展示态（默认） | 两张卡片「请求头白名单（req_headers）」「响应头白名单（res_headers）」，以只读 tag 展示已配置名称；未配置显示「未配置（不采集任何请求头/响应头）」；右上角「编辑」按钮 |
| 编辑态 | 右上角切换为「取消 / 保存」；两段白名单为带边框的 tag 容器（tag 可关闭）+ 输入框 + 「添加」按钮（回车等价）+ 卡片内规则提示；「取消」丢弃草稿，「保存」校验通过后提交并回到展示态 |
| 权限 | Feature `FeatureAccessLog`（scope=System）；GET 需 `read`、PUT 需 `update`；写操作记 `operation_log`；只读角色（`admin_readonly`）隐藏全部写入口 |
| 菜单入口 | 顶级「系统安全」组（`systemSecurity.admin.list`）下「访问日志」（`AccessLog.list`），紧跟「密钥收敛」之后 |

**核心变更依据**：

- 2026-11-16（变更记录 `modifications/2026-11-16-access-log-config-and-llm-key-concurrency/ui-code-changes.md`，api `v0.2.0-dev` 拉取 `90e62c2` → `d2d1e1e`）：**新增本模块**（api-define 新增 `access-log.md`），同时带出集群 `max_concurrency_per_key`、服务商描述字节口径、报表明细 TTFT/TPOT 口径三项对齐改动（分别见对应模块文档）。

本轮语义要点：

- **单例 + 全量替换**：`PUT` 用请求体整体替换两段白名单；未传入的段按空数组处理（等价清空），不存在「局部追加」语义。
- **名称归一**：服务端按 `http.CanonicalHeaderKey` 归一（如 `x-request-id` → `X-Request-Id`）后存储与下发；**页面展示的是归一后的形式**，不是用户原始输入的大小写。
- **归一去重**：同一列表内 `x-id` 与 `X-ID` 视为同一名称，重复 → `422 Param Illegal`；前端在「添加」时即按大小写不敏感拦截。
- **敏感头硬拒绝**：`Authorization` / `Proxy-Authorization`（大小写不敏感）出现在任一列表 → `422`，不落库；前端同样直接拦截。
- **元素格式**：trim 后非空、长度 ≤128 字节（UTF-8 计）、仅允许 RFC 7230 token 字符（`!#$%&'*+-.^_`|~` + 字母数字）。
- **空数组 = 不采集**：缺省 / `null` 均按 `[]` 处理；存量部署行为不变。
- **Cookie / Set-Cookie**：允许配置，服务端记录 Warn 级审计日志提示会话凭证风险（前端不拦截）。
- **采集语义由数据面实现**：多值头按逗号（`,`）拼接为一个值；Header 值超过 2048 字节截断；控制面不感知。
- **菜单依赖**：路由名 `AccessLog.list` 必须存在于后端 `nav_tree.toml`，否则前端路由守卫会跳回登录页（不只是菜单不显示）。

## 配置顺序 / 依赖关系

```text
后端 nav_tree.toml 登记 AccessLog.list
        │（否则前端守卫拦截，页面不可达）
        ▼
GET access-log/config → 展示态（tag 只读展示 / 空态）
        │ 点「编辑」
        ▼
编辑态（tag 增删 + 输入添加）→ 取消（丢弃草稿） / 保存（全量 PUT）
        │ 保存成功
        ▼
回到展示态（服务端归一后的名称） → 数据面按白名单采集 → 写入访问日志 req_headers / res_headers
```

| 关系 | 说明 |
| --- | --- |
| 菜单项 → 页面可达（**前置**） | 后端 `conf/nav_tree.toml` 缺 `AccessLog.list` 时，前端路由守卫按「导航树无此菜单」跳登录页 |
| 白名单 → 数据面采集（**联动**） | 控制面只负责存储与下发；采集、拼接、截断行为由 BFE `mod_access_pb3` 实现 |
| 配置 → 下游分析（**下游**） | 写日志的 Header 名为归一形式，下游聚合键稳定；空白名单 = 不采集 |

## 横切能力备注

- **只读视角**：`admin_readonly` 全站隐藏写入口（前端指令 `v-has`）；本页仅保留只读查看能力与只读提示，无其它差异。
- **操作日志**：PUT 成功写 `operation_log`（内容为整组白名单）；GET 不写日志。
- **权限边界**：前端隐藏仅为体验，服务端按 `FeatureAccessLog` + `read/update` 校验，越权返回 403。
- **接口兜底**：前端校验与后端规则逐条对齐（长度/token 字符/归一去重/敏感头），后端 422 为最终边界，负向用例须断言「拒绝后 GET 回读零变更」。
