### AC-D-07：查看抽屉与列表展示数据同接口响应一致性-全字段核对

**功能模块**: 查看  
**优先级**: P1  
**用例编号**: AC-D-07  
**设计依据**: `ai-cache-rules.md` §1 数据模型；`AICache/index.vue` `buildRuleColumns/strategyLabel/formatTtl/formatBytes`；`AICache/components/RuleView.vue`

#### 前置条件

- 已通过 `GET /ai-cache-rules` 拉取到非空规则集合，并保存完整响应 JSON 便于逐字段比对
- 集合内至少 1 条规则含缓存 TTL、最大请求体、最大缓存值；建议另含缓存键策略为「缓存豁免（disabled）」的规则

#### 测试步骤

1. 记录 `GET /ai-cache-rules` 返回的规则集合数组字段与顺序
2. 逐行核对列表 7 个数据列展示值与响应逐字段是否一致（含策略 Tag 颜色与文案）
3. 打开某条规则的「查看」抽屉，核对 7 个 `info-row` 展示值与该规则响应字段是否一致
4. 关闭抽屉后重新打开同一行「查看」，确认展示值不随重新打开而变化

#### 预期结果

1. 列表行序 = 响应规则集合数组顺序（首条即最高优先级），前端未重排
2. 列表「规则名称」「生效条件」两列展示值分别等于接口返回的规则名称、生效条件字段值；字段缺失时展示 `-`
3. 列表「缓存键策略」列以 Tag 展示，文案映射为 `lastQuestion`→`仅最后一个问题（lastQuestion）`、`allQuestions`→`全部问题（allQuestions）`、`disabled`→`缓存豁免（disabled）`；`disabled` 用 `warning` 色、其余用 `primary` 色
4. 列表「缓存 TTL」列：`0`→`不过期（0）`、正数→`{value} 秒`、`null`/缺省→`-`，与响应中对应规则的缓存 TTL 一致
5. 列表「最大请求体」「最大缓存值」两列：有值→`{value} B`、`null`/缺省→`-`，分别与响应中对应规则的最大请求体、最大缓存值一致
6. 查看抽屉 7 个只读信息行与列表对应列展示**完全相同**：「规则名称」「生效条件」（等宽字体原文）「缓存键策略」「缓存 TTL」「最大请求体」「最大缓存值」「语义缓存」
7. 抽屉展示值与步骤 1 记录的同一规则响应字段逐一对应，无偏差
8. 响应中的只读字段创建时间 / 更新时间在列表与抽屉均**不展示**（UI 无展示位）
9. 响应中的语义缓存在列表「语义缓存」列与查看抽屉「语义缓存」行**均展示**：`true`→`开启`（列表列 `success` 色 Tag）、否则→`关闭`（`default` 色 Tag）；列表列仅展示「开启/关闭」，抽屉行在缓存键策略为「缓存豁免（disabled）」时追加「（策略为 disabled，忽略）」后缀（见 AC-D-08 / AC-D-09）
10. 关闭抽屉后重新打开该行「查看」，展示值仍与接口数据保持一致（提交成功后重新 GET 后应回填最新只读时间但不影响上述展示）
