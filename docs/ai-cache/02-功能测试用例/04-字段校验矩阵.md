## 4. 字段校验矩阵

> ⚠️ **UI 文案偏差（以实际 UI 为准）**：本文件用例标题中的字段名「规则名称」「生效条件」在设计原型表述如此，实际 UI 表单标签复用 `route.ruleName`/`route.expression` 渲染为「规则名」「表达式」；校验提示文案（「请输入规则名称」「请填写生效条件」等）与实际 UI 一致。自动化断言字段标签采用实际 UI 文案。

字段校验依据 `design-docs/api-define/OpenAPI接口定义/ai-cache-rules.md` §1 与 `AICache/components/RuleForm.vue` 的 `ruleValidate`。校验错误提示在 FormItem 内单行展示；规则名称使用 `validateName` 自定义校验（trim 判空 + `length > 128`），**不使用** `maxlength` 硬截断。集合内唯一性有两条：规则名称唯一（`name`）与生效条件唯一（`cond`，**逐字节比较**，编辑时排除自身），后者在「本地保存」与「提交并生效」两处各校验一次（`AICache/index.vue` `onFormSubmit` / `submitRules`），后端对应错误为 `422 Param Illegal: duplicate ai cache rule cond: <cond>`。

### 4.0 字段校验规则矩阵

|字段|必填|类型/取值|默认值|校验规则|错误提示文案|
|---|---|---|---|---|---|
|name|是|string|—|trim 后非空；长度 ≤128（`validateName`）|请输入规则名称 / 规则名称长度应为 1-128 字符|
|cond|是|string|—|非空；须能通过 BFE `condition.Build` 编译（`validateCond`，`condErrmsg` 优先）；**集合内唯一**（逐字节比较，编辑时排除自身；本地保存 + 提交并生效前各一次，用例见 AC-V-03）|请填写生效条件 / （编译错误信息） / 生效条件已存在，集合内必须唯一|
|cache_key_strategy|否|enum|null|枚举 `lastQuestion`/`allQuestions`/`disabled`|—|
|cache_ttl|否|int|null|校验 `< 0` 拦截（0 合法）|缓存 TTL 不能小于 0|
|max_body_bytes|否|int|null|校验 `<= 0` 拦截（须为正整数）|最大请求体必须大于 0|
|max_value_bytes|否|int|null|校验 `<= 0` 拦截（须为正整数）|最大缓存值必须大于 0|
|enable_semantic_cache|否|bool|false|布尔，无额外组合校验（缓存键策略为「缓存豁免（disabled）」时被忽略，不报错）|—|
|created_at|否（只读）|string(RFC3339)|—|**响应不返回**（整组替换语义）；表单无输入项；请求体携带按未知字段忽略|—|
|updated_at|否（只读）|string(RFC3339)|—|**响应不返回**（整组替换语义）；表单无输入项；请求体携带按未知字段忽略|—|
|规则名称集合内唯一|是|—|—|全集合规则名称去重（提交前 + 本地保存时；与 `cond` 唯一同见 AC-V-03）|规则名称已存在，集合内必须唯一|

### 4.1 语义设置字段校验规则矩阵

字段校验依据 `design-docs/api-define/OpenAPI接口定义/ai-cache-semantic-settings.md` §1 与 `AICache/index.vue` 的 `semanticRules`。

|字段|必填|类型/取值|默认值|校验规则|错误提示文案|
|---|---|---|---|---|---|
|top_k|是|int|1|整数且在 1-10 之间（`validInt`，拦截空值/非整数/越界，含小数）|Top K 须为 1-10 的整数|

|created_at|否（只读）|string(RFC3339)|—|客户端只读，提交时不传|—|
|updated_at|否（只读）|string(RFC3339)|—|客户端只读，提交时不传|—|

### AC-V-03：规则名称与生效条件集合内唯一

**功能模块**: 字段校验矩阵  
**优先级**: P0  
**用例编号**: AC-V-03  
**设计依据**: `ai-cache-rules.md` §1「`name` 集合内唯一」与「同一集合内 `rules[].cond` 不得重复（逐字节比较）」、§2.1 执行逻辑第 2 步；`AICache/index.vue` `onFormSubmit` / `submitRules`；`aiCache.tipNameDuplicate` / `aiCache.tipCondDuplicate`

#### 前置条件

- 集合内已存在名为 `cache-rule-01`、生效条件为 `req_path_in("/v1/chat/completions", false)`（记为 `condA`）的规则，且其余规则条件与之不同
- 可构造「仅空白差异」的等价表达式（如 `req_path_in("/v1/chat/completions",  false)`），并可绕过前端直接 `PUT`

#### 测试步骤

1. 新增一条规则，「规则名称」填写为 `cache-rule-01`，点击「本地保存」
2. 新增一条规则，「规则名称」填写集合内不存在的名称，「生效条件」填写 `condA`，点击「本地保存」
3. 「生效条件」改为 `req_path_in("/v1/chat/completions",  false)`（逗号后**两个空格**，其余字符相同），再次「本地保存」
4. 使本地集合出现两条名称不同、`cond` 相同的规则（由 `GET` 回填或 mock 注入带入），制造净改动后点击「提交并生效」
5. 绕过前端直接 `PUT /ai-cache-rules`，提交两条 `cond` 相同的规则

#### 预期结果

1. 步骤 1：名称查重命中，提示「规则名称已存在，集合内必须唯一」，抽屉不关闭、不写入集合
2. 步骤 2：名称查重通过后 `cond` 查重命中，提示「生效条件已存在，集合内必须唯一」，抽屉不关闭、不写入集合
3. 步骤 3：仅空白差异即视为**不同**条件（逐字节比较、不做 trim 归一），校验通过并保存成功
4. 步骤 4：整集合 `cond` 查重命中，提交被拦截，同样提示「生效条件已存在，集合内必须唯一」，**不发 `PUT`**，停留编辑模式（见 AC-L-15）
5. 步骤 5：后端返回 `422 Param Illegal: duplicate ai cache rule cond: <cond>`，集合整体回滚、零变更（后续 `GET` 与提交前一致）
6. 逐字节口径只比较字节、不做语义归一；但差异表达式仍须先通过 `condition.Build` 编译，故用例应选「可编译且字节不同」的差异（如空白数量），不要用可能编译失败的大小写变体
7. 两条唯一性校验的先后顺序为「名称 → 生效条件」：名称重复时只提示名称重复

> **2026-10-22 扩展**：本用例原仅覆盖「规则名称集合内唯一」，本轮按 `ai-cache-rules.md` §1 扩展为「名称 + 生效条件双唯一」（`cond` 逐字节比较、编辑时排除自身见 AC-C-10、提交前整集合二次校验见 AC-L-15）。
