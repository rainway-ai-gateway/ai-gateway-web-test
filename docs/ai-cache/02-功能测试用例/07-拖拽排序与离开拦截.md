### 阻塞记录（§7.6）：视图模式下表格行仍可拖拽（`draggable` 永不回收）

**状态**: `已通过`（2026-10-16 时点为「阻塞」——`test_07_ai_cache_drag_leave.spec.js` 中 AC-DR-01 保持原断言红色，不做轮询/重试绕过；产品修复后 2026-10-17 复跑转绿，该阻塞已解除，见下条）

#### 现象

进入 AI 缓存规则页 → 进入编辑模式（行 `draggable="true"`，符合预期）→ 点击「退出编辑模式」（无改动，确认框确实未弹、页面确实回到视图模式）→ 表格数据行 `<tr>` 的 `draggable` 属性**仍为 `"true"`，永不回收**。

断言报错形态（AC-DR-01 第 5 步）：

```
expectRuleRowsDraggable(page, false) →
  Expected: null
  Received: "true"
```

#### 探针实测数据（真实浏览器，非推测）

由本任务委派方（主 agent）在 `/ai-cache-rules` 上用真实浏览器探针执行「进入编辑模式 → 退出编辑模式 → 多次读取行 `draggable` 属性」，时间轴如下（每次读取的均为 `.show-iView-Table .ivu-table-body tbody tr` 的 `draggable` 属性）：

```
退出后约 200ms:  ["true","true","true"]
退出后约 800ms:  ["true","true","true"]
退出后约 2000ms: ["true","true","true"]
退出后约 5000ms: ["true","true","true"]
已回到视图模式（「进入编辑模式」按钮可见）: true
```

**结论**：页面状态确已回到视图模式（页头按钮已切回「进入编辑模式」），但行的 `draggable` 属性在 200ms ~ 5000ms 内**全程保持 `"true"`** —— 因此这**不是时序/竞态问题**，不能靠加等待或轮询修复。

#### 根因方向与源码依据（静态可复核）

1. **属性的产生**：`ai-gateway-web/src/modules/AICache/index.vue:63` 把 `:draggable="mode === 'edit'"` 传给 `pageTable`；`src/components/table/pageTable.vue:54` 原样传给 iView `Table`；`node_modules/iview/src/components/table/table.vue:19,58,84` → `table-body.vue:9` → `table-tr.vue:1` 逐层透传（三处均为已声明的 `draggable` prop，链路本身是响应式的）。
2. **属性不回收的直接原因**：`node_modules/iview/src/components/table/table-tr.vue:1-3` 用一个 `v-if="draggable"` / `v-else` 的**双 `<tr>` 分支**：

   ```html
   <tr :class="rowClasses(row._index)" :draggable="draggable" @dragstart=… @drop=… @dragover=… v-if="draggable"><slot></slot></tr>
   <tr :class="rowClasses(row._index)" v-else><slot></slot></tr>
   ```

   `draggable` 由 `true → false` 时，render 产出的是**不带 `attrs`** 的第二个 `<tr>`；两个分支同为 `tr` 标签且都无 `key`（key 在父级 `table-body.vue:11` 上，值恒为行下标），Vue 走**原地 patch**（`sameVnode → patchVnode`），而不是替换元素。此时 `v-else` 分支的 vnode `data` 只有 `class`，**没有 `attrs`**，于是：

   - `updateAttrs` 的「新增/更新」循环没有可设的键 → 不会执行 `setAttribute('draggable', 'false')`；
   - `updateAttrs` 的「清理」循环本应移除该属性，但**被 Vue 的枚举属性特判挡掉** —— `vue@2.7.16` `node_modules/vue/dist/vue.runtime.esm.js:6133` 定义 `isEnumeratedAttr = makeMap('contenteditable,draggable,spellcheck')`，同文件 `:7333-7342`：

     ```js
     for (key in oldAttrs) {
       if (isUndef(attrs[key])) {
         if (isXlink(key)) { elm.removeAttributeNS(xlinkNS, getXlinkProp(key)); }
         else if (!isEnumeratedAttr(key)) { elm.removeAttribute(key); }   // ← draggable 命中枚举属性，跳过移除
       }
     }
     ```

     `draggable` 属于枚举属性，**Vue 有意不 removeAttribute**（枚举属性「缺省 ≠ false」，正确做法是显式写 `"false"`），而本实现的 `v-else` 分支又根本不带 `attrs`，于是「不删也不写」——属性值永久停留在 `"true"`。

   > 与委派方给出的「属性与事件都没被清理」相比：**属性不清理这一条已核实，但成因是 Vue 的枚举属性特判**（不是「双 `<tr>` 无 key 导致 patch 不会清理属性」这一泛化说法）；双分支只是让 `attrs` 彻底消失、从而同时错过「写 false」与「删 true」两条补救路径，是必要的触发条件。

3. **监听是否也残留（与委派方结论不同，静态推导倾向「已解除」）**：`v-else` 分支的 vnode 同样没有 `on`，`patchVnode` 会调用 `updateDOMListeners`（`vue.runtime.esm.js:7511-7523`，只要 `oldVnode.data.on` 或 `vnode.data.on` 有一方存在即进入），其 `updateListeners` 会移除「旧有新无」的监听（同文件 `:1862-1867`）：

   ```js
   for (name in oldOn) { if (isUndef(on[name])) { removed(event.name, oldOn[name], event.capture); } }
   ```

   即 `dragstart` / `dragover` / `drop` 三个监听**会随分支切换被移除**。因此「残留 `draggable="true"` → 视图模式误拖 → 静默重排草稿 → 可能被后续提交推送」这一影响链条，**静态推导的结论是「不会重排」**（没有 `drop`/`dragover` 处理函数 → `table-tr.onDrop` → `Table.dragAndDrop` 不会触发；没有 `dragover.preventDefault()` → 浏览器也不接受 drop）。本文件不把「会静默重排」写成既成事实；**需一项真机探针定性**：视图模式下拖拽两行，观察顺序是否变化（变化 → 升级为数据面缺陷；不变化 → 仅为 UI/能力信号不一致）。

#### 影响面

- **已确证**：视图模式下 `<tr>` 仍被浏览器视为可拖拽元素（用户可拖起该行、出现拖拽光标/幽灵图，松开后无效果），**UI 表现与「视图模式不可拖拽」的验收点矛盾**；`AC-DR-01` 第 5 条这类「退出编辑模式后行拖拽属性应回收」的断言在全站各模块**必然为红**（ai-cache / ai-context / traffic-mirror 同形同因）。
- **待真机复核**：是否会真正触发业务重排（依据第 3 点，静态推导为否）；无论结论如何，属性不回收本身就是缺陷 —— 因为「行可拖拽」这一能力信号已失真，任何依赖该属性判断「视图模式不会改动数据」的自动化与人工验收都失去依据。
- **不受影响**：编辑模式的拖拽排序（AC-DR-02 / AC-DR-03）、提交脏检查、两条离开拦截路径（AC-DR-04 / AC-DR-05）均已通过。

#### 恢复条件

- 需**产品侧**修复（测试侧不得改断言迁就）：让 `draggable` 在两种模式下都被显式写到同一个 `<tr>` 上，使 Vue 能按枚举属性语义写入 `"false"`。可选改法：
  1. 合并 `node_modules/iview/src/components/table/table-tr.vue` 的双分支为单个 `<tr :draggable="draggable">`，由 `onDrag/onDrop/allowDrop` 内部在 `draggable` 为假时早退（事件仍按需绑定）；
  2. 或在 `v-else` 分支显式写 `:draggable="false"`；
  3. 或退回 `table-body` 层，在 `draggable` 为假时用 `:key` 强制重建数据行元素（成本最高，不推荐）。
