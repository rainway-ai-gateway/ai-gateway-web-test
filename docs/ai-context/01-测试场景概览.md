# AI 上下文压缩 - 测试场景概览

## 模块概述

AI 上下文压缩模块负责 AI 网关「上下文压缩」能力的配置，包含**集合级压缩规则**与**单例全局设置**两部分，分别对应两个相互独立的接口：`PUT /ai-context-rules`（整体替换语义）与 `PUT /ai-context-settings`（单例单行覆盖式 upsert）。

|功能区域|说明|
|---|---|
|单页双 Tab|页面为「压缩规则」+「全局设置」两个 Tab，点击可正常切换|
|压缩规则列表|展示生效条件、压缩档位、预算上限、预留输出、操作 共 5 列；按数组顺序（优先级）展示|
|视图/编辑双模式|规则 Tab 支持视图模式与编辑模式切换；视图模式只读并可查看，编辑模式可新增/编辑/删除并「提交并生效」|
|新增与编辑|抽屉表单配置 生效条件、压缩档位、预算上限、预留输出（无 name / enabled / priority，生效条件即身份）|
|查看|独立只读抽屉，纯文案展示 4 项字段，无任何输入控件与必填标记|
|删除与清空|编辑模式下删除单条规则或以 `{"rules":[]}` 清空全部规则，提交后整体生效|
|规则字段校验|对 生效条件必填/可编译/集合内唯一、压缩档位必填四枚举、两数值 ≥ 0 进行前端校验|
|全局设置|单例表单，8 个字段（含 rewrite 嵌套两项）；设置 Tab 用「编辑 / 取消 / 保存」|
|设置字段校验|触发阈值 / 保护 token 存活率 取 `(0,1]`，保留最近图片数 / 工具结果最大字符数 / 图片估值 token ≥ 0，文本估算系数 ≥ 1，thinking 块策略 / 改写强度 枚举|

**导航路径**：路由管理 → 功能增强 → AI上下文压缩（页面路由名 `AIContextRule.list`）。

集合级写语义：无 `/{id}`、无分页、无 `enabled`/`priority`/`name`；删除即从集合数组移除，`{"rules":[]}` 表示清空；响应**不返回** 创建时间/更新时间。全局设置为单例，独立于规则集合维护（清空规则不影响设置）。

**核心变更依据**：

- 2026-10-12（变更记录 `modifications/2026-10-12-readonly-admin/ui-code-changes.md`）：引入「系统管理员（只读）」角色（后端以 `role` 枚举取代 `is_admin`，新增 `system_admin_readonly`）。只读视角（`role === 'system_admin_readonly'`）**全站隐藏所有写操作按钮**（实现为全局指令 `v-has`，只读登录态给元素加 `.v-has-hidden { display:none !important; }`），仅保留只读入口（查看 / 详情 / 查询）。`pages/ai-context.html` 只读视角**保留「查看」**，**隐藏「添加规则 / 进入(退出)编辑 / 保存」**；「全局设置」Tab 的「编辑 / 保存」写入口一并隐藏。新增只读视角用例 AX-RO-01~03。

## 配置顺序

AI 上下文压缩的规则与设置均不依赖其他模块的属主数据，可独立配置；但压缩能力的生效依赖网关侧 BFE 条件编译能力（`mod_ai_context`）与配置下发。

```text
进入 AI上下文压缩（AIContextRule.list）→ 「压缩规则」Tab
        │                                   │
        │                                   └── 视图/编辑模式切换 → 新增/编辑规则（本地草稿）
        │                                              └── 提交并生效（PUT /ai-context-rules 整体替换）
        │                                                              └── 重新 GET /ai-context-rules 回填
        └──「全局设置」Tab → 编辑 → 保存（PUT /ai-context-settings 单例 upsert）
                              └── 重新 GET /ai-context-settings 回填
```

- **两接口独立**：`/ai-context-rules`（集合）与 `/ai-context-settings`（单例）各自独立 PUT，保存规则不得连带提交设置，反之亦然
- **集合级提交**：`PUT /ai-context-rules` 单事务整体替换全部规则，后端对生效条件做控制面编译校验
- **优先级顺序**：数组顺序即匹配顺序（first-match-wins）；新增规则默认置顶（数组头部）
- **零值语义**：预算上限 / 预留输出 未传或 `0` = 用模型窗口默认/自动 clamp；前端 `0` 不写入请求体
- **设置默认值**：设置行不存在时 `GET /ai-context-settings` 返回默认值对象（HTTP 200），无时间戳

## 测试数据准备

|数据类别|准备内容|用途|
|---|---|---|
|压缩规则集合|至少 2 条规则，含不同压缩档位取值|列表展示、编辑、删除、排序|
|规则生效条件|`req_path_in("/v1/chat/completions", false)`、`default_t()` 等可编译表达式|新增与校验|
|规则压缩档位|不处理（off） / 仅无损裁剪（conservative） / 裁剪 + lite 改写（balanced） / 裁剪 + full 改写（aggressive）|档位展示与枚举校验|
|规则数值|预算上限=64000、预留输出=8192（另含 0/缺省）|格式化展示、零值省略|
|空集合|`{"rules": []}`|空列表、清空、提交|
|全局设置|默认值对象 8 字段（含 `rewrite` 嵌套）|设置展示、回填、保存、校验|

- **生效条件**：BFE 条件表达式，须能通过控制面编译，示例 `default_t()`；集合内唯一
- **压缩档位**：四枚举 `off`（不处理）/ `conservative`（仅无损裁剪）/ `balanced`（裁剪 + lite 改写）/ `aggressive`（裁剪 + full 改写）
- **预算上限**：≥ 0，未传/`0` = 用模型表窗口，示例 `64000`
- **预留输出**：≥ 0，未传/`0` = 自动 `clamp(窗口×15%, 256, 16000)`，示例 `8192`
- **触发阈值**：`(0,1]`，默认 `0.7`；**保护 token 存活率**：`(0,1]`，默认 `0.95`
- **保留最近图片数**：≥ 0，默认 `2`（0 = 完全不裁图）；**工具结果最大字符数**：≥ 0，默认 `2000`（0 = 不截断）
- **文本估算系数**：≥ 1，默认 `4`；**图片估值 token**：≥ 0，默认 `1200`
- **thinking 块策略**：`仅保留最后一条 assistant（trim-all-but-last）` / `保留全部（keep）`；**改写强度**：`保守规则包（lite）` / `激进规则包（full）`

## 接口差异/说明

复查接口定义与 UI 源码后，以下能力与当前实现的关系如下，已在用例中按实际 UI 行为描述，并标注 API 侧能力：

|能力|API / 原型|当前 UI 行为|用例处理|说明|
|---|---|---|---|---|
|页面结构|原型 Tab 双页（`initTabs` 成对 toggle 修复）|Vue 使用 iView 原生 `Tabs`/`TabPane`，不受原型缺陷影响|AX-L-01 验证 Tab 可切换|原型缺陷（§3.4）仅影响原型|
|集合级写|`PUT /ai-context-rules` 整体替换，数组顺序即优先级|编辑模式在本地集合上增删改，点「提交并生效」后整体 PUT|AX-L-14、AX-DEL-01~05 按整体替换语义验证|无单条 `/{id}` 接口|
|清空集合|`{"rules": []}` 清空全部|编辑模式删除全部规则后提交|AX-DEL-03 验证提交体为 `{"rules":[]}`|—|
|name / enabled / priority|接口无这些字段，生效条件即身份|UI 不展示名称/启用/显式优先级，仅凭数组顺序|未覆盖|禁用一条规则 = 移除（或显式「压缩档位」为「不处理（off）」兜底）|
|创建时间 / 更新时间|响应**不返回**时间戳|UI 回填时不展示、不提交|AX-DEL-04 验证重新 GET 后无时间戳|与 `ai-cache-rules` 一致|
|零值语义|预算上限/预留输出 未传或 0 = 模型窗口默认|表单仅在值 `> 0` 时写入字段，否则省略|AX-C-10、AX-V-07|`formatTokens` 将 null/0 展示为「模型默认（0）」|
|生效条件查重|接口做控制面编译校验；集合内唯一为 UI 约束|本地保存与提交前按生效条件集合去重|AX-C-08/09、AX-L-16、AX-V-03|提交前查重拦截，不发 PUT|
|设置单例|`GET /ai-context-settings` 缺行返回默认值对象|`fetchSettings` 将响应与 `DEFAULT_SETTINGS` 深合并|AX-S-02|设置独立于规则集合|
|设置取消|原型对设置/规则共用「有未保存改动→二次确认」|Vue 设置「取消」**无二次确认**，直接回滚|AX-S-05 按源码行为验证|见下方「需人工确认点」|
|分页|原型有分页器（pageSize 20）|Vue 使用 `pageTable`，集合级接口无分页参数|AX-L-06 仅验证客户端搜索/筛选|数据量大时需关注前端性能|

## 需人工确认点（原型 / api-define ↔ 源码差异）

以下差异在文档中**以 UI 源码与 `src/i18n/zh.js` 的 `aiContext` 命名空间为准**，建议人工复核后统一：

1. **退出编辑确认文案**：原型 `ai-context.html` `exitEditMode` 内容为「当前有未提交的改动，取消将丢弃这些改动，确认取消？」、确认 toast「已放弃未保存的改动」、取消 toast「已取消」；Vue 实现（规则 Tab）为 `aiContext.exitConfirm`=「当前有未提交的改动，退出编辑模式将丢弃这些改动，确认退出？」、确认 toast「已退出编辑模式」（`exitDone`）、取消 toast「已取消退出」（`exitCancelled`）。
2. **设置 Tab「取消」行为**：原型 `exitEditMode` 对规则与设置共用 `hasUnsavedChanges`（同时检查 `settings`）并在有改动时二次确认；Vue `cancelSettingsEditMode` **无二次确认**，直接回滚设置。文档按 Vue 描述。
3. **提交前生效条件查重提示**：原型为「生效条件表达式已存在，请调整后再提交」；Vue（`tipCondDuplicate`）为「生效条件已存在，集合内必须唯一」。
4. **生效条件必填提示**：原型为「请输入生效条件表达式」；Vue（`tipCondRequired`）为「请填写生效条件」。
5. **设置范围校验提示**：原型 `submitSettings` 为「触发阈值须在 (0,1] 之间」「保护 token 存活率须在 (0,1] 之间」；Vue（`tipTriggerRatio` / `tipProtectedSurvivalRate`）为「触发阈值须大于 0 且不超过 1」「保护 token 存活率须大于 0 且不超过 1」。
6. **校验呈现方式**：原型设置/抽屉校验用 `Prototype.toast` 弹提示；Vue 为 FormItem 内联错误 + 整体 `com.tipValidateError`（「请检查参数填写是否规范!」）。文档按 Vue 描述。
