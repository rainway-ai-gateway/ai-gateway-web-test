## 4. 字段校验矩阵

### 字段校验规则矩阵（总览）

|字段|合法性条件（api-define）|前端校验实现|前端提示文案（`aiContext`）|接口侧校验|
|---|---|---|---|---|
|`rules`|必填；`null` 按 `[]` 处理|—|—|必填；`null` 按 `[]` 处理|
|`rules[].cond`|必填、非空、控制面编译校验；集合内唯一|`validateCond`（`condErrmsg` 优先，其次非空）；`onFormSubmit`/`submitRules` 集合去重|`tipCondRequired`「请填写生效条件」；`tipCondDuplicate`「生效条件已存在，集合内必须唯一」|非法表达式 422|
|`rules[].mode`|必填；`off` / `conservative` / `balanced` / `aggressive`|`validateMode`（`MODES` 四枚举）|`tipModeInvalid`「压缩档位不合法」|缺失或非法 422|
|`rules[].max_context_tokens`|≥ 0|`validateNonNegative`|`tipMaxTokensNegative`「预算上限不能小于 0」|≥ 0，逾界 422|
|`rules[].reserve_tokens`|≥ 0|`validateNonNegative`|`tipReserveTokensNegative`「预留输出不能小于 0」|≥ 0，逾界 422|

> 规则为**集合级**接口，任一元素校验失败时整体 `422`、集合不变；前端在表单「本地保存」与集合「提交并生效」两处拦截。

### AX-V-01：生效条件必填

**功能模块**: 字段校验  
**优先级**: P0  
**用例编号**: AX-V-01  
**设计依据**: `src/modules/AIContext/components/RuleForm.vue`（`validateCond`）；`ai-context-rules.md` §1（`cond` 必填、非空）；`src/i18n/zh.js` `aiContext.tipCondRequired`、`com.tipValidateError`

#### 前置条件

- 已打开新增或编辑抽屉

#### 测试步骤

1. 保持生效条件为空（不输入表达式）
2. 点击「本地保存」

#### 预期结果

1. `validateCond`：`condErrmsg` 为空时判定非空，空值回调错误「请填写生效条件」（`tipCondRequired`）
2. `FormItem` `prop="cond"` 内联展示错误，保存被拦截
3. 整体校验失败时弹出 `com.tipValidateError`「请检查参数填写是否规范!」
4. 规则不写入本地集合

### AX-V-02：生效条件控制面编译校验

**功能模块**: 字段校验  
**优先级**: P0  
**用例编号**: AX-V-02  
**设计依据**: `src/modules/AIContext/components/RuleForm.vue`（`onExpressionChanged`、`validateCond` 的 `condErrmsg`）；`ai-context-rules.md` §1「控制面编译校验（非法表达式 422）」

#### 前置条件

- 已打开新增或编辑抽屉，表达式编辑块（`Expression`）可用
- 控制面可返回编译结果（`errmsg`）

#### 测试步骤

1. 在表达式编辑块输入非法/不可编译的表达式（如括号不闭合）
2. 观察校验反馈
3. 点击「本地保存」

#### 预期结果

1. `Expression` 组件通过 `expressionChanged` 回传 `{ expression, errmsg }`，写入 `formData.cond` 与 `formData.condErrmsg`，并触发 `validateField('cond')`
2. `validateCond` 优先校验 `condErrmsg`：非空时直接以该 `errmsg` 报错
3. 本地保存被拦截，整体提示「请检查参数填写是否规范!」
4. 接口侧：提交并生效时对非法表达式返回 `422`，整体拒绝、集合不变

### AX-V-03：生效条件集合内唯一

**功能模块**: 字段校验  
**优先级**: P0  
**用例编号**: AX-V-03  
**设计依据**: `ai-context-rules.md` §1「`cond` 即规则身份、集合内唯一」；`src/modules/AIContext/index.vue`（`onFormSubmit`、`submitRules`）；`src/i18n/zh.js` `aiContext.tipCondDuplicate`

#### 前置条件

- 集合内存在已知生效条件的规则

#### 测试步骤

1. 表单级：新增或编辑时，使生效条件与集合内另一条规则相同，点击「本地保存」
2. 提交级：构造两条生效条件相同的规则，点击「提交并生效」

#### 预期结果

1. 表单级：`onFormSubmit` 以生效条件查重（编辑时 `excludeIndex` 排除自身），命中提示「生效条件已存在，集合内必须唯一」（`tipCondDuplicate`），不写入集合
2. 提交级：`submitRules` 剔除空生效条件后对全集合做 Set 去重，命中提示 `tipCondDuplicate`，**不发送** `PUT`
3. 生效条件是集合内规则身份，必须唯一（接口无 `id`/`name` 字段）
4. 集合内唯一性由 UI 保证，接口侧以控制面编译校验兜底

### AX-V-04：压缩档位必填四枚举

**功能模块**: 字段校验  
**优先级**: P0  
**用例编号**: AX-V-04  
**设计依据**: `src/modules/AIContext/components/RuleForm.vue`（`validateMode`、`MODES`）；`ai-context-rules.md` §1（`mode` 必填、四枚举）；`src/i18n/zh.js` `aiContext.tipModeInvalid`

#### 前置条件

- 已打开新增或编辑抽屉

#### 测试步骤

1. 观察「压缩档位」下拉的可选项与默认值
2. 通过自动化注入非法压缩档位值并尝试提交

#### 预期结果

1. `validateMode`：值不在 `['off','conservative','balanced','aggressive']` 时报「压缩档位不合法」（`tipModeInvalid`）
2. 下拉限定四枚举，常规 UI 操作不会产生非法值
3. 默认值为 `off`（不处理）
4. 接口侧：缺失或非法压缩档位返回 `422`，控制面前置拦截

### AX-V-07：两个数值字段空值与零值合法

**功能模块**: 字段校验  
**优先级**: P1  
**用例编号**: AX-V-07  
**设计依据**: `src/modules/AIContext/components/RuleForm.vue`（`validateNonNegative` 空值放行、`handleSubmit` 仅 `>0` 写入）；`ai-context-rules.md` §1（未传/`0` 合法）

#### 前置条件

- 已打开新增或编辑抽屉

#### 测试步骤

1. 将「预算上限」「预留输出」均留空，点击「本地保存」

### AX-V-08：校验错误提示单行展示与整体提示

**功能模块**: 字段校验  
**优先级**: P1  
**用例编号**: AX-V-08  
**设计依据**: `src/modules/AIContext/components/RuleForm.vue`（`FormItem` 内联错误、`handleSubmit` 整体提示）；`src/i18n/zh.js` `com.tipValidateError`

#### 前置条件

- 已打开新增或编辑抽屉

#### 测试步骤

1. 构造多个字段同时非法（如生效条件为空且预算上限为负）
2. 点击「本地保存」

#### 预期结果

1. 各字段错误经 iView `FormItem` 内联展示于对应控件下方（单行展示）
2. 任一字段校验失败时，`handleSubmit` 的 `validate` 回调 `valid=false`，弹出整体提示「请检查参数填写是否规范!」（`com.tipValidateError`）
3. 抽屉保持打开，便于修正后重新提交
4. 不符合校验规则的数据不写入集合，也不发送写请求
