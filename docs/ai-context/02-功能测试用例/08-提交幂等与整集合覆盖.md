## 8. 提交幂等与整集合覆盖（2026-11-01 补审计）

> 审计背景（2026-11-01，ai-context 深度审计，与 ai-cache 同源）：
>
> - 规则 Tab「提交并生效」与设置 Tab「保存」均为**整体 PUT**，按钮只有 `:loading`；
>   全模块无「连点只发一次」用例（ai-cache 已在 AC-CC-01 补齐同类）。
> - 集合级 PUT 无版本号/乐观锁：编辑期间他人发布的集合会被本次提交**整体覆盖**
>   （last-write-wins），与 cluster `BC-C-01`、intent-config `IC-CC-01` 同语义。
>
> 注：ai-context 规则**没有 `name` 字段**，集合内身份即 `cond`；断言一律以 cond 标识。

### AX-CC-01：连点「提交并生效」只发一次 PUT

**功能模块**: 压缩规则 / 提交  
**优先级**: P1  
**用例编号**: AX-CC-01  
**设计依据**: `index.vue` `submitRules`（`submittingRules` + `:loading`）；iView loading 态按钮 `pointer-events: none`

#### 前置条件

- 规则集合已有 1 条规则；进入编辑模式后本地新增 1 条（产生 dirty，提交按钮可用）

#### 测试步骤

1. 用 `page.route` 把 `PUT /ai-context-rules` 延迟 1500ms（模拟慢网络）
2. 点击「提交并生效」；300ms 后再次点击同一按钮（loading 中，预期不可点）
3. 等待回到视图模式

#### 预期结果

1. 全程只产生 **1 次** PUT（第二次点击被 loading 拦截）
2. 提交成功后回到视图模式

### AX-CC-02：他人先发布被本次提交整集合覆盖（last-write-wins）

**功能模块**: 压缩规则 / 并发  
**优先级**: P1  
**用例编号**: AX-CC-02  
**设计依据**: `submitRules` 整体 PUT + `buildRulePayload`（本地数组全量提交），无版本校验

#### 前置条件

- 集合：`req_path_in("/ax_cc02_mine", false)`；编辑模式下本地新增 `req_path_prefix_in("/ax_cc02_local", true)`

#### 测试步骤

1. 编辑期间通过接口把集合整体替换为 `req_path_in("/ax_cc02_theirs", false)`
2. 确认服务端已是他人版本，页面仍显示本地快照
3. 点击「提交并生效」，抓取 PUT 体
4. `GET` 回读

#### 预期结果

1. PUT 体为**本地快照**：含 local 与 mine 两条，**不含** theirs
2. 回读集合 = 本地版本，他人规则被覆盖消失
3. 页面回到视图模式（结论记录：整体覆盖 = last-write-wins，无冲突提示）
