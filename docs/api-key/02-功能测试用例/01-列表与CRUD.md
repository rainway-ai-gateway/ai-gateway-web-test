## 3. API-Key管理

> **归属场景**: 场景三(管理员配置API-Key)

### 3.1 API-Key列表展示

**功能模块**: API-Key管理  
**优先级**: P1  
**用例编号**: EM-K-01

#### 前置条件

- 系统已正常运行
- 已使用管理员账号登录系统

#### 测试步骤

1. 打开浏览器，访问AI网关管理控制台
2. 在左侧导航栏中，点击展开"消费者管理"分组
3. 在"消费者管理"分组下，点击"API Key管理"菜单项
4. 观察页面加载情况
5. 查看页面顶部的搜索和筛选区域
6. 查看API-Key列表表格

#### 预期结果

- 页面成功加载，显示"API Key管理"标题
- 左侧显示蓝色"添加"按钮
- 搜索和筛选区域包含：
  - Key ID 搜索框，可按 Key ID 搜索
  - Key值搜索框，占位文字为"请输入Key值查询"
  - 描述搜索框，占位文字为"请输入描述查询"
  - 状态筛选下拉框，占位文字为"请选择状态"，选项包含"启用"、"停用"
  - 配额类型筛选下拉框，占位文字为"请选择配额类型"，选项包含"有限"、"无限"
  - 配额搜索框，占位文字为"请输入配额查询"
  - 限流状态筛选下拉框，占位文字为"请选择限流状态"，选项包含"已启用"、"未启用"
  - 挂载Entity搜索框，占位文字为"请输入挂载Entity查询"
- API-Key列表表格正确显示，包含以下列：
  - Key标识列
  - Key值列（脱敏显示）
  - 描述列
  - 状态列：显示"启用"或"停用"标签
  - 配额类型列：显示"有限"或"无限"
  - 配额列：显示已使用/总量（如"0 / 100.0M"）
  - 限流状态列：显示"已启用"或"未启用"标签
  - 挂载Entity列：显示Entity名称或"-"
  - 操作列（宽度300）：包含"管理路由规则"（绿色按钮，第一位）、"编辑"（蓝色按钮）、"删除"（红色按钮）
- 页面底部显示分页控件
- **空态展示**：无数据时显示空态提示，不显示空白表格
- 长文本不破坏表格布局（截断或折行，见 [§6](#6-布局合理性检查清单横切)）
- **样式变化**：状态列"启用"/"停用"使用不同颜色标签区分；限流状态列同理
- **降级展示**：接口异常时显示友好错误提示，不白屏或无限 loading
- **长文本布局**：表格列长文本截断或折行，不撑破列宽；Key值脱敏后不撑破列宽，可复制

### 3.5 创建API-Key-带限流策略

**功能模块**: API-Key管理  
**优先级**: P0  
**用例编号**: EM-K-05

#### 前置条件

- 已登录系统并进入API-Key管理页面

#### 测试步骤

1. 点击"添加"按钮
2. 在"描述"输入框中输入描述（如"带限流的API-Key"）
3. 在"限流配置"区域配置限流策略：
   - 启用限流：选择"是"
   - TPM规则：点击"添加规则"按钮，填写规则：
     - 规则名称：输入规则名（如"tpm_rule_1"）
     - 适用模型：选择"全部模型"（或从模型接口获取的具体模型）
     - 时间窗口(分)：输入1-360之间的数值（如1）
     - 最大Token数：输入任意正整数（如10000，显示为10,000，带千位分隔符）
     - 滑动步长(分)：输入数值（如1）
   - RPM规则：点击"添加规则"按钮，填写规则：
     - 规则名称：输入规则名（如"rpm_rule_1"）
     - 适用模型：选择"全部模型"（或从模型接口获取的具体模型）
     - 时间窗口(分)：输入1-360之间的数值（如1）
     - 最大请求数：输入1-360之间的数值（如100，显示为100，带千位分隔符），且必须小于等于最大Token数
   - 最大并发：下拉选择"不限制"/"封禁"/"限制并发数"（选择"限制并发数"后输入数值，如50），默认值为"不限制"
4. 点击"提交"按钮
5. 观察列表显示

#### 预期结果

- 创建成功
- 列表中该API-Key的限流状态列显示"已启用"

#### 测试数据

- 描述：带限流的API-Key
- TPM规则名称：tpm_rule_1
- TPM时间窗口：1
- TPM最大Token数：10000
- TPM滑动步长：1
- RPM规则名称：rpm_rule_1
- RPM时间窗口：1
- RPM最大请求数：100
- 最大并发：50

### 3.11 创建API-Key-允许子网校验

**功能模块**: API-Key管理  
**优先级**: P1  
**用例编号**: EM-K-11

#### 前置条件

- 已登录系统并进入API-Key管理页面

#### 测试步骤

1. 点击"添加"按钮
2. 在"描述"输入框中输入描述（如"测试子网校验"）
3. 在"允许子网"输入框中输入重复的CIDR：
   - 第一行：192.168.0.0/24
   - 第二行：192.168.0.0/24（与第一行重复）
4. 点击"提交"按钮
5. 观察校验提示
6. 清除输入框，输入包含关系的CIDR：
   - 第一行：192.168.0.0/24
   - 第二行：192.168.0.0/25（被第一行包含）
7. 点击"提交"按钮
8. 观察校验提示
9. 清除输入框，输入不重复且无包含关系的CIDR：
   - 第一行：192.168.0.0/24
   - 第二行：192.168.1.0/24
10. 点击"提交"按钮
11. 观察创建结果
12. 清除输入框，输入合法 IPv6 CIDR：
    - 第一行：2001:db8::/32
    - 第二行：2001:db8:1::/48
13. 点击"提交"按钮
14. 观察创建结果
15. 清除输入框，输入非法 IPv6 CIDR（前缀长度超限）：
    - 第一行：2001:db8::/129
16. 点击"提交"按钮
17. 观察校验提示
18. 清除输入框，混合输入 IPv4 和 IPv6：
    - 第一行：192.168.0.0/24
    - 第二行：2001:db8::/32
19. 点击"提交"按钮
20. 观察创建结果

#### 预期结果

- 步骤4-5：输入重复CIDR时，点击提交后弹窗不关闭，显示错误提示（如"存在重复的子网配置"）
- 步骤7-8：输入包含关系的CIDR时，点击提交后弹窗不关闭，显示错误提示（如"存在包含关系的子网配置"）
- 步骤10-11：输入不重复且无包含关系的IPv4 CIDR时，创建成功
- 步骤13-14：输入合法IPv6 CIDR时，创建成功（IPv6格式应被支持）
- 步骤16-17：输入非法IPv6 CIDR（前缀长度 >128）时，点击提交后弹窗不关闭，显示格式错误提示
- 步骤19-20：混合输入IPv4和IPv6 CIDR时，创建成功

#### 测试数据

- 描述：测试子网校验
- 重复子网：192.168.0.0/24（两行）
- 包含子网：192.168.0.0/24 和 192.168.0.0/25
- 正常IPv4子网：192.168.0.0/24 和 192.168.1.0/24
- 合法IPv6子网：2001:db8::/32 和 2001:db8:1::/48
- 非法IPv6子网：2001:db8::/129（前缀长度超过128）
- 混合子网：192.168.0.0/24 和 2001:db8::/32

### 3.19b API-Key详情数据与接口一致性

**功能模块**: API-Key管理  
**优先级**: P1  
**用例编号**: EM-K-19b

#### 前置条件

- 已登录系统并进入API-Key管理页面
- 已创建API-Key（含配额、限流、挂载Entity）

#### 测试步骤

1. 通过接口获取API-Key详情（GET /api-keys/{id}）
2. 在列表中点击该API-Key行打开详情抽屉
3. 验证详情展示数据与接口返回一致：
   - 基本信息：描述、状态
   - 配额信息：无限配额、配额不足时放行、配额总量、配额单位、已使用、剩余量、重置周期、使用进度
   - 限流信息：限流状态
   - 挂载Entity

#### 预期结果

- 详情抽屉正常打开
- 基本信息字段与接口返回一致：
  - 描述与 `description` 一致
  - 状态与 `enabled` 一致（启用/停用）
- 配额信息字段与接口返回一致：
  - 无限配额与 `quota_plan.unlimited` 一致
  - 配额不足时放行与 `quota_plan.allow_over_quota` 一致
  - 配额类型与 `quota_plan.quota_type` 一致（有限/无限）
  - 配额总量与 `quota_plan.quota` 一致（带千位分隔符）
  - 配额单位与 `quota_plan.quota_unit` 一致
  - 已使用与 `quota_plan.used` 一致（含百分比）
  - 剩余量与 `quota_plan.remaining` 一致（带千位分隔符）
  - 重置周期与 `quota_plan.reset_cycle` 一致
  - 使用进度条百分比与已使用/总量比例一致
- 限流状态与接口返回的 `rate_limit_policy.enabled` 一致
- 挂载Entity与接口返回的 `entity_id` 对应的Entity名称一致
