### 3.30 E2E-API-Key全流程

**功能模块**: API-Key管理（依赖 Entity 类型 + 组织）  
**优先级**: P0  
**用例编号**: EM-K-30  
**归属场景**: 场景三步骤15 / 场景四 EM-J-01  
**自动化**: `test_05_entity_full_journey.spec.js`（第一条 EM-J-01 覆盖本用例目标）

**设计依据**: 复用 EM-T-02、EM-E-02、EM-K-02/04/06、EM-K-16、EM-K-19、EM-K-18（删除）、EM-T-12、EM-E-16 的单步预期  
**实现状态**: 已对齐（`test_05_entity_full_journey` EM-J-01）

#### 前置条件

- 已登录系统
- **前置 Entity 类型与 Entity 均通过 UI 创建**（非 API 造数）
- 按配置顺序：Entity 类型 → Entity 组织 → API-Key

#### 测试步骤

1. **Entity 类型管理**：UI 创建类型（级别 1），搜索确认列表可见
2. **Entity 组织管理**：UI 创建根节点 Entity（名称 + 上一步类型），搜索确认可见
3. **API Key 管理**：UI 创建 API-Key：
   - 填写描述
   - 无限配额 = 否，配额总量 = 1000，单位 = total_token，重置周期 = 永不重置
   - 挂载 Entity = 步骤 2 的 Entity
   - 提交
4. **API Key 管理**：UI 编辑该 Key，修改描述，提交
5. 点击列表**数据行**打开 API-Key 详情，点击「重置配额」，输入新配额总量与重置原因，确认
6. **API Key 管理**：UI 删除该 Key（确认弹窗点确定）
7. **Entity 组织管理**：UI 删除步骤 2 的 Entity
8. **Entity 类型管理**：UI 删除步骤 1 的类型

#### 预期结果

- 步骤 1~2：类型、Entity 创建成功（预期同 EM-T-02、EM-E-02）
- 步骤 3：Key 创建成功；列表「挂载 Entity」列显示 Entity 名称；配额类型为「有限」
- 步骤 4：描述更新成功，列表显示新描述
- 步骤 5：重置配额弹窗可打开；提交后重置成功（预期同 [EM-K-19](#319-重置api-key配额)）
- 步骤 6：Key 从列表移除（预期同 [EM-K-18](#318-删除api-key)）
- 步骤 7~8：Entity、类型均从列表移除

#### 测试数据

- **类型名 / Entity 名**：运行时唯一生成
- **API-Key 描述**：`API-Key_journey_{timestamp}`
- **编辑后描述**：原描述 + `_edited`
- **配额总量（创建）**：1000（显示为1,000）
- **重置配额总量**：100000000（显示为100,000,000，见 DOC 约定）
- **重置原因**：月度重置
