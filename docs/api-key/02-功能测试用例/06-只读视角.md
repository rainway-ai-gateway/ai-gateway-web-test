## 8. 只读管理员视角（写操作隐藏）

> 变更依据：`design-docs/modifications/2026-10-12-readonly-admin/ui-code-changes.md`（已 Review 通过）。
> 后端以 `role` 枚举取代 `is_admin`（`system_admin` / `system_admin_readonly`）；只读视角（`role === 'system_admin_readonly'`）**全站隐藏所有写操作按钮**，仅保留只读入口（详情 / 查看 / 查询）。前端实现为全局指令 `v-has`：只读登录态下给挂载元素加 `.v-has-hidden { display:none !important; }`。
> 密钥读端点（`GET /api-keys`、`GET /api-keys/{id}`）按角色返回：系统管理员明文；只读返回**掩码值**（由后端 `lib/xmask` 完成，前端原样展示，无需新增脱敏逻辑）。

### EM-K-RO-01：只读视角列表工具栏写按钮隐藏

**功能模块**: API-Key 管理
**优先级**: P0
**用例编号**: EM-K-RO-01
**生命周期**: 已通过（2026-10-12）
**自动化**: tests/api-key/test_06_api_key_readonly.spec.js
**OpenAPI**: `GET /api-keys`

#### 前置条件

1. 以**只读系统管理员**登录（`role=system_admin_readonly`，原型 `viewer` 账号语义）。
2. 「API-Key 管理」菜单可达并进入页面。

#### 测试步骤

1. 进入「API-Key 管理」页面。
2. 观察列表工具栏（筛选栏区域）的按钮区。
3. 逐项核对工具栏中写操作入口的可见性。

#### 预期结果

1. 工具栏**不显示**「添加」（创建 API-Key）写操作按钮（对应 EM-K-01 中管理员可见的蓝色「添加」按钮）。
2. 只读视角下工具栏不含任何创建 / 新增写入口，仅保留检索、筛选等只读控件。
3. 切换为系统管理员（`role=system_admin`）登录时，该「添加」按钮正常显示（对照组）。

#### 测试数据

- 只读账号：`role=system_admin_readonly`
- 管理员账号：`role=system_admin`

#### 补充说明

- 隐藏实现：写按钮挂全局指令 `v-has`，只读视角加 `.v-has-hidden`；前端隐藏外，后端对写端点做 403 兜底。

### EM-K-RO-04：只读视角密钥掩码展示与鉴权失效

**功能模块**: API-Key 管理
**优先级**: P0
**用例编号**: EM-K-RO-04
**生命周期**: 已通过（2026-10-12）
**自动化**: tests/api-key/test_06_api_key_readonly.spec.js
**OpenAPI**: `GET /api-keys`、`GET /api-keys/{id}`

#### 前置条件

1. 存在至少一条 API-Key 记录，其明文 `key` 长度 > 8。
2. 分别准备只读系统管理员与系统管理员登录态。

#### 测试步骤

1. 以**只读系统管理员**调用 `GET /api-keys`，查看返回项中的 `key` 字段。
2. 以只读系统管理员调用 `GET /api-keys/{id}`，查看详情返回的 `key` 字段。
3. 以系统管理员调用同样两个端点，查看 `key` 字段。
4. 尝试使用只读视角返回的掩码值作为 API-Key 发起鉴权请求。

#### 预期结果

1. 只读视角下两处 `key` 均返回**掩码值**，规则：长度 > 8 → 前 4 位 + `********` + 后 4 位；4 < 长度 ≤ 8 → 前 2 位 + `****` + 后 2 位；长度 ≤ 4 → 全掩码。
2. 掩码值在列表与详情抽屉中**原样展示**（前端不做二次脱敏）。
3. 系统管理员视角两处 `key` 均返回**明文**（对照组）。
4. 掩码值**不可用于鉴权**（不能作为 API-Key 调用业务接口）。

#### 测试数据

- 明文示例：`sk-abcdefghijklmn`（>8）→ 掩码 `sk-a********klmn`
- 边界样本：长度 8、长度 4、长度 3

#### 补充说明

- 脱敏由后端 `lib/xmask` 完成；前端只消费返回值，故本用例以**接口层**验证为主，UI 侧重展示一致性。
