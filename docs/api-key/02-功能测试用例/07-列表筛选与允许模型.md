## 9. 列表配额类型筛选 / 允许模型链路（2026-11-01 补审计）

> 审计背景（2026-11-01，api-key 模块深度审计）：
>
> - 列表「配额类型」列是 8 个可搜索列中**唯一没有用例**的维度；页对象 `selectApiKeyQuotaTypeFilter` 写好后从未被调用（与 entity「级别筛选」同型缺口）。该 helper 原用 `.ivu-form-item` 定位，而 pageTable 搜索区是**表格行**（每个 td 一个控件），选择器永不命中——本轮一并修正。
> - 「允许模型」多选此前只在详情一致性（EM-K-55）里随整段文本断言，没有「选具体模型 → 提交 → 接口回读」的链路验证（与 entity EM-E-63 同型缺口）。

### EM-K-68：列表按配额类型筛选

**功能模块**: 列表与筛选  
**优先级**: P2  
**用例编号**: EM-K-68  
**设计依据**: `ApiKeyList.vue` `quota_plan_unlimited` 列（`searchable` + `searchType: 'select'`，选项 无限/有限）；`pageTable` 纯前端过滤  
**OpenAPI**: `GET /api-keys` 响应体 `quota_plan.unlimited`

#### 前置条件

- 造数：同一 Entity 下 1 个无限配额 API-Key（`unlimited_quota=true`）、1 个有限配额（`quota_plan.unlimited=false`，配额 1000 total_token）

#### 测试步骤

1. 描述搜索 `ak68_` 收窄到两条记录
2. 「配额类型」下拉选「无限」
3. 改选「有限」

#### 预期结果

1. 选「无限」时仅无限配额行可见，有限配额行被过滤
2. 选「有限」时仅有限配额行可见，无限配额行被过滤

### EM-K-69：允许模型选择与回读

**功能模块**: 创建 API-Key / 模型白名单  
**优先级**: P1  
**用例编号**: EM-K-69  
**设计依据**: `Upsert.vue`「允许模型」`el-select multiple`（`*` + 集群模型分组）；默认值为 `['*']`  
**OpenAPI**: `POST /api-keys` body `models`；`GET /api-keys/{id}` 响应体 `models`

#### 前置条件

- 环境 `GET /clusters` 至少返回 1 个具体模型；无模型时用例跳过
- 已存在可挂载的 Entity

#### 测试步骤

1. 打开「添加 API-Key」抽屉，填写描述
2. 摘掉「允许模型」默认的「全部模型」标签，选择具体模型 A
3. 提交并抓取 `POST /api-keys` 请求体
4. `GET /api-keys/{id}` 回读

#### 预期结果

1. 抽屉内「允许模型」选中项为模型 A（不残留 `*`）
2. 请求体 `models == ["<A>"]`
3. 接口回读 `models == ["<A>"]`（未被后端丢弃或归一化）
