### BT-L-01：列表加载与游标分页

**功能模块**: 批量任务列表
**优先级**: P0
**用例编号**: BT-L-01
**OpenAPI**: `GET /batches`

#### 前置条件

1. 以系统管理员登录，具备 `FeatureBatch` 读权限。
2. 「消费者管理 → 批量任务」（`BatchTask.list`）菜单可达。
3. 环境中存在 ≥ 2 页批量任务数据（`PAGE_LIMIT=50`）。

#### 测试步骤

1. 进入「批量任务」页面，等待列表加载完成。
2. 抓取首页请求，核对 Query 参数。
3. 观察翻页区按钮状态与页码 / 条数提示。
4. 点击「下一页」，抓取第二页请求。
5. 点击「上一页」，观察请求与列表。
6. 在筛选栏输入一个未查询的服务商值，直接点「下一页」，核对请求参数。
7. 点击「首页」，观察列表与按钮状态。

#### 预期结果

1. 页面标题为「批量任务」，筛选栏包含「任务状态 / 服务商 / API Key ID / 创建时间起 / 创建时间止」与「查询 / 重置」。
2. 首页请求使用**游标分页**参数：`cursor`（首页为空 / 不传）、`limit`（`PAGE_LIMIT=50`），**不携带** `page` / `page_size`。
3. 表格渲染首页数据；「下一页」可用（响应 `next_cursor` 非空）；「首页」「上一页」置灰；翻页区显示「第 1 页」与「本页 M 条」，且分页条位于表格下方**左侧、与表格左边界对齐**（「下一页」与页码/条数之间保留间距）。
4. 点击「下一页」时请求携带上一页响应返回的 `next_cursor`；列表切换为第二页数据；页码变为「第 2 页」，「首页」「上一页」可点。
5. 点击「上一页」回到首页数据；请求游标回退到上一页对应位置。
6. 未点「查询」时翻页**沿用已应用的筛选条件**：第二页请求不携带新输入的服务商值（条件快照）。
7. 点击「首页」直接回到第 1 页（无需逐页回退），「首页」「上一页」重新置灰。

#### 测试数据

- **分页参数**：`cursor`（首页空）、`limit=50`
- **`next_cursor` 语义**：空串 = 无更多数据

#### 补充说明

若首页 `next_cursor` 为空串，则「下一页」按钮应立即 `disabled`（与 BT-L-10 联动）；末页若因恰好取满一页而出现空列表，前端会自动退回上一页（与 BT-L-10 联动）。

### BT-L-05：按创建时间范围筛选

**功能模块**: 批量任务列表
**优先级**: P1
**用例编号**: BT-L-05
**OpenAPI**: `GET /batches`（`start_time` / `end_time`）

#### 前置条件

1. 环境存在分布在多个日期的批量任务。

#### 测试步骤

1. 在「创建时间起」选择日期 `D1`。
2. 在「创建时间止」选择日期 `D2`（`D2 > D1`）。
3. 点击「查询」。
4. 核对请求参数与结果。

#### 预期结果

1. 请求携带 `start_time` / `end_time`（Unix 时间戳，秒），按创建时间**闭区间**过滤。
2. 列表仅返回创建时间落在 `[D1, D2]` 内的任务。
3. 只填起始或只填结束时间时，仅按单边过滤（不报错）。

#### 测试数据

- **`start_time` / `end_time`**：int64 时间戳（秒）
- **提示**：与 `end_time` 同时传入时查询该时间闭区间

#### 补充说明

- **点「查询」前必须先关闭日期面板**：iView DatePicker 展开时，浮层外的**第一次点击**会被其 `v-click-outside`（capture 阶段的 mousedown / click 均 `preventDefault` + `stopPropagation`）整体吞掉，表现为「点了查询但后端 0 条 `GET /batches` 请求」。手工执行时同样是「先点浮层外一次再点查询」，两次点击才是完整动作。
- **面板不会自己关**：`fill` + `Enter` 后 iView 把 Enter 当作「选中当前聚焦日」，面板保持展开，且此时焦点已不在输入框，`Esc` 不会经 picker 的 keydown 关闭面板。因此自动化必须在点「查询」前显式收起浮层（本项目 `Vue.use(iView, { i18n })` 未开 `transfer`，浮层就地渲染在 `.ivu-date-picker` 内；「面板是否打开」按「可见的 `.ivu-select-dropdown` 且含 `.ivu-picker-panel-body`」判定）。

### BT-L-10：游标翻页与按钮置灰

**功能模块**: 批量任务列表
**优先级**: P1
**用例编号**: BT-L-10
**OpenAPI**: `GET /batches`（`cursor` / `next_cursor`）

#### 前置条件

1. 环境存在恰好 1 页批量任务（`next_cursor` 为空串）与 ≥ 2 页两类场景。

#### 测试步骤

1. 在 1 页数据的场景下进入列表，观察「首页」「上一页」「下一页」按钮。
2. 在 ≥ 2 页数据的场景下进入列表，翻至最后一页。
3. 在最后一页观察「页面按钮」，再点击「首页」。
4. 观察「上一页」按钮在首页的状态。

#### 预期结果

1. 首页且 `next_cursor` 为空串时，「首页」「上一页」「下一页」均 `disabled`。
2. ≥ 2 页时首页「首页」「上一页」`disabled`、「下一页」可用；翻至最后一页后（`next_cursor` 为空串），「下一页」`disabled`，「首页」「上一页」可点；页码显示「第 N 页」并随翻页递增。
3. 点击「首页」直接回到第 1 页，页码回到「第 1 页」，「首页」「上一页」重新 `disabled`。
4. 首页「上一页」`disabled`；翻页后「上一页」可用，返回后按钮状态随之更新。

#### 测试数据

- **`next_cursor`**：空串 = 无更多数据

#### 补充说明

- **前置数据要求**：`GET /batches` 的数据只能由数据面透传产生（控制面见不到造数入口），环境为空或不足 2 页时「首页即末页」，置灰语义无法区分首页与末页 —— 自动化在该前置条件不成立时按既有做法 `test.skip`（同 BT-L-04 / BT-L-11 的数据守卫），不改断言。

#### 测试步骤

1. 抓取列表请求 `GET /batches` 的完整返回体，定位目标任务所在行。
2. 逐一比对表格 6 列展示值与接口返回字段值。
3. 悬停「请求计数」列头帮助图标，核对 tooltip 文案。
4. 核对状态列、结算状态列 Tag 文案与接口枚举值的映射。

#### 预期结果

列表 6 列依次为：批量任务ID / 状态 / 请求计数 / 结算状态 / 创建时间 / 操作（2026-10-20 UI 改版由 12 列精简，服务商 / API Key ID / Entity ID / 用量 / 预留金额 / 结算金额 6 列已移除）。

字段比对（校验方式 = 文本一致 / 数值一致 / 数组逐项比对 / 时间戳转换一致，与接口返回 JSON 一致）：

- **batch_id**（文本一致）：批量任务ID 列与接口 `batch_id` 相同（string 原样展示）
- **status**（文本一致，含中文（枚举）映射）：状态列 Tag 文案与接口 `status` 的映射一致，如 `in_progress` → 「进行中（in_progress）」
- **request_counts.total / .completed / .failed**（数值一致，展示形如 `总数/完成/失败`）：请求计数列展示 `100 / 40 / 1`，与接口 `request_counts` 三个子字段逐一相等
- **settle_status**（文本一致，含中文（枚举）映射）：结算状态列 Tag 文案与接口 `settle_status` 映射一致，如 `reserved` → 「已预留（reserved）」
- **created_at**（时间戳转换一致）：创建时间列与接口 `created_at`（RFC3339）转换后的日期时间一致
- **操作**（文本一致，非接口字段）：操作列为行内按钮「详情 / 取消」，与 `status` 终态判断联动

**一致性比对矩阵**

| UI 展示项 | 接口字段 | 校验方式 | 通过标准 |
| --- | --- | --- | --- |
| 批量任务ID | `batch_id` | 文本一致 | 逐字相同 |
| 状态 | `status` | 文本一致（枚举映射） | Tag 文案 = 中文（枚举），如 进行中（in_progress） |
| 请求计数 | `request_counts.total` / `.completed` / `.failed` | 数值一致 | 展示 `总数/完成/失败`，三值均相等 |
| 结算状态 | `settle_status` | 文本一致（枚举映射） | Tag 文案 = 已预留/已结算/已释放（枚举） |
| 创建时间 | `created_at` | 时间戳转换一致 | 与 RFC3339 转换后一致 |
| 操作 | 非接口字段 | 文本一致 | 行内按钮「详情 / 取消」 |

**整体预期**：

1. 进入列表页时调用 `GET /batches`，接口返回 200
