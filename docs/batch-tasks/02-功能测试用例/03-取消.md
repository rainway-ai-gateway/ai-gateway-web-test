## 3. 取消

**功能模块**: 批量任务取消
**设计依据**: `prototype-design/pages/batches.html` 取消交互、`src/i18n/zh.js` `batchTasks.*`
**OpenAPI**: `POST /batches/{batch_id}/cancel`

---

### BT-C-01：取消二次确认

**功能模块**: 批量任务取消
**优先级**: P1
**用例编号**: BT-C-01
**OpenAPI**: `POST /batches/{batch_id}/cancel`

#### 前置条件

1. 列表中存在**非终态**任务（`validating` / `queued` / `in_progress` / `finalizing`）。

#### 测试步骤

1. 点击该行「取消」。
2. 观察确认弹窗内容。
3. 点击「取消」（弹窗按钮）关闭。

#### 预期结果

1. 弹出确认框，标题为「提示」。
2. 正文为「确认取消批量任务 {batchId}？取消将调用 provider cancel 端点并释放金额预留。」（{batchId} 替换为实际 `batch_id`）。
3. 点击弹窗「取消」后关闭，**不发起** `POST /batches/{batch_id}/cancel`，任务状态不变。

#### 测试数据

- **确认文案**：`确认取消批量任务 {batchId}？取消将调用 provider cancel 端点并释放金额预留。`

### BT-C-02：取消成功状态流转

**功能模块**: 批量任务取消
**优先级**: P0
**用例编号**: BT-C-02
**OpenAPI**: `POST /batches/{batch_id}/cancel`

#### 前置条件

1. 存在非终态任务，且控制面 → provider 出网可达。

#### 测试步骤

1. 点击该行「取消」，在确认框点击「确定」。
2. 观察请求、提示与列表行状态。

#### 预期结果

1. 发起 `POST /batches/{batch_id}/cancel`，路径参数为所选 `batch_id`。
2. 返回成功后提示「取消请求已受理，任务进入 cancelling 状态」。
3. 该行状态更新为「取消中（cancelling）」，结算状态更新为「已释放（released）」。
4. 列表刷新后状态保持为 `cancelling`。

#### 测试数据

- **成功提示**：`取消请求已受理，任务进入 cancelling 状态`
- **状态流转**：`status=cancelling`、`settle_status=released`

### BT-C-03：终态任务取消按钮置灰

**功能模块**: 批量任务取消
**优先级**: P0
**用例编号**: BT-C-03
**OpenAPI**: `POST /batches/{batch_id}/cancel`（409 语义）

#### 前置条件

1. 列表中存在**终态**任务：`completed` / `expired` / `failed` / `cancelled`。

#### 测试步骤

1. 定位终态任务行，观察「取消」按钮状态。
2. 悬停「取消」按钮查看提示。
3. 尝试点击「取消」。

#### 预期结果

1. 终态任务的「取消」按钮 `disabled`（视觉置灰）。
2. 悬停展示提示「终态任务不可取消」（`title="终态任务不可取消"`）。
3. 点击无响应，**不发起**取消请求。
4. 非终态任务的「取消」按钮保持可用。

#### 测试数据

- **终态集合**：`completed` / `expired` / `failed` / `cancelled`
- **提示文案**：`终态任务不可取消`

### BT-C-04：取消 409 提示

**功能模块**: 批量任务取消
**优先级**: P1
**用例编号**: BT-C-04
**OpenAPI**: `POST /batches/{batch_id}/cancel`（409）

#### 前置条件

1. 可构造取消接口返回 409 的场景：任务已进入终态，或他实例正在处理（条件更新抢占失败）。

#### 测试步骤

1. 对非终态任务点击「取消」并确认，使接口返回 409。
2. 观察错误提示与列表状态。

#### 预期结果

1. 展示可读错误提示「任务已进入终态或正在被其它实例处理，取消未生效」。
2. 列表刷新后该任务状态以服务端为准（不出现本地已取消的假状态）。

#### 测试数据

- **409 文案**：`任务已进入终态或正在被其它实例处理，取消未生效`

### BT-C-05：取消 502 提示

**功能模块**: 批量任务取消
**优先级**: P1
**用例编号**: BT-C-05
**OpenAPI**: `POST /batches/{batch_id}/cancel`（502）

#### 前置条件

1. 控制面 → provider **不可达**（无出网 / provider 故障），取消接口返回 502。

#### 测试步骤

1. 对非终态任务点击「取消」并确认，使接口返回 502。
2. 观察错误提示。

#### 预期结果

1. 展示可读错误提示「provider 不可达，取消请求失败，请稍后重试」。
2. 任务仍可查看（列表 / 详情不受影响），允许稍后重试。

#### 测试数据

- **502 文案**：`provider 不可达，取消请求失败，请稍后重试`

#### 补充说明

降级部署无出网时取消退化为不可用，批量任务仅支持展示。

### BT-C-06：取消 404 提示

**功能模块**: 批量任务取消
**优先级**: P2
**用例编号**: BT-C-06
**OpenAPI**: `POST /batches/{batch_id}/cancel`（404）

#### 前置条件

1. 可构造任务在取消前被清理（DB 与 Redis 均 miss，或不属于调用方产品线）。

#### 测试步骤

1. 对任务点击「取消」并确认，使接口返回 404。
2. 观察错误提示与列表。

#### 预期结果

1. 展示可读错误提示「批量任务不存在或已被清理」。
2. 列表刷新后不再展示该任务（若已被清理）。

#### 测试数据

- **404 文案**：`批量任务不存在或已被清理`
