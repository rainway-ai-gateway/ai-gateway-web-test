## 3. 取消

**功能模块**: 批量任务取消
**设计依据**: `prototype-design/pages/batches.html` 取消交互、`src/i18n/zh.js` `batchTasks.*`
**OpenAPI**: `POST /batches/{batch_id}/cancel`

> **样本要求与前置（BT-C-01 ~ BT-C-06 统一口径，2026-10-17 补记）**
>
> 取消类用例取「可取消样本」的完整谓词是 **「非终态 且 非 `cancelling`」，且样本必须出现在列表首页**
> （自动化见 `tests/batch-tasks/test_03_batch_task_cancel.spec.js` 的 `pickActiveTask`）。三条约束的来源：
>
> 1. **必须是非终态**：只有非终态任务可取消。注意 `cancelling` 属「受理中」中间态、**仍是非终态**
>    （终态集合见 `ai-gateway-api/model/ibatch/types.go` 的 `TerminalStatuses` 注释：
>    `completed` / `expired` / `failed` / `cancelled`）。
> 2. **不能已是 `cancelling`**：对它再取消，后端按冲突返回 **409**，BT-C-02 要的 200 拿不到；
>    而 BT-C-04 / BT-C-05 / BT-C-06 断言「取消失败后不出现本地假取消态（取消中）」，
>    样本本身就是「取消中」时该断言恒不成立。
> 3. **必须限定首页**：列表 UI 固定 `limit=50`，只渲染首页；跨页取到的样本在页面上不存在，
>    `expectRowVisible` 会直接失败（曾试过跨页取数，实测 6 条全红，已回退）。
>
> **跑前必须恢复样本状态：`npm run seed:batch:execute`**（`scripts/seed-batch-task-data.cjs`）。
> 造数 PLAN 的设计里首页（id 1001~1020）本有 3 个合格样本（id 末两位 `02` / `03` / `04`
> = `in_progress` / `validating` / `finalizing`；另 `queued` / `in_progress` 各 1 条在第二页），
> 但**每次真实取消都会把样本推进到 `cancelling` / `cancelled`**：2026-10-17 全量回归前实测
> `batch-seed-02/03/04/05` 已被历次取消类用例消耗成 `cancelling`，首页再无合格样本，
> BT-C-04 / BT-C-05 / BT-C-06 因此被跳过（**属环境数据依赖，不是用例缺陷**）。
> 恢复设计状态后单跑该 spec：**5 通过 / 1 跳过**（BT-C-01/03/04/05/06 通过，BT-C-02 按设计跳过）。

### BT-C-02：取消成功状态流转

**功能模块**: 批量任务取消
**优先级**: P0
**用例编号**: BT-C-02
**OpenAPI**: `POST /batches/{batch_id}/cancel`

#### 前置条件

1. 存在非终态任务，且控制面 → provider 出网可达。
2. 样本须为「**非终态且非 `cancelling`**」并可见于列表**首页**；跑前先 `npm run seed:batch:execute`
   恢复样本状态（三条约束详见本文顶部「样本要求与前置」）。

#### 测试步骤

1. 点击该行「取消」，在确认框点击「确定」。
2. 观察请求、提示与列表行状态。

#### 预期结果

1. 发起 `POST /batches/{batch_id}/cancel`，路径参数为所选 `batch_id`。
2. 返回成功后提示「取消请求已受理，任务进入 cancelling 状态」。
3. 该行状态更新为「取消中（cancelling）」，结算状态更新为「已释放（released）」。
4. 列表刷新后状态保持为 `cancelling`。

#### 测试数据

- **成功提示**：`取消请求已受理，任务进入 cancelling 状态`
- **状态流转**：`status=cancelling`、`settle_status=released`

#### 补充说明

- **合理环境跳过（2026-10-17 实测）**：本机是降级环境、无出网，取消请求因 provider 不可达返回 **502**
  （`ErrUpstreamUnreachable`），取消成功的状态流转无法验证，自动化按既有守卫**设计跳过**本用例
  （同批另外 5 条通过）—— 属环境限制，**不是功能缺陷**。502 分支本身由 BT-C-05 覆盖（打桩 502 断言提示文案）。
- **区分 502 与 500**：非终态样本的 `provider` 必须取「有可用实例 + 有可用 key」者（造数取 `deepseek`）；
  `demo-provider` 的 `api_keys` 为空会走 `errProviderUnavailable`（**500**）分支，那不是本用例预期的降级语义。
- 样本与前置要求见本文顶部「样本要求与前置」（非终态且非 `cancelling`、首页可见、跑前先 `npm run seed:batch:execute`）。

### BT-C-05：取消 502 提示

**功能模块**: 批量任务取消
**优先级**: P1
**用例编号**: BT-C-05
**OpenAPI**: `POST /batches/{batch_id}/cancel`（502）

1. 控制面 → provider **不可达**（无出网 / provider 故障），取消接口返回 502。

#### 测试步骤

#### 测试数据

- **502 文案**：`provider 不可达，取消请求失败，请稍后重试`

降级部署无出网时取消退化为不可用，批量任务仅支持展示。
