## CASE-BT-01：`cellsByBatchId` 未折叠空白导致严格比较失败（BT-L-09 / BT-L-12，用例自身缺陷）

**现象（2026-10-16 首次真正执行该两条用例时暴露）**

```
Expected: "55000000"      Received: "     55000000 "        # BT-L-09 金额列
Expected: "batch-seed-01" Received: "   batch-seed-01   "    # BT-L-12 列表一致性
```

**根因**：`pages/batch-tasks/BatchTaskPage.js` 的 `cellsByBatchId` 使用 `allTextContents()`（textContent 原样返回节点文本，**不折叠空白**），而 iView 单元格 DOM 实测为：

```html
<div class="ivu-table-cell"><!----> <!----> <!----> <span>55000000</span> <!----> <!----> <!----></div>
```

空白来自 Vue 的空占位注释与 iView 模板空格。判定为**用例自身缺陷而非 UI 问题**的三条依据：

1. HTML 渲染时行首/行尾连续空白会被折叠，用户视觉上无多余空格；
2. 同表其它断言（BT-L-03 服务商、BT-L-04 API Key）走 innerText（天然折叠空白）全部通过 → 渲染值本身正确；
3. 断言期望值 `uiText(item.reserve_units)` 是无空白的原始值，说明用例本意就是比较纯值，只是读取路径未归一。

**为何此前未暴露**：BT-L-09 / BT-L-12 此前 100% 被 `requireData` 空数据守卫跳过，从未真正执行——与 BUG-BT-01 同属「跳过掩盖问题」。

**处置（2026-10-16）**：`cellsByBatchId` 读取后统一 `trim()`。影响面仅本模块 4 个调用点（`test_01` 两处严格 `toBe`、`test_03` 两处 `toContain`，trim 后语义不变）。

**后续发现（同日，同属「造数未满足用例声明前置」）**：trim 修复后 BT-L-09 转绿，但 BT-L-12 仍失败于 `Expected: "-" / Received: ""` —— 定位为**造数首行 `entity_id` 为空**，违反该用例声明的前置（`docs/batch-tasks/02-功能测试用例/01-列表页.md:362`：「环境存在至少 1 条**字段完整、各字段均有值**的批量任务」，示例 `entity_id: "entity-5"`）。

- 该用例固定取接口返回的 `list[0]`，故**首行必须是全字段有值样本**；已把造数首行改为终态 `completed` 且 `entity_id` 非空（`api-key-9` → `entity-2`）。
- **不是产品缺陷**：原型 `prototype-design/pages/batches.html:176` 的列表 Entity ID 列同为原样渲染（不带 `-` 兜底），实现与原型一致；`-` 兜底只存在于原型/实现的**详情面板**（`batches.html:303,309` 的 `htmlValue || '-'`）。
- 处置后 `test_01` **12 通过 / 0 失败 / 0 跳过**，全模块 **26 条 / 20 通过 / 0 失败 / 6 跳过**（证据 [report/test-report-20261016-150909.md](../../report/test-report-20261016-150909.md)）。

## BUG-BT-02：只读视角列表重渲染后行内「取消」丢失 `.v-has-hidden`（BT-RO-02，**已修复（2026-10-17）**）

> **2026-10-17 复验结论（12:03 轮时点）：当时仍未修复**。同轮 `tests/batch-tasks/` 全模块复跑（26 通过 / 1 失败 / 2 跳过）中，BT-RO-02 仍是**唯一失败项**，失败签名与首轮完全一致（`toHaveClass` 期望 `/v-has-hidden/`、实得 `"ivu-btn ivu-btn-error ivu-btn-small"`，24 次重试均如此）。已核对 web 侧与本缺陷相关的三个文件 mtime 均**未变化**（`BatchTasks/index.vue` 2026-10-12、`utils/directive.js` 2026-10-12、`components/table/pageTable.vue` 2026-10-15），即本轮修复只覆盖了 BUG-BT-01（api 侧），**未触及本缺陷**。断言保留不弱化；证据 [report/test-report-20261017-120335.md](../../report/test-report-20261017-120335.md)。
>
> **修复结论（2026-10-17，标题「未修复」与上条复验均已过期）**：本缺陷当日修复，修法为 `v-has` 指令**补同名属性兜底** —— `src/utils/directive.js` 新增 `HIDDEN_ATTR = 'v-has-hidden'`（`applyHas` 在加 / 删类的同时 `setAttribute` / `removeAttribute` 同名属性），`src/assets/css/global.less:65-68` 的隐藏选择器由 `.v-has-hidden` 扩为 `.v-has-hidden, [v-has-hidden]`，`display:none !important` 不变。
> **根因（已定论，取代下方「具体触发点待下一轮诊断确认」）**：`v-has` 用**命令式** `el.classList.add` 加隐藏类，而 iView Button 的根节点 class 有**响应式属主**（`:class="classes"`）。按钮 props 变化触发 Button 组件自身重渲染时，Vue 的 class 模块会 `el.setAttribute('class', cls)` **整串重写** class 属性，命令式加的类被抹掉，且父级本轮不再 patch、指令 `update` 钩子不再执行 —— 「筛选后行对象换位 + 组件复用」恰好命中**变体发生切换的那一行**。用**属性**（不归 Vue class 模块管）作兜底即可：修复后该行 `class` 仍会被抹掉（原现象未被掩盖），但 `[v-has-hidden]` 属性在、命中 `display:none`，**不再是可见写入口**。
> **证据**：产品变更记录 [2026-10-17-ui-defect-fixes/ui-code-changes.md](../../../ai-gateway-web/design-docs/modifications/2026-10-17-ui-defect-fixes/ui-code-changes.md) §4.1（含浏览器探针实测：只读态批量任务列表进页 20 个隐藏标记 → 筛选「取消中」后第一行 class 丢失但 `[v-has-hidden]` 在、`display:none` → 再查一次恢复；`store.isReadonly()` 全程 `true`）。
> **测试侧复跑**：`tests/batch-tasks/test_04_batch_task_readonly.spec.js` **BT-RO-01/02/03 3/3 全绿**（断言未改，口径仍为「仍在 DOM + 不可见」，隐藏标记接受「类或属性至少一种」，见 `utils/readonly.js:230-241`），取证于全量回归 [report/test-report-20261017-130924.md](../../report/test-report-20261017-130924.md) 与受影响 spec 复跑 [report/test-report-20261017-134114.md](../../report/test-report-20261017-134114.md)（31 通过 / 0 失败，含本 spec 3/3）；`02-功能测试用例/00-索引与映射.md` 的 `test_04` 行已回写 `已通过` / `最近通过 2026-10-17`。
