# AI 业务集群（Business Cluster）模块 - 测试场景概览

## 模块概述

AI 业务集群模块负责配置路由转发的目标集群，是资源管理的核心模块。集群通过 `llm_config.provider` 引用模型服务商（Providers），由 Provider 提供实例池、模型列表、Keys 等数据。

对应接口文档：`ai-gateway-web/design-docs/api-define/OpenAPI接口定义/clusters.md`；对应原型：`ai-gateway-web/design-docs/prototype-design/pages/cluster-wizard.html`、`cluster-list.html`。

> **关联模块**：
>
> - **模型服务商（Providers）**：集群强依赖 Provider；Provider 的 `instance_pool`、`models`、`keys` 会同步影响引用它的集群。
> - **路由管理（Route Management）**：路由规则通过 `cluster_name` 指向业务集群。

**核心变更依据**：

- 2026-10-12（变更记录 `modifications/2026-10-12-epp-runtime-params/ui-code-changes.md`）：集群在 `balance_mode=EPP` 时新增可选 `epp_runtime` 运行时参数（BFE 访问 EPP 的健康检查 `check` + 超时 `timeout`），接入创建/编辑向导的 EPP 配置区并在复查页展示；`tls`/`breaker` 由后端固定下发、不对外暴露。`POST`/`PATCH`/`GET /clusters` 新增可选 `epp_runtime`。
- 2026-10-12（变更记录 `modifications/2026-10-12-readonly-admin/ui-code-changes.md`）：引入「系统管理员（只读）」（`role === "system_admin_readonly"`），前端以全局自定义指令 `v-has` 在全站隐藏写操作按钮（本模块隐藏「添加集群」与向导内「提交」），仅保留只读查看能力。
- 2026-10-13（变更记录 `modifications/2026-10-12-epp-runtime-params/ui-code-changes.md` §3.4/§8）：`epp_runtime` 的 4 个 duration 字段改为「数字框 + 单位下拉（`ms`/`s`/`m`）」复合控件——切单位换算数值保持物理时长（`500ms` → `s` = `0.5s`）、组合写法（`1m30s`）回退文本输入；校验与 `time.ParseDuration` 对齐（`+1s`/`1.s`/`.5s` 合法），数字框填 `0` 拦截报错、不再静默取默认值；提示图标精简为 3 个字段。新增 RM-BC-122（P1，场景二）。
- 2026-10-22（变更记录 [ui-code-changes.md](../../../ai-gateway-web/design-docs/modifications/2026-10-22-desc-bytes-and-cache-cond-unique/ui-code-changes.md)）：集群描述 `description` 的长度口径由「0-256 字符」改为「**0-256 字节（按 UTF-8 字节计）**」，控制字符约束不变；`BaseConfig.vue` 校验由 `value.length > 256` 改为 `utf8ByteLength(value) > 256`，文案改为「集群描述不能超过256字节（按 UTF-8 字节计）」「集群描述不能包含控制字符」。后端实测：256 字节 ASCII 通过；200 汉字（600 字节）`PATCH /clusters/{name}` 返回 `422 Param Illegal: description length must be <= 256`。既有 RM-BC-39 按字节口径改写，**不新增用例**。

## 配置顺序

```text
① 配置模型服务商（Providers）          基础数据：实例池 / 模型 / Keys
        │
        ▼
② 配置 AI 业务集群（Clusters）          llm_config.provider 指向服务商 → 转发模型 / Keys
        │
        ▼
③ 路由规则 / 全链路                     将请求转发至集群
```

**依赖说明**：

| 关系 | 说明 |
| --- | --- |
| Providers → Clusters（强依赖） | 必须先创建 Provider，集群大模型配置才能选择服务商、转发模型和 Keys |
| Clusters → Route（被引用） | 集群可被默认规则或路由规则引用；被引用时不可删除 |

### 场景二：EPP 运行时参数配置

**场景描述**：管理员在 `balance_mode=EPP` 的集群上配置「EPP 运行时参数」（`epp_runtime`）分组——BFE 访问 EPP 的健康检查（`check`）与超时（`timeout`），验证分组展示与默认值、开关交互、字段校验与拦截、提交体与整体替换语义、编辑回读与默认补齐、WRR 保留不生效与禁止字段、复查页展示与未配置提示。

| 步骤 | 操作 | 对应编号 | 优先级 | 生命周期 |
| --- | --- | --- | --- | --- |
| 1 | EPP 模式下展示「EPP 运行时参数」分组与默认值 | RM-BC-115 | P1 | 已通过（2026-10-13） |
| 2 | 切换「关闭后台健康检查」开关并核对交互 | RM-BC-116 | P1 | 已通过（2026-10-13） |
| 3 | duration（>0）与阈值（>=1）非法值校验与拦截 | RM-BC-117 | P1 | 已通过（2026-10-13） |
| 4 | 提交体包含 `epp_runtime` 与整体替换语义 | RM-BC-118 | P0 | 已通过（2026-10-13） |
| 5 | 编辑回读与未设置子字段默认补齐 | RM-BC-119 | P1 | 已通过（2026-10-13） |
| 6 | WRR 模式保留不生效与 `tls`/`breaker` 禁止字段（422） | RM-BC-120 | P1 | 已通过（2026-10-13） |
| 7 | 复查页展示与未配置「BFE 补默认」提示 | RM-BC-121 | P1 | 已通过（2026-10-13） |
| 8 | duration 复合控件交互（单位切换保持物理时长、组合写法回退、小数输入） | RM-BC-122 | P1 | 已通过（2026-10-13） |

**测试目标**：验证 `epp_runtime` 分组展示、默认值/校验/整体替换语义与 `GET` 回读一致；`tls`/`breaker` 不可配置；未配置态如实展示。

> **执行结果（2026-10-13 · `tests/cluster/test_09_business_cluster_balance_mode.spec.js`）**：RM-BC-115~122 **全部通过**（全量 24/24，含既有 93~109 无回归）。执行中发现两项并对齐：① 「EPP 运行时参数」原写作「可折叠分组」属原型遗留描述（原型 `▾` 未接线、UI 为普通 Card）→ 已按用户决策修订 02/原型为「普通卡片」并删除折叠断言（[测试问题复盘](./测试问题复盘.md) BUG-BC-01）；② duration 数字框非法字符残留 → 已修复 `DurationInput` 并补断言（BUG-BC-02）。
>
> RM-BC-121 预期 4 的「未配置（BFE 补默认）」提示在**向导复查页**无法构造（进入复查页必先经第 4 步提交，`balance_mode=EPP` 时按默认补齐并下发 `epp_runtime`），已改用同一 `Review` 组件的**详情页**验证通过；未配置集群 `GET /clusters/{name}` 回读为 `null` 亦已断言。
>
> **EPP 运行时参数（2026-10-12）**：`epp_runtime` 为 `POST`/`PATCH`/`GET /clusters` 新增的可选对象，仅 `balance_mode=EPP` 时导出到 BFE（WRR 时保留但不生效、非空仍校验）；`check`（关闭健康检查/间隔/失败阈值/冷却/成功阈值）+ `timeout`（连接/调用）未设置子字段按默认补齐，传入即整体替换、不传则保留原值。验收以 [02b 向导步骤](./02-功能测试用例/02b-向导步骤.md)（RM-BC-115~122）与 [03 字段校验矩阵](./02-功能测试用例/03-字段校验矩阵.md) 为准。
>
> **duration 控件与校验（2026-10-13）**：4 个 duration 字段为「数字框 + 单位下拉（`ms`/`s`/`m`）」复合控件，切换单位换算数值保持物理时长不变（`500ms` → `s` = `0.5s`），组合写法（`1m30s`）回退为纯文本输入；校验与 `time.ParseDuration` 对齐（`+1s`/`1.s`/`.5s` 合法），数字框填 `0` 拦截报错、不再静默取默认值，清空视为「未设置」；`?` 提示图标仅 3 个字段保留。验收以 [02b 向导步骤](./02-功能测试用例/02b-向导步骤.md)（RM-BC-115~122）与 [03 字段校验矩阵](./02-功能测试用例/03-字段校验矩阵.md) 为准。
