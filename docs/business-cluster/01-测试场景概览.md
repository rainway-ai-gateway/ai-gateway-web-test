# AI 业务集群（Business Cluster）模块 - 测试场景概览

## 模块概述

AI 业务集群模块负责配置路由转发的目标集群，是资源管理的核心模块。集群通过 `llm_config.provider` 引用模型服务商（Providers），由 Provider 提供实例池、模型列表、Keys 等数据。

对应接口文档：`ai-gateway-web/design-docs/api-define/OpenAPI接口定义/clusters.md`；对应原型：`ai-gateway-web/design-docs/prototype-design/pages/cluster-wizard.html`、`cluster-list.html`。

> **关联模块**：
>
> - **模型服务商（Providers）**：集群强依赖 Provider；Provider 的 `instance_pool`、`models`、`keys` 会同步影响引用它的集群。
> - **路由管理（Route Management）**：路由规则通过 `cluster_name` 指向业务集群。
> - **AI 网关实例池（Gateway Pool）**：全局单例资源（`/alb-pool`，网关转发引擎实例集合），与 Provider 的 `instance_pool`（服务商后端实例）是两个独立对象；集群的实例配置已改由 Provider 提供，与本网关实例池无关。详见 [gateway-pool 模块说明](../gateway-pool/01-测试场景概览.md)。

---

## 配置顺序

```text
① 配置模型服务商（Providers）          基础数据：实例池 / 模型 / Keys
        │
        ▼
② 配置 AI 业务集群（Clusters）          llm_config.provider 指向服务商 → 转发模型 / Keys
        │
        ▼
③ 路由规则 / 全链路                     将请求转发至集群
```

**依赖说明**：

| 关系 | 说明 |
| --- | --- |
| Providers → Clusters（强依赖） | 必须先创建 Provider，集群大模型配置才能选择服务商、转发模型和 Keys |
| Clusters → Route（被引用） | 集群可被默认规则或路由规则引用；被引用时不可删除 |

## 场景测试设计

### 场景一：管理员搭建 AI 业务集群

**场景描述**：管理员创建 AI 业务集群并配置相关参数，形成路由可指向的目标集群。

| 步骤 | 操作 | 对应场景编号 | 优先级 |
| --- | --- | --- | --- |
| 1 | 进入 AI 业务集群，添加集群（**5 步**向导） | RM-BC-02 | P0 |
| 2 | 配置基础信息（名称、协议、连接数/缓存边界、哈希 Header 联动） | RM-BC-03、RM-BC-21、RM-BC-23、RM-BC-26、RM-BC-31 | P0/P1 |
| 3 | 配置超时与重传、健康检查（含 Host FQDN、逐步校验） | RM-BC-04~RM-BC-05、RM-BC-27~RM-BC-28、RM-BC-32 | P1 |
| 4 | 配置大模型：**所属服务商（必填下拉，引用 Provider）**、转发模型（全选）、裁剪/匹配前缀、模型重定向、Keys 配置（服务商 Key + 权重，可选）、Key 路由策略、hash_strategy、**Key 亲和性** | RM-BC-07、RM-BC-40、RM-BC-52~56、RM-BC-65~68、RM-BC-71~79、RM-BC-81、RM-BC-87~91 | P0/P1 |
| 5 | 大模型必填/格式、重定向 | RM-BC-08、RM-BC-29、RM-BC-73~RM-BC-75 | P1 |
| 6 | 第 5 步复查确认并提交（**复查页完整展示大模型配置，不含实例池**） | RM-BC-11、RM-BC-35 | P0 |
| 7 | 编辑集群（**5 步**，与创建步骤一致）；名称不可改 | RM-BC-12、RM-BC-16、RM-BC-36 | P0 |
| 8 | 点击「详情」查看集群全配置只读 | RM-BC-15、RM-BC-34 | P1 |
| 9 | 删除无引用的集群 | RM-BC-13 | P0 |
| 10 | 删除被默认规则/路由规则引用的集群（约束） | RM-BC-14 | P0 |

**测试目标**：验证业务集群创建与编辑流程；删除约束正确。

> **向导步骤（2026-08-24/25 变更后）**：**创建 5 步**（基础配置 → 超时和重传 → 被动健康检查 → **大模型配置** → 复查&检查）；**编辑 5 步**（与创建一致）。已移除「实例配置」步骤——实例池改由**模型服务商（Providers）**维护，集群通过 `llm_config.provider` 引用；复查页完整展示大模型配置字段（不含实例池）；`hash_strategy` 默认 `CLIENT_IP_ONLY`；Keys **非必填**（空行不参与校验、提交时过滤空行）。
>
> **Key 亲和性（2026-08-26）**：大模型配置新增「Key 亲和性」Card（`llm_config.key_affinity`，默认 `enabled: false`）；启用后展示绑定空闲超时(秒)（默认 600，>0 整数）、Key 惩罚（默认开启）、Redis Key 前缀（默认 `bfe:ai:key_affinity`，非空）；复查页展示启用状态与明细，编辑回显一致。验收以 [02d 大模型与校验](./02-功能测试用例/02d-大模型与校验.md)（RM-BC-87~91）与 [02e 一致性验证](./02-功能测试用例/02e-一致性验证.md)（复查/回显）为准。

## 测试数据准备

| 数据类别 | 准备内容 | 用途 |
| --- | --- | --- |
| 业务集群 | 完成大模型最小配置（含多 Key、key_policy、provider） | 默认规则/路由目标 |

| 数据项 | 说明 | 示例值 |
| --- | --- | --- |
| 动态命名 | 时间戳后缀避免冲突 | `bc_{ts}` |
| 删除顺序 | 路由 → 业务集群 | — |
| 服务鉴权 Keys | 服务商 Key 下拉（name）+ 权重（weight）两列，支持多行动态增删；非空时 weight 总和=100；空行不校验 | `[{name: key-1, weight: 70}, {name: key-2, weight: 30}]` |
| key_policy | strategy=weighted_random；max_retries=0；retry_backoff_initial=500；retry_backoff_max=5000 | Key 路由策略与重试配置 |
| 所属服务商（provider） | 必填下拉，引用已存在的 Provider；选择后拉取其 models/keys | `deepseek`、`qwen` |
| match_prefix / strip_prefix | match_prefix 字符串必须以 `/` 结尾；strip_prefix 布尔默认 false | `openrouter/` + `true` |
| key_affinity | enabled 布尔默认 false；ttl 整数默认 600（>0）；redis_prefix 字符串默认 `bfe:ai:key_affinity`（非空）；penalty_enable 布尔默认 true | `{enabled: true, ttl: 600, redis_prefix: "bfe:ai:key_affinity", penalty_enable: true}` |
