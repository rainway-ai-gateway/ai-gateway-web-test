### 2.10 向导第4步-均衡模式配置

**用例编号**: RM-BC-93~102 | **优先级**: P1  
**设计依据**: prototype-design `cluster-upsert.js`（`balanceModeHtml`）  

> 均衡模式配置卡片位于大模型配置第 4 步「Key 亲和性」Card 之后。此卡片集中管理集群的均衡调度策略。

#### 卡片布局说明

- **Card 标题**：「均衡模式配置」
- **位置**：在「Key 亲和性」Card 之后，最后一组配置项
- **字段分组**：`balance_mode` 选择器为顶层字段；EPP 模式下展开 `epp_config` 子字段面板

#### balance_mode 选择器

| 选项 | 说明 |
| --- | --- |
| `WRR`（默认） | 加权轮询（Weighted Round Robin），基础均衡模式 |
| `EPP` | 端点池规划（Endpoint Pool Planning），高级均衡模式 |

- 选择 `WRR` 时不展示 `epp_config` 子字段
- 选择 `EPP` 时动态展示 `epp_config` 配置区域

#### epp_config 子字段（EPP 模式时展示）

| 字段 | 控件类型 | 说明 |
| --- | --- | --- |
| `load_profile` | select | 实例负载画像：queue-first（排队优先）/ balanced（均衡，默认）/ kv-first（KV 空闲优先） |
| `affinity` | select | 亲和强度：off（关闭亲和）/ low（0.3）/ medium（0.6，默认）/ high（1.0） |
| `prefix_cache_affinity` | switch | 前缀缓存亲和性开关（默认 true；`affinity=off` 时不注入亲和 scorer，字段名后追加「（off 时不生效）」） |
| `session_affinity_enabled` | switch | 会话亲和性启用开关（默认 false；`affinity=off` 时不注入亲和 scorer，字段名后追加「（off 时不生效）」）；开启后展示 `session_affinity_header` |
| `session_affinity_header` | input | 会话亲和性 Header 名称（仅 session_affinity_enabled=true 时可见；条件必填） |
| `kv_cache_utilization_max` | InputNumber | KV 缓存最大利用率（默认 0.9，取值 (0,1]；KV 阈值单一来源） |
| `waiting_queue_max` | InputNumber | 排队长度过滤阈值（默认 0，≥0，整数；0=不启用） |
| `running_requests_max` | InputNumber | 在飞请求数过滤阈值（默认 0，≥0，整数；0=不启用） |
| `fallback_on_empty` | switch | 无端点时回退派发（默认 false） |
| `metrics_staleness_threshold_ms` | InputNumber | 指标失效剔除阈值（ms，默认 200，须为正整数） |
| `flow_control` | 普通卡片（无折叠交互） | 内含 max_requests、queue_ttl、no_endpoint_queue_ttl、enable_eviction |

> `affinity=off` 时，`affinity` 字段名后展示橙色提示「亲和强度为 off，不生效」。

#### flow_control 子字段

| 字段 | 控件类型 | 说明 |
| --- | --- | --- |
| `max_requests` | InputNumber | 最大请求数（>0 或 -1 表示不限） |
| `queue_ttl` | InputNumber | 队列 TTL（≥0 整数，0 表示显式禁用驱逐） |
| `no_endpoint_queue_ttl` | InputNumber | 无端点队列 TTL（≥0 整数，0 表示显式禁用驱逐） |
| `enable_eviction` | switch（禁用态只读） | 是否启用驱逐；**当前仅允许 false（true 将 422 拒绝），UI 为禁用态只读开关，提示「当前不支持开启，保持关闭」** |

> `flow_control` 整体缺省时不下发该字段；`enable_eviction` 编译产物不下发。

#### 交互行为

- WRR ↔ EPP 切换时，已填写的 EPP 配置应保留（不丢失），切换回 EPP 时恢复
- **`epp_config` 非空即参与字段校验，与 balance_mode 无关**（含从 EPP 切到 WRR 后休眠保留的配置）
- 纯 WRR 新集群（无 EPP 历史配置）提交时不携带 `epp_config`
- flow_control 为普通卡片（无折叠交互），与其余 EPP 配置卡片一致
- `balance_mode=EPP` 时 `epp_config` **必填**：缺省提交返回 `422`（2026-10-13 实测补记；WRR 时可选）

详细校验见 [02d 大模型与校验](./02d-大模型与校验.md)（RM-BC-93~102）。

## 2b-2. EPP 运行时参数（2026-10-12；控件形态与校验 2026-10-13）

> 集群在 `balance_mode=EPP` 时新增可选 `epp_runtime` 运行时参数（BFE 访问 EPP 的健康检查 `check` + 超时 `timeout`）。本次在集群创建/编辑向导的 EPP 配置区接入「EPP 运行时参数」分组（普通卡片，与其余 EPP 配置卡片一致，无折叠交互），并在复查页展示。
>
> 分组子字段（`epp_runtime`）：
>
> - `check.disabled`（bool，默认 `false`）：是否关闭后台健康检查
> - `check.check_interval`（duration，默认 `2s`，须 `>0`）：健康检查探活间隔
> - `check.fail_threshold`（int，默认 `3`，须 `>=1`）：主地址连续失败次数阈值
> - `check.cooldown`（duration，默认 `45s`，须 `>0`）：冷却期
> - `check.success_threshold`（int，默认 `2`，须 `>=1`）：连续成功次数阈值
> - `timeout.connect`（duration，默认 `500ms`，须 `>0`）：建立 gRPC 连接/流超时
> - `timeout.call`（duration，默认 `3s`，须 `>0`）：首条消息超时
>
> **输入控件（2026-10-13）**：4 个 duration 字段（`check_interval`/`cooldown`/`timeout.connect`/`timeout.call`）采用「数字框 + 单位下拉（`ms`/`s`/`m`）」复合控件（iView `Input` + `append` 槽内嵌 `Select`，`src/components/DurationInput/`），提交值仍为 duration 字符串；切换单位时**换算数值保持物理时长不变**（`500ms` → `s` = `0.5s`）；组合写法（如 `1m30s`）无法拆分时回退为纯文本输入。2 个阈值字段为整数数字框（`InputNumber`，`min=1`）。提示图标仅保留 3 个（关闭后台健康检查、冷却时长、调用超时）。
>
> **校验（2026-10-13 起与 `time.ParseDuration` 对齐）**：duration 须为 `>0` 的合法 Go duration（`+1s`、`1.s`、`.5s` 等写法合法）；数字框填 `0` 须**拦截并报错**，不得静默替换为默认值；数字框清空视为「未设置」（提交空串，由后端按默认补齐）。
>
> `tls`/`breaker` 由后端固定下发（`EPPTLS` 恒 `{Plaintext:true}`、`EPPBreaker` 恒 `{Disabled:true}`），前端不提供入口，携带返回 `422`（见 RM-BC-120）。
>
> 字段定义以 `design-docs/api-define/OpenAPI接口定义/clusters.md`「EPP运行时配置（`epp_runtime`）」为准；字段校验矩阵见 [03 字段校验矩阵](./03-字段校验矩阵.md)。

2. 保持「连接超时」数值为 `500`，将单位下拉由 `ms` 切为 `s`，观察数字框变化
3. 将「冷却时长」数字框填 `0.5`、单位选 `m`
4. 将「调用超时」数字框清空后再输入 `2`，观察单位下拉取值
