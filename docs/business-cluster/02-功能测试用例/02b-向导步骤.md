## 2b. 向导步骤

> 创建与编辑向导均为 **5 步**：① 基础配置 ② 超时和重传 ③ 被动健康检查 ④ **大模型配置** ⑤ 复查&检查；**不存在**「实例配置」步骤。步骤切换、上一步 / 下一步交互与旧 6 步向导一致。

### 2.3 向导第1步-基础配置

**用例编号**: RM-BC-03 | **优先级**: P0  
**自动化**: `tests/cluster/test_02_business_cluster_wizard.spec.js`（**部分**：验证向导第 1 步可进入第 2 步；**未单独断言** `sticky_sessions.enabled` 开关显隐与提交值，见 [§3.8](./03-字段校验矩阵.md#38-自动化覆盖状态)）

#### 测试步骤

1. 集群名称 `bc_{ts}`（**全局唯一**，见 OpenAPI `clusters`）
2. 配置协议（默认 **https**）
3. 配置哈希策略 `hash_strategy`（`CLIENT_ID_ONLY` / `CLIENT_IP_ONLY` / `CLIENT_ID_PREFERED`，默认 `CLIENT_IP_ONLY`）；启用+`CLIENT_ID_ONLY`/`CLIENT_ID_PREFERED` → `hash_header` **必填**（留空被拦截）；`CLIENT_IP_ONLY` 不要求
4. 配置**会话保持**开关（`sticky_sessions.enabled`：`true`/`false`）；仅当启用时配置哈希策略与 Header
5. 可选填写**描述**（≤256 字符，禁止控制字符，见 RM-BC-39）
6. 点击「下一步」

#### 预期结果

- 必填项校验通过后可进入第 2 步
- `enabled=false` 时不展示/不要求 hash_strategy、hash_header
- 默认值与 design 一致（如哈希策略默认 `CLIENT_IP_ONLY`、最大空闲连接数默认 2、写缓存默认 512）
- **已移除**：旧版 `session_sticky_type` / 「会话保持级别 INSTANCE/SUB_CLUSTER」字段

### 2.6 向导第4步-大模型基础配置

**用例编号**: RM-BC-07 | **优先级**: P0

#### 测试步骤

1. 选择**所属服务商**（provider，必填下拉，从 `GET /providers/actions/get-provider-names` 拉取）
2. 待服务商详情加载后，选择**转发模型**（多选，含「全选」）
3. 配置「裁剪前缀」（strip_prefix）开关：默认关闭；开启后出现「匹配前缀」（match_prefix）输入框，填写如 `openrouter/`
4. 配置**服务鉴权 Keys**（多 Key 动态表格，Card 包裹；含 name / key / weight 三列；支持添加/删除行；**可选**）
5. 配置**Key 路由策略**（Card 包裹；含 strategy、max_retries、retry_backoff_initial、retry_backoff_max）
6. 配置**Key 亲和性**（Card 包裹；启用关闭/开启；开启后展示 ttl / Key 惩罚 / Redis Key 前缀）
7. 配置**均衡模式**（Card 包裹；`balance_mode` 选择器 WRR/EPP；EPP 模式下展示 `epp_config` 各子字段）
8. 配置模型重定向（`source_model` / `target_model`，见 RM-BC-08、RM-BC-40）

#### 预期结果

- 必填项满足后可下一步
- LLM 配置界面按 **Card 分组**展示，共 **6 张 Card**：
  1. **模型服务配置**（provider、转发模型、Header 等）
  2. **模型重定向**（source_model / target_model 表格）
  3. **服务鉴权 Keys**（多 Key 动态表格）
  4. **Key 路由策略**（key_policy 各字段）
  5. **Key 亲和性**（key_affinity 启用与条件字段）
  6. **均衡模式配置**（balance_mode 选择器；EPP 模式下展示 epp_config 子字段）
- 所属服务商必填，未选时下一步/提交被拦截
- 选择服务商后自动拉取其 `models` 与 `keys`；切换服务商时转发模型与 Keys 联动刷新
- match_prefix 填写必须以 `/` 结尾；strip_prefix=true 时 match_prefix 必填（详见 RM-BC-66、RM-BC-67）
- 从开启切回关闭时 match_prefix 自动清空
- **已移除**：旧版 provider_type 输入框、模型列表协议/URI 手动配置、单 key 字段、「服务名称」「分组」表单项
- **已重构**：原单 key 字段 → `llm_config.keys` 多 Key 数组 + `llm_config.key_policy` 路由策略对象 + `llm_config.key_affinity`

### 2.9 向导第5步-复查并提交

**用例编号**: RM-BC-11 | **优先级**: P0

#### 测试步骤

1. 在「复查 & 检查」页核对各步摘要
2. 点击「提交」

#### 预期结果

- 展示基础配置、超时、健康检查、大模型等摘要
- **不存在「实例配置」摘要**（实例池由 Provider 维护，不再属于集群配置）
- 大模型段摘要展示：
  - **所属服务商**：展示 provider 名称
  - **转发模型**：展示已选模型
  - **LLM Keys 表格**：展示 name / weight 两列（key 值在集群侧不展示）
  - **Key 路由策略（Key Policy）**：展示 strategy、max_retries、retry_backoff_initial、retry_backoff_max
  - **Key 亲和性**：展示启用状态；启用时展示 ttl / Redis Key 前缀 / Key 惩罚
  - **裁剪前缀 / 匹配前缀**：当前复查页（Review）**是否展示**以 design 为准；一致性校验以提交请求体 + 创建后 GET 读回为准
- 提交成功后返回列表并出现新集群
- **复查页字段与将提交数据一致**见 **RM-BC-35**

### 2.10 向导第4步-均衡模式配置

**用例编号**: RM-BC-93~102 | **优先级**: P1  
**设计依据**: prototype-design `cluster-upsert.js`（`balanceModeHtml`）  

> 均衡模式配置卡片位于大模型配置第 4 步「Key 亲和性」Card 之后。此卡片集中管理集群的均衡调度策略。

#### 卡片布局说明

- **Card 标题**：「均衡模式配置」
- **位置**：在「Key 亲和性」Card 之后，最后一组配置项
- **字段分组**：`balance_mode` 选择器为顶层字段；EPP 模式下展开 `epp_config` 子字段面板

#### balance_mode 选择器

| 选项 | 说明 |
| --- | --- |
| `WRR`（默认） | 加权轮询（Weighted Round Robin），基础均衡模式 |
| `EPP` | 端点池规划（Endpoint Pool Planning），高级均衡模式 |

- 选择 `WRR` 时不展示 `epp_config` 子字段
- 选择 `EPP` 时动态展示 `epp_config` 可折叠/展开区域

#### epp_config 子字段（EPP 模式时展示）

| 字段 | 控件类型 | 说明 |
| --- | --- | --- |
| `scheduling_profile` | select | latency-first / balanced / throughput-first |
| `cache_affinity` | select | low / medium / high |
| `prefix_cache_affinity` | switch | 前缀缓存亲和性开关 |
| `session_affinity_enabled` | switch | 会话亲和性启用开关；开启后展示 `session_affinity_header` |
| `session_affinity_header` | input | 会话亲和性 Header 名称（仅 session_affinity_enabled=true 时可见） |
| `kv_cache_utilization_max` | InputNumber | KV 缓存最大利用率 |
| `flow_control` | 可折叠卡片 | 内含 max_requests、queue_ttl、no_endpoint_queue_ttl、enable_eviction |

#### flow_control 子字段

| 字段 | 控件类型 | 说明 |
| --- | --- | --- |
| `max_requests` | InputNumber | 最大请求数 |
| `queue_ttl` | InputNumber | 队列 TTL |
| `no_endpoint_queue_ttl` | InputNumber | 无端点队列 TTL |
| `enable_eviction` | switch | 是否启用驱逐 |

#### 交互行为

- WRR ↔ EPP 切换时，已填写的 EPP 配置应保留（不丢失），切换回 EPP 时恢复
- WRR 模式下不校验 epp_config 必填
- EPP 模式下 epp_config 为条件必填
- flow_control 为可折叠卡片，默认折叠/展开状态以 design 为准

详细校验见 [02d 大模型与校验](./02d-大模型与校验.md)（RM-BC-93~102）。
