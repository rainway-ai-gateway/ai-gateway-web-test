## 2e. 一致性验证

> 本章按**功能**组织：详情 / 列表 / 复查页 / 编辑回显 与 OpenAPI 及各步输入的一致性。大模型配置已改为**引用模型服务商（Provider）**，`llm_config.provider` 必填、`keys[]` 仅含 `{name, weight}`（无 key 明文），并新增 `key_affinity`（Key 亲和性）；复查页与详情**不再展示**「实例配置 / 服务商实例池」面板。

### 2.34 业务集群详情与 OpenAPI 一致

**用例编号**: RM-BC-34 | **优先级**: P1  
**设计依据**: `design/business-cluster/09-detail.jpg`  
**OpenAPI**: `GET /products/{product_name}/clusters/{cluster_name}`

#### 前置条件

- 已完成创建（RM-BC-11），集群 `bc_{ts}` 含健康检查、大模型配置

#### 测试步骤

1. `GET .../clusters/bc_{ts}`，记录 `basic`、`timeouts`、`retries`、`passive_health_check`、`llm_config` 等
2. UI 点击「详情」，逐区块比对

#### 预期结果

| UI 详情区块 | OpenAPI 来源 | 比对要点 |
| ------------- | -------------- | ---------- |
| 基础配置 | `basic`、`sticky_sessions` | 协议、连接数、**enabled** 开关、哈希等与 API 一致 |
| 超时和重传 | `basic.timeouts`、`basic.retries.max_retry_in_cluster` | 各超时 ms、集群内重试一致 |
| 健康检查 | `passive_health_check` | host 可选、statuscode 0 或 100–599 |
| 大模型配置 | `llm_config` | 含 `provider`（所属服务商）、`models`（转发模型）、`model_mappings`（source_model/target_model）、`keys[]`（name/weight，无 key 明文）、`key_policy`、`key_affinity`、`match_prefix` / `strip_prefix` 与 OpenAPI 一致；**不含** service_name/group、instance_pool |

- **不再展示「实例配置」面板**：实例池由 Provider 维护，集群详情不再展示实例池明细；也不展示服务商实例池面板
- 所属服务商名称可跳转服务商详情；keys 仅展示 key 名称（脱敏，不展示 key 明文）
- 映射见 §3.7

### 2.35 复查页与提交数据一致

**用例编号**: RM-BC-35 | **优先级**: P1  
**设计依据**: `design/business-cluster/08-step-review.jpg`、`08-step-review-part1.jpg`

#### 前置条件

- 创建向导已完成第 1~4 步，进入第 5 步「复查 & 检查」

#### 测试步骤

1. 记录第 1~4 步表单中的**关键输入快照**（集群名、协议、超时、健康检查、模型等）
2. 在复查页读取各段摘要文案/表格
3. （可选）抓取提交请求 body 或创建后 `GET clusters` 结果

#### 预期结果

- 复查页各段展示与第 1~4 步输入**逐项一致**（无遗漏、无错显、单位一致）
- 提交成功后 `GET clusters` 与复查页**可比对字段**一致（健康检查、基础/超时等）
- 大模型段与提交后读回一致（接口见 §3.7），重点比对：
  - **所属服务商**：展示 provider 名称
  - **转发模型**：展示已选模型
  - **服务鉴权 Keys**：复查页展示 name / weight 与第 4 步输入的 keys 数组逐行一致；空行不出现在复查表格中；key 值在复查页不展示
  - **Key 路由策略**：strategy、max_retries、retry_backoff_initial、retry_backoff_max 四个字段与第 4 步输入一致（默认值也须正确展示）
  - **Key 亲和性**：未启用时仅显示「启用：关闭」；启用时展示「启用：开启」+ 绑定空闲超时(秒) / Redis Key 前缀 / Key 惩罚（开启/关闭）
  - **match_prefix / strip_prefix**：复查页暂不展示，比对提交请求体 + 创建后 GET
- **复查页「大模型配置」区完整展示**：所属服务商、转发模型、Keys（name/weight）、Key 路由策略、Key 亲和性、裁剪/匹配前缀、模型重定向等（如 design 复查面板展示）
- **不存在「实例配置」复查段**（实例池由 Provider 维护）
- **长文本布局**：复查摘要中包含超长配置值时各段摘要正常展示，无溢出

### 2.36 编辑向导回显与 OpenAPI 一致

**用例编号**: RM-BC-36 | **优先级**: P1  
**设计依据**: `design/business-cluster/10-edit-wizard-step-basic.jpg` 等

#### 前置条件

- 已存在集群 `bc_{ts}`（RM-BC-11）

#### 测试步骤

1. `GET .../clusters/bc_{ts}` 获取当前配置
2. UI 点击「编辑」，逐步打开第 1~4 步
3. 比对各步表单预填值与 API

#### 预期结果

| 向导步骤 | OpenAPI 段 | 比对要点 |
| ---------- | ------------ | ---------- |
| 1 基础配置 | `name`（只读）、`basic`、`sticky_sessions` | 名称不可改；其余与 GET 一致 |
| 2 超时重传 | `basic.timeouts`、`basic.retries` | 数值一致 |
| 3 健康检查 | `passive_health_check` | 各字段一致 |
| 4 大模型 | §3.7 注 | 与读回接口一致；所属服务商（provider）正确回显下拉值；转发模型回显勾选；**keys 数组**（name/weight，空时自动补一行空行）；**key_policy**（strategy/max_retries/retry_backoff_initial/retry_backoff_max）；**key_affinity**（enabled/ttl/redis_prefix/penalty_enable，无 key_affinity 字段的旧集群按默认值展示「启用：关闭」）；**match_prefix**（回显非空值）、**strip_prefix**（开关回显）；**model_mappings**（source_model/target_model）回显 |

- **不存在「实例配置」步骤**（实例池由 Provider 维护）
- 修改某字段并保存后，再次 `GET` 与详情（RM-BC-34）一致
- **长文本布局**：编辑表单中预填超长值时正常展示，不破坏表单布局
