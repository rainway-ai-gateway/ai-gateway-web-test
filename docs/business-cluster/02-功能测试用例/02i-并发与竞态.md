# AI 业务集群 - 并发与竞态（02i）

> 承载**并发/竞态**用例：共享控制面下的三人称视角——编辑期间他人修改、编辑期间被删除、
> 重复点击提交（docs/覆盖缺口清单.md #5）。编号前缀 BC-C（Business Cluster · Concurrency）。
>
> **设计取向**：不做真实「两个窗口同时点提交」的抖动型并发，而是用「API 侧变更 + UI 侧旧状态提交」
> 构造**确定性**竞态，断言系统行为与降级表现；真实双窗口并发留给性能/混沌专项。

### BC-C-01：编辑期间他人修改 → UI 提交覆盖（last-write-wins）

**优先级**: P1  
**前置条件**：集群 X 存在（描述为空）；管理员 A 打开编辑向导停留在第 1 步

#### 测试步骤

1. A 打开编辑向导
2. 通过 API 模拟管理员 B 修改集群描述为 `changed-by-others`（同一会话）
3. A 在向导内填写描述 `ui-value`，直接完成向导并提交（不重新加载数据）
4. `GET /clusters/{name}` 读回描述

#### 预期结果

1. B 的修改成功（PATCH 200）
2. A 的提交成功，**最终描述为 `ui-value`**——即后写覆盖，无乐观锁/版本校验
3. 该行为作为**已知偏差**记录：并发编辑会静默覆盖他人修改，运维应以「单一编辑人」为约定；如需防覆盖，需产品侧引入版本号/If-Match

### BC-C-02：编辑期间集群被删除 → 提交被拒且页面可继续使用

**优先级**: P1

#### 测试步骤

1. 打开集群 X 的编辑向导
2. 通过 API 删除集群 X（模拟他人删除）
3. 在向导内完成各步并提交
4. 关闭抽屉，回到列表

#### 预期结果

1. `PATCH /clusters/{name}` 返回 4xx（记录不存在），**无未捕获异常**
2. 抽屉可正常关闭；列表页可继续使用（无白屏/无卡死）
3. 列表中不再出现集群 X

---

### BC-C-03：重复点击提交 → 同名集群仅落库一条

**优先级**: P1

#### 测试步骤

1. 走完创建向导到复查页
2. 连续点击「提交」两次
3. 查询集群列表

#### 预期结果

1. 同名集群**仅一条**（后端名称唯一约束兜底；UI 不应产生重复行）
2. `POST /clusters` 请求次数 ≤ 2（第二次被 UI 关闭或后端拒绝）
3. 列表可正常定位该集群
