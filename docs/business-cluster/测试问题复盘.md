## BUG-BC-02：duration 数字框非法字符残留（RM-BC-122，非阻塞）

**预期（02）**：02b RM-BC-122 预期 5 / RM-BC-117 预期 4 —— 「数字框仅接受数字与小数点，`-`、字母等非数字字符无法输入」。

**实际**：`src/components/DurationInput/index.vue` 的 `onNumInput()` 会清洗 `numText`（仅保留数字与小数点），但当清洗结果为**空串**时组件 `value` prop 不变（`'' → ''`），子组件不重渲染，输入框内**残留用户原始字符**；清洗结果为空/非空都不影响 `v-model` 值。

实测（Chromium，逐字输入「健康检查间隔」数字框）：

1. 输入 `-` / `-a` / `-ab` / `-abc`：输入框显示依次为 `-`、`-a`、`-ab`、`-abc`（失焦后仍残留）；而组件值为空串 → 视为「未设置」
2. 输入 `-1`：输入框显示 `1`（负号被过滤，正常）
3. 输入 `1.` / `.5` / `1.5`：正常（`1.5` 未被吞成 `15`，2026-10-13 修复有效）

**证据**：`tests/cluster/test_09_business_cluster_balance_mode.spec.js` RM-BC-122 步骤 5 —— 输入 `-1` 后断言输入框为 `1`；输入 `abc` 后校验不报错，且复查页「健康检查间隔」按默认 `2s` 展示（说明非法字符**未进入提交值**）。因此该问题为「显示与模型不一致」的 UI 残留，不产生非法 duration 值。

**结论（2026-10-13 已修复）**：RM-BC-122 按 02b RM-BC-117 预期 4 的口径（「无法输入为非法 duration 值」）判定**已通过**；显示残留同步修复——`DurationInput.onNumInput` 在清洗后经 `this.$refs.combo` 强制把清洗值回写 DOM（iView `Input` 在 `value` prop 未发生变化时不回写 DOM，故此前残留原始字符）。修复后输入 `-abc` 输入框即时清空，用例断言不变、重跑通过。

## BUG-BC-03：`affinity=off` 时 Header 仅字段级校验跳过，提交级仍拦截（RM-BC-98，**已处置**：修订 02 预期 + 补充可操作提示）

**预期（02）**：`docs/business-cluster/02-功能测试用例/02d-大模型与校验.md` §2.98 预期 5 末句 / §2.123 预期 9 —— 「`affinity=off` 时……Header 的条件必填校验不触发（存量 `session_affinity_enabled=true` 且 header 为空的集群可正常提交）」。

**实际（`ai-gateway-web` @ dev-server `http://localhost:8180`）**：`affinity=off` 后两个亲和字段确实不渲染，iView 表单的**字段级**条件规则随之跳过（无 `.ivu-form-item-error-tip`），但点击「下一步 / 提交」时 `GatewayConfig.handleSubmit()` 仍执行 `validateEppConfig()`：

- `src/modules/Clusters/components/GatewayConfig.vue`：`validateSessionAffinityHeader` 已加 `affinity === 'off'` 豁免（字段级）；而 `validateEppConfig()` 中的 `if (epp.session_affinity_enabled && !header) return 启用会话亲和性时，Header 不能为空` **未加同样豁免**。
- 实测路径：开启会话亲和性 → Header 留空 → 亲和强度选 `off`（两字段隐藏、无内联错误）→ 点击「下一步」→ 全局提示「启用会话亲和性时，Header 不能为空」，步骤停在「大模型配置」，无法进入「复查&检查」。
- 前提本身亦不可构造：后端 `ai-gateway-api/model/epp_pool/epp_config.go` 的 `EppConfigSimplified.Validate()` 对 `session_affinity_enabled=true` 同样要求 header 非空（缺省或空串 422），因此「存量 `enabled=true` 且 header 为空」的集群无法通过 UI 或 OpenAPI 建立；即便前端豁免，`buildEppConfig()` 仍会下发空串 header 而被后端拒绝。

**证据（Playwright 产物，2026-10-28 `test_09` 全量执行）**：

- 截图：`test-results/tests-cluster-test_09_busi-dc911-f-时-Header-条件必填不触发（02-预期-5）/test-failed-1.png`
- 页面快照：同目录 `error-context.md`（步骤树停在「5 待进行 复查&检查」）
- 失败断言：`tests/cluster/test_09_business_cluster_balance_mode.spec.js` 用例「RM-BC-98 affinity=off 时 Header 条件必填不触发（02 预期 5）」步骤 3 `utils.expectWizardStep(page, '复查&检查')`

**处置（待产品决策）**：

1. 修实现：`validateEppConfig` 对 `affinity === 'off'` 豁免 header 必填，并同步后端 `Validate()`（或前端在 `affinity === 'off'` 时不下发 `session_affinity_header`）；
2. 或修订 02 预期末句：明确「`affinity=off` 只会跳过字段级条件必填；`enabled=true` 时 header 仍须非空（前后端一致）」，并删除「存量…可正常提交」的不可能前提。

在决策前，该用例保持 `阻塞`，断言按 02 保留不改；RM-BC-98 的其余预期与 RM-BC-123 全部预期均已通过（`test_09` 定向 3/4 通过、`test_11` 3/3 通过）。
