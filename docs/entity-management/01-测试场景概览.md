# Entity管理模块 - 测试场景概览

## 模块概述

Entity管理模块是AI网关系统的配额控制与限流管理核心模块，负责管理API访问的身份凭证和资源实体。该模块包含三个核心功能区域：

| 功能区域 | 说明 |
| --------- | ------ |
| **Entity类型管理** | 定义Entity类型（如部门、团队、个人等），支持层级级别设置（1-5级） |
| **Entity组织管理** | 创建和管理Entity实体，支持层级结构，配置配额和限流策略 |
| **API-Key管理** | 创建、管理API访问凭证，配置配额计划和限流策略，挂载到Entity |

## 配置顺序

三个模块的配置存在依赖关系，必须按照以下顺序进行：

```
Entity组织管理（默认Tab） → Entity类型管理 → API-Key管理
```

## 场景测试设计

本模块采用**场景测试**方法，从真实用户的使用流程出发，模拟用户在特定情境下完整操作系统，验证系统是否能正常工作。

### 场景一：管理员配置Entity类型

**场景描述**：系统管理员首次配置系统，定义Entity类型（如部门、团队、个人），建立组织架构的基础。

**涉及测试场景**：

| 步骤 | 操作 | 对应场景编号 | 优先级 |
| ------ | ------ | ------------ | -------- |
| 1 | 进入Entity类型管理页面，查看现有类型列表 | EM-T-01 | P1 |
| 2 | 点击"创建类型"，填写类型名、描述和级别，点击确定 | EM-T-02 | P0 |
| 3 | 验证类型名必填、重复、格式、长度边界校验 | EM-T-03~EM-T-06 | P1/P2 |
| 4 | 创建过程中取消操作 | EM-T-07 | P1 |
| 5 | 创建多个不同级别的类型 | EM-T-02（多次） | P0 |
| 6 | 在搜索框输入类型名进行搜索、分页 | EM-T-08~EM-T-09 | P1/P2 |
| 7 | 点击"编辑"，验证类型名不可修改，修改描述和级别 | EM-T-10~EM-T-11 | P1 |
| 8 | 点击"删除"，确认/取消删除类型 | EM-T-12~EM-T-13 | P0/P1 |

**测试目标**：验证管理员能否顺利创建、编辑、删除Entity类型，系统各项校验机制是否正常工作。

| 数据类别 | 准备内容 | 用途 |

## 自动化实施注意事项

> 以下规范详见 [SKILL.md](../../.trae/skills/ai-gateway-test-generation/SKILL.md) 对应章节。

### 测试标签（Tag）

| 标签 | 用途 | 示例 |
| ------ | ------ | ------ |
| `@smoke` | 冒烟测试，核心功能快速验证 | `test('@smoke 验证列表页面加载', ...)` |
| `@regression` | 回归测试，完整 CRUD 流程 | `test('@regression 验证创建成功', ...)` |
| `@validation` | 表单校验 | `test('@validation 验证必填校验', ...)` |
| `@journey` | 端到端场景串联 | `test('@journey 全流程配置链验证', ...)` |

### Spec 文件结构

- 使用 `test.step()` 组织步骤，步骤描述清晰
- 前置条件中有数据清理（防残留）
- 结尾有 `清理测试数据` step
- 使用 Page Object 模式，spec 中无裸选择器

### 并发安全

- 多 worker 并行时，测试数据必须加时间戳/随机后缀隔离
- 命名规范：`test_{模块}_{时间戳}_{随机数}`
- 避免多用例同时操作同一资源（如同一父 Entity 下创建同名子节点）

### 异步等待

- 使用 Playwright 内置的 auto-waiting 机制
- 避免硬编码 `waitForTimeout`
- 长流程用例设置合理超时时间

### 敏感信息处理

- 密码、Token、Session Key 等不得硬编码在代码中
- 使用环境变量或 `config/config.ts` 中的配置管理
- 测试账号信息通过 `auth.setup.ts` 统一获取

### 环境依赖

- 不同环境（test/staging/prod）可能有差异，用例需兼容
- 避免依赖特定环境的预置数据
- 每个用例应能独立运行，不依赖其他用例的执行结果

### 用例追溯标记

- 用例标题中包含需求 ID 和 Bug ID，便于追溯和影响分析
- 格式：`EM-T-01 Entity类型列表展示 [REQ-xxx]`
- 精准回归时可根据标记快速定位受影响用例
