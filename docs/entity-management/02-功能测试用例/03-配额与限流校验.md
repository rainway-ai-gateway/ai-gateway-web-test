### 2.23 创建Entity-配额总量小数校验

**功能模块**: Entity组织管理  
**优先级**: P0  
**用例编号**: EM-E-23

#### 前置条件

- 已登录系统并进入 Entity 组织管理页面
- 已存在至少一个 Entity 类型

- 不出现后端 JSON 解析类错误（如 `cannot unmarshal number 5.3 into … int64`）

#### 测试数据

- 配额总量：`5.3`（自动化经 Vue 模型注入；UI 无法直接键入）

### 2.26 TPM/RPM 规则字段校验

**功能模块**: Entity组织管理  
**优先级**: P0  
**用例编号**: EM-E-26 ~ EM-E-37  
**自动化**: `test_06_entity_rate_limit_fields.spec.js`

#### 前置条件

- 已登录并进入 Entity 组织管理
- 已存在 Entity 类型
- 创建 Entity 表单中**启用限流 = 是**，并已添加对应 TPM/RPM 规则行

> **序号说明**：错误提示中的「第 **n** 条」= 该类型（TPM 或 RPM）规则列表中**从 1 计数**的序号，与出错的那一行一一对应（UI 校验 `{ index: i + 1 }`）。仅添加 1 条规则时 n=1；若第 2 条规则字段非法，则显示「第2条…」，以此类推。

#### 校验矩阵

1. **EM-E-26 · TPM 规则名称**：输入留空 → 预期「第{n}条TPM规则请输入规则名称」
2. **EM-E-27 · TPM 时间窗口(分)**：输入 `0` → 预期「第{n}条TPM规则时间窗口范围为1-360分钟」
3. **EM-E-28 · TPM 时间窗口(分)**：输入 `361` → 预期「第{n}条TPM规则时间窗口范围为1-360分钟」
4. **EM-E-29 · TPM 滑动步长(分)**：输入 `0` → 预期「第{n}条TPM规则滑动步长范围为1-360分钟」
5. **EM-E-30 · TPM 滑动步长(分)**：输入 `361` → 预期「第{n}条TPM规则滑动步长范围为1-360分钟」
6. **EM-E-31 · TPM 最大Token数**：输入 `0` → **允许为 0**（合法下界）
7. **EM-E-32 · TPM 最大Token数**：输入 `9223372036854775808` → 预期「第{n}条TPM规则最大Token数超出允许范围」
8. **EM-E-33 · RPM 规则名称**：输入留空 → 预期「第{n}条RPM规则请输入规则名称」
9. **EM-E-34 · RPM 时间窗口(分)**：输入 `0` → 预期「第{n}条RPM规则时间窗口范围为1-360分钟」
10. **EM-E-35 · RPM 时间窗口(分)**：输入 `361` → 预期「第{n}条RPM规则时间窗口范围为1-360分钟」
11. **EM-E-36 · RPM 最大请求数**：输入 `0` → 允许为 0（合法下界）
12. **EM-E-37 · RPM 最大请求数**：输入 `9223372036854775808` → 预期「第{n}条RPM规则最大请求数超出允许范围」

#### 字段取值约定

- **规则名称**：必填，非空字符串
- **时间窗口(分)**：1 ~ 360
- **滑动步长(分)（仅 TPM）**：1 ~ 360，且 ≤ 时间窗口
- **最大Token数（TPM）**：0 ~ 9223372036854775807
- **最大请求数（RPM）**：0 ~ 9223372036854775807
