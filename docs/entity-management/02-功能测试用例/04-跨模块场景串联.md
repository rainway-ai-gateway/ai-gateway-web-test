### 4.1 管理员首次配置全UI流程

**功能模块**: Entity 类型 + Entity 组织 + API-Key（跨模块）  
**优先级**: P0  
**用例编号**: EM-J-01  
**自动化**: `test_05_entity_full_journey.spec.js` 第一条

**设计依据**: [01 场景四](../01-测试场景概览.md#场景四跨模块场景串联journey)  
**覆盖目标**: [EM-K-30](../../api-key/02-功能测试用例/03-E2E全流程.md#330-e2e-api-key全流程)（含类型/组织 UI 前置）

#### 前置条件

- 已登录系统（`globalSetup` + `auth.json`）
- 单条用例内按顺序完成，不依赖其他 spec 残留数据
- 失败时 `afterEach` 通过 API 清理已追踪资源

#### 测试步骤

与 [EM-K-30](../../api-key/02-功能测试用例/03-E2E全流程.md#330-e2e-api-key全流程) 步骤 1~8 一致，且明确要求：

- 步骤 1~3、6~8 均为 **UI 操作**（禁止 API 造数替代创建）
- 模块切换使用侧栏或 Tab，不重复登录

#### 预期结果

- 完整走通「类型 → 组织 → API-Key → 编辑 → 重置配额 → 删除 Key → 删除 Entity → 删除类型」
- 各步预期分别引用 EM-T/E/K 对应单条用例
- 用例结束时环境无残留测试数据（UI 删除成功或 cleanup 兜底）
