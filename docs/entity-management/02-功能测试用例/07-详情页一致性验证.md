## 6. 详情页全字段一致性验证

> **归属场景**: 场景六 (详情页全字段一致性验证)

### 6.1 Entity Org 详情页全字段与接口数据一致性

**功能模块**: Entity 组织管理  
**优先级**: P0  
**用例编号**: EOD-01

#### 前置条件

- 已登录系统并进入 Entity 组织管理页面
- 已创建至少一个 Entity 类型

#### 测试步骤

1. 通过接口创建带完整配置的子 Entity：
   - 名称：自定义名称
   - 类型：选择已有类型
   - 父 Entity：选择已有根 Entity
   - 描述：自定义描述
   - 配额信息：有限配额，配额总量 100000000，配额单位 total_token，重置周期每月
   - 限流信息：启用限流，TPM 规则（名称 tpm-rule，时间窗口 60 分，最大 Token 数 10000），RPM 规则（名称 rpm-rule，时间窗口 1 分，最大请求数 100）
2. 在列表中点击该 Entity 行，打开详情抽屉
3. 逐一验证详情页字段与接口返回数据一致：

**基本信息验证**:

- 名称：与接口 `name` 一致
- 类型：与接口 `type` 对应的类型名称一致
- 父 Entity：与接口 `parent_id` 对应的父 Entity 名称一致
- 描述：与接口 `description` 一致

**配额信息验证**:

- 无限配额：与接口 `quota_plan.unlimited` 一致（是/否）
- 配额单位：与接口 `quota_plan.unit` 一致（`total_token` / `RMB`）
- 配额总量：按 unit 动态展示
  - `unit=total_token` → 显示为 `xxx tokens`（整数，带千位分隔符），与接口 `quota_plan.quota` 数值一致
  - `unit=RMB` → 显示为 `¥xxx`（4 位小数），数值与接口 `quota_plan.quota` 一致（四舍五入到 4 位）
- 已使用（`balance.used`）：按 unit 动态展示
  - `unit=total_token` → `xxx tokens`（整数，带千位分隔符），与接口 `quota_plan.used` 一致
  - `unit=RMB` → `¥xxx`（4 位小数），与接口 `quota_plan.used` 一致（四舍五入到 4 位）
- 剩余量（`balance.remaining`）：按 unit 动态展示
  - `unit=total_token` → `xxx tokens`（整数，带千位分隔符），与接口 `quota_plan.remaining` 一致
  - `unit=RMB` → `¥xxx`（4 位小数），与接口 `quota_plan.remaining` 一致（四舍五入到 4 位）
- 重置周期：与接口 `quota_plan.reset_period` 一致（每月/每周/永不重置）

**限流信息验证**:

- 限流状态：与接口 `rate_limit_policy.enabled` 一致（已启用/未启用）
- TPM 规则名称：与接口 `rate_limit_policy.rules.tpm[0].name` 一致
- TPM 时间窗口：与接口 `rate_limit_policy.rules.tpm[0].window_minutes` 一致
- TPM 最大 Token 数：与接口 `rate_limit_policy.rules.tpm[0].max_tokens` 一致
- RPM 规则名称：与接口 `rate_limit_policy.rules.rpm[0].name` 一致
- RPM 时间窗口：与接口 `rate_limit_policy.rules.rpm[0].window_minutes` 一致
- RPM 最大请求数：与接口 `rate_limit_policy.rules.rpm[0].max_requests` 一致

**时间信息验证**:

- 创建时间：显示日期格式，与接口 `create_time` 时间戳转换后一致
- 更新时间：显示日期格式，与接口 `update_time` 时间戳转换后一致

#### 预期结果

- 详情页所有字段与接口返回数据完全一致

#### 测试数据

- 名称：entity_eod01_时间戳
- 类型：type_时间戳
- 父 Entity：root_entity_时间戳
- 描述：Entity 详情验证测试
- 配额总量：100000000（显示为 100,000,000）
- TPM 规则：tpm-rule / 60 分 / 10000 tokens
- RPM 规则：rpm-rule / 1 分 / 100 requests
