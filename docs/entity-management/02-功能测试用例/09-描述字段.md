## 8. Entity 描述（2026-09-22）

> 变更背景：
>
> 1. **Entity 新增可选字段 `description`**：长度 0–255 字符；不能包含控制字符；**非必填**（留空允许提交）。
> 2. **创建 / 编辑表单**：「描述」**不加必填星号**；**不展示提示小字**；placeholder 为「请输入Entity描述」（不体现「选填」）。
> 3. **列表**：新增「描述」列（位置：名称 → 描述 → 类型）；空值展示 `-`；支持搜索（placeholder「请输入描述查询」）与排序。
> 4. **详情**：基本信息区新增「描述」行（顺序：名称 → 描述 → 类型）；空值展示 `-`。
> 5. **提交语义**：编辑走 `PATCH /entities/{id}` —— 省略 `description` 保留原值，显式传空字符串 `""` 清空。
>
> 接口依据：`entities.md` §2.1 字段表 `description`、§2.2 创建 body、§3.2 响应体、§4.1 PUT（全量，省略即清空）、§4.2 PATCH（增量，省略保留 / `""` 清空）；DDL `db_ddl_sqlite.sql` `entities.description TEXT NOT NULL DEFAULT ''`。  
> UI 依据：`modifications/2026-09-22-entity-description-and-protocol-paths/ui-code-changes.md`；原型 `prototype-design/assets/js/entity-upsert.js`、`prototype-design/pages/entity.html`。

### EM-DESC-01：Entity 列表-描述列展示与搜索

**功能模块**: Entity 描述  
**优先级**: P0  
**用例编号**: EM-DESC-01  
**设计依据**: 原型 `pages/entity.html` 实体列表列定义；`ui-code-changes.md` §2.4 / §2.6  
**OpenAPI**: `GET /entities` 响应体 `description`

#### 前置条件

- 已登录系统并进入 Entity 组织管理页面
- 已存在至少 2 个 Entity：其一描述为「运营部，负责线上业务」，另一描述留空

#### 测试步骤

1. 查看列表表头列顺序
2. 查看有描述行与无描述行在「描述」列的展示
3. 在「描述」列搜索框输入「运营部」并搜索
4. 点击「描述」列表头排序

#### 预期结果

1. 列顺序为：ID → Entity名称 → **描述** → 类型 → 父Entity → 配额计划 → 限流状态 → 操作
2. 有描述行展示接口返回的 `description` 原文；描述为空的行展示 `-`
3. 「描述」列搜索框 placeholder 为「请输入描述查询」；搜索后仅保留描述命中的行（按 `description` 模糊匹配）
4. 「描述」列支持自定义排序，排序请求参数与结果与接口一致
