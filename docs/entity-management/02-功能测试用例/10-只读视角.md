## 9. 只读管理员视角（写操作隐藏）

> 变更背景：
>
> 1. **角色模型调整**：后端以 `role` 取代 `is_admin`，角色取值为 `system_admin`（系统管理员，可读写）与 `system_admin_readonly`（只读管理员）。本模块页面依据当前登录用户的 `role` 决定写操作入口是否展示。
> 2. **全站隐藏写操作按钮**：只读视角（`role === 'system_admin_readonly'`）下，全站隐藏**所有写操作按钮**，仅保留只读入口（详情/查看/查询）。实现为全局 Vue 指令 `v-has`，只读命中时追加 `.v-has-hidden` 类（`display:none !important`）。
> 3. **Entity 页面**（`pages/entity.html`）：只读视角保留「管理路由规则」；隐藏「创建Entity」「创建类型」「编辑」「删除」「类型编辑/删除」。
> 4. **详情抽屉「重置配额」按钮**：只读视角隐藏（不展示写操作入口）。
>
> 接口依据：`ui-code-changes.md` §2 / §3.4（`pages/entity.html` 保留「管理路由规则」，隐藏「创建Entity/创建类型/编辑/删除/类型编辑删除」）；角色字段 `role`。  
> UI 依据：`modifications/2026-10-12-readonly-admin/ui-code-changes.md`。  
> 自动化：`tests/entity-management/test_11_entity_readonly.spec.js`（EM-E-RO-01~03，每个用例先管理员对照再切只读账号 `viewer`）。  
> 前端源码依据（`ai-gateway-web/src/modules/Entity`）：`EntityList.vue:20/207/229`、`EntityTypeList.vue:20/124/143`、`EntityView.vue:126` 写入口均挂全局指令 `v-has` → 只读态加 `.v-has-hidden`（`display:none !important`），元素**仍在 DOM 中**，故只读断言用「仍在 DOM + 含 `.v-has-hidden` + 不可见」三重判定；本模块无 `store.isReadonly()` / `v-show` 模式收敛分支。

### EM-E-RO-01：只读视角列表工具栏写按钮隐藏

**功能模块**: Entity组织管理  
**优先级**: P0  
**用例编号**: EM-E-RO-01  
**设计依据**: `ui-code-changes.md` §3.4（`pages/entity.html` 只读隐藏「创建Entity/创建类型」）  
**OpenAPI**: `GET /entities`、`GET /entity-types`

#### 前置条件

- 以只读管理员账号（`role = system_admin_readonly`）登录系统，进入 Entity 管理页面
- 已存在至少一个 Entity 类型与一个 Entity

#### 测试步骤

1. 切换到「Entity 组织管理」Tab，查看列表工具栏
2. 切换到「Entity 类型管理」Tab，查看列表工具栏
3. 以系统管理员账号（`role = system_admin`）登录后重复步骤 1~2，对比工具栏

#### 预期结果

1. 只读视角下，「Entity 组织管理」工具栏的「创建Entity」按钮**不展示**（命中 `.v-has-hidden`，`display:none`）
2. 只读视角下，「Entity 类型管理」工具栏的「创建类型」按钮**不展示**
3. 系统管理员视角下上述按钮正常展示，与只读视角形成对照

#### 测试数据

- 只读账号：`role = system_admin_readonly`（原型 `viewer`）；管理员账号：`role = system_admin`
- 数据策略：**复用环境已有数据**。前置「已存在至少一个 Entity 类型与一个 Entity」由环境满足，本用例只查看工具栏、不依赖特定数据。
  自动化侧在 `beforeAll` 用独立 admin context 经 `GET /entity-types` / `GET /entities` 读取首条复用；仅当列表为空才造数并在 `afterAll` 清理，不污染共享环境。

### EM-E-RO-02：只读视角列表操作列写按钮隐藏

**功能模块**: Entity组织管理  
**优先级**: P0  
**用例编号**: EM-E-RO-02  
**设计依据**: `ui-code-changes.md` §3.4（`pages/entity.html` 只读保留「管理路由规则」，隐藏「编辑/删除/类型编辑删除」）  
**OpenAPI**: `GET /entities`、`GET /entity-types`

#### 前置条件

- 以只读管理员账号（`role = system_admin_readonly`）登录系统，进入 Entity 管理页面
- 已存在至少一个 Entity 类型与一个 Entity

#### 测试步骤

1. 切换到「Entity 组织管理」Tab，查看列表数据行的操作列
2. 切换到「Entity 类型管理」Tab，查看列表数据行的操作列
3. 以系统管理员账号登录后重复步骤 1~2，对比操作列

#### 预期结果

1. 只读视角下，「Entity 组织管理」操作列隐藏「编辑」「删除」按钮，仅保留「管理路由规则」（绿色按钮，可跳转），其余写操作入口均不展示
2. 只读视角下，「Entity 类型管理」操作列隐藏「编辑」「删除」按钮
3. 系统管理员视角下操作列完整展示「管理路由规则」「编辑」「删除」，与只读视角形成对照

#### 测试数据

- 只读账号：`role = system_admin_readonly`；管理员账号：`role = system_admin`
- 目标行：环境已存在的「有限配额 Entity」（取值策略见 EM-E-RO-03 测试数据）+ `GET /entity-types` 首条类型名
- 数据策略：**复用环境已有数据**，只读用例不新建 / 不修改 / 不删除任何记录；目标行经列表「名称 / 类型名」前端筛选定位（该检索本身即只读能力的验证）
- 断言方式：写按钮虽被隐藏但仍在 DOM 中，用「仍在 DOM + class 含 `.v-has-hidden` + 不可见」判定；「管理路由规则」断言保留可见、可点击且为 `success`（绿色）型按钮

### EM-E-RO-03：只读视角详情抽屉「重置配额」按钮隐藏

**功能模块**: Entity组织管理  
**优先级**: P0  
**用例编号**: EM-E-RO-03  
**设计依据**: `ui-code-changes.md` §3.4（只读视角隐藏写操作按钮，含详情「重置配额」）  
**OpenAPI**: `GET /entities/{id}`

#### 前置条件

- 以只读管理员账号（`role = system_admin_readonly`）登录系统
- 已存在一个有限配额的 Entity

#### 测试步骤

1. 在 Entity 列表点击 Entity 名称打开详情抽屉，查看配额信息区域
2. 以系统管理员账号登录后打开同一 Entity 详情抽屉，对比配额信息区域

#### 预期结果

1. 只读视角下，详情抽屉配额信息区域**不展示**「重置配额」按钮，其余只读字段（无限配额、配额总量、配额单位、已使用、剩余量、重置周期、使用进度等）正常展示
2. 系统管理员视角下详情抽屉正常展示「重置配额」按钮，与只读视角形成对照
3. Entity 详情不含密钥/Key 字段，无掩码展示相关校验

#### 测试数据

- 只读账号：`role = system_admin_readonly`；管理员账号：`role = system_admin`
- 「有限配额 Entity」判定：`quota_plan.unlimited !== true && !== 'true'`（对应 `EntityView.vue:382 quotaPlanUnlimited`）；只有有限配额才渲染配额信息区与「重置配额」入口
- 数据策略：**优先复用环境已存在的有限配额 Entity**（`GET /entities` 逐条按上述规则判定），复用时不删除、不修改任何环境数据；
  环境全部为无限配额时，自动化侧在 `beforeAll`（独立 admin context）造 1 条 `total_token / quota=100000 / reset_period=monthly` 的 Entity 作为目标，`afterAll` 按 id 删除
- 断言方式：「重置配额」用「仍在 DOM + class 含 `.v-has-hidden` + 不可见」判定；配额信息区只读字段（无限配额 / 配额总量 / 配额单位 / 已使用 / 剩余量 / 重置周期 / 使用进度）逐个断言可见
