## 11. Entity 模型白名单 / 黑名单（2026-11-01 补审计）

> 审计背景（2026-11-01，entity-management 模块深度审计）：
>
> Entity 创建/编辑表单自 v0.0.3 起即有「允许模型」「禁止模型」两个多选下拉，详情抽屉也有对应两行展示，但**本模块此前 0 条用例、0 处文档描述**（仅 `api-key` 模块的「允许模型」有文档），属元素级覆盖空白。
>
> 产品语义依据（模型继承）：`ai-gateway-api/design-docs/sys-design/details/API-Key与Entity关联及模型继承.md` §5
>
> - `allow_models`：沿 `parent_id` 向上取**交集**，含 `*` 的层级不参与；
> - `block_models`：沿 `parent_id` 向上取**并集**，含 `*` 的层级不参与；
> - 前端提交约定：`allow_models` 默认 `["*"]`（全部模型）；`block_models` 为空时提交 `["*"]` 作为「未设置」哨兵，详情页/编辑回显均按「未设置」处理（详情「禁止模型」展示 `-`）。
>
> 选项数据源：`GET /clusters` → `llm_config.models` 去重（前端 `fetchModelServices`）。

### EM-E-63：创建 Entity-配置允许模型与禁止模型

**功能模块**: Entity 组织管理 / 模型白名单与黑名单  
**优先级**: P1  
**用例编号**: EM-E-63  
**设计依据**: `EntityUpsert.vue`「允许模型/禁止模型」多选（`FormItem` 无 `prop`，不经 FormItem 校验）；`EntityView.vue` `allowModelsText` / `blockModelsText`  
**OpenAPI**: `POST /entities` body `allow_models` / `block_models`；`GET /entities` 响应体同名

#### 前置条件

- 已登录系统（管理员）并进入 Entity 组织管理页面
- 环境 `GET /clusters` 至少返回 2 个具体模型（去重后）；不足时用例自动跳过并记录原因

#### 测试步骤

1. 打开创建 Entity 抽屉，查看「允许模型」默认选中项
2. 摘掉「允许模型」默认的「全部模型」标签，选择具体模型 A
3. 「禁止模型」选择具体模型 B（A ≠ B）
4. 填写名称、选择类型，提交
5. 抓取 `POST /entities` 请求体；提交成功后 `GET /entities` 回读
6. 点击该行打开详情抽屉

#### 预期结果

1. 「允许模型」默认选中「全部模型」（对应 `*`）
2. 允许模型仅保留模型 A（不残留 `*`）；禁止模型仅含模型 B
3. `POST /entities` 请求体 `allow_models == ["<A>"]`、`block_models == ["<B>"]`
4. `GET /entities` 回读 `allow_models` / `block_models` 与请求体一致（未被后端归一化或丢弃）
5. 详情「基本信息」区「允许模型」展示 A、「禁止模型」展示 B

### EM-E-64：编辑 Entity-修改允许模型与禁止模型

**功能模块**: Entity 组织管理 / 模型白名单与黑名单  
**优先级**: P1  
**用例编号**: EM-E-64  
**设计依据**: `EntityUpsert.vue` `normalizeModelFields`（编辑回显时 `*` 归一为「全部模型」/ 空）与 PATCH 提交组装  
**OpenAPI**: `PATCH /entities/{id}` body `allow_models` / `block_models`

#### 前置条件

- 接口造数：类型 + Entity（`allow_models=["*"]`、`block_models=[]`、无限配额）
- 刷新 Entity 组织管理页并搜索到该 Entity

#### 测试步骤

1. 点击该行「编辑」打开抽屉，查看「允许模型」「禁止模型」回显
2. 摘掉「全部模型」，改选具体模型 A；「禁止模型」改选模型 B
3. 提交并抓取 `PATCH /entities/{id}` 请求体
4. `GET /entities` 回读并打开详情抽屉

#### 预期结果

1. 「允许模型」回显「全部模型」；「禁止模型」无标签（`[]` 表示未设置）
2. PATCH 请求体 `allow_models == ["<A>"]`、`block_models == ["<B>"]`（增量语义：显式携带即覆盖）
3. 接口回读与详情展示均与所选一致（允许模型 A / 禁止模型 B）

### EM-E-65：未配置禁止模型时的默认语义

**功能模块**: Entity 组织管理 / 模型白名单与黑名单  
**优先级**: P1  
**用例编号**: EM-E-65  
**设计依据**: `EntityUpsert.vue` 提交前归一（空 `block_models` → `["*"]`）、编辑回显归一（`["*"]` → `[]`）、`EntityView.vue` `blockModelsText` 过滤 `*`  
**OpenAPI**: `POST /entities` body `block_models`；`GET /entities` 响应体

#### 前置条件

- 打开创建 Entity 抽屉，已存在可用 Entity 类型

#### 测试步骤

1. 只填名称与类型，不触碰「允许模型」「禁止模型」，直接提交
2. 抓取 `POST /entities` 请求体并 `GET /entities` 回读
3. 打开详情抽屉查看「允许模型」「禁止模型」两行
4. 再次点「编辑」打开抽屉查看「禁止模型」标签

#### 预期结果

1. 请求体 `allow_models == ["*"]`、`block_models == ["*"]`（前端「未设置」哨兵）
2. 详情「允许模型」展示「全部模型」；「禁止模型」展示 `-`（不出现字面量 `*`）
3. 编辑抽屉「禁止模型」无任何标签（回显归一为空）
4. 接口回读 `block_models` 不含任何具体模型（仅可能含 `*` 哨兵），即「未配置禁止模型」不会误禁具体模型
