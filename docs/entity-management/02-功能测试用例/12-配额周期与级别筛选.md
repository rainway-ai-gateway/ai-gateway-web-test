>
> - 「重置周期」（`reset_period`：永不重置 / 每周 / 每月）与「配额不足时放行」（`pass_when_no_enough_quota`）此前**只有详情只读一致性（EOD-01）读取**，没有任何用例验证「设置后能否落库、能否回显」——即设置路径空白。
> - 列表「级别」列（`level`，来源为 Entity 所属类型的级别）与搜索区「级别」下拉（1~5）此前无任何用例。

> 接口依据：`entities.md` §2.2 创建 body（`quota_plan.reset_period` / `quota_plan.pass_when_no_enough_quota`）、§4.2 PATCH 增量语义；`GET /entity-types` 提供 `level`（1~5）。

### EM-E-66：创建 Entity-配置重置周期与配额不足时放行

**功能模块**: Entity 组织管理 / 配额信息  
**优先级**: P1  
**用例编号**: EM-E-66  
**设计依据**: `EntityUpsert.vue` 配额卡片「重置周期」（iView Select，选项 永不重置/每周/每月）与「配额不足时放行」（是/否）；`EntityView.vue` `getResetPeriodText` 映射  
**OpenAPI**: `POST /entities` body `quota_plan.quota` / `unit` / `reset_period` / `pass_when_no_enough_quota`

#### 前置条件

- 已登录并进入 Entity 组织管理页面；已存在一个级别 1 的 Entity 类型

#### 测试步骤

1. 打开创建 Entity 抽屉，填写名称、选择类型
2. 「无限配额」选「否」，配额总量填 `1000`，配额单位 `total_token`
3. 「重置周期」选「每周」；「配额不足时放行」选「是」
4. 提交并 `GET /entities` 回读
5. 打开该 Entity 详情抽屉

#### 预期结果

1. 表单「重置周期」「配额不足时放行」选中项分别为「每周」「是」
2. 提交成功（列表刷新、抽屉关闭）
3. 接口回读 `quota_plan.quota == 1000`、`unit == "total_token"`、`reset_period == "weekly"`、`pass_when_no_enough_quota == true`
4. 详情「配额信息」区「重置周期」展示「每周」、「配额不足时放行」展示「是」

### EM-E-67：列表按级别筛选

**功能模块**: Entity 组织管理 / 列表查询  
**优先级**: P2  
**用例编号**: EM-E-67  
**设计依据**: `EntityList.vue` `level` 列（`searchable` + `searchType: 'select'`，搜索区 placeholder「请选择级别」，选项 1~5）；`pageTable` 纯前端过滤  
**OpenAPI**: `GET /entities` 响应体 `level`

#### 前置条件

- 接口造数：级别 1 类型 + 其下 Entity A；级别 2 类型 + 其下 Entity B
- 刷新 Entity 组织管理页

#### 测试步骤

1. 分别搜索 A、B，读取「级别」列文本
2. 级别下拉选 `1`，依次搜索 A、B
3. 级别下拉改选 `2`，依次搜索 A、B
4. 清除级别筛选，依次搜索 A、B

#### 预期结果

1. A 的「级别」列为 `1`，B 为 `2`（与所属类型级别一致）
2. 筛选 `1` 时 A 可见、B 被过滤
3. 筛选 `2` 时 B 可见、A 被过滤
4. 清除筛选后 A、B 均可见

> 说明：级别筛选与名称搜索为**叠加**过滤（AND），故本用例以「名称搜索锁定单行 + 级别筛选」组合断言，避免受分页与既有环境数据干扰。
