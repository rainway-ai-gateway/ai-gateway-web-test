# Entity 组织管理 - 布局与最大长度

> **背景（2026-11-02）**：项目无视觉回归测试（无 `toHaveScreenshot`/像素比对），「输入到最大长度后样式混乱或不可见」此前无覆盖（见 [覆盖缺口清单 §27](../../覆盖缺口清单.md)）。本文件用 **DOM 指标断言**（`utils/layout.js`：scrollWidth/clientWidth、getBoundingClientRect 重叠与越界、line-height 行数估算）覆盖 Entity 组织管理的满载布局场景。
>
> **断言工具**：`utils/layout.js`（`expectNoHorizontalOverflow` / `expectNoRectOverlap` / `expectCellLineCap` / `expectFooterVisibleInViewport` / `readLayoutMetrics`）。

## EM-LAY-01 创建抽屉满载布局（P1）

- **测试数据**：类型经 UI 创建（避免下拉同步延迟）；名称 64 字符、描述 255 字符。
- **步骤**：
  1. Entity 组织管理页打开「创建Entity」抽屉，填满名称 64 + 描述 255；
  2. 抽屉内容区（`.ivu-drawer-body`）无横向溢出（`scrollWidth <= clientWidth + 1`）；
  3. 名称提示行（`.form-tip`，「1–64 字符；仅小写字母、数字、_、-」）与描述输入框矩形不重叠；
  4. 底部按钮区（`.drawer-footer`）完整落在视口内；
  5. 取消抽屉并确认关闭。
- **预期**：全部通过（2026-11-02 定向 4/4 spec 通过时本用例真实通过）。
- **自动化**：`tests/entity-management/test_15_entity_layout_max_length.spec.js`

## EM-LAY-02 列表行满载布局（P1）

- **测试数据**：API 创建类型 + Entity（描述 255 字符 ASCII）；列表按名称搜索定位行。
- **步骤**：
  1. 列表表格容器（`.ivu-table-wrapper`）无横向溢出；
  2. 描述单元格行数 ≤3 行（按 `scrollHeight / lineHeight` 估算），或 ellipsis 截切实效（`text-overflow=ellipsis` 且内容被裁切）。
- **预期**：通过（2026-11-02 修复后真实通过）。
- **修复记录（2026-11-02）**：原缺陷——「描述」列 `white-space:normal; word-break:break-all` 无 ellipsis，255 字符折行约 8 行、行高 ~336px（探针实测）。修复：`EntityList.vue` 描述列 `ellipsis: true` + render span `.cell-ellipsis` + `title` 悬浮全文；同表「名称」「类型」「父Entity」列一并加上（修复后发现 26 字符类型名即可把行高撑到 104px——探针实测，故类型/父Entity列同批处理）。**同批缺陷**：PR-LAY-01 / RT-LAY-01 / TM-LAY-01 / AC-LAY-01（详见覆盖缺口清单 §二十七）。
- **自动化**：`tests/entity-management/test_15_entity_layout_max_length.spec.js`
