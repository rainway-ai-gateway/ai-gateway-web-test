# Entity类型管理 - 测试场景概览

## 模块概述

Entity类型管理模块负责定义AI网关系统中的Entity类型（如部门、团队、个人等），支持层级级别设置（1-5级，数字越小级别越高），是 Entity 组织管理与 API-Key 管理的**前置基础**。

| 功能区域 | 说明 |
| --------- | ------ |
| Entity类型列表 | 展示系统已定义的类型，支持按名称搜索、分页 |
| Entity类型创建 | 填写类型名、描述、级别，支持 1-5 级（描述 0-255 字节，非必填） |
| Entity类型编辑 | 修改类型描述与级别；**类型名不可修改**（描述 0-255 字节，与创建同口径） |
| Entity类型删除 | 删除无关联的类型；有关联 Entity 的类型拦截并提示 |
| 字段校验 | 类型名必填、重复、格式（仅小写字母/数字/下划线/连字符）、长度边界（1-32）；描述 0-255 **字节**（按 UTF-8 字节计）且不能包含控制字符 |

## 核心变更依据

- [2026-10-12 只读管理员（系统管理员·只读）](../../../ai-gateway-web/design-docs/modifications/2026-10-12-readonly-admin/ui-code-changes.md)：后端引入「系统管理员（只读）」角色（`role` 枚举取代 `is_admin`，新增 `system_admin_readonly`）；只读视角**全站隐藏所有写操作按钮**，仅保留只读入口（查看 / 详情 / 查询）。前端由全局 Vue 自定义指令 `v-has` 实现（只读登录态给元素加 `.v-has-hidden { display:none !important; }`）。Entity 类型管理页只读保留列表只读查看，隐藏「创建类型」「编辑」「删除」等写操作。
- [2026-10-22 描述长度按 UTF-8 字节判定](../../../ai-gateway-web/design-docs/modifications/2026-10-22-desc-bytes-and-cache-cond-unique/ui-code-changes.md)：Entity 类型描述上限由 **1024 字符**收口为 **0-255 UTF-8 字节**（`EntityTypeUpsert.vue` 的 `maxlength` 与校验上限 1024 → 255，校验改自定义 validator 按 `utf8ByteLength` 计字节），新增**控制字符**校验与提示行「最多255字节（按 UTF-8 字节计），不能包含控制字符」；错误文案改为 Entity 类型专属的「类型描述不能超过255字节（按 UTF-8 字节计）」/「类型描述不能包含控制字符」（旧文案取自 API-Key 口径的「512 字符」，已不再复用）。接口契约 `entity-types.md` §1/§2.1/§2.2 同步为「0-255 字节；不能包含控制字符」，`PATCH /entity-types/{type_name}`（编辑）本次补齐同口径说明。后端实测：255 字节 ASCII 通过；200 汉字（600 字节）返回 `422 Param Illegal: description length must be <= 255`。

> 说明：本模块历史变更记录见表末「变更说明」。

## 配置顺序

Entity类型管理处于配置链路的**最前端**，必须先于 Entity 组织与 API-Key 完成配置：

```text
Entity类型管理 → Entity组织管理 → API-Key管理
```

> 跨模块串联（全 UI）场景见 [Entity管理模块场景四](../entity-management/01-测试场景概览.md#场景四跨模块场景串联journey)。

## 场景测试设计

本模块采用**场景测试**方法，从真实用户的使用流程出发，模拟管理员定义类型、建立组织架构基础的完整操作。

### 场景一：管理员配置Entity类型

**场景描述**：系统管理员首次配置系统，定义Entity类型（如部门、团队、个人），建立组织架构的基础。

**涉及测试场景**：

| 步骤 | 操作 | 对应场景编号 | 优先级 |
| ------ | ------ | ------------ | -------- |
| 1 | 进入Entity类型管理页面，查看现有类型列表 | EM-T-01、EM-T-01b | P1 |
| 2 | 点击"创建类型"，填写类型名、描述和级别，点击确定（含描述 0-255 UTF-8 字节与控制字符校验） | EM-T-02 | P0 |
| 3 | 验证类型名必填、重复、格式、长度边界校验 | EM-T-03~EM-T-06 | P1/P2 |
| 4 | 创建过程中取消操作 | EM-T-07 | P1 |
| 5 | 创建多个不同级别的类型 | EM-T-02（多次） | P0 |
| 6 | 在搜索框输入类型名进行搜索、分页 | EM-T-08~EM-T-09 | P1/P2 |
| 7 | 点击"编辑"，验证类型名不可修改，修改描述和级别（含描述 255 字节/控制字符校验，PATCH 同口径） | EM-T-10、EM-T-10b、EM-T-11 | P1 |
| 8 | 点击"删除"，确认/取消删除类型 | EM-T-12~EM-T-13 | P0/P1 |
| 9 | 验证删除有关联Entity的类型时的处理 | EM-T-14 | P1 |
| 10 | 修改Entity类型级别 | EM-T-15 | P1 |

**测试目标**：验证管理员能否顺利创建、编辑、删除Entity类型，系统各项校验机制是否正常工作。

### 场景二：只读管理员视角（写操作隐藏）（2026-10-12）

**场景描述**：以「系统管理员（只读）」角色登录后进入 Entity 类型管理页，验证「创建类型」「编辑」「删除」等写操作按钮全部隐藏，仅保留类型列表的只读查看（列表、搜索、分页），使只读视角下页面为纯只读展示。

**涉及测试场景**：

| 步骤 | 操作 | 对应编号 | 优先级 | 生命周期 |
| ------ | ------ | ------------ | -------- | -------- |
| 1 | 只读视角进入页面，「创建类型」按钮隐藏 | EM-T-RO-01 | P0 | 已通过 |
| 2 | 只读视角列表操作列「编辑」「删除」按钮隐藏 | EM-T-RO-02 | P0 | 已通过 |

**测试目标**：验证只读管理员（`role === 'system_admin_readonly'`）在 Entity 类型管理页**写操作全部隐藏**、只读查看能力保留，与 `v-has` 指令及 2026-10-12 变更记录一致。
