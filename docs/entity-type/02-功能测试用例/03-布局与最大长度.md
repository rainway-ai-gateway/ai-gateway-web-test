# Entity 类型管理 - 布局与最大长度

> **背景（2026-11-02）**：项目无视觉回归测试（见 [覆盖缺口清单 §27](../../覆盖缺口清单.md)）。本文件用 **DOM 指标断言**（`utils/layout.js`）覆盖类型创建抽屉满载（类型名 32 + 描述 255）场景。
>
> **断言工具**：`utils/layout.js`（`expectWordLimitInline` / `expectNoHorizontalOverflow` / `expectNoRectOverlap` / `expectFooterVisibleInViewport`）。

## EM-TL-01 描述字数计数器（P1）

- **测试数据**：类型名 32 字符、描述 255 字符（创建抽屉，不提交）。
- **步骤**：
  1. 打开「创建类型」抽屉，填满类型名 32 + 描述 255；
  2. 描述输入框渲染字数计数器 `.ivu-input-word-count`，文本为 `255/255`；
  3. 计数器与输入框同一行（计数器垂直范围落在输入框垂直范围内，不压到下方提示行）。
- **预期**：通过（2026-11-02 修复后真实通过，计数器文本与位置均符合）。
- **修复记录（2026-11-02）**：本项目 iView 3.5.4 的 Input 组件源码**无** `showWordLimit`/`ivu-input-word-count`（`node_modules/iview/dist/iview.js` 全文检索 0 命中），原 `EntityTypeUpsert.vue:31/41` 与 `EntityUpsert.vue:30` 的 `show-word-limit` 为**无效属性**，计数器从未渲染，本文档所属 02 系列既有描述「带字数计数」曾失实。修复：自实现计数器——`.word-limit-field` 包裹 Input + 绝对定位 `.ivu-input-word-count` 显示 `n/上限`（类型名 `n/32`、描述 `n/255`、Entity 名称 `n/64`），并移除无效属性；既有「带字数计数」描述自修复起属实。
- **自动化**：`tests/entity-type/test_06_entity_type_layout_max_length.spec.js`

## EM-TL-02 创建抽屉布局健康（P1）

- **测试数据**：同 EM-TL-01；视口参数化 1280×720 / 1440×900。
- **步骤**：
  1. 填满类型名 32 + 描述 255；
  2. 抽屉内容区无横向溢出；
  3. 描述提示行（「最多255字节（按 UTF-8 字节计），不能包含控制字符」）与「级别」字段矩形不重叠；
  4. 底部按钮区完整落在视口内；
  5. 取消抽屉并确认关闭。
- **预期**：两视口均真实通过（2026-11-02 定向通过，不受 EM-TL-01 缺陷影响）。
- **自动化**：`tests/entity-type/test_06_entity_type_layout_max_length.spec.js`
