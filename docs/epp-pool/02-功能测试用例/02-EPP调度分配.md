## 2. EPP 调度分配

> **归属场景**: 场景二
> **导航路径**: 资源管理 → EPP 调度 → Tab2「EPP 调度分配」
> **数据来源**: 分配视图是 `epp_assignments`（cluster→{group, primary}）与 `epp_instances`（/epp-pool）的读时 join
> **触发场景**: `balance_mode=EPP` 的集群出现在本视图中

### 2.1 Tab2 调度分配视图表格展示

**用例编号**: EP-ASGN-01 | **优先级**: P0

#### 前置条件

- EPP 实例池已配置，含 ≥2 个实例组
- 存在 ≥2 个 `balance_mode=EPP` 的业务集群，且已有分配记录
- 其中某实例在 2 个不同集群间分别担任主和备（如集群A primary=`epp-a`, 集群B standby=`epp-a`）

#### 测试步骤

1. 进入 EPP 调度页面，点击 Tab2「EPP 调度分配」
2. 观察分配视图表格的列结构与数据展示
3. 在搜索框中输入某集群名称，观察 URL 是否携带 `?cluster=xxx` 参数
4. 清空搜索框，观察 URL 参数恢复

#### 预期结果

- 表格包含列：集群名称、实例组、主实例、备实例、状态、操作
- 集群名称：展示集群名
- 实例组：展示分配的实例组名；未分配显示 `-`
- 主实例：展示主实例 ID；未分配或降级显示 `-`
- 备实例：展示备实例 ID（同组除 primary 外的另一实例）；单实例组显示「无」；同一实例可在不同集群间分别担任主和备（合法）
- 状态：`正常`（绿色）或 `降级`（红色）
  - **降级触发条件**：①primary 引用的实例已被移出实例池；②primary 所属的实例组已不存在。如仅 standby 异常而 primary 正常，不降级
- 操作：每行有「编辑」按钮
- 数据与 `GET /epp-assignments` 接口返回一致
- 搜索集群名称后，接口应携带 `?cluster=xxx` 查询参数；清空搜索后参数移除

### 2.2 集群名称搜索

**用例编号**: EP-ASGN-02 | **优先级**: P1

#### 前置条件

- 分配视图存在 ≥3 个集群，名称可区分

#### 测试步骤

1. 进入 Tab2 分配视图
2. 在搜索框输入完整的集群名称
3. 清空搜索框
4. 输入部分名称（模糊匹配）
5. 输入不存在的名称

#### 预期结果

- 输入完整名称时，表格仅展示该集群的行
- 清空搜索框后，恢复展示全量集群
- 输入部分名称时，表格展示名称包含输入内容的集群（模糊匹配）
- 输入不存在的名称时，表格展示为空，提示「暂无数据」

### 2.4 统计汇总：已分配/未分配/空闲实例组数

**用例编号**: EP-ASGN-04 | **优先级**: P1

#### 前置条件

- 分配视图存在已分配集群、未分配集群、空闲实例组的混合数据

#### 测试步骤

1. 进入 Tab2 分配视图
2. 观察页面顶部统计区域

#### 预期结果

- 展示「已分配集群」数量（有有效分配的集群数）
- 展示「未分配集群」数量（`balance_mode=EPP` 但无有效记录或降级的集群数）
- 展示「空闲实例组」数量（实例池中未承担任何分配的组数）
- 未分配集群数量 > 0 时，数字为红色告警样式
- 统计数值与 `GET /epp-assignments` 返回的 `clusters`、`unassigned_clusters`、`idle_groups` 长度一致

### 2.6 手动覆写抽屉：选组+选实例+PATCH

**用例编号**: EP-ASGN-06 | **优先级**: P0

#### 前置条件

- 实例池含 ≥2 个实例组，每组 ≥2 个实例
- 存在已分配的 EPP 集群

#### 测试步骤

##### Part A：正常覆写

1. 进入 Tab2 分配视图
2. 点击某集群行的「编辑」按钮
3. 观察抽屉表单字段：实例组（下拉）、主实例 ID（下拉）
4. 选择一个实例组，主实例 ID 自动更新为该组内的实例列表
5. 选择主实例 ID
6. 点击「确认」提交

##### Part B：关联更新

1. 修改后再次打开该集群的抽屉，验证回显

##### Part C：校验场景

1. 实例组下拉选择空值
2. 主实例 ID 与组内实例不匹配（如先选组 A 再通过接口篡改）
3. 选择某实例组后，手动选择同组中与 `standby` 地址相同的实例作为 `primary`

##### Part D：跨模式持久化

1. 记录某个 EPP 集群当前的分配（如 group=g1, primary=epp-a）
2. 在集群基础信息中将 `balance_mode` 从 `EPP` 切回 `WRR`
3. 将 `balance_mode` 再切回 `EPP`
4. 进入分配视图，观察该集群的分配记录

#### 预期结果

##### Part A：正常覆写

- 抽屉弹出，表单展示「实例组」下拉（选项来自当前实例池中的组）和「主实例 ID」下拉（依所选组动态更新）
- 选择实例组后，主实例 ID 下拉选项更新为该组内实例
- 提交成功，Toast 提示「修改成功」，抽屉关闭
- 表格更新为新的分配数据
- 备实例自动为同组内另一实例（单实例组为 `null`）
- `PUT /epp-assignments/{cluster}` 响应应包含 `server_data_conf` 版本号递增

##### Part B：关联更新

- 再次打开该集群的编辑抽屉，表单预填上一次提交的组和实例 ID

##### Part C：校验场景

- 不选择实例组时提交被拦截，提示必填
- `primary` 与 `standby` 必须是不同地址的实例；选择同地址实例作为 primary 时提交被拦截（实际上 standby 是读时展开，此校验需确保组内存在 ≥2 个不同地址的实例）
- 请求体 `{ group_name, primary_instance_id }` 与 API 一致
- `PUT /epp-assignments/{cluster}` 返回成功，视图同步更新

##### Part D：跨模式持久化

- 集群从 EPP 切回 WRR 后，分配记录在服务端**休眠保留**（不删除，仅不再展示）
- 集群从 WRR 切回 EPP 后，原有分配记录**自动恢复生效**，分配视图可见
