## 3. 只读管理员视角（写操作隐藏）

> 变更依据：`design-docs/modifications/2026-10-12-readonly-admin/ui-code-changes.md`（已 Review 通过）。
> 后端以 `role` 枚举取代 `is_admin`（`system_admin` / `system_admin_readonly`）；只读视角（`role === 'system_admin_readonly'`）**全站隐藏所有写操作按钮**，仅保留只读入口（查看 / 详情 / 查询）。前端实现为全局指令 `v-has`：只读登录态下给挂载元素加 `.v-has-hidden { display:none !important; }`。
> 本模块依据变更记录 §3.4 / §4：`pages/epp.html` 只读视角**仅查看**，隐藏「编辑池 / 覆写编辑 / 确认」；`EppPool.Assignments` render 操作列写按钮加 `directives: [{ name: 'has' }]`。

### EP-RO-01：EPP实例池只读视角编辑入口隐藏

**功能模块**: EPP 实例池
**优先级**: P0
**用例编号**: EP-RO-01
**OpenAPI**: `GET /epp-pool`

#### 前置条件

1. 以**只读系统管理员**登录（`role=system_admin_readonly`），「资源管理 → EPP 调度」菜单可达。
2. Tab1「EPP 实例池」默认激活，实例池含 ≥1 个实例组 / 实例。

#### 测试步骤

1. 进入「资源管理 → EPP 调度」页，观察 Tab1「EPP 实例池」工具栏。
2. 逐项核对「编辑池」等编辑入口的可见性。
3. 检查树形表格是否出现行内编辑控件 / 添加 / 删除 / 保存按钮。

#### 预期结果

1. **隐藏**「编辑池」按钮（对应 EP-POOL-04 中管理员进入编辑模式的入口）。
2. 树形表格仅以**只读**方式展示组 / 实例（实例组名、实例 ID、主机、端口），不出现行内编辑控件。
3. **隐藏**「添加组」「添加实例」「删除」「保存」等写操作按钮（对应 EP-POOL-05、EP-POOL-06）。
4. 切换为系统管理员（`role=system_admin`）登录时，「编辑池」「添加组」「保存」正常显示（对照组）。

#### 测试数据

- 只读账号：`viewer` / `viewer123`（`role=system_admin_readonly`，见 `utils/readonly.js` 的 `READONLY_USER`）
- 管理员账号：`conf.json` 配置的 `system_admin`（对照组）
- 实例池：2~3 个实例组，每组恰好 1 个实例
- 数据策略：**复用联调环境现有实例池、不造数**——自动化取 `GET /epp-pool` 的首个实例组（当前环境为 `g-a/g-b/g-c` 各 2 实例）作为只读展示对照基线，全程只读不写，无需清理

#### 补充说明

- 依据变更记录 §3.4：`pages/epp.html` 只读视角仅查看，隐藏「编辑池 / 覆写编辑 / 确认」。隐藏实现为全局指令 `v-has`（`.v-has-hidden { display:none !important; }`）。
- 隐藏机制（按产品源码，自动化据此选择断言方式）：`components/Pool.vue:58` 查看态工具栏 `v-else v-has`（内含「编辑」）→ 只读视角**元素仍在 DOM 并带 `.v-has-hidden`**，用 `expectVHasHidden` 断言工具栏容器；「保存 / 取消」在 `:38` 的编辑态工具栏（同挂 `v-has`，只读视角进不了编辑态故也不可见）；`:82`（添加组）、`:188`（操作列删除组）、`:640`（行内实例输入）、`:776`（添加实例）均写在 `editing` 分支内 → 只读视角**根本不渲染**，用 `expectHidden`。
- 预期 2 的自动化口径：按「实例列表」列的 `实例ID(主机:端口)` 文本（`components/Pool.vue:176-184`）断言实例 ID / 主机 / 端口只读可见，并断言表格内 `input` 计数为 0（不出现行内编辑控件）。

### EP-RO-02：EPP调度分配只读视角覆写编辑入口隐藏

**功能模块**: EPP 调度分配
**优先级**: P0
**用例编号**: EP-RO-02
**OpenAPI**: `GET /epp-assignments`

#### 前置条件

1. 以**只读系统管理员**登录，切换至 Tab2「EPP 调度分配」。
2. 存在 ≥1 个 `balance_mode=EPP` 且已分配的集群。

#### 测试步骤

1. 进入 Tab2「EPP 调度分配」视图表格。
2. 观察每行行尾「操作」列。
3. 逐项核对「覆写编辑」写入口的可见性。

#### 预期结果

1. 操作列**隐藏**「覆写编辑」写操作入口（对应 EP-ASGN-06 中管理员打开覆写抽屉的入口）。
2. 表格集群名称 / 实例组等列**正常只读展示**；统计汇总、未分配 / 空闲区域只读展示保留。
3. 管理员视角下操作列的「覆写编辑」正常显示（对照组）。

#### 测试数据

- 只读账号：`viewer` / `viewer123`（`role=system_admin_readonly`）
- 管理员账号：`conf.json` 配置的 `system_admin`（对照组）
- 已分配 EPP 集群 ≥1 个
- 数据策略：**复用环境现有数据、不造数**——自动化取 `GET /epp-assignments.clusters` 首条集群（当前环境为 `test → g-a`）做行级对照，统计汇总与空闲 / 未分配区域按同一快照口径断言（为空则断言该区域不渲染），全程无写入、无需清理

#### 补充说明

- 依据变更记录 §4：`EppPool.Assignments` render 操作列写按钮加 `directives: [{ name: 'has' }]`；只读视角操作列仅剩只读展示。
- 隐藏机制（按产品源码，自动化据此选择断言方式）：操作列写入口由 render 函数声明 `directives: [{ name: 'has' }]`（`components/Assignments.vue:249`）→ 只读视角**元素仍在 DOM 并带 `.v-has-hidden`**（iView `Button` 的根 `<button>` 即该 class 落点），自动化逐行用 `expectVHasHidden`；列定义不变，故「操作」列头仍保留。
- 文案偏差：「覆写编辑」的 UI 实际按钮文案为「编辑」（`eppAssignment.override`，`ai-gateway-web src/i18n/zh.js`），两者为同一写入口，自动化按 UI 实际文案定位。

### EP-RO-03：EPP调度分配只读视角覆写抽屉确认按钮隐藏

**功能模块**: EPP 调度分配
**优先级**: P0
**用例编号**: EP-RO-03
**OpenAPI**: `PATCH /epp-assignments`

#### 前置条件

1. 以**只读系统管理员**登录，已进入 Tab2「EPP 调度分配」。

#### 测试步骤

1. 检查操作列是否提供可以打开「覆写编辑」抽屉的入口。
2. 尝试通过任何入口打开覆写抽屉。
3. 检查页面是否出现「确认」提交类按钮。

#### 预期结果

1. 只读视角下**无法打开**覆写编辑抽屉（覆写入口已隐藏）。
2. 抽屉内「确认」提交类写按钮**不出现**（对应 EP-ASGN-06 管理员的覆写提交入口）。
3. 只读视角**不发起** `PATCH /epp-assignments` 请求。
4. 切换为系统管理员（`role=system_admin`）登录时，「覆写编辑 → 确认」链路正常可用（对照组）。

#### 测试数据

- 只读账号：`viewer` / `viewer123`（`role=system_admin_readonly`）
- 管理员账号：`conf.json` 配置的 `system_admin`（对照组）
- 目标集群：`GET /epp-assignments.clusters` 首条（复用环境数据，与 EP-RO-02 同一快照口径）
- 数据策略：只读视角全程不写；自动化在只读阶段记录 `epp-assignments` 的**非 GET** 请求并断言为空（预期 3），管理员对照只做「打开抽屉 → 点取消」，不提交，故无造数 / 无清理

#### 补充说明

- 依据变更记录 §3.4：`pages/epp.html` 只读视角隐藏「编辑池 / 覆写编辑 / 确认」；提交类按钮挂全局指令 `v-has`，后端对 `PATCH /epp-assignments` 做 403 兜底。
- **与产品源码的两处偏差（自动化按源码实现，2026-10-16 复核）**：
  1. 覆写抽屉「确认」按钮**未挂** `v-has`（`components/Assignments.vue:129-136`）。只读视角看不到它，是因为操作列入口被 `v-has` 隐藏（`:249`）且抽屉体 `v-if="drawerVisible"`（`:85`）不渲染，因此预期 2 的断言用「不可见」而非「带 `.v-has-hidden`」；
  2. 覆写接口后端为 `PUT /epp-assignments/{cluster}`（`ai-gateway-api/endpoints/openapi_v1/epp_assignments/put.go:37`，`Method: http.MethodPut`；`iauth.FA(FeatureBFEPool, ActionUpdate)` 对只读作用域拒绝），**无 PATCH 路由**，故预期 3 实现为「只读视角不发起任何非 GET 的 `epp-assignments` 请求」。
- 预期 1「无法打开抽屉」的自动化口径：先断言入口不可见，再对入口发一次 3s 超时的真实点击尝试（`display:none` 下可操作性检查必然失败），断言点击未落下且 `.ivu-drawer-wrap:not(.ivu-drawer-hidden)` 计数为 0。
