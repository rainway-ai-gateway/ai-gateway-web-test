## 4. 实例约束校验补全（2026-11-01 补审计）

> 审计背景（2026-11-01，epp-pool 深度审计）：`Pool.vue` 的 `validatePool()` 共 9 类校验
> （组名必填 / 组名重复 / 组内实例至少 1 个 / **组内恰好 1 个** / 实例 ID 必填 / 实例 ID 重复 /
> 主机格式 / 端口 1–65535 / host:port 组合唯一），但 `EP-POOL-05` 只覆盖「空组名 / 重复组名 /
> 非法主机」3 类。本用例补齐其中 3 类可稳定驱动的校验。
>
> 不可达说明：「组内 >1 实例」在 UI 层**不可达**——组内已有 1 个实例时「+添加实例」按钮
> 直接 `disabled`，`groupInstanceExactlyOne` 只是兜底；端口越界由 InputNumber `:min/:max` 钳制，
> 同样无法通过界面触发。

### EP-POOL-07：实例约束校验（组内实例为空 / 实例 ID 重复 / host:port 组合重复）

**功能模块**: EPP 实例池  
**优先级**: P1  
**用例编号**: EP-POOL-07  
**自动化**: `tests/epp-pool/test_05_epp_pool_instance_validation.spec.js`  
**设计依据**: `Pool.vue` `validatePool()`（`groupNeedInstance` / `instanceIdDup` / `instanceHostPortDup`）

#### 前置条件

- 通过接口把实例池重置为 3 组 × 1 实例（`epv-a/epv-b/epv-c`，各 1 台，端口 9002）
- 进入编辑模式并展开目标组（接口改数据后必须**硬刷新页面**再进编辑，否则 UI 仍是旧数据）

#### 测试步骤

1. 展开 `epv-c`，删除其唯一实例 → 保存
2. 展开 `epv-b`，把实例 ID 改为 `epv-a1` → 保存
3. 展开 `epv-b`，把主机改为 `10.0.221.1`（与 `epv-a` 相同、端口同为 9002）→ 保存

#### 预期结果

1. 步骤 1：提示「至少需包含 1 个实例」，停留编辑模式
2. 步骤 2：提示「实例 ID「epv-a1」重复」，停留编辑模式
3. 步骤 3：提示「「10.0.221.1:9002」组合重复」，停留编辑模式
4. 用例结束还原实例池原始状态

> 提示断言使用「与点击并发等待」的写法（`getByText(msg).waitFor()` 与 `click()` 同时发起），
> 避免 iView Message 约 3s 自动消失导致偶发假失败。
