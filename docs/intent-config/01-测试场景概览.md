# 意图配置 - 测试场景概览

## 模块概述

意图配置模块负责 AI 网关**意图分类**能力的配置，对应 BFE `mod_ai_intent` 模块：维护意图分类的**问题集**与**置信度门控阈值**。该资源为**单例**（唯一一行），采用**单行覆盖式全量读写**——不提供历史版本查询、无单字段更新接口，每次 `PUT` 覆盖唯一一行并生成新的内部版本。

|功能区域|说明|
|---|---|
|全局配置|全局最小置信度门控阈值「最小置信度」（0-1，默认 0.6，全局门限，可被单问题覆盖）|
|问题列表|以**表格**展示问题的「问题名称 / 类型 / 判定说明 / 操作」；问题数量 0-10，`[]` = 停用意图分类（软开关）|
|问题新增与编辑|「添加问题」抽屉；「枚举（choice）」（枚举多选一）/「评分（score）」（刻度打分）双类型；选项/档位 1-10；「选项」 ↔ 「档位」互斥|
|问题查看|只读抽屉，全字段纯文案展示，footer 隐藏，不出现必填 `*` 号|
|保存并发布|整体 `PUT /intent-config`，成功后重新 `GET` 回填并回到视图模式|

问题在路由规则 `cond` 中通过 `req_ai_intent_in("<name>", ...)` 引用（路由规则不在本资源内，见 `route-tables.md`）。

**核心变更依据**：

- 2026-10-12（变更记录 `modifications/2026-10-12-readonly-admin/ui-code-changes.md`）：引入「系统管理员（只读）」角色（后端以 `role` 枚举取代 `is_admin`，新增 `system_admin_readonly`）。只读视角（`role === 'system_admin_readonly'`）**全站隐藏所有写操作按钮**（实现为全局指令 `v-has`），仅保留只读入口（查看 / 详情 / 查询）。本模块 `pages/intent-config.html` 只读视角保留「查看」，隐藏「添加问题 / 进入(退出)编辑 / 保存并发布」。新增只读视角用例 IC-RO-01~03。

## 配置顺序

意图配置为**单例整体覆盖**写模式，无依赖其它模块即可独立配置；一次「保存并发布」即完成全量生效。

```text
进入意图配置（单例）
        │
        ├─ 未发布过（GET 404）→ 渲染默认配置 → 自动进入编辑模式（顶部「尚未发布」提示）
        │
        └─ 已发布（GET 200）→ 视图模式
                                 │
                                 ├─ 进入编辑模式 → 修改全局阈值 / 新增·编辑·删除问题
                                 │        │
                                 │        └─ 保存并发布（整体 PUT）→ 回视图模式并回填
                                 │
                                 └─ 退出编辑模式（有改动 → 二次确认并回滚）
```

- **未发布过**：`GET /intent-config` 返回 404，UI 直接渲染默认配置（全局最小置信度为 0.6、问题列表为空）并**自动进入编辑模式**，顶部展示「尚未发布」提示，不展示空态。
- **已发布但空数组**：`GET /intent-config` 正常返回、`questions: []` 展示为空列表（停用软开关，非「未配置」）。
- **问题配置**：问题新增/编辑统一走单抽屉；「枚举（choice）」用「选项」、「评分（score）」用「档位」，二者互斥。
- **路由引用**：问题名通过路由规则表达式引用，路由规则模块本次无变更，不在本模块用例内。

|未发布系统|无配置（`GET` 返回 404）|404 自动进入编辑模式|
|空问题数组|`questions: []`|停用软开关（IC-L-15 / IC-P-03）|

|数据项|说明|示例值|
|---|---|---|
|全局阈值|`min_confidence`，0-1，默认 0.6|0.6 / 0.7|
|问题名称|`questions[].name`，全局唯一|task_type、complexity|
|问题类型|`questions[].type`|choice、score|
|判定说明|`questions[].instructions`，非空|「这条请求属于哪类研发任务？」|
|选项|`criteria`（choice），`map<string,string>` 选项名→描述|coding → 「编写或修改代码」|
|档位|`levels`（score），`[{name, description}]`，低→高|simple、medium、complex|
|单问题阈值|`questions[].min_confidence`，0-1，可选|0.7、留空（null）|

## 测试用例与 API 接口差异说明

复查 `intent-config.md` 后，以下能力与当前 UI 实现存在差异，已在用例中按实际 UI 行为描述，并标注 API 侧能力：

|能力|API 定义|当前 UI 行为|用例处理|说明|
|---|---|---|---|---|
|未发布查询|`GET /intent-config` 未发布过返回 404|捕获 404 → `published=false`，渲染默认配置并**自动进入编辑模式**（顶部「尚未发布」提示），不展示空态|IC-L-14 按 UI 行为验证|已发布但 `questions: []` 正常返回（IC-L-15）|
|问题名称长度|接口仅要求**非空**|`QuestionForm.vue` `validateName` 额外校验 `length > 64` 报错（非 `maxlength`）|IC-V-05、IC-Q-04 按 UI 严于接口描述|UI 校验严于接口|
|criteria 结构|`map<string,string>`（选项名→描述）|UI 内部以 `[{name, description}]` 列表维护，提交时 `buildQuestionPayload` 转为 map|IC-P-02 校验提交体为 map|查看态按「选项名：选项描述」逐行展示|
|levels 顺序|要求**从低到高**|UI 以列表行顺序承载，不做自动排序|IC-V-13 按顺序语义验证|顺序由用户维护|
|全量覆盖写|`PUT` 单行覆盖；无历史版本、无单字段更新|「保存并发布」整体 `PUT`，成功后重新 `GET` 回填|IC-P-01、IC-P-02 按整体 PUT 验证|无单条/局部接口|
|只读字段|创建时间 / 更新时间只读；版本不暴露|提交体不含只读字段|IC-V-16 校验提交体剔除|版本为下发链路内部字段|
|问题列表分页|pageTable 组件默认分页|问题 ≤10，CSS 隐藏分页器（`.page-table .page { display:none }`）|IC-L-04 验证分页不可见|数量上限内无需分页|
