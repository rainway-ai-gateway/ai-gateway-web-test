### IC-D-08：查看抽屉与列表展示数据同接口响应一致性-全字段核对

**功能模块**: 问题查看  
**优先级**: P1  
**用例编号**: IC-D-08  
**设计依据**: `intent-config.md` §2.2（GET 响应数据模型：`Data.min_confidence` / `Data.questions[]` / 只读字段）；`index.vue` `fetchConfig()` / `buildQuestionColumns()` / 视图模式全局阈值展示；`QuestionView.vue` `typeLabel` / `options` / `minConfidenceText`

#### 前置条件

- 已发布意图配置，`GET /intent-config` 返回 200，问题列表至少含 1 个类型为「枚举（choice）」的问题（选项 ≥ 2 项）与 1 个类型为「评分（score）」的问题（档位 ≥ 2 档），且其中一个问题设置了单问题阈值、另一个未设置
- 已保存本次 GET 的完整响应 JSON，供逐字段核对

#### 测试步骤

1. 保持页面处于视图模式，记录顶部全局「最小置信度」展示值与问题列表各列取值
2. 依次打开每个问题的「查看」抽屉，记录抽屉内各行展示值
3. 将上述界面取值与保存的接口响应 JSON 逐字段核对
4. 刷新页面（重新 `GET /intent-config`），再次核对上述字段

#### 预期结果

1. 全局「最小置信度」展示值等于响应中的全局最小置信度（数值精度一致，如 `0.6` 不显示为 `0.60`；响应缺省时展示默认 `0.6`）
2. 列表行数与响应中的问题列表条数一致，且行顺序与数组顺序一致
3. 列表「问题名称」「判定说明」列取值与响应中对应字段一致（均为纯文本；空值展示占位 `-`）
4. 列表「类型」Tag 文案与接口类型映射一致：`choice` → 「枚举（choice）」（`primary` 色）、`score` → 「评分（score）」（`success` 色）
5. 查看抽屉「问题名称」「类型」「判定说明」分别与该问题的问题名称、类型映射文案、判定说明一致
6. 类型为「枚举（choice）」的问题：抽屉「选项」行按选项键值对逐行展示，行顺序与配置顺序一致，每行为 `选项名：选项描述`（描述为空时仅显示选项名）；类型为「评分（score）」的问题：抽屉「档位」行按档位顺序展示，每行为 `档位名：档位描述`（描述为空时仅显示档位名）
7. 抽屉「最小置信度覆盖」：设置了单问题阈值的问题展示该数值字符串；未设置的问题展示「使用全局门限（{全局门限}）」，其中括注值为当前响应中的全局最小置信度
8. 界面**不展示**响应只读字段创建时间 / 更新时间（响应中亦不含版本）
9. 刷新后重复步骤 1~2，各展示值仍与最新 GET 响应逐字段一致

### IC-P-01：保存并发布整体PUT成功回视图模式

**功能模块**: 保存并发布  
**优先级**: P0  
**用例编号**: IC-P-01  
**设计依据**: `index.vue` `saveConfig()`；`intent-config.md` §2.1（单行覆盖式写）

#### 前置条件

- 处于编辑模式，配置通过全部校验

#### 测试步骤

1. 修改全局阈值与问题列表
2. 点击「保存并发布」

#### 预期结果

1. 校验通过后发起 **`PUT /intent-config`**（`openapi`），为**整体全量覆盖**提交
2. 返回 200 后，页面 `mode` 切回**视图模式**
3. 页面重新 `GET /intent-config` 回填；右上角恢复为「进入编辑模式」
4. 无单条 / 单字段更新接口调用

### IC-P-02：提交体结构校验

**功能模块**: 保存并发布  
**优先级**: P0  
**用例编号**: IC-P-02  
**设计依据**: `index.vue` `buildQuestionPayload()`；`intent-config.md` §1 数据模型

#### 前置条件

- 处于编辑模式，问题列表同时含 `choice` 与 `score` 问题

#### 测试步骤

1. 点击「保存并发布」，抓取 `PUT /intent-config` 请求体
2. 逐字段核对结构

#### 预期结果

1. 顶层为 `{ min_confidence: Number, questions: Array }`
2. `choice` 问题：`criteria` 为 `map<string,string>`（选项名 → 描述），**不含** `levels`
3. `score` 问题：`levels` 为 `[{ name, description }]` 数组，**不含** `criteria`
4. 每个问题仅含 `name` / `type` / `instructions`（及对应的 `criteria` 或 `levels`）；填写了单问题阈值时附加 `min_confidence`
5. 提交体**不含**只读字段 `created_at` / `updated_at`、内部字段 `version`，也不含内部 `_uid`
6. 所有文本字段已 `trim`
