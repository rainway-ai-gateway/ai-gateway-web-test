### IC-V-01：全局最小置信度范围校验

**功能模块**: 字段校验  
**优先级**: P0  
**用例编号**: IC-V-01  
**设计依据**: `index.vue` `validateAll()`；`intentConfig.tipMinConfidence`；`intent-config.md` §1

#### 前置条件

- 处于编辑模式

#### 测试步骤

1. 将全局最小置信度设置为 `0`，点击「保存并发布」
2. 设置为 `1`，点击「保存并发布」
3. 设置为超出范围的值（如通过脚本置入 `1.5` 或 `-0.1`），点击「保存并发布」

#### 预期结果

1. `0` 与 `1` 为合法边界，提交成功
2. 超出 `0-1` 被拦截，提示「最小置信度必须为 0-1」
3. 该字段为必填的全局门限，默认值 `0.6`

#### 前置条件

#### 测试步骤

1. 删除全部问题后点击「保存并发布」
2. 逐个添加至 10 个问题，观察是否可继续添加

3. 若经非常规途径存在 11 个问题，发布前校验提示「问题数量不能超过 10」

## 接口合法性条件 ↔ UI 校验实现 一致性比对矩阵

| 字段 / 规则 | 接口合法性条件（`intent-config.md` §1） | UI 校验实现（源码） | 一致性 | 说明 |
| --- | --- | --- | --- | --- |
| `min_confidence` | 非必填，默认 0.6，取值 0-1 | `validateAll` 校验必填且 0-1（`tipMinConfidence`），默认填 0.6 | 基本一致 | UI 将全局阈值作为必填项，默认值兜底为 0.6 |
| `questions` | 必填，0-10，`[]` = 停用软开关 | `maxQuestions=10`；允许 0 且可发布（IC-P-03） | 一致 | 空数组为合法停用语义 |
| `questions[].name` | 必填、非空、全局唯一 | `validateName`（非空）+ `onQuestionSubmit`（全局唯一） | 一致 | — |
| `questions[].name`（长度） | 未规定上限 | `validateName`：`length > 64` 报错 | **UI 严于接口** | 提示「问题名称不能超过 64 字符」 |
| `questions[].type` | 必填，枚举 choice / score | `handleSubmit` / `validateAll` 校验（`tipTypeInvalid`） | 一致 | 下拉仅两个选项 |
| `questions[].instructions` | 必填、非空 | `ruleValidate.instructions`（required）+ `validateAll` | 一致 | — |
| `criteria` | choice 必填，1-10 项，选项名唯一非空、不含 ` | ` | `validateOptions`：数量 / 空名 / 竖线 / 唯一（对应各 tip） | 一致 | — |
| `criteria` / `levels` 互斥 | 二者互斥 | `onTypeChange` 清空另一列表；`buildQuestionPayload` 只输出对应结构 | 一致 | — |
| `levels` | score 必填，1-10 档，`{name,description}`，name 唯一非空，与 criteria 互斥 | `validateOptions`：数量 / 空名 / 唯一 | 一致 | — |
| `levels` 顺序 | 从低到高 | 不自动校验 / 排序，顺序由用户维护（IC-V-13） | **未强校验** | 数据语义要求，展示按输入顺序 |
| `questions[].min_confidence` | 非必填，0-1 | `validateOverride`：留空合法，否则 0-1 | 一致 | 留空即继承全局门限 |
| `created_at` / `updated_at` | 只读 | 提交体不含（IC-V-16） | 一致 | 由服务端生成 |
| `version` | 不暴露 | 提交体不含 | 一致 | 下发链路内部字段 |
| `criteria` 结构 | `map<string,string>` | UI 以 `[{name,description}]` 维护，`buildQuestionPayload` 提交时转 map | 一致 | 提交前完成转换 |
