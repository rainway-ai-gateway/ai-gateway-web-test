## 3. 详情页验证

### MP-D-01：详情页全字段与接口数据一致性

**功能模块**: 详情页  
**优先级**: P0  
**用例编号**: MP-D-01

#### 前置条件

- 系统中存在一条字段完整的模型定价记录，且各字段均有值（含 capabilities、supported_parameters、limits、prices 多个键、metadata 等）

#### 测试数据参考（接口 GET /model-prices/{id} 返回体示例）

```json
{
  "id": 12345,
  "provider": "openai",
  "model": "gpt-4-turbo",
  "base_model": "gpt-4",
  "mode": "chat",
  "capabilities": ["chat", "vision", "reasoning", "tools"],
  "supported_parameters": ["temperature", "top_p", "max_tokens", "stream"],
  "limits": {
    "context_window": 128000,
    "max_input_tokens": 128000,
    "max_output_tokens": 4096
  },
  "prices": {
    "input_cost_per_token": 0.00003,
    "output_cost_per_token": 0.00006,
    "cache_creation_input_token_cost": 0.000015,
    "cache_read_input_token_cost": 0.0000075
  },
  "price_currency": "RMB",
  "metadata": {
    "source": "https://openai.com/pricing",
    "notes": "2024 年最新定价"
  },
  "create_time": 1718000000,
  "update_time": 1719000000
}
```

#### 测试步骤

1. 管理员登录系统，进入「模型定价」列表页
2. 找到上述预置记录，点击「查看详情」（或点击行进入详情页）
3. 页面加载完成后，逐一比对详情页展示的字段值与接口返回值
4. 观察「基本信息」Card 的字段排布，确认「创建时间」「更新时间」位于该 Card 底部

#### 预期结果

布局说明：详情页由「基本信息」「限制对象（limits）」「价格」「元数据」四个 Card 组成；**创建时间（create_time）与更新时间（update_time）展示在「基本信息」Card 底部，不再单独作为独立时间戳 Card**。

字段比对（校验方式 = 文本/数值/数组逐项比对，与接口返回 JSON 一致）：

- **id**（文本一致）：与接口 `id` 相同（int64 原样展示）
- **provider**（文本一致）：与接口 `provider` 相同
- **model**（文本一致）：与接口 `model` 相同
- **base_model**（文本一致）：与接口 `base_model` 相同
- **mode**（文本一致，含中英文映射）：与接口 `mode` 相同（若 UI 显示为中文标签，需与枚举映射表一致，如 chat → 对话）
- **capabilities**（数组逐项比对，顺序不限）：标签/列表中展示的值集合与接口 `capabilities` 数组完全一致，不多不少
- **supported_parameters**（数组逐项比对，顺序不限）：标签/列表中展示的值集合与接口 `supported_parameters` 数组完全一致
- **limits.context_window**（数值一致）：与接口 `limits.context_window` 相同
- **limits.max_input_tokens**（数值一致）：与接口 `limits.max_input_tokens` 相同
- **limits.max_output_tokens**（数值一致）：与接口 `limits.max_output_tokens` 相同
- **prices.input_cost_per_token**（**数值**一致）：与接口值相等；展示允许科学计数法（如 `1.5e-6` 与 `0.0000015` 等价），**不要**按十进制字符串逐字比对
- **prices.output_cost_per_token**（数值一致）：与接口值相等
- **prices 其他键**（键集合一致，数值等价）：所有 prices 的键均在详情页展示；极小值按量级格式化为科学计数法（见 MP-D-02）
- **price_currency**（文本一致）：固定为 `RMB`，与接口返回一致
- **metadata.source**（文本一致）：与接口 `metadata.source` 相同；若为 URL，应为可点击的链接
- **metadata.notes**（文本一致）：与接口 `metadata.notes` 相同
- **create_time**（时间戳转换一致）：与接口 `create_time` Unix 时间戳转换后的日期时间一致（秒级精度）
- **update_time**（时间戳转换一致）：与接口 `update_time` Unix 时间戳转换后的日期时间一致（秒级精度）

**整体预期**：

1. 进入详情页时调用 `GET /model-prices/{id}`，接口返回 200
2. 详情页展示的所有字段值均与接口返回的 JSON 字段值一一对应，无遗漏、无错配
3. 面包屑导航正确（如「模型定价 / 详情」），点击「返回列表」可回到列表页
4. 若存在「编辑」按钮，点击后跳转至编辑表单且回显数据与详情一致

### MP-D-03：查看态批量折扣系数展示

**功能模块**: 详情页  
**优先级**: P1  
**用例编号**: MP-D-03

#### 前置条件

- 存在一条 `mode != batch` 且已配置 `batch_discount` 的定价记录
- 存在一条 `mode=batch` 的定价记录

#### 测试步骤

1. 打开 `mode != batch` 记录的详情页，查看「批量折扣系数」信息行
2. 打开 `mode=batch` 记录的详情页，查看「批量折扣系数」信息行
3. 打开一条未配置 `batch_discount`（值为 null）的非 batch 记录详情页

#### 预期结果

1. 非 batch：展示系数值（如 `0.5`）
2. `mode=batch`：展示「-（mode=batch 的价格行不配置批量折扣系数）」
3. 未配置（null）：合理兜底展示（如 `-`），页面不报错
4. 「批量折扣系数」信息行展示于基本信息 Card（与 mode 相邻），不影响既有字段展示

#### 补充说明

- `mode=batch` 不渲染输入见 MP-V-14；取值范围校验见 MP-V-13；提交 payload 规则见 [01-列表与CRUD](./01-列表与CRUD.md) 的 MP-C-07

### MP-D-04：详情接口数据与页面展示一致性（含 mode=batch / batch_discount）

**功能模块**: 详情页  
**优先级**: P0  
**用例编号**: MP-D-04  
**OpenAPI**: GET /model-prices/{id}

#### 前置条件

- 系统中存在一条 `mode=batch` 的定价记录（批量任务价格行本身不配置 `batch_discount`）
- 系统中存在一条 `mode != batch` 且已配置 `batch_discount` 的定价记录
- 两条记录均字段完整（含 capabilities、supported_parameters、limits、prices / tier_prices、metadata 等）

#### 测试数据参考（接口 GET /model-prices/{id} 返回体示例）

`mode=batch` 记录（批量价格行不配置 `batch_discount`，字段取值为空）：

```json
{
  "id": 8,
  "provider": "deepseek",
  "model": "DeepSeek V3",
  "base_model": "deepseek-v3",
  "mode": "batch",
  "capabilities": ["chat", "reasoning"],
  "supported_parameters": ["temperature", "max_tokens"],
  "limits": {
    "context_window": 128000,
    "max_output_tokens": 8192
  },
  "prices": {
    "input_cost_per_token": 1.35e-7,
    "output_cost_per_token": 5.5e-7,
    "cache_read_input_token_cost": 3.5e-8
  },
  "batch_discount": null,
  "price_currency": "RMB",
  "metadata": {
    "source": "https://platform.deepseek.com/pricing",
    "notes": "批量任务价格行（由系数展开或手工维护）"
  },
  "create_time": 1728400000,
  "update_time": 1728400000
}
```

非 batch 记录（携带 `batch_discount` 与分时段价格）：

```json
{
  "id": 12345,
  "provider": "deepseek",
  "model": "deepseek-v3",
  "base_model": "deepseek-v3",
  "mode": "chat",
  "capabilities": ["chat", "reasoning", "tools"],
  "supported_parameters": ["temperature", "top_p", "max_tokens"],
  "limits": {
    "context_window": 128000,
    "max_input_tokens": 128000,
    "max_output_tokens": 8192
  },
  "prices": {
    "input_cost_per_token": 2e-6,
    "output_cost_per_token": 8e-6,
    "cache_read_input_token_cost": 5e-7
  },
  "tier_prices": {
    "peak": {
      "input_cost_per_token": 4e-6,
      "output_cost_per_token": 1.6e-5,
      "cache_read_input_token_cost": 1e-6
    }

    "source": "https://platform.deepseek.com/pricing",
    "notes": "DeepSeek V3"
  },
  "create_time": 1716883200,
  "update_time": 1716883200

```

#### 测试步骤

1. 管理员登录系统，进入「模型定价」列表页
2. 打开 `mode=batch` 记录的详情页，页面加载完成后逐一比对详情页展示的字段值与接口返回值
3. 打开非 batch 记录的详情页，逐一比对展示字段与接口返回值，重点核对「批量折扣系数」展示值与接口 `batch_discount`
4. 观察「批量折扣系数」信息行的渲染位置与文案

#### 预期结果

字段比对（校验方式 = 文本一致/数值一致/数组逐项比对/时间戳转换一致，与接口返回 JSON 一致）：

- **id**（文本一致）：与接口 `id` 相同（int64 原样展示）
- **provider**（文本一致）：与接口 `provider` 相同
- **model**（文本一致）：与接口 `model` 相同
- **base_model**（文本一致）：与接口 `base_model` 相同
- **mode**（文本一致，含中英文映射）：`mode=batch` 记录展示为 batch 对应文案（如「批量任务」或原值 `batch`），非 batch 记录展示为对应枚举文案，均与 `mode` 枚举映射表一致
- **capabilities**（数组逐项比对，顺序不限）：标签/列表中展示的值集合与接口 `capabilities` 数组完全一致，不多不少
- **supported_parameters**（数组逐项比对，顺序不限）：展示的值集合与接口 `supported_parameters` 数组完全一致
- **limits 各键**（数值一致）：`limits` 下各键展示值与接口对应整数值相同
- **prices 各键**（数值一致）：本行所有 `prices` 键均展示，展示值等于接口值；允许科学计数法（如 `1.35e-7` 与 `0.000000135` 等价），**不要**按十进制字符串逐字比对
- **tier_prices.peak 各键**（数值一致）：非 batch 记录的分时段价格逐档展示，数值与接口 `tier_prices.peak` 对应键相等
- **batch_discount**（数值一致 / 特殊展示，按记录区分）：
  - 非 batch 记录：展示值等于接口 `batch_discount`（如 `0.5`，允许科学计数法等价）
  - `mode=batch` 记录：接口返回 `null`（不配置），UI 展示「-（mode=batch 的价格行不配置批量折扣系数）」
- **price_currency**（文本一致）：固定为 `RMB`，与接口返回一致
- **metadata.source / metadata.notes**（文本一致）：与接口对应值相同；source 若为 URL 应为可点击的链接
- **create_time / update_time**（时间戳转换一致）：与接口 Unix 时间戳（秒级）转换后的日期时间一致

**一致性比对矩阵**：

| UI 展示项 | 接口字段 | 校验方式 | 通过标准 |
| --- | --- | --- | --- |
| mode | `mode` | 文本一致（含枚举映射） | `mode=batch` 展示 batch 对应文案；非 batch 展示对应枚举文案，均与映射表一致 |
| 批量折扣系数（非 batch 记录） | `batch_discount` | 数值一致 | 展示值等于接口值（如 `0.5`），允许科学计数法等价 |
| 批量折扣系数（mode=batch 记录） | `batch_discount` | 特殊展示 | 接口为 null 时展示「-（mode=batch 的价格行不配置批量折扣系数）」，页面不报错 |
| id / provider / model / base_model | 同名字段 | 文本一致 | 逐字与接口值相同 |
| capabilities | `capabilities` | 数组逐项比对 | 展示集合与接口数组完全一致，不多不少 |
| supported_parameters | `supported_parameters` | 数组逐项比对 | 展示集合与接口数组完全一致 |
| limits 各键 | `limits.*` | 数值一致 | 各键展示值与接口整数值相同 |
| prices 各键 | `prices.*` | 数值一致 | 逐键展示，数值与接口相等（允许科学计数法等价） |
| tier_prices.peak 各键 | `tier_prices.peak.*` | 数值一致 | 分时段价格逐档展示，数值与接口相等 |
| price_currency | `price_currency` | 文本一致 | 固定 `RMB` |
| metadata.source / notes | `metadata.*` | 文本一致 | 与接口对应值相同 |
| create_time / update_time | `create_time` / `update_time` | 时间戳转换一致 | Unix 秒级时间戳转换后的日期时间一致 |

**整体预期**：

1. 打开详情页时调用 `GET /model-prices/{id}`，上述两条记录接口均返回 200
2. 详情页展示的所有字段值均与接口返回的 JSON 字段值一一对应，无遗漏、无错配
3. `mode=batch` 记录的「批量折扣系数」信息行展示「-（mode=batch 的价格行不配置批量折扣系数）」，不因该字段为空而报错
4. 非 batch 记录的「批量折扣系数」信息行展示系数值，且与接口 `batch_discount` 一致
5. 「批量折扣系数」信息行位于基本信息 Card（与 mode 相邻），不影响既有字段展示
6. 面包屑导航正确（如「模型定价 / 详情」），点击「返回列表」可回到列表页

#### 补充说明

- 全字段逐项比对的基线用例见本文件 MP-D-01；批量折扣系数查看态展示语义见 MP-D-03
- 非 batch 记录批量折扣系数取值范围校验见 MP-V-13；`mode=batch` 不渲染输入见 MP-V-14
- 提交 payload 中 `batch_discount` 的附带规则见 [01-列表与CRUD](./01-列表与CRUD.md) 的 MP-C-07
