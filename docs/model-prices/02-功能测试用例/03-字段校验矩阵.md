## 4. 字段校验矩阵

> **定位**：汇总模型定价新增 / 编辑表单各字段的**必填、长度、枚举、非负、唯一性、格式**等校验规则；与 [01-列表与CRUD](./01-列表与CRUD.md) 中 CRUD 主流程用例互为补充。

### 校验矩阵总览

| 字段 | 规则 | 错误提示（参考） | 用例编号 | 优先级 |
| --- | --- | --- | --- | --- |
| provider | 必填 | 请输入 Provider | MP-V-01-1 | P0 |
| model | 必填 | 请输入 Model | MP-V-01-2 | P0 |
| base_model | 必填 | 请输入 Base Model | MP-V-01-3 | P0 |
| mode | 必填 | 请选择 Mode | MP-V-01-4 | P0 |
| prices | 至少包含一个价格字段 | 请至少配置一个价格项 | MP-V-01-5 | P0 |
| provider | 长度 1–255 字符 | Provider 长度需在 1-255 字符之间 | MP-V-02-1 | P1 |
| model | 长度 1–255 字符 | Model 长度需在 1-255 字符之间 | MP-V-02-2 | P1 |
| base_model | 长度 1–255 字符 | Base Model 长度需在 1-255 字符之间 | MP-V-02-3 | P1 |
| mode | 必须为枚举值之一（chat/completion/responses/image_generation/image_edit/embedding/rerank/audio_speech/audio_transcription/video_generation/ocr/search/realtime 共 13 种） | 请选择合法的 Mode | MP-V-03 | P0 |
| prices | 至少包含一个价格字段（空对象不合法） | 请至少配置一个价格项 | MP-V-04 | P0 |
| prices.* | 所有价格字段值必须为非负数 | 价格不能为负数 | MP-V-05 | P0 |
| limits.* | 值必须为非负整数 | Limits 值必须为非负整数 | MP-V-06 | P1 |
| (provider, model, mode) | 三元组唯一 | 该 Provider + Model + Mode 组合已存在 | MP-V-07 | P0 |
| capabilities | 多选标签，可选值为枚举（共 21 种） | — | MP-V-08 | P1 |
| supported_parameters | 多选标签，可选值为枚举（共 15 种） | — | MP-V-09 | P1 |
| metadata.source | URL 格式校验（若 UI 支持） | 请输入合法的 URL | MP-V-10 | P2 |

### MP-V-02：字符串长度边界校验

#### MP-V-02-1：provider 长度边界

**功能模块**: 字段校验  
**优先级**: P1  
**用例编号**: MP-V-02-1

#### 前置条件

- 打开新增模型定价表单

#### 测试步骤

1. 其他字段均填写合法值
2. provider（可下拉选择 / 手写的自动补全框）输入 **0 字符**（空字符串）→ 提交
3. provider 输入 **1 字符**（如 `a`）→ 提交
4. provider 输入 **255 字符**（重复 `a` 共 255 次）→ 提交
5. provider 输入 **256 字符**（重复 `a` 共 256 次）→ 提交

#### 预期结果

1. 0 字符：触发必填错误（与 MP-V-01-1 一致）
2. 1 字符：校验通过，可提交
3. 255 字符：校验通过，可提交
4. 256 字符：输入框限制为 255 字符，或提交后显示错误提示「Provider 长度需在 1-255 字符之间」

### MP-V-03：mode 枚举值校验

**功能模块**: 字段校验  
**优先级**: P0  
**用例编号**: MP-V-03

#### 前置条件

- 打开新增模型定价表单

#### 测试步骤

1. 其他字段均填写合法值
2. 点击 mode 下拉框，查看可选选项
3. 依次选择枚举值并尝试提交：chat、completion、responses、image_generation、image_edit、embedding、rerank、audio_speech、audio_transcription、video_generation、ocr、search、realtime（共 13 种，与接口文档一致）
4. （可选）通过接口注入非法 mode 值，验证后端返回错误

#### 预期结果

1. 下拉框选项与接口定义的枚举值一一对应（13 种）
2. 选择任意合法枚举值均可通过校验，提交成功
3. 非法 mode 值（如 `invalid_mode`）提交后后端返回 400 错误，前端显示「请选择合法的 Mode」或等效文案

### MP-V-05：prices 字段值非负校验

**功能模块**: 字段校验  
**优先级**: P0  
**用例编号**: MP-V-05

#### 前置条件

- 打开新增模型定价表单，且已添加至少一个价格项

#### 测试步骤

1. 其他字段均填写合法值
2. 在 prices 区域，将 `input_cost_per_token` 设为 **-0.0001**（负数）
3. 点击「确定」提交
4. 改为 **0** → 提交
5. 改为 **0.00003**（正数）→ 提交

#### 预期结果

1. 负值：前端拦截或后端返回 400，显示错误「价格不能为负数」或等效文案
2. 0：校验通过，可提交（0 为合法非负数）
3. 正数：校验通过，可提交
4. 所有价格字段（output_cost_per_token、cache_creation_input_token_cost 等）均适用相同规则

### MP-V-06：limits 字段值非负整数校验

**功能模块**: 字段校验  
**优先级**: P1  
**用例编号**: MP-V-06

- 打开新增模型定价表单，已进入 limits 配置区域

2. 添加 `context_window`，输入 **-1** → 提交
3. 改为 **0** → 提交
4. 改为 **8192.5**（小数）→ 提交

#### 预期结果

4. 8192：校验通过，可提交
5. limits 下所有键（max_input_tokens、max_output_tokens、max_tokens 等）均适用相同规则

### MP-V-07：(provider, model, mode) 唯一性校验

**功能模块**: 字段校验  
**优先级**: P0  
**用例编号**: MP-V-07

#### 前置条件

- 系统中已存在一条记录：provider=`openai`，model=`gpt-4`，mode=`chat`

#### 测试步骤

1. 进入新增模型定价表单
2. 填写 provider=`openai`，model=`gpt-4`，mode=`chat`（与已有记录完全相同）
3. 其他字段（base_model、prices 等）填写合法值
4. 点击「确定」提交

#### 预期结果

1. 后端返回 400 / 409 错误，提示「该 Provider + Model + Mode 组合已存在」或等效文案
2. 弹窗不关闭，用户可修改字段后重试
3. 修改其中任意一个字段（如 mode 改为 `completion`）后重新提交，创建成功
