## 6. 跨模块联动（软关联）

> 本节验证模型定价在真实配置链路（**服务商 → 模型定价 → 集群大模型配置引用**）中的联动行为。关联模块用例：`providers`（PR-LINK）、`business-cluster`（RM-BC-71~78）。
> 联动关系：定价 `provider` 字段关联服务商名（**软关联**）；服务商列表「查询模型价格」直达本模块；集群转发模型与服务商模型一致时定价用于计费；删除服务商**不级联删除**定价。

### MP-LINK-01：为服务商模型创建定价（provider 关联）

**功能模块**: 跨模块联动  
**优先级**: P0  
**用例编号**: MP-LINK-01

#### 前置条件

- 已创建模型服务商 `deepseek`（已「获取」模型 deepseek-chat / deepseek-v3）

#### 测试步骤

1. 模型定价列表「新增」
2. provider 填写服务商名 `deepseek`（Provider 为可下拉选择 / 手写的自动补全框，候选含已创建服务商；可从下拉选中或手写），model 手写 `deepseek-v3`（服务商探测到的模型），mode=chat，配置默认价格
3. 提交

#### 预期结果

1. `POST /model-prices` 成功，请求体 `provider: "deepseek"` 与服务商名一致
2. 列表新增该记录；服务商侧「查询模型价格」可命中（联动 PR-LINK-01 / PR-L-11）
3. **软关联**：即使 provider 名称不对应任何服务商也可创建（定价独立存在），但推荐流程先建服务商再配置

---

### MP-LINK-02：从服务商列表直达定价详情

**功能模块**: 跨模块联动  
**优先级**: P0  
**用例编号**: MP-LINK-02

#### 前置条件

- 服务商 `deepseek` 已有 provider=deepseek 的定价记录（含 tier_prices）

#### 测试步骤

1. 服务商列表点击「查询模型价格」
2. 在定价列表页验证跳转参数、筛选与自动打开详情

#### 预期结果

1. 跳转携带 `provider=deepseek&autoView=1`，列表按该 provider 筛选（联动 PR-L-11）
2. 自动打开**第一条**该 provider 定价详情，价格区展示默认价格 + 分时段价格（联动 MP-T-08）
3. 无定价记录时提示「未找到提供商 deepseek 的模型定价」，不报错

---

### MP-LINK-03：集群转发模型与定价记录对应

**功能模块**: 跨模块联动  
**优先级**: P1  
**用例编号**: MP-LINK-03

#### 前置条件

- 服务商 `deepseek` 含模型 deepseek-v3；已存在该模型的定价记录；进入集群大模型配置

#### 测试步骤

1. 集群大模型配置选择服务商 `deepseek`，转发模型选择 `deepseek-v3`，提交集群
2. 核对集群详情与定价记录

#### 预期结果

1. 集群转发模型 `deepseek-v3` 与服务商探测模型一致（联动 RM-BC-73）
2. provider=deepseek + model=deepseek-v3 的定价记录存在，用于该转发模型的计费
3. 若定价记录缺失，计费侧按无价格处理（本用例验证数据对应关系即可）

---

### MP-LINK-04：删除服务商后定价记录保留

**功能模块**: 跨模块联动  
**优先级**: P1  
**用例编号**: MP-LINK-04

#### 前置条件

- 服务商 `deepseek` 未被集群引用；存在 provider=deepseek 的定价记录

#### 测试步骤

1. 删除服务商 `deepseek`（成功，见 PR-DEL-04）
2. 在定价列表按 provider=deepseek 查询

#### 预期结果

1. 服务商删除成功，`/model-prices` 同名记录**不阻塞**删除
2. 定价记录**保留**，计费 / 报表数据不丢失（软关联，联动 PR-LINK-08）
3. 定价记录仍可正常编辑 / 删除
