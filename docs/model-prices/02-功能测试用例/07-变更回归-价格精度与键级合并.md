## 8. 变更回归：价格精度与 PUT 键级合并（2026-09-08）

> 变更背景：
>
> 1. **科学计数法**：`prices` / `tier_prices` 输入同时接受 `1.5e-6` 与 `0.0000015`；前端文本框失焦后按量级格式化（绝对值 `< 1e-4` 或 `≥ 1e6` 用科学计数法，其余十进制）；去掉 8 位小数截断。
> 2. **上限**：单价格折算 `价格 × 1e8` 不得超过 `2^53`（约 `9e15`）。
> 3. **PUT 键级合并**（issue #140）：编辑提交时 `prices` / `tier_prices` 传入的键覆盖原值，未传入的键保留；删除某行再提交**不会**从后端清除该键。
>
> 接口依据：`model-prices.md` §1.2、§3.7/§3.8。  
> UI 依据：`ai-gateway-web/design-docs/modifications/2026-09-08-model-price-scientific-and-merge/`。

### MP-V-11：prices 科学计数法与失焦格式化

**功能模块**: 字段校验  
**优先级**: P0  
**用例编号**: MP-V-11  
**设计依据**: 原型 `model-price-upsert.js` 失焦格式化；`src/utils/price.js`

#### 前置条件

- 打开新增模型定价抽屉
- 其他必填字段已填合法值

#### 测试步骤

1. 添加默认价格项 `input_cost_per_token`，输入 `1.5e-6`，失焦
2. 清空后输入 `0.0000015`，失焦
3. 改为 `7.6234102728e-08`，失焦后提交
4. 再创建一条：输入 `0.04`，失焦后提交

#### 预期结果

1. `1.5e-6` 失焦后仍为科学计数法（或与 `1.5e-6` 数值等价的规范写法），可提交
2. `0.0000015` 失焦后格式化为 `1.5e-6`（绝对值 `< 1e-4`）
3. `7.6234102728e-08` 不被截成 `0` 或 8 位小数；提交 `POST /model-prices` 成功，读回数值与输入等价
4. `0.04` 失焦后仍为十进制 `0.04`

**功能模块**: 字段校验  
**优先级**: P0
