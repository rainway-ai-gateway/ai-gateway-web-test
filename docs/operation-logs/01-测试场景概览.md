# 操作日志（Operation Logs）模块 - 测试场景概览

## 模块概述

操作日志模块提供系统管理员对平台写操作审计记录的**只读查询**能力，对应 API 端点：`GET /operation-logs`。日志由系统在内部写操作成功后（或失败后）自动写入，**不对外暴露写入接口**。

对应接口文档：`design-docs/api-define/OpenAPI接口定义/operation-logs.md`；对应原型：`design-docs/prototype-design/pages/operation-logs.html`。

| 功能区域 | 说明 |
| --- | --- |
| 操作日志列表 | 服务端分页；顶部时间范围筛选（起始时间 / 结束时间 + 查询）；表格列搜索（操作人 / 操作动作 / 资源类型 / 资源名称 / 结果） |
| 日志详情 | 右侧 Drawer（720px）；展示操作者类型、操作人、动作、资源信息、变更摘要（可折叠 JSON）、请求信息、操作时间；不展示 `id` / `log_id` / `operator_id` |
| 权限 | 暂仅系统管理员可查询（`system_admin` / `FeatureOperationLog` 读权限） |

**核心变更依据**（2026-09-01 UI 变更）：

- v0.0.9 新增操作日志查询接口与独立列表页。
- 列表采用**服务端分页**（`page` / `page_size`），与服务商等模块的前端分页不同。
- 详情弹框字段按接口返回顺序排列，变更摘要使用 vue-json-viewer 可折叠展示。

---

## 配置顺序 / 依赖关系

操作日志为**只读审计模块**，不阻塞其他模块配置，但依赖其他模块的写操作产生日志数据：

```text
其他模块写操作（Entity / API-Key / Provider / Cluster / Route 等）
        │ 系统自动写入操作日志
        ▼
操作日志列表查询与详情查看
```

| 关系 | 说明 |
| --- | --- |
| 写操作 → 操作日志（**被动依赖**） | 执行 Entity 创建、Provider 更新等写操作后，系统自动产生对应日志；日志模块本身无前置配置 |
| 操作日志 → 其他模块（**无依赖**） | 查询日志不修改任何配置，不影响业务数据 |

## 场景测试设计

### 场景一：管理员查看操作日志列表

**场景描述**：系统管理员进入操作日志列表页，查看日志记录，使用时间范围筛选与表格列搜索，并通过服务端分页浏览。

| 步骤 | 操作 | 对应编号 | 优先级 |
| --- | --- | --- | --- |
| 1 | 进入操作日志列表页，验证列表加载 | OL-L-01 | P0 |
| 2 | 使用时间范围筛选（起始 / 结束时间 + 查询） | OL-L-02 | P0 |
| 3 | 按操作人模糊搜索 | OL-L-03 | P1 |
| 4 | 按操作动作下拉筛选 | OL-L-04 | P1 |
| 5 | 按资源类型下拉筛选 | OL-L-05 | P1 |
| 6 | 按资源名称模糊搜索 | OL-L-06 | P1 |
| 7 | 按结果下拉筛选（成功 / 失败） | OL-L-07 | P1 |
| 8 | 组合筛选 | OL-L-08 | P1 |
| 9 | 服务端分页（翻页 / 页码跳转 / 每页条数） | OL-L-09 | P1 |
| 10 | 空列表展示 | OL-L-10 | P2 |
| 11 | 操作动作 Tag 颜色展示 | OL-L-11 | P2 |

**测试目标**：验证列表服务端分页加载、时间筛选、列搜索与 Tag 展示正确。

---

### 场景二：管理员查看日志详情

**场景描述**：管理员在列表中点击「详情」，打开右侧 Drawer 查看完整日志信息，包括变更摘要的可折叠 JSON 展示。

| 步骤 | 操作 | 对应编号 | 优先级 |
| --- | --- | --- | --- |
| 1 | 点击「详情」打开 Drawer | OL-D-01 | P0 |
| 2 | 详情字段完整性与接口数据一致 | OL-D-02 | P0 |
| 3 | 变更摘要可折叠展开（变更前 / 变更后 JSON） | OL-D-03 | P1 |
| 4 | 失败日志错误信息条件展示 | OL-D-04 | P1 |
| 5 | 关闭 Drawer（遮罩 / X / 关闭按钮） | OL-D-05 | P1 |

**测试目标**：验证详情 Drawer 字段与原型一致，变更摘要可交互，条件字段正确展示。

---

### 场景三：写操作产生日志（跨模块联动）

**场景描述**：管理员在其他模块执行写操作后，验证操作日志中自动产生对应记录。

| 步骤 | 操作 | 对应编号 | 优先级 |
| --- | --- | --- | --- |
| 1 | 创建 Entity 后，操作日志出现 create 记录 | OL-LINK-01 | P0 |
| 2 | 更新 Entity 后，日志含 change_summary（before / after / diff_keys） | OL-LINK-02 | P1 |
| 3 | 删除操作后，日志 action 为 delete | OL-LINK-03 | P1 |

**测试目标**：验证系统自动写入日志的行为与接口定义 §3 一致。

## 测试前置条件

| 测试场景 | 前置条件 |
| --- | --- |
| OL-L-01 ~ OL-L-09 | 系统中存在 ≥20 条操作日志（覆盖不同 action / resource_type / status），便于分页与筛选验证 |
| OL-L-10 空列表 | 时间范围筛选至无记录区间，或全新环境无写操作 |
| OL-D-01 ~ OL-D-05 | 存在含 change_summary 的成功日志与含 error_msg 的失败日志各至少 1 条 |
| OL-LINK-01 ~ OL-LINK-03 | 管理员有 Entity 模块写权限；操作日志列表可访问 |

## 测试数据准备

| 数据类别 | 准备内容 | 用途 |
| --- | --- | --- |
| 基础日志 | 通过 Entity 创建 / 更新 / 删除产生 | 列表 / 详情 / 联动 |
| 含变更摘要 | update 操作产生的日志，change_summary 含 before / after / diff_keys | OL-D-02 / OL-D-03 |
| 失败日志 | 触发失败的写操作（如删除被引用资源） | OL-D-04 / OL-L-07 |
| 分页数据 | ≥21 条日志 | OL-L-09 翻页验证 |

| 数据项 | 说明 | 示例值 |
| --- | --- | --- |
| operator_name | 操作人名称 | admin |
| action | 操作动作 | create / update / delete / reset / import / bind / unbind |
| resource_type | 资源类型 | entity / provider / cluster / api_key 等 |
| status | 结果（1 成功，2 失败） |
| created_at | 操作时间 | Unix 时间戳（秒），格式化为 `yyyy-MM-dd HH:mm:ss` |
