## 1. 列表页

### OL-L-01：列表加载与服务端分页

**功能模块**: 操作日志列表  
**优先级**: P0  
**用例编号**: OL-L-01  
**OpenAPI**: `GET /operation-logs`

#### 前置条件

- 系统中存在 ≥3 条操作日志记录
- 管理员已登录，有操作日志读权限

#### 测试步骤

1. 管理员登录，从侧边栏进入「操作日志」列表页
2. 观察列表加载过程中的网络请求
3. 检查筛选栏与表格列

#### 预期结果

1. 页面路由为 `/operation-logs`；面包屑 / 页面标题展示「操作日志」
2. 列表请求为 `GET /operation-logs`，携带 `page=1`、`page_size=20`（服务端分页，对齐原型与 UI 源码 `server-pagination: true`）
3. 筛选栏包含：**起始时间**、**结束时间**（DatePicker datetime 类型）、**查询**按钮
4. 表格列包含：**操作人**、**操作动作**（Tag）、**资源类型**、**资源名称**、**结果**（Tag）、**操作时间**、**操作**（详情按钮）
5. 加载成功后列表正常渲染，无报错；操作时间格式为 `yyyy-MM-dd HH:mm:ss`

### OL-L-02：时间范围筛选

**功能模块**: 操作日志列表  
**优先级**: P0  
**用例编号**: OL-L-02  
**OpenAPI**: `GET /operation-logs`（`start_time` / `end_time`）

#### 前置条件

- 存在时间跨度 ≥1 天的多条操作日志

#### 测试步骤

1. 在筛选栏设置「起始时间」为昨天 00:00:00
2. 设置「结束时间」为今天 23:59:59
3. 点击「查询」按钮
4. 观察网络请求与列表结果

#### 预期结果

1. 点击「查询」后触发 `GET /operation-logs`，Query 携带 `start_time` 与 `end_time`（Unix 秒级时间戳）
2. 列表仅展示 `created_at` 落在该时间闭区间内的日志
3. 查询后页码重置为第 1 页
4. 清空时间后再次查询，恢复全量（不传 `start_time` / `end_time`）

### OL-L-09：服务端分页

**功能模块**: 操作日志列表  
**优先级**: P1  
**用例编号**: OL-L-09  
**OpenAPI**: `GET /operation-logs`（`page` / `page_size`）

#### 前置条件

- 存在 ≥21 条操作日志（默认每页 20 条）

#### 测试步骤

1. 进入列表页，确认第 1 页展示 20 条
2. 点击「下一页」或页码 2
3. 修改每页条数为 50（如支持）
4. 观察网络请求

#### 预期结果

1. 翻页触发 `GET /operation-logs`，`page` 参数递增
2. 第 2 页展示剩余记录；分页总数与接口 `pagination.total` 一致（与首页 `total` 相同，且 `total > 20`）
3. 修改每页条数后 `page_size` 参数更新，页码重置为 1
4. 点击页码 / 下一页后，分页页码（1、2）仍可见，当前页高亮正确（回归 [#95](https://github.com/rainway-ai-gateway/ai-gateway-web/issues/95)：翻页后页码消失）
