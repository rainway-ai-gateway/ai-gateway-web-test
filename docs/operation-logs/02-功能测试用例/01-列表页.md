## 1. 列表页

### OL-L-01：列表加载与服务端分页

**功能模块**: 操作日志列表  
**优先级**: P0  
**用例编号**: OL-L-01  
**OpenAPI**: `GET /operation-logs`

#### 前置条件

- 系统中存在 ≥3 条操作日志记录
- 管理员已登录，有操作日志读权限

#### 测试步骤

1. 管理员登录，从侧边栏进入「操作日志」列表页
2. 观察列表加载过程中的网络请求
3. 检查筛选栏与表格列

#### 预期结果

1. 页面路由为 `/operation-logs`；面包屑 / 页面标题展示「操作日志」
2. 列表请求为 `GET /operation-logs`，携带 `page=1`、`page_size=20`（服务端分页，对齐原型与 UI 源码 `server-pagination: true`）
3. 筛选栏包含：**起始时间**、**结束时间**（DatePicker datetime 类型）、**查询**按钮
4. 表格列包含：**操作人**、**操作动作**（Tag）、**资源类型**、**资源名称**、**结果**（Tag）、**操作时间**、**操作**（详情按钮）
5. 加载成功后列表正常渲染，无报错；操作时间格式为 `yyyy-MM-dd HH:mm:ss`

**功能模块**: 操作日志列表

**用例编号**: OL-L-09  
**OpenAPI**: `GET /operation-logs`（`page` / `page_size`）

- 存在 ≥21 条操作日志（默认每页 20 条）

#### 测试步骤

1. 进入列表页，确认第 1 页展示 20 条
2. 点击「下一页」或页码 2

1. 翻页触发 `GET /operation-logs`，`page` 参数递增
2. 第 2 页展示剩余记录；分页总数与接口 `pagination.total` 一致（`total > 20`，且与同期重新取到的首页 `total` 相差 ≤5 —— 前序用例的清理动作会异步落库成新日志，`total` 在秒级内自增，跨步骤比对绝对值不可靠）
3. 修改每页条数后 `page_size` 参数更新，页码重置为 1
4. 点击页码 / 下一页后，分页页码（1、2）仍可见，当前页高亮正确（回归 [#95](https://github.com/rainway-ai-gateway/ai-gateway-web/issues/95)：翻页后页码消失）

### OL-L-13：列表接口数据与页面展示一致性

**功能模块**: 操作日志列表  
**优先级**: P1  
**用例编号**: OL-L-13  
**OpenAPI**: `GET /operation-logs`

#### 前置条件

- 系统中存在 ≥1 条字段完整的操作日志（覆盖不同 `action` / `resource_type` / `status`）
- 管理员已登录，有操作日志读权限；已打开浏览器开发者工具 Network 面板

#### 测试数据参考（接口 GET /operation-logs 返回体示例）

```json
{
  "ErrNum": 0,
  "ErrMsg": "success",
  "Data": {
    "total": 152,
    "page": 1,
    "page_size": 20,
    "list": [
      {
        "id": 1001,
        "log_id": "a1b2c3d4",
        "operator_type": 0,
        "operator_name": "admin",
        "action": "update",
        "resource_type": "batch",
        "resource_id": "batch-9",
        "resource_name": "rd-team-batch",
        "resource_parent_id": "entity-1",
        "status": 1,
        "change_summary": {
          "before": { "allow_models": ["gpt-4"] },
          "after": { "allow_models": ["gpt-4", "gpt-4o"] },
          "diff_keys": ["allow_models"]
        },
        "request_path": "/open-api/v1/entities/entity-5",
        "request_method": "PUT",
        "client_ip": "10.0.0.5",
        "user_agent": "Mozilla/5.0 ...",
        "created_at": 1725091200
      }
    ]
  }
}
```

#### 测试步骤

1. 管理员登录，进入操作日志列表页，打开开发者工具 Network 面板
2. 触发并观察 `GET /operation-logs` 请求，记录响应体 `Data.list[]` 与 `Data.pagination.total`
3. 将表格第 1 行的「操作人 / 操作动作 / 资源类型 / 资源名称 / 结果 / 操作时间」列与 `Data.list[0]` 逐字段比对
4. 核对分页组件展示的总条数与 `Data.pagination.total` 一致
5. 翻页后，重复比对第 2 页行与 `Data.list[]` 对应元素

#### 预期结果

字段比对（校验方式 = 文本一致 / 数值一致 / 时间戳转换一致，与接口返回 JSON 一致）：

- **操作人**（文本一致）：列表「操作人」列展示文本 = `Data.list[].operator_name`，原样展示
- **操作动作**（文本一致 + Tag 映射）：列表「操作动作」列 Tag 内文案 = `Data.list[].action`；Tag 颜色按 `ACTION_COLOR_MAP`（`create`→green / `update`→blue / `delete`→red / `reset`→orange / `import`→purple / `bind`→cyan / `unbind`→volcano，未知 action 用 default）
- **资源类型**（中文映射一致）：列表「资源类型」列展示 = `Data.list[].resource_type` 的中文映射（其中 `batch`→「批量任务」、`batch_file`→「批量文件」）；无映射的枚举回退展示原始值，不出现中文与英文枚举错配
- **资源名称**（文本一致）：列表「资源名称」列展示文本 = `Data.list[].resource_name`
- **结果**（数值映射一致）：列表「结果」列 Tag 文案与颜色由 `Data.list[].status` 决定（`1`→绿色「成功」；`2`→红色「失败」）
- **操作时间**（时间戳转换一致）：列表「操作时间」列 = `Data.list[].created_at`（Unix 秒级时间戳）转换后的 `yyyy-MM-dd HH:mm:ss`，与接口值对应的时刻一致
- **操作**（行级一致，无对应接口字段）：每行「操作」列均渲染「详情」按钮，与 `Data.list` 行数一一对应
- **分页 total**（数值一致）：分页组件总条数 = `Data.pagination.total`（接口若以平铺 `Data.total` 返回则取该值），翻页前后取值一致

**一致性比对矩阵**：

| UI 展示项 | 接口字段 | 校验方式 | 通过标准 |
| --- | --- | --- | --- |
| 操作人 | `operator_name` | 文本一致 | 列文本 = 接口 `operator_name` |
| 操作动作 | `action` | 文本一致 + Tag 映射 | Tag 文案 = `action`，颜色按 `ACTION_COLOR_MAP` |
| 资源类型 | `resource_type` | 中文映射一致 | 列展示 = 中文映射（`batch`→批量任务 / `batch_file`→批量文件） |
| 资源名称 | `resource_name` | 文本一致 | 列文本 = 接口 `resource_name` |
| 结果 | `status` | 数值映射一致 | `1`→绿色「成功」 / `2`→红色「失败」 |
| 操作时间 | `created_at` | 时间戳转换一致 | 列展示 = `created_at` 转 `yyyy-MM-dd HH:mm:ss` |
| 操作 | —（无对应字段） | 行级一致 | 每行均有「详情」按钮，行数 = `list.length` |
| 分页总数 | `pagination.total` | 数值一致 | 分页 total = 接口 `pagination.total` |

**整体预期**：

1. 列表请求 `GET /operation-logs` 返回 200，`Data.list` 逐行渲染为表格行，行数 = `Data.list.length`
2. 表格各列展示值与 `Data.list[]` 对应字段一一对应，无错位、无遗漏、无错配
3. 操作动作 / 结果以 Tag 展示且颜色语义正确；资源类型以中文展示，不出现原始英文枚举
4. 翻页 / 修改每页条数后重复比对仍保持一致，分页 total 与接口返回一致
