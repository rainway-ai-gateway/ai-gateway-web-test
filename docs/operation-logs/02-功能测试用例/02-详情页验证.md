## 2. 详情页验证

### OL-D-01：打开详情 Drawer

**功能模块**: 操作日志详情  
**优先级**: P0  
**用例编号**: OL-D-01

#### 前置条件

- 列表中存在至少 1 条操作日志

#### 测试步骤

1. 进入操作日志列表页
2. 点击某行「操作」列的「详情」按钮

#### 预期结果

1. 右侧滑出 Drawer，宽度 720px
2. Drawer 标题为「日志详情」
3. 点击遮罩可关闭 Drawer
4. 详情数据来自当前列表行（不额外请求详情接口）

---

### OL-D-02：详情字段完整性与接口数据一致

**功能模块**: 操作日志详情  
**优先级**: P0  
**用例编号**: OL-D-02  
**设计依据**: 原型 `operation-logs.html` 详情区块；`ui-code-changes.md` 字段顺序

#### 前置条件

- 存在一条字段完整的成功日志（含 change_summary、request_path、client_ip、user_agent 等）

#### 测试步骤

1. 打开含完整字段的日志详情
2. 逐字段核对展示值与列表行 / 接口返回一致

#### 预期结果

1. 字段按以下顺序展示（每行两项，操作时间在最后）：
   - **操作者类型** | **操作人**（`operator_type` 0→「用户」，1→「Token」）
   - **操作动作**（Tag）| **资源类型**
   - **资源ID** | **资源名称**
   - **父级资源ID** | **结果**（Tag：成功 / 失败）
   - **错误信息**（仅 `error_msg` 非空时展示，红色文字）
   - **变更摘要**（仅 `change_summary` 存在时展示，见 OL-D-03）
   - **请求路径** | **请求方式**（Tag）
   - **客户端IP** | **User-Agent**
   - **操作时间**（格式 `yyyy-MM-dd HH:mm:ss`）
2. **不展示** `id`、`log_id`、`operator_id` 字段
3. 空值字段展示 `-`

---

### OL-D-03：变更摘要可折叠 JSON

**功能模块**: 操作日志详情  
**优先级**: P1  
**用例编号**: OL-D-03

#### 前置条件

- 存在含 `change_summary` 的 update 日志，`before` / `after` / `diff_keys` 均有值

#### 测试步骤

1. 打开该日志详情
2. 观察「变更摘要」区块
3. 点击「变更前」「变更后」区域展开 / 折叠

#### 预期结果

1. 展示「变更摘要」标题
2. 「变更前」区域以 vue-json-viewer 展示 `change_summary.before` JSON，可折叠展开
3. 「变更后」区域以 vue-json-viewer 展示 `change_summary.after` JSON，可折叠展开
4. 「差异字段」展示 `diff_keys` 数组 join 结果（蓝色高亮），如 `allow_models`
5. `before` / `after` 为空时展示 `-`

### OL-D-04：失败日志错误信息展示

**功能模块**: 操作日志详情  
**优先级**: P1  
**用例编号**: OL-D-04

#### 前置条件

- 存在 `status=2`（失败）且 `error_msg` 非空的日志

#### 测试步骤

1. 在列表中筛选「失败」结果
2. 打开该日志详情

#### 预期结果

1. 列表「结果」列为红色 Tag「失败」
2. 详情中「结果」为红色 Tag「失败」
3. 展示「错误信息」字段，内容为 `error_msg` 值，红色文字
4. 成功日志（`error_msg` 为空）不展示「错误信息」区块

### OL-D-06：详情抽屉资源类型中文展示

**功能模块**: 操作日志详情  
**优先级**: P1  
**用例编号**: OL-D-06

#### 前置条件

- 列表中存在 `resource_type` 为 `batch`（批量任务）与 `batch_file`（批量文件）的日志

#### 测试步骤

1. 在列表中找到 `resource_type` 为 `batch` 的日志，点击「详情」打开 Drawer
2. 观察详情「资源类型」字段展示
3. 关闭后重新打开 `resource_type` 为 `batch_file` 的日志详情，观察展示

#### 预期结果

1. 资源类型为 `batch` 的日志，详情「资源类型」展示中文「批量任务」
2. 资源类型为 `batch_file` 的日志，详情「资源类型」展示中文「批量文件」
3. 详情中资源类型展示与列表 `resource_type` 列一致，均以**中文标签**展示（`entity`→`Entity`、`entity_type`→`Entity 类型`、`api_key`→`API Key`、`provider`→服务商、`cluster`→集群、`route`→路由、`certificate`→证书、`quota_plan`→配额计划、`model_price`→模型定价、`batch`→批量任务、`batch_file`→批量文件、`user`→用户、`token`→Token），不出现原始英文枚举值

### OL-D-07：详情接口数据与页面展示一致性

**功能模块**: 操作日志详情  
**优先级**: P1  
**用例编号**: OL-D-07  
**OpenAPI**: `GET /operation-logs`（详情数据来自列表行，不额外请求详情接口）

#### 前置条件

- 存在一条字段完整的操作日志（含 `change_summary`、`request_path`、`client_ip`、`user_agent` 等），可在列表中定位
- 管理员已登录，有操作日志读权限；已打开浏览器开发者工具 Network 面板

#### 测试数据参考（接口 GET /operation-logs 返回体示例）

```json
{
  "ErrNum": 0,
  "ErrMsg": "success",
  "Data": {
    "total": 152,
    "page": 1,
    "page_size": 20,
    "list": [
      {
        "id": 1001,
        "log_id": "a1b2c3d4",
        "operator_type": 0,
        "operator_id": 1,
        "operator_name": "admin",
        "action": "update",
        "resource_type": "entity",
        "resource_id": "entity-5",
        "resource_name": "rd-team",
        "resource_parent_id": "entity-1",
        "status": 1,
        "error_msg": "",
        "change_summary": {
          "before": { "allow_models": ["gpt-4"] },
          "after": { "allow_models": ["gpt-4", "gpt-4o"] },
          "diff_keys": ["allow_models"]
        },
        "request_path": "/open-api/v1/entities/entity-5",
        "request_method": "PUT",
        "client_ip": "10.0.0.5",
        "user_agent": "Mozilla/5.0 ...",
        "created_at": 1725091200
      }
    ]
  }
}
```

#### 测试步骤

1. 管理员登录，进入操作日志列表页，打开开发者工具 Network 面板，记录 `GET /operation-logs` 响应体 `Data.list[]`
2. 点击目标行的「详情」按钮打开右侧 Drawer
3. 按 OL-D-02 的字段顺序，逐项比对 Drawer 展示值与接口 `Data.list[]` 对应行
4. 确认打开详情时未触发额外的详情接口请求（数据源为列表行）

#### 预期结果

字段比对（校验方式 = 文本一致 / 数值一致 / 数组逐项比对 / 时间戳转换一致，与接口返回 JSON 一致）：

- **操作者类型**（数值映射一致）：= `Data.list[].operator_type`（`0`→「用户」 / `1`→「Token」，其余 / 空为 `-`）
- **操作人**（文本一致）：= `Data.list[].operator_name`，空值展示 `-`
- **操作动作**（文本一致 + Tag）：Drawer「操作动作」Tag 文案 = `Data.list[].action`
- **资源类型**（中文标签映射一致）：= `Data.list[].resource_type` 的中文标签映射（`entity`→`Entity`、`entity_type`→`Entity 类型`、`api_key`→`API Key`、`provider`→服务商、`cluster`→集群、`route`→路由、`certificate`→证书、`quota_plan`→配额计划、`model_price`→模型定价、`batch`→批量任务、`batch_file`→批量文件、`user`→用户、`token`→Token），不出现原始英文枚举
- **资源ID**（文本一致）：= `Data.list[].resource_id`，空值展示 `-`
- **资源名称**（文本一致）：= `Data.list[].resource_name`，空值展示 `-`
- **父级资源ID**（文本一致）：= `Data.list[].resource_parent_id`，空值展示 `-`
- **结果**（数值映射一致）：= `Data.list[].status`（`1`→「成功」 / `2`→「失败」），Tag 颜色语义正确
- **错误信息**（文本一致，条件展示）：`Data.list[].error_msg` 非空时展示红色文字且等于该值；为空时不展示该区块
- **变更摘要**（键 / 值一致，数组逐项比对）：= `Data.list[].change_summary`（`before` / `after` 以可折叠 JSON 展示，`diff_keys` 按数组 join 展示）；`change_summary` 不存在时不展示该区块
- **请求路径**（文本一致）：= `Data.list[].request_path`，空值展示 `-`
- **请求方式**（文本一致 + Tag）：Drawer「请求方式」Tag 文案 = `Data.list[].request_method`
- **客户端IP**（文本一致）：= `Data.list[].client_ip`，空值展示 `-`
- **User-Agent**（文本一致）：= `Data.list[].user_agent`，空值展示 `-`
- **操作时间**（时间戳转换一致）：= `Data.list[].created_at`（Unix 秒级时间戳）转换后的 `yyyy-MM-dd HH:mm:ss`

**一致性比对矩阵**：

| UI 展示项 | 接口字段 | 校验方式 | 通过标准 |
| --- | --- | --- | --- |
| 操作者类型 | `operator_type` | 数值映射一致 | `0`→用户 / `1`→Token |
| 操作人 | `operator_name` | 文本一致 | Drawer 文本 = 接口 `operator_name`（空值 `-`） |
| 操作动作 | `action` | 文本一致 + Tag | Tag 文案 = 接口 `action` |
| 资源类型 | `resource_type` | 中文映射一致 | 中文映射（`batch`→批量任务 / `batch_file`→批量文件） |
| 资源ID | `resource_id` | 文本一致 | 文本 = 接口 `resource_id`（空值 `-`） |
| 资源名称 | `resource_name` | 文本一致 | 文本 = 接口 `resource_name`（空值 `-`） |
| 父级资源ID | `resource_parent_id` | 文本一致 | 文本 = 接口 `resource_parent_id`（空值 `-`） |
| 结果 | `status` | 数值映射一致 | `1`→成功 / `2`→失败 |
| 错误信息 | `error_msg` | 文本一致（条件展示） | 非空时展示且等于 `error_msg`；为空不展示 |
| 变更摘要 | `change_summary` | 键/值一致 + 数组逐项比对 | `before`/`after` JSON 与 `diff_keys` 与接口一致 |
| 请求路径 | `request_path` | 文本一致 | 文本 = 接口 `request_path`（空值 `-`） |
| 请求方式 | `request_method` | 文本一致 + Tag | Tag 文案 = 接口 `request_method` |
| 客户端IP | `client_ip` | 文本一致 | 文本 = 接口 `client_ip`（空值 `-`） |
| User-Agent | `user_agent` | 文本一致 | 文本 = 接口 `user_agent`（空值 `-`） |
| 操作时间 | `created_at` | 时间戳转换一致 | 展示 = `created_at` 转 `yyyy-MM-dd HH:mm:ss` |

**整体预期**：

1. 打开详情 Drawer 时不产生额外的详情接口请求，数据来源为列表行 `Data.list[]`
2. Drawer 展示的所有字段值与接口对应行一一对应，无遗漏、无错配，字段顺序与 OL-D-02 一致
3. 空值字段统一展示 `-`；不展示 `id`、`log_id`、`operator_id`
4. 资源类型以中文展示；变更摘要、错误信息等条件区块按接口数据的有无正确展示 / 隐藏
