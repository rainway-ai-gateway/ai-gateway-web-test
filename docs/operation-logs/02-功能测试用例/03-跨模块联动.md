## 3. 跨模块联动

### OL-LINK-01：创建 Entity 产生操作日志

**功能模块**: 跨模块联动  
**优先级**: P0  
**用例编号**: OL-LINK-01  
**OpenAPI**: `POST /entities` → 自动写入操作日志；`GET /operation-logs` 查询

#### 前置条件

- 管理员有 Entity 创建权限与操作日志读权限
- 记录创建前的日志总数（可选）

#### 测试步骤

1. 在 Entity 管理模块创建一个新 Entity（记录 entity_id 与名称）
2. 进入操作日志列表页
3. 按资源类型筛选 `entity`，按操作动作筛选 `create`
4. 在资源名称搜索刚创建的 Entity 名称

#### 预期结果

1. 操作日志列表出现一条新记录：
   - `action` = `create`
   - `resource_type` = `entity`
   - `resource_id` = 新创建的 entity_id
   - `resource_name` = 新创建的 Entity 名称
   - `status` = 1（成功）
   - `operator_name` = 当前登录管理员用户名
2. 日志 `created_at` 在创建操作之后

### OL-LINK-02：更新操作含变更摘要

**功能模块**: 跨模块联动  
**优先级**: P1  
**用例编号**: OL-LINK-02  
**OpenAPI**: `PUT /entities/{id}` → 自动写入操作日志

#### 前置条件

- 存在一个可编辑的 Entity
- 管理员有 Entity 编辑权限

#### 测试步骤

1. 修改该 Entity 的某个字段（如描述或 allow_models）
2. 进入操作日志列表，筛选 `action=update`、`resource_type=entity`
3. 找到对应日志，打开详情

#### 预期结果

1. 日志 `action` = `update`，`status` = 1
2. 详情含「变更摘要」区块
3. `change_summary` 包含：
   - `before`：变更前的字段值
   - `after`：变更后的字段值
   - `diff_keys`：变更字段名列表
4. 敏感字段（如 api-key token、密码）已脱敏，不记录原始值（对齐接口 §1 说明）

### OL-LINK-03：删除操作产生日志

**功能模块**: 跨模块联动  
**优先级**: P1  
**用例编号**: OL-LINK-03  
**OpenAPI**: `DELETE /entities/{id}` → 自动写入操作日志

#### 前置条件

- 存在一个可删除的 Entity（无引用约束）
- 管理员有 Entity 删除权限

#### 测试步骤

1. 删除该 Entity（记录 entity_id 与名称）
2. 进入操作日志列表，筛选 `action=delete`、`resource_type=entity`
3. 在资源名称搜索被删除的 Entity 名称

#### 预期结果

1. 操作日志出现一条 `action=delete` 的记录
2. `resource_id` = 被删除的 entity_id
3. `resource_name` = 被删除的 Entity 名称
4. `status` = 1（删除成功时）

#### 补充说明

- 删除失败（如被引用）时，`status` = 2，`error_msg` 含失败原因（见 OL-D-04）
- 接口 §3 列出的其他写操作（Provider / Cluster / Route 等）同样会触发日志，本用例以 Entity 为标杆验证
