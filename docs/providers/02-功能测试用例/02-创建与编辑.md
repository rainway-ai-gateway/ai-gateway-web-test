## 2. 创建与编辑

### PR-C-01：创建服务商-成功（IP 模式）

**功能模块**: 创建与编辑  
**优先级**: P0  
**用例编号**: PR-C-01

#### 前置条件

- 不存在与待创建名称重复的服务商

#### 测试步骤

1. 列表页点击「添加服务商」，打开创建抽屉
2. **基本信息**：填写名称 `deepseek_{ts}`、描述「DeepSeek 官方 API」
3. **实例池**：实例形态选择「IP」；填写一行实例：地址 `127.0.0.1`、端口 `80`、权重 `100`（表格列：**IP/域名、端口、权重、操作**，无名称列）
4. **模型服务配置**：模型协议多选 `openai`；schema 默认 `https`，uri 默认 `/v1/models`，只读 addr:port 展示首个实例
5. 可选执行「获取」回填模型（见 PR-C-08），或手动输入模型名回车添加（见 PR-C-10）
6. **服务鉴权 Keys**：添加 1 行，Key 名称 `key-primary`、Key 值 `sk-xxx`
7. 点击「提交」

#### 预期结果

1. 提交调用 `POST /providers`，返回 200 与完整对象
2. 提交体：`instance_pool[].name` **不传**（服务端默认与 addr 相同）；`keys` 含 name+key；不含 `create_time` / `update_time`（见 PR-C-13）
3. 提交成功后关闭抽屉，列表刷新出现新服务商
4. 实例池表格无「名称」列，行首列标题为 IP/域名

### PR-C-08：「获取」模型-回填

**功能模块**: 创建与编辑  
**优先级**: P0  
**用例编号**: PR-C-08

#### 前置条件

- 已选择模型协议且已填写实例地址（「获取」可用）

#### 测试步骤

1. 点击「获取」按钮
2. 观察请求与模型列表回填
3. 不点「提交」，关闭抽屉后重新打开

#### 预期结果

1. 调用 `POST /providers/tools/discover-models`，Body 传：`{model_protocol, schema, addr, port, uri?, apikey?}`
2. 返回 `Data.models` 后回填到模型列表（多选形式，支持手动输入 / 删除）
3. 请求过程无 toast；失败时（如连接失败）给出错误提示且不回填
4. 回填结果**不自动保存**——须点「提交」才写入 Provider（见 PR-C-12）

### PR-C-13：提交体结构校验

**功能模块**: 创建与编辑  
**优先级**: P0  
**用例编号**: PR-C-13

#### 前置条件

- 打开创建抽屉并填写完整合法数据

#### 测试步骤

1. 填写完整数据后提交，抓取请求体
2. 对照接口定义（`POST /providers`）

#### 预期结果

1. 请求体**不含** `create_time` / `update_time`（系统生成）
2. `instance_pool[].name` 不传（服务端默认与 addr 相同）
3. `models` 仅当「获取」回填后才存在；未获取时不传或传空
4. 不再配置 `headers.Authorization`；模型发现接口认证头由 `model_protocols` 决定（openai → `Authorization: Bearer`，anthropic → `x-api-key`）
5. 未传 `time_zone` 时服务端默认 `Asia/Shanghai`
