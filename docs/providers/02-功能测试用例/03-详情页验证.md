### PR-D-01：详情页全字段与接口数据一致性

**功能模块**: 详情页  
**优先级**: P0  
**用例编号**: PR-D-01  
**设计依据**: 原型 `providers.html`（详情抽屉）；`providers.md` §2.3 Provider 详情  

#### 前置条件

- 存在一条字段完整的服务商记录（含实例池多实例、多协议、多个 keys、已配置分段计价），且未被任何集群引用或已配置完整

#### 测试数据参考（接口 GET /providers/{provider_name} 返回体示例）

```json
{
  "name": "deepseek",
  "description": "DeepSeek 官方 API",
  "model_endpoint": { "schema": "https", "uri": "/v1/models" },
  "models": ["deepseek-chat", "deepseek-coder", "deepseek-reasoner"],
  "keys": [
    { "name": "key-primary", "key": "sk-aaaaaaaaaaaa" },
    { "name": "key-secondary", "key": "sk-bbbbbbbbbbbb" }
  ],
  "instance_pool": [
    { "name": "backend-1", "addr": "api.deepseek.com", "weight": 100, "port": 443 }
  ],
  "model_protocols": ["openai"],
  "time_zone": "Asia/Shanghai",
  "tiers": [
    { "name": "peak", "time_ranges": [
      { "weekdays": [1,2,3,4,5], "start": "09:00", "end": "12:00" },
      { "weekdays": [1,2,3,4,5], "start": "14:00", "end": "18:00" }
    ]}
  ],
  "create_time": 1716883200,
  "update_time": 1716883200
}
```

#### 测试步骤

1. 列表页点击「详情」，打开详情 Drawer
2. 逐一比对详情页各字段与接口返回值

#### 预期结果

区域比对（校验方式 = 文本 / 列表 / 脱敏逐项比对，与接口返回 JSON 一致）：

- **基本信息**：名称、描述、**创建时间 / 更新时间**（时间戳转换后展示，并入基本信息 Card，不再有独立「时间戳」Card）
- **实例池**：实例列表：地址 / 端口 / 权重（IP 或域名），与接口 `instance_pool` 一致；多实例逐行展示
- **模型服务配置**：模型协议（join 展示）、模型列表接口 schema / uri / addr:port、模型列表（tags），与接口一致
- **服务鉴权 Keys**：Key 名称 + **Key 值脱敏**（如 `sk-a****aaaa`，首尾保留少量字符中间掩码），不展示明文；**视角补充**：接口 `keys[].key` 为系统管理员明文、只读视角返回掩码值（规则同 api-keys，前端原样展示，见 PR-RO-03）
- **分段计价配置**：时区、忙时（peak）、时间段表（适用时段 / 开始时间 / 结束时间），与接口 `time_zone` / `tiers` 一致

**整体预期**：

1. 进入详情调用 `GET /providers/{name}` 返回 200
2. 全部字段展示值与接口 JSON 一一对应，无遗漏、无错配
3. 详情不渲染禁用输入框（只读卡片形态）
4. 面包屑 / 返回列表正确

### PR-D-05：详情页 K8s 池实例列表实时读取与降级

**功能模块**: 详情页  
**优先级**: P0  
**用例编号**: PR-D-05  
**设计依据**: `ProviderView.vue` `currentData` watcher（打开详情时按 `k8s_pool_name` 调 `GET /open-api/v1/k8s_pools/{name}`；响应拦截器对 HTTP 错误 resolve，故 404 以 `res.status === 404` 判定 → 「K8s 池不存在（≡ 零实例）」，200 空数组 → 「暂无镜像实例（池不存在 ≡ 零实例）」——2026-11-02 按当前 i18n 对齐，空池文案较旧版「当前池暂无实例（空池为合法状态）」已变更）；`ui-code-changes.md` §4.2  
**OpenAPI**: `k8s-pools.md` §2.2（`GET /open-api/v1/k8s_pools/{name}`；池不存在 404、空池 200 + `instances: []`）

#### 前置条件

- 存在 `instance_source=k8s_pool` 的服务商（`k8s_pool_name` 有值）
- 场景 ①：同名池含 ≥1 个实例（InnerAPI `PUT /inner-api/v1/k8s_pools/{name}/instances` 造池）
- 场景 ②：同名池存在但 `instances: []`（空池为合法状态）
- 场景 ③：`k8s_pool_name` 引用的池不存在（InnerAPI `DELETE /inner-api/v1/k8s_pools/{name}` 删池）

#### 测试步骤

1. 场景 ①：打开引用了有实例池的服务商详情，查看 K8s 分支实例表
2. 场景 ②：打开引用空池的服务商详情，查看 K8s 分支实例区
3. 场景 ③：打开引用不存在池的服务商详情，查看 K8s 分支实例区

#### 预期结果

1. 场景 ①：实例表（表头：实例地址 / 端口 / 权重）与 `GET /open-api/v1/k8s_pools/{k8s_pool_name}` 返回的 `instances[]`（`addr` / `port` / `weight`）**逐行一致**，为实时读取而非 provider 镜像字段
2. 场景 ②：接口返回 200 + `instances: []` → 实例区展示文案「暂无镜像实例（池不存在 ≡ 零实例）」（2026-11-02 按当前 i18n 对齐）
3. 场景 ③：接口返回 404 → 实例区展示文案「K8s 池不存在（≡ 零实例）」

> ✅ **缺陷已修复（2026-10-28）**：池详情 404 时实例区正确展示「K8s 池不存在（≡ 零实例）」。修复点：`ProviderView.vue` 的 `currentData` watcher 改为在 `then` 中判断 `res.status === 404`（`src/utils/request.js` 拦截器对 HTTP 错误 resolve `error.response` 而非 reject，原 `.catch` 分支为死代码），并加 `unneedTips` 避免 404 弹出全局错误提示。自动化 `tests/providers/test_03_provider_detail.spec.js` PR-D-05 三条场景已实测通过。
