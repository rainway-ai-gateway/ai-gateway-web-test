## 6. 字段校验矩阵

> 校验规则依据 `design-docs/api-define/OpenAPI接口定义/providers.md` §3 校验规则；以下为 UI 侧应拦截 / 提示的校验用例，后端拦截以接口 422 为准。

### PR-V-01：name 必填校验

**功能模块**: 字段校验  
**优先级**: P0  
**用例编号**: PR-V-01

#### 前置条件

- 打开创建抽屉

#### 测试步骤

1. 名称留空，提交
2. 仅输入空白字符，提交

#### 预期结果

- 提交被拦截，提示名称必填；创建后名称不可修改

---

### PR-V-02：name 格式校验

**功能模块**: 字段校验  
**优先级**: P0  
**用例编号**: PR-V-02

#### 前置条件

- 打开创建抽屉

#### 测试步骤

依次输入以下名称并触发校验：

1. **长度 >64**：65 个字符 → 预期拦截，提示长度超限
2. **非法字符**：`deep seek`、`deep*seek`、`deep.` → 预期拦截，仅允许字母 / 数字 / `_` / `-` / `.`
3. **首尾非法**：`.deepseek`、`-deepseek`、`_deepseek`、`deepseek-` → 预期拦截，首尾不能为 `.` / `-` / `_`
4. **含空白**：`deep seek` → 预期拦截，不能包含空白字符
5. **合法值**：`deepseek`、`deep-seek.v2` → 预期通过

### PR-V-15：tiers / time_ranges 校验

**功能模块**: 字段校验  
**优先级**: P1  
**用例编号**: PR-V-15

#### 前置条件

- 打开分段计价 Drawer

#### 测试步骤

分别验证以下场景并提交：

1. **time_ranges 为空** → 预期拦截，「忙时至少包含 1 个时间段」
2. **weekdays 元素越界（如 7）** → 预期拦截（元素须 0-6，UI 为固定 7 项 Checkbox 不会产生越界）
3. **start/end 非 HH:MM** → 预期拦截
4. **end <= start** → 预期拦截
5. **同 tier 时间段重叠（适用时段有交集且时间相交）** → 预期拦截
6. **合法配置（含 `weekdays: []` 表示每天）** → 预期通过

> UI 通过固定 Checkbox 约束 `weekdays` 取值，越界校验主要由后端兜底；前端重点覆盖格式 / 大小 / 重叠校验。
