## 7. 跨模块联动（软关联）

> 本节验证服务商作为**数据源**，在真实配置链路（服务商 → 模型定价 → 集群大模型配置引用）中的联动行为。关联模块用例：`model-prices`（MP-C/MP-T/MP-LINK）、`business-cluster`（RM-BC-70~86）。
> 联动关系：集群 `llm_config.provider` 引用服务商名；集群转发模型 / Keys 均来自服务商数据；服务商删除受集群引用保护（409）；模型定价 `provider` 字段关联服务商名（**软关联**，删除服务商不级联删除定价）。

### PR-LINK-01：服务商模型定价（provider 关联服务商名）

**功能模块**: 跨模块联动  
**优先级**: P0  
**用例编号**: PR-LINK-01

#### 前置条件

- 已创建服务商 `deepseek`（含探测模型 deepseek-chat / deepseek-v3）

#### 测试步骤

1. 在模型定价列表「新增」，provider 填写服务商名 `deepseek`，model 填写 `deepseek-v3`，配置默认价格（及可选分时段价格）
2. 提交成功
3. 返回服务商列表，点击该服务商「查询模型价格」

#### 预期结果

1. 定价创建成功（`POST /model-prices`），provider 与服务商名一致
2. 服务商列表「查询模型价格」跳转定价列表 `provider=deepseek&autoView=1` 并自动打开该定价详情（联动 PR-L-11 / MP-LINK-02）
3. 服务商与定价为**软关联**：服务商不存在时定价仍可独立存在（见 PR-LINK-08）

**功能模块**: 跨模块联动  
**优先级**: P0  
**用例编号**: PR-LINK-02

#### 前置条件

- 已创建服务商 `deepseek`

#### 测试步骤

1. 进入集群创建向导第 4 步「大模型配置」
2. 展开「所属服务商」下拉

#### 预期结果

1. 下拉选项来自 `GET /providers/actions/get-provider-names`，包含 `deepseek`（联动 RM-BC-71）
2. 选择 `deepseek` 后调用 `GET /providers/deepseek` 拉取详情
3. **服务商不存在时**该下拉无法出现其名称，集群无法引用（强依赖）

### PR-LINK-05：修改服务商实例池 → 引用集群实例池同步

**功能模块**: 跨模块联动  
**优先级**: P0  
**用例编号**: PR-LINK-05

#### 前置条件

- 存在引用 `deepseek` 的集群；服务商实例池当前为 1 个实例

#### 测试步骤

1. 编辑服务商 `deepseek`，新增 / 修改实例池（如新增一个实例、修改权重）
2. 提交成功后打开引用集群详情

#### 预期结果

1. 服务商更新成功（`PATCH /providers/deepseek`）
2. **后端同步**：引用该 provider 的集群实例池随之更新（集群本身无需重新编辑）
3. 集群详情展示的实例池与服务商最新实例池一致
4. 修改服务商 Keys（name 变更）后，引用集群 Keys 一并更新（联动校验）
