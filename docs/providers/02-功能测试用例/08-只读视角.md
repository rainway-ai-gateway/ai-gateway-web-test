## 8. 只读管理员视角（写操作隐藏）

> 变更依据：`design-docs/modifications/2026-10-12-readonly-admin/ui-code-changes.md`（已 Review 通过）。
> 后端以 `role` 枚举取代 `is_admin`（`system_admin` / `system_admin_readonly`）；只读视角（`role === 'system_admin_readonly'`）**全站隐藏所有写操作按钮**，仅保留只读入口（详情 / 查看 / 查询）。前端实现为全局指令 `v-has`：只读登录态下给挂载元素加 `.v-has-hidden { display:none !important; }`。
> 密钥读端点（`GET /providers`、`GET /providers/{name}`）响应 `keys[].key` 按角色返回：系统管理员明文；只读返回**掩码值**（由后端 `lib/xmask` 完成，规则同 api-keys，前端原样展示）。

### PR-RO-01：只读视角列表工具栏写按钮隐藏

**功能模块**: 列表页
**优先级**: P0
**用例编号**: PR-RO-01
**OpenAPI**: `GET /providers`

#### 前置条件

1. 以**只读系统管理员**登录（`role=system_admin_readonly`，原型 `viewer` 账号语义）。
2. 「模型服务商」菜单可达并进入列表页。

#### 测试步骤

1. 进入服务商列表页。
2. 观察列表工具栏（筛选栏上方）的按钮区。
3. 逐项核对工具栏中写操作入口的可见性。

#### 预期结果

1. 工具栏**不显示**「添加服务商」写操作按钮。
2. 只读视角下工具栏不含任何创建 / 新增写入口，仅保留筛选等只读控件。
3. 切换为系统管理员（`role=system_admin`）登录时，该「添加服务商」按钮正常显示（对照组）。

#### 测试数据

- 只读账号：`role=system_admin_readonly`（环境已有 `viewer` / `viewer123`）
- 管理员账号：`role=system_admin`
- **数据策略（自动化）**：复用环境数据，`beforeAll` 造 1 条专用服务商 `provider_ro_<ts>` 供行级断言，`afterAll` 按名称删除还原；工具栏可见性断言与数据无关。

#### 补充说明

- 依据变更记录 §3.4：`pages/providers.html` 只读视角隐藏「添加服务商」，写按钮挂全局指令 `v-has`。

### PR-RO-02：只读视角列表操作列写按钮隐藏

**功能模块**: 列表页
**优先级**: P0
**用例编号**: PR-RO-02
**OpenAPI**: `GET /providers`

#### 前置条件

1. 以**只读系统管理员**登录，列表中已存在至少一条服务商记录。

#### 测试步骤

1. 进入服务商列表页。
2. 观察列表行尾「操作」列的按钮。
3. 点击只读入口（如「详情」），核对是否可用。

#### 预期结果

1. 操作列**隐藏**「编辑」「删除」「分段计价配置」等写操作按钮。
2. 操作列**保留**「详情」「查询模型价格」只读入口（不计入隐藏）。
3. 管理员视角下操作列的写按钮正常显示（对照组）。

#### 测试数据

- 只读账号：`role=system_admin_readonly`（`viewer`）
- 存在 1 条以上服务商记录
- **数据策略（自动化）**：复用环境数据 + `beforeAll` 造 1 条专用服务商 `provider_ro_<ts>`（`afterAll` 删除还原）作为行级断言锚点，避免依赖环境既有记录的分布（前端分页 20 条/页，目标行可能不在第 1 页，断言前先按名称本地筛选）。

#### 补充说明

- 依据变更记录 §3.4：`pages/providers.html` 只读视角保留「详情 / 查询模型价格」，隐藏「添加服务商 / 分段计价配置 / 编辑 / 删除」。

### PR-RO-03：只读视角服务商 keys 掩码展示与鉴权失效

**功能模块**: 详情页 / 列表页
**优先级**: P0
**用例编号**: PR-RO-03
**OpenAPI**: `GET /providers`、`GET /providers/{name}`

#### 前置条件

1. 存在至少一条含 `keys`（`keys[].key` 明文长度 > 8）的服务商记录。
2. 分别准备只读系统管理员与系统管理员登录态。

#### 测试步骤

1. 以**只读系统管理员**调用 `GET /providers`，查看返回项中 `keys[].key`。
2. 以只读系统管理员调用 `GET /providers/{name}`，查看响应 `keys[].key`。
3. 以系统管理员调用同样两个端点，查看 `keys[].key`。
4. 尝试使用只读视角返回的掩码值作为服务商鉴权 Key 发起上游请求。

#### 预期结果

1. 只读视角下两处 `keys[].key` 均返回**掩码值**，规则同 api-keys：长度 > 8 → 前 4 位 + `********` + 后 4 位；4 < 长度 ≤ 8 → 前 2 位 + `****` + 后 2 位；长度 ≤ 4 → 全掩码。
2. 掩码值在列表与详情抽屉中**原样展示**（前端不做二次脱敏）。
3. 系统管理员视角两处 `keys[].key` 均返回**明文**（对照组）。
4. 掩码值**不可用于鉴权**。

#### 测试数据

- 明文示例：`sk-aaaaaaaaaaaa`（>8）→ 掩码 `sk-a********aaaa`
- 边界样本：长度 8 → `ab****gh`、长度 4 → `********`、长度 3 → `********`
- **数据策略（自动化）**：`beforeAll` 造 1 条专用服务商 `provider_ro_<ts>`，`keys` 含上述 4 个边界样本（15 / 8 / 4 / 3），`afterAll` 删除还原；接口断言分别在管理员态与只读态调用 `GET /providers`、`GET /providers/{name}`。

#### 补充说明

- 脱敏由后端 `lib/xmask` 完成；本用例以**接口层**验证为主，UI 侧重展示一致性（与 PR-D-01 的 Key 脱敏展示联动）。
- **UI 展示规则偏差（2026-10-16 记录）**：源码 `src/modules/Providers/components/ProviderView.vue:140` 对 key 追加调用前端 `maskSecretKey`（`src/utils/const.js:562`：长度 ≤12 → `****`；>12 → 前 8 位 + `****` + 后 4 位），即详情抽屉展示的是「后端掩码值再经前端掩码」的**二次结果**，与本节预期 2「前端不做二次脱敏」不符。自动化按**源码实际行为**断言（期望值 = 前端规则(xmask(明文))）；明文长度 >12 时两条规则结果一致。
- **预期 4「掩码值不可用于鉴权」的自动化边界**：上游鉴权发生在网关向上游注入 Key 时，管理台 UI 无该链路入口，无法在 UI 层复现；自动化以「掩码值 ≠ 明文且不含完整明文、无法原样复用」的可观测断言落地，上游拒绝由后端 / 网关用例覆盖。
