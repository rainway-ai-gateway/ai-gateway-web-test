# 密钥收敛（Reencrypt Sweep）模块 - 测试场景概览

## 模块概述

密钥收敛模块提供系统管理员对**密钥静态加密（DB 落盘加密）收敛任务**的触发、历史列表翻查与进度查询能力，对应接口端点：

- `POST /open-api/v1/security/reencrypt-sweeps`（触发收敛任务）
- `GET /open-api/v1/security/reencrypt-sweeps`（**历史任务列表**，本轮新增：过滤 / 分页 / 排序）
- `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`（查询单个任务状态与进度）

模块对库内敏感列（`providers.api_keys`、`api_keys.api_key`）做批量重加密 / 解密；任务**异步执行**，POST 立即返回（body `status=running`），进度经 GET 轮询。

对应接口文档：`design-docs/api-define/OpenAPI接口定义/security.md`；对应原型：`design-docs/prototype-design/pages/security.html`。

| 功能区域 | 说明 |
| --- | --- |
| 触发区 | 变换方向 `mode`（reencrypt / decrypt）/ 扫描范围 `scope`（all / providers / api_keys）/ 预演模式 `dry_run` switch + 「触发任务」按钮 + 409 互斥提示区 |
| 当前运行任务 | 由**列表结果**（`list` 中 `status=running` 项）识别，唯一 `running` 任务横幅；每 **800ms** 轮询 `GET /{task_id}` 展示进度；无则显示「当前无运行中任务，可直接触发。」 |
| 历史任务列表 | **消费新增 `GET /security/reencrypt-sweeps`**：筛选栏（任务状态 / 变换方向 / 扫描范围 / 预演模式 / 开始时间起止）+ **服务端 offset 分页**（`page`/`page_size`，默认 1/20，上限 100）+ **列头排序**（`sort_by` 仅 `started_at`/`task_id`，默认 `started_at desc`）；**9 列**：任务ID / 状态 / 变换方向 / 扫描范围 / 预演 / 触发者(`created_by`) / 开始时间 / 耗时(ms) / 操作；**运行中任务同样出现在列表中** |
| 任务详情 | 右侧抽屉（60% 宽）：task_id / 状态 / 变换方向 / 预演模式 / 扫描范围 / **触发者(`created_by`)** / 活跃密钥ID / 起止时间 / 耗时 / 按 `scope` 分组的统计块 / 错误 |
| 权限 | Feature `FeatureSecurity`（scope=System）；POST 需 `update`、GET 需 `read`；触发与完成均写 operation_logs（列表 GET 只读、不写日志） |

**核心变更依据**：

- 2026-10-10（变更记录 `modifications/2026-10-10-batch-tasks-and-key-reencrypt/ui-code-changes.md`）：v0.11.0 首次引入密钥收敛模块（触发 + 轮询查询 2 接口）。
- 2026-10-11（变更记录 `modifications/2026-10-11-reencrypt-sweeps-list-endpoint/ui-code-changes.md`，后端 commit `50b2866`）：**新增 `GET /security/reencrypt-sweeps` 列表端点**，并对外暴露 `created_by`，同时把三处语义与实现对齐。**上一轮「无列表接口」前提作废**。
- 2026-10-12（变更记录 `modifications/2026-10-12-readonly-admin/ui-code-changes.md`）：**新增「系统管理员（只读）」角色**（后端以 `role` 取代 `is_admin`），只读视角全站隐藏写操作按钮（前端全局指令 `v-has`）；本页隐藏触发区「触发任务」入口，保留历史列表 / 详情只读查看。

本轮语义要点：

- **列表接口取代「本会话累积」**：进入页面即调用 `GET security/reencrypt-sweeps`（默认 `page=1`、`page_size=20`、`sort_by=started_at`、`sort_order=desc`）；历史任务来自服务端（持久化无 TTL），支持过滤 / 服务端分页 / 列头排序。
- **运行中任务出现在列表中**：`status=running` 项也在列表内；其 `summary` 为空对象、`duration_ms=0`、`finished_at` 为空、`error` 为空串（**不是** 0/0/0 统计，也**不是** 耗时 0ms）。
- **`created_by`**：任务触发者名称，未识别时为空串，列表 / 详情显示 `-`；POST 触发响应**不含** `created_by`。
- **异步语义**：POST 立即返回 HTTP 200（body `status=running`），**非 202**；进度经 GET 轮询（UI 每 800ms）。
- **集群级单例互斥**：任一时刻仅一个任务运行；运行中重复触发返回 **409** 并携带持有者 `task_id`（**不排队**，直接轮询该任务）。
- **dry-run 语义标记**：预演任务 `status=succeeded`、`error` 固定为 `"dry_run"`（非失败）；详情以**蓝色语义提示**展示，不走红色失败告警。其余 `failed`（含 `executor lost`）走红色告警。
- **scope 决定统计渲染**：`all` 渲染 providers + api_keys 两张统计块；`providers` / `api_keys` 只渲染对应一张。
- 菜单入口：顶级「系统安全」组（`systemSecurity.admin.list`）下「密钥收敛」（`ReencryptSweep.list`），紧跟「消费者管理」之后（本轮无菜单变更）。

## 配置顺序 / 依赖关系

密钥收敛为**运维 / 安全类模块**，与业务配置无强依赖，但其执行结果影响 providers / api_keys 的落盘形态：

```text
keyring（active 钥）就绪
        │
        ▼
触发收敛任务（mode / scope / dry_run）→ POST 立即返回 running
        │ 触达后刷新列表（新任务以 running 出现在列表） + 800ms 轮询 GET /{task_id}
        ▼
进度（status 翻转）→ 终态 succeeded / failed（完成时 summary / duration_ms / finished_at 落库）
        │
        ▼
列表翻查历史（过滤 / 分页 / 排序），详情按 scope 渲染统计
```

| 关系 | 说明 |
| --- | --- |
| 触发 → keyring active 钥（**前置**） | `active_key_id` 为任务启动时 keyring 的 active 钥；`decrypt` 模式为 0 |
| 单例互斥（**强约束**） | 任一时刻仅一个任务运行；运行中重复触发 409，不排队 |
| 执行实例失联（**接管**） | 心跳超时由后续触发自动接管，旧任务标记 `executor lost` |
| 列表 → 运行中横幅（**识别**） | 运行中横幅由列表 `list` 中 `status=running` 项识别；无则显示空态 |

## 测试前置条件

- **RS-T-01 ~ RS-T-05**：管理员具备 `FeatureSecurity` 权限；keyring 已就绪（存在 active 钥）；环境**当前无运行中任务**
- **RS-T-02**：存在可被扫描的 providers / api_keys 数据（否则任务可能瞬间完成，`summary` 计数为小值）
- **RS-T-03**：已存在一个运行中任务（可先触发一个长任务，或在轮询期间重复触发）
- **RS-P-01 ~ RS-P-05**：本会话已触发至少一个任务，或列表返回中已有 `status=running` 项
- **RS-L-01 ~ RS-L-11**：历史列表中存在足量任务记录（≥1 页，最好 ≥20 条以验证分页与排序）；可构造 422 时间区间
- **RS-D-01 ~ RS-D-09**：列表中存在终态任务；可构造 `failed` / `dry_run` / `decrypt` / 不同 `scope` 样本；可构造 404

## 测试数据准备

- **运行中任务**：触发后处于 `running`，且出现在列表中（`summary={}` / `duration_ms=0` / `finished_at=""`）→ RS-T-03 / RS-P-01 / RS-L-02 / RS-L-11 / RS-D-03
- **成功任务**：`status=succeeded`，含 `summary` 双分组、`duration_ms` / `finished_at` 落库 → RS-P-03 / RS-D-02
- **失败任务**：`status=failed`，`error` 含 `executor lost` → RS-D-04
- **预演任务**：`dry_run=true`、`status=succeeded`、`error="dry_run"`，`rewritten` 为「将要重写」数 → RS-T-04 / RS-D-05
- **解密任务**：`mode=decrypt`，`active_key_id=0` → RS-T-05 / RS-D-07
- **单表 scope 任务**：`scope=providers` / `scope=api_keys`，`summary` 只含对应表键 → RS-D-06
- **触发者**：`created_by` 为 `admin` / `operator-chen` 等；另构造空串样本 → RS-L-02 / RS-D-01
- **分页数据**：≥20 条历史任务（可多次触发或预置）→ RS-L-07 / RS-L-08
- **只读账号**：`role=system_admin_readonly`（与原「系统管理员」同权限面，仅隐藏写操作入口）→ RS-RO-01 ~ RS-RO-03

**字段取值约定**（以 `security.md` §1 / §3 为准）：

- **`status`**：`running` / `succeeded` / `failed`（`failed` 含 `executor lost` 执行实例失联被接管）。
- **`mode`**：`reencrypt`（默认，非目标形态行重写为 active 钥密文）/ `decrypt`（全部密文行解密为明文，仅用于回滚预案）。
- **`dry_run`**：`true` 只扫描统计、不写库；默认 `false`。
- **`scope`**：`all` / `providers` / `api_keys`；默认 `all`。
- **`active_key_id`**：0–255；`decrypt` 模式为 0。
- **`created_by`**：任务触发者名称；未识别时为空串。
- **`summary`**：`{ providers: {scanned, rewritten, skipped}, api_keys: {scanned, rewritten, skipped} }`；**完成时按表分组落库，running 时为空对象 `{}`**。
- **`duration_ms`**：≥0；**完成时写入最终耗时，running 时为 0**。
- **`error`**：`failed` 时为可归因错误；**dry-run 成功任务固定为 `"dry_run"`**；其余为空。
- **分页 / 排序**：`page`/`page_size` 默认 1/20（上限 100）；`sort_by` 有效字段仅 `started_at`、`task_id`，其他值回落默认；`sort_order` 仅 `asc`/`desc`，默认 `desc`。
