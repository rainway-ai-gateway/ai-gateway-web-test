### RS-T-01：触发区参数与默认值

**功能模块**: 密钥收敛触发
**优先级**: P1
**用例编号**: RS-T-01
**生命周期**: 已评审
**OpenAPI**: `POST /open-api/v1/security/reencrypt-sweeps`

#### 前置条件

1. 以系统管理员登录，具备 `FeatureSecurity`（scope=System）权限。
2. 「系统安全 → 密钥收敛」（`ReencryptSweep.list`）菜单可达。

#### 测试步骤

1. 进入「密钥收敛」页面。
2. 核对触发区卡片标题与三个参数控件。
3. 核对默认值。

#### 预期结果

1. 触发区卡片标题为「触发收敛任务」。
2. 含三个参数：「变换方向」（Select）、「扫描范围」（Select）、「预演模式」（Switch）与「触发任务」按钮。
3. 默认值：变换方向 = 「重加密（reencrypt）」；扫描范围 = 「全部（all）」；预演模式 = 关闭（「否」）。
4. 「变换方向」选项为「重加密（reencrypt）」「解密（decrypt）」；「扫描范围」选项为「全部（all）」「仅 providers 表（providers）」「仅 api_keys 表（api_keys）」。

#### 测试数据

- **`mode`**：`reencrypt`（默认）/ `decrypt`
- **`scope`**：`all`（默认）/ `providers` / `api_keys`
- **`dry_run`**：默认 `false`

### RS-T-02：触发成功异步返回与进入轮询

**功能模块**: 密钥收敛触发
**优先级**: P0
**用例编号**: RS-T-02
**生命周期**: 已评审
**OpenAPI**: `POST /open-api/v1/security/reencrypt-sweeps`

#### 前置条件

1. 环境当前**无运行中任务**。
2. keyring 已就绪（存在 active 钥）。

#### 测试步骤

1. 保持默认参数，点击「触发任务」。
2. 抓取 POST 请求与响应。
3. 观察提示、列表刷新与运行中任务横幅。
4. 观察随后的轮询请求。

#### 预期结果

1. 发起 `POST /open-api/v1/security/reencrypt-sweeps`。
2. **异步语义**：POST **立即返回** HTTP 200（`ErrNum=200`），body `Data.status=running`，**非 202**；`Data` 含 `task_id`、`mode`、`dry_run`、`scope`、`active_key_id`（**不含** `created_by` / `summary`）。
3. 触发成功提示「任务已触发，task_id: {id}，轮询进度中」。
4. **触发后刷新列表**：触发成功后 `page` 复位为 **1** 并重取 `GET /open-api/v1/security/reencrypt-sweeps`；新任务以 `status=running` 出现在列表**首位**（默认 `started_at desc`，最新启动在前）。
5. 运行中任务卡片展示该任务，并按 **800ms** 间隔轮询 `GET /open-api/v1/security/reencrypt-sweeps/{task_id}` 刷新进度。
6. 轮询请求路径参数为 POST 返回的 `task_id`。

#### 测试数据

- **成功提示**：`任务已触发，task_id: {id}，轮询进度中`
- **轮询间隔**：800ms
- **触发后列表参数**：`page=1`（其余沿用当前筛选 / 排序）

### RS-T-03：运行中重复触发 409 单例互斥

**功能模块**: 密钥收敛触发
**优先级**: P0
**用例编号**: RS-T-03
**生命周期**: 已评审
**OpenAPI**: `POST /open-api/v1/security/reencrypt-sweeps`（409）

#### 前置条件

1. 已存在一个运行中任务（`status=running`）。

#### 测试步骤

1. 在运行中任务未完成时，再次点击「触发任务」。
2. 观察提示区 / Toast 与请求结果。

#### 预期结果

1. 触发被拒绝，返回 **409**；页面展示互斥提示「409 已有任务运行中，task_id: {id}，请等待完成；可直接轮询该任务，不排队。」（`{id}` 为持有者 `task_id`，从响应归因中提取）。
2. 提示明确「**不排队**」，引导直接轮询该任务；**不**新建任务、**不**改变既有运行中任务。
3. 运行中任务横幅仍为原任务，继续轮询。

#### 测试数据

- **409 文案**：`409 已有任务运行中，task_id: {id}，请等待完成；可直接轮询该任务，不排队。`
- **约束**：集群级单例互斥，任一时刻仅一个任务运行

### RS-T-04：预演模式 dry_run

**功能模块**: 密钥收敛触发
**优先级**: P1
**用例编号**: RS-T-04
**生命周期**: 已评审
**OpenAPI**: `POST /open-api/v1/security/reencrypt-sweeps`（`dry_run`）

#### 前置条件

1. 环境当前无运行中任务。

#### 测试步骤

1. 打开「预演模式」Switch。
2. 核对 Switch 文案与提示。
3. 点击「触发任务」。
4. 核对 POST 请求体与结果统计。

#### 预期结果

1. 打开后 Switch 展示「是（仅统计，不落库）」，关闭为「否」；提示为「开启后仅统计"将要重写"的行数，不落库」。
2. POST 请求体携带 `dry_run=true`。
3. 任务详情 `summary.rewritten` 为「**将要重写**」的行数（非实际写入数）；库内密文形态**不变**。
4. 预演任务完成后 `status=succeeded`，且 `error` 固定为 **`"dry_run"`**（**非失败语义标记**）；详情以**蓝色语义提示**展示（详见 RS-D-05），**不**走红色失败告警。

#### 测试数据

- **`dry_run`**：`true`（仅统计，不落库）/ `false`（默认）
- **提示文案**：`开启后仅统计"将要重写"的行数，不落库`
- **完成语义**：`status=succeeded`、`error="dry_run"`

### RS-P-01：运行中横幅与 800ms 轮询进度

**功能模块**: 密钥收敛进度
**优先级**: P0
**用例编号**: RS-P-01
**生命周期**: 已评审
**OpenAPI**: `GET /open-api/v1/security/reencrypt-sweeps`、`GET /open-api/v1/security/reencrypt-sweeps/{task_id}`

#### 前置条件

1. 列表返回中存在一个 `status=running` 的任务（或本会话触发后处于 `running`）。

#### 测试步骤

1. 进入页面，核对「当前运行任务」卡片。
2. 抓取连续多次轮询请求并核对路径与间隔。
3. 观察卡片内状态、耗时与统计块的展示。

#### 预期结果

1. 「当前运行任务」卡片标题为「当前运行任务」，展示**由列表结果识别**的 `status=running` 任务（`list` 中无 running 时以本地 `activeTask` 兜底）。
2. 卡片内状态 Tag 为「运行中」，其后紧跟「轮询中…」文本。
3. 每 **800ms** 轮询 `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`（路径参数为该任务 `task_id`）；同一时刻「当前运行任务」卡片仅展示**唯一** running 任务。

5. 耗时展示为 `-`（running 时未落库，**不**显示 `0 ms`）。

#### 测试数据

- **轮询接口**：`GET /open-api/v1/security/reencrypt-sweeps/{task_id}`
- **轮询间隔**：800ms
- **运行中占位**：`任务运行中，统计将于完成后写入。`

### RS-P-03：任务完成停止轮询并刷新列表

**功能模块**: 密钥收敛进度
**优先级**: P1
**用例编号**: RS-P-03
**生命周期**: 已评审
**OpenAPI**: `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`、`GET /open-api/v1/security/reencrypt-sweeps`

#### 前置条件

1. 本会话已触发任务（或列表中存在 running 任务），且任务逐渐完成。

#### 测试步骤

1. 等待运行中任务进入终态（`succeeded` / `failed`）。
2. 观察轮询是否停止、列表是否刷新。
3. 核对终态任务在列表中的展示。

#### 预期结果

1. 轮询响应 `status` 翻转为 `succeeded` / `failed` 后，**停止轮询**（清除定时器），本地 `activeTask` 清空。
2. 完成时 `summary` / `duration_ms` / `finished_at` 已**落库**；立即重取 `GET /open-api/v1/security/reencrypt-sweeps` 使列表落定。
3. 该任务在列表中展示为终态：状态 Tag 为「成功」/「失败」；`耗时(ms)` 显示实际毫秒数（不再为 `-`）。
4. 「当前运行任务」卡片回到空态「当前无运行中任务，可直接触发。」，或切换到下一个（若有）运行中任务。

#### 测试数据

- **终态**：`succeeded` / `failed`（`failed` 含 `executor lost`）
- **完成后落库**：`summary` 按表分组、`duration_ms` 最终耗时、`finished_at` 有值

### RS-P-04：轮询就地刷新列表与详情

**功能模块**: 密钥收敛进度
**优先级**: P1
**用例编号**: RS-P-04
**生命周期**: 已评审
**OpenAPI**: `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`

#### 前置条件

1. 列表中存在 `status=running` 任务，页面已加载列表并处于轮询中。
2. 已对该任务设置若干筛选条件（如「任务状态 = 全部」并修改排序 / 页码）。

#### 测试步骤

1. 在轮询进行中，观察列表中该任务行的更新方式。
2. 打开该 `running` 任务的详情抽屉，观察抽屉是否随轮询刷新。
3. 观察筛选栏控件值、页码与排序是否被轮询改变。

#### 预期结果

1. 轮询命中列表中该 `task_id` 时，**按 task_id 就地合并**更新该行（去重合并，非整表重取），不新增重复行。
2. 若详情抽屉正打开该任务，抽屉内 `detail` 随轮询**同步刷新**（不关闭抽屉、不清空数据）。
3. 运行中横幅（`activeTask`）随轮询同步刷新。
4. 轮询**不改变**筛选栏控件值、页码与排序，用户操作上下文保持。

#### 测试数据

- **合并键**：`task_id`（就地更新，非整表重取）
- **保持项**：筛选项 / 页码 / 排序不变

#### 补充说明

- **抽屉初值可观测性**：打开抽屉时 `onDetail(row)` 先用**列表行数据**渲染，随后被轮询结果覆盖；产品轮询周期为 800ms（`pollInterval`）且轮询自首次列表加载即开始，因此「列表行初值」的窗口不足一个轮询周期。自动化校验该初值时须给详情接口响应加延迟（如 2000ms）把窗口拉开，属时序脆弱点处置，不改用例语义。

### RS-P-05：运行中横幅进度与接口数据一致性

**功能模块**: 密钥收敛进度
**优先级**: P1
**用例编号**: RS-P-05
**生命周期**: 已评审
**OpenAPI**: `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`

#### 前置条件

1. 列表中存在一个 `status=running` 任务，且「当前运行任务」横幅正在展示该任务。
2. 管理员具备 `FeatureSecurity`（scope=System）权限。
3. 可抓取轮询 `GET /open-api/v1/security/reencrypt-sweeps/{task_id}` 的响应 `Data`。

#### 测试数据参考（接口 GET /open-api/v1/security/reencrypt-sweeps/{task_id} 返回体示例）

```json
{
  "ErrNum": 200,
  "ErrMsg": "success",
  "Data": {
    "task_id": "rsp-01J9AB7K9M",
    "status": "running",
    "mode": "reencrypt",
    "dry_run": false,
    "scope": "all",
    "active_key_id": 2,
    "created_by": "admin",
    "started_at": "2026-10-10T09:30:00Z",
    "finished_at": "",
    "duration_ms": 0,
    "summary": {},
    "error": ""
  }
}
```

#### 测试步骤

1. 记录横幅展示的任务 `task_id`。
2. 抓取该 `task_id` 的轮询响应 `Data`。
3. 逐字段比对横幅字段展示与 `Data`。
4. 核对横幅统计块的展示（`summary` 为空对象时的占位）。

#### 预期结果

布局说明：运行中横幅由一组字段行（任务ID / 状态 / 变换方向 / 预演模式 / 扫描范围 / 触发者 / 活跃密钥ID / 起止时间 / 耗时）与按 `scope` 渲染的统计块组成；`running` 时 `summary` 为空对象，统计块展示占位。

字段比对（校验方式 = 文本一致/数值一致/时间戳转换一致，与接口返回 JSON 一致）：

- **任务ID**（文本一致）：横幅「任务ID」= `Data.task_id`
- **status**（文本一致，含枚举映射）：横幅状态 Tag 文案 = `Data.status` 映射，`running` 时 Tag 颜色为 primary，并展示「轮询中…」
- **mode**（文本一致，含枚举映射）：横幅「变换方向」= `Data.mode` 映射（`reencrypt`=重加密、`decrypt`=解密）
- **dry_run**（文本一致，含枚举映射）：横幅「预演模式」= `Data.dry_run` 映射（`true`=是（仅统计，不落库）、`false`=否）
- **scope**（文本一致，含枚举映射）：横幅「扫描范围」= `Data.scope` 映射（`all`=全部、`providers`=仅 providers 表、`api_keys`=仅 api_keys 表）
- **created_by**（文本一致）：横幅「触发者」= `Data.created_by`；空串显示 `-`
- **active_key_id**（数值一致）：横幅「活跃密钥ID」= `Data.active_key_id`
- **started_at / finished_at**（时间戳转换一致）：横幅「开始 / 结束时间」= `Data.started_at / Data.finished_at`；`finished_at` 空显示 `-`
- **duration_ms**（数值一致）：`running` 时横幅「耗时」展示 `-`（不展示 `Data.duration_ms=0`）
- **summary 占位**（文本一致）：`Data.summary` 为空对象时，横幅统计块展示「任务运行中，统计将于完成后写入。」（**不**展示计数）

一致性比对矩阵：

| UI 展示项 | 接口字段 | 校验方式 | 通过标准 |
| --- | --- | --- | --- |
| 横幅·任务ID | Data.task_id | 文本一致 | 与接口相同 |
| 横幅·状态 | Data.status | 文本一致（映射） | running → 运行中 + 「轮询中…」 |
| 横幅·变换方向 | Data.mode | 文本一致（映射） | reencrypt/decrypt → 重加密/解密 |
| 横幅·预演模式 | Data.dry_run | 文本一致（映射） | true/false → 是（仅统计，不落库）/否 |
| 横幅·扫描范围 | Data.scope | 文本一致（映射） | all/providers/api_keys → 全部/仅 providers 表/仅 api_keys 表 |
| 横幅·触发者 | Data.created_by | 文本一致 | 与接口相同；空串显示 `-` |
| 横幅·活跃密钥ID | Data.active_key_id | 数值一致 | 与接口相等 |
| 横幅·开始 / 结束时间 | Data.started_at / Data.finished_at | 时间戳转换一致 | 与接口一致；`finished_at` 空显示 `-` |
| 横幅·耗时 | Data.duration_ms | 数值一致 | running 时显示 `-`（非 0 ms） |
| 横幅·统计块 | Data.summary | 文本一致 | running 空对象显示占位文案 |

**整体预期**：

1. 轮询 `GET /open-api/v1/security/reencrypt-sweeps/{task_id}` 返回 200。
2. 横幅展示的字段值与轮询接口 `Data` 一一对应，无遗漏、无错配。
3. `running` 时 `summary` 为空对象、`duration_ms=0`、`finished_at` 为空，横幅据此展示占位与 `-`，**不**编造统计值、**不**显示耗时 0。
4. 状态 / 变换方向 / 预演模式 / 扫描范围的展示遵循 i18n `security.*` 枚举映射。

#### 补充说明

- 本用例对**运行中**横幅字段与轮询接口数据逐项比对，与 RS-L-11（列表一致性）、RS-D-09（详情一致性）互为运行态 / 列表态 / 详情态的一致性子集。
