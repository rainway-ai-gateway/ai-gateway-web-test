### RS-D-01：打开详情抽屉

**功能模块**: 密钥收敛详情
**优先级**: P1
**用例编号**: RS-D-01
**生命周期**: 已评审
**OpenAPI**: `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`

#### 前置条件

1. 列表中存在至少一条终态任务。
2. 管理员具备 `FeatureSecurity`（scope=System）权限。

#### 测试步骤

1. 在历史任务列表中点击某行的「详情」。
2. 观察抽屉标题、宽度与打开动效。
3. 核对抽屉内的字段区块与统计块。

#### 预期结果

1. 右侧抽屉打开，标题为「任务详情」，宽度为 **60%**。
2. 抽屉内依次展示字段：任务ID、状态、变换方向、预演模式、扫描范围、**触发者**、活跃密钥ID、开始 / 结束时间、耗时。
3. 下方按 `scope` 渲染统计区块（`scope=all` 时为「providers 表收敛统计」「api_keys 表收敛统计」两块），各含已扫描 / 已重写 / 已跳过三个计数与进度条。
4. 「详情」以列表该行的 `task_id` 打开（与列表「操作」列一致，详见 RS-L-11）。

#### 测试数据

- **抽屉标题**：`任务详情`
- **抽屉宽度**：60%
- **字段标签**：`任务ID` / `状态` / `变换方向` / `预演模式` / `扫描范围` / `触发者` / `活跃密钥ID` / `开始 / 结束时间` / `耗时`

### RS-D-02：详情字段与双分组统计一致

**功能模块**: 密钥收敛详情
**优先级**: P0
**用例编号**: RS-D-02
**生命周期**: 已评审
**OpenAPI**: `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`

#### 前置条件

1. 列表中存在一条 `status=succeeded` 且 `scope=all` 的任务，其 `summary` 含 `providers` 与 `api_keys` 两个分组。

#### 测试步骤

1. 点击该任务「详情」，抓取 `GET /open-api/v1/security/reencrypt-sweeps/{task_id}` 响应。
2. 逐字段核对抽屉展示与响应 `Data`。
3. 核对两个统计区块的计数与进度条百分比。

#### 预期结果

1. 抽屉字段与响应一致：任务ID = `task_id`；状态展示「成功」；变换方向展示「重加密」；预演模式展示「否」；扫描范围展示「全部」；触发者 = `created_by`（空串显示 `-`）；开始 / 结束时间 = `started_at / finished_at`；耗时 = `{duration_ms} ms`。
2. **双分组统计一致**：`providers 表收敛统计` 的已扫描 / 已重写 / 已跳过 = `summary.providers.scanned / rewritten / skipped`；`api_keys 表收敛统计` 的对应计数 = `summary.api_keys.scanned / rewritten / skipped`。
3. 进度条百分比与 `scanned / (scanned + skipped)` 比例一致（分母为 0 时百分比为 0，不报错）。
4. `status=succeeded` 时不出现错误 Alert（`error` 为空）。

#### 测试数据

- **`summary`**：`{ providers: {scanned, rewritten, skipped}, api_keys: {scanned, rewritten, skipped} }`
- **耗时文案**：`{ms} ms`

#### 测试步骤

2. 观察状态字段的展示。

### RS-D-04：失败任务展示错误归因

**功能模块**: 密钥收敛详情
**优先级**: P1
**用例编号**: RS-D-04
**生命周期**: 已评审
**OpenAPI**: `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`

#### 前置条件

1. 存在一条 `status=failed` 的任务，其 `error` 非空（如含 `executor lost`）。

#### 测试步骤

1. 打开该 `failed` 任务详情。
2. 核对状态展示与错误区块。
3. 核对错误内容不含密钥 / 密文材料。

#### 预期结果

1. 状态展示「失败」Tag（红色 / error）。
2. 抽屉底部出现错误 Alert（`type=error`，带图标），文案为「错误：{error}」，其中 `error` 为响应原值（`executor lost` 可读）。
3. 错误信息**不含任何密钥或密文材料**。
4. `failed` 且 `error` **不等于** `"dry_run"`（`error="dry_run"` 属成功预演语义，走 RS-D-05 蓝色提示，**不**走红色告警）。

#### 测试数据

- **失败文案**：`失败`
- **错误前缀**：`错误：`
- **归因样例**：`executor lost`

### RS-D-05：预演任务蓝色语义提示

**功能模块**: 密钥收敛详情
**优先级**: P1
**用例编号**: RS-D-05
**生命周期**: 已评审
**OpenAPI**: `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`

#### 前置条件

1. 存在一条 `dry_run=true`、`status=succeeded` 的任务，其 `error` 固定为 `"dry_run"`。

#### 测试步骤

1. 打开该预演任务详情。
2. 核对状态展示与错误区展示。
3. 核对统计 `rewritten` 的语义说明。

#### 预期结果

1. 状态展示「成功」Tag（success），**非**失败。
2. 底部**不**出现红色错误 Alert；改以**蓝色语义提示**展示（浅蓝底、蓝色文字），文案为「预演任务（dry_run）：rewritten 为"将要重写"的行数，未落库。」（对应 i18n `security.dryRunNote`）。
3. 统计块的 `rewritten` 为「**将要重写**」的行数（未落库）；库内密文形态未变。
4. 蓝色提示与红色失败告警**互斥**：同一抽屉不同时出现两者。

#### 测试数据

- **`error`**：`dry_run`（成功预演语义标记）
- **蓝色提示文案**：`预演任务（dry_run）：rewritten 为"将要重写"的行数，未落库。`

### RS-D-06：scope 决定统计块渲染范围

**功能模块**: 密钥收敛详情
**优先级**: P1
**用例编号**: RS-D-06
**生命周期**: 已评审
**OpenAPI**: `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`

#### 前置条件

1. 存在 `scope=all`、`scope=providers`、`scope=api_keys` 三条任务（`succeeded`）。

#### 测试步骤

1. 分别打开三条任务的详情抽屉。
2. 核对统计区块的数量与标题。
3. 核对未命中表是否残留空块。

#### 预期结果

1. `scope=all` → 渲染「providers 表收敛统计」与「api_keys 表收敛统计」**两块**。
2. `scope=providers` → **仅**渲染「providers 表收敛统计」一块。
3. `scope=api_keys` → **仅**渲染「api_keys 表收敛统计」一块。
4. 未命中范围的表**不渲染空块**（不出现空白统计区）。
5. 各块计数与后端 `summary` 对应键一致（`summary` 可能只含被扫描表键）。

#### 测试数据

- **`scope` 映射**：`all` → providers + api_keys；`providers` → 仅 providers；`api_keys` → 仅 api_keys
- **块标题**：`providers 表收敛统计` / `api_keys 表收敛统计`

### RS-D-07：活跃密钥 ID 展示

**生命周期**: 已评审

### RS-D-09：详情接口数据与页面展示一致性

**功能模块**: 密钥收敛详情
**优先级**: P0
**用例编号**: RS-D-09
**生命周期**: 已评审
**OpenAPI**: `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`

#### 前置条件

1. 列表中存在一条字段完整的终态任务（`status=succeeded`、`scope=all`，`summary` 含 `providers` 与 `api_keys` 两个分组，`started_at` / `finished_at` 均有值，`created_by` 非空）。
2. 管理员具备 `FeatureSecurity`（scope=System）权限。

#### 测试数据参考（接口 GET /open-api/v1/security/reencrypt-sweeps/{task_id} 返回体示例）

```json
{
  "ErrNum": 200,
  "ErrMsg": "success",
  "Data": {
    "task_id": "rsp-01J8XQ7K9M",
    "status": "succeeded",
    "mode": "reencrypt",
    "dry_run": false,
    "scope": "all",
    "active_key_id": 2,
    "created_by": "admin",
    "started_at": "2026-10-05T10:00:00Z",
    "finished_at": "2026-10-05T10:00:08Z",
    "duration_ms": 8300,
    "summary": {
      "providers": { "scanned": 120, "rewritten": 118, "skipped": 2 },
      "api_keys": { "scanned": 2400, "rewritten": 2390, "skipped": 10 }
    },
    "error": ""
  }
}
```

#### 测试步骤

1. 在历史任务列表中点击该任务「详情」，打开右侧抽屉。
2. 抓取 `GET /open-api/v1/security/reencrypt-sweeps/{task_id}` 响应 `Data`。
3. 逐字段比对抽屉展示值与 `Data`。
4. 核对两个统计区块的计数与进度条百分比。

#### 预期结果

布局说明：详情抽屉由一组字段行（任务ID / 状态 / 变换方向 / 预演模式 / 扫描范围 / 触发者 / 活跃密钥ID / 开始 / 结束时间 / 耗时）与按 `scope` 渲染的统计区块组成，底部按需展示错误 Alert 或预演蓝色提示。

字段比对（校验方式 = 文本一致/数值一致/时间戳转换一致，与接口返回 JSON 一致）：

- **task_id**（文本一致）：抽屉「任务ID」= `Data.task_id`（原样，为空显示 `-`）
- **status**（文本一致，含枚举映射）：状态 Tag 文案 = `Data.status` 映射（`running`=运行中、`succeeded`=成功、`failed`=失败），Tag 颜色随之（primary/success/error）
- **mode**（文本一致，含枚举映射）：变换方向 = `Data.mode` 映射（`reencrypt`=重加密、`decrypt`=解密）
- **dry_run**（文本一致，含枚举映射）：预演模式 = `Data.dry_run` 映射（`true`=是（仅统计，不落库）、`false`=否）
- **scope**（文本一致，含枚举映射）：扫描范围 = `Data.scope` 映射（`all`=全部、`providers`=仅 providers 表、`api_keys`=仅 api_keys 表）
- **created_by**（文本一致）：触发者 = `Data.created_by`；为空显示 `-`
- **active_key_id**（数值一致）：活跃密钥ID = `Data.active_key_id`；为空显示 `-`
- **started_at / finished_at**（时间戳转换一致）：开始 / 结束时间 = `Data.started_at / Data.finished_at`；为空显示 `-`
- **duration_ms**（数值一致）：耗时 = `{duration_ms} ms`（`running` 时显示 `-`，**不**显示 0 ms）
- **summary.providers.scanned / rewritten / skipped**（数值一致）：providers 表收敛统计的已扫描 / 已重写 / 已跳过逐值等于接口值
- **summary.api_keys.scanned / rewritten / skipped**（数值一致）：api_keys 表收敛统计的已扫描 / 已重写 / 已跳过逐值等于接口值
- **error**（文本一致）：`failed` 非空时底部展示红色错误 Alert（文案「错误：{error}」）；`error="dry_run"` 时展示蓝色预演提示（不展示红色 Alert）；其余 `error` 为空时不出现提示

一致性比对矩阵：

| UI 展示项 | 接口字段 | 校验方式 | 通过标准 |
| --- | --- | --- | --- |
| 详情·任务ID | Data.task_id | 文本一致 | 与接口相同；空显示 `-` |
| 详情·状态 | Data.status | 文本一致（映射） | running/succeeded/failed → 运行中/成功/失败 |
| 详情·变换方向 | Data.mode | 文本一致（映射） | reencrypt/decrypt → 重加密/解密 |
| 详情·预演模式 | Data.dry_run | 文本一致（映射） | true/false → 是（仅统计，不落库）/否 |
| 详情·扫描范围 | Data.scope | 文本一致（映射） | all/providers/api_keys → 全部/仅 providers 表/仅 api_keys 表 |
| 详情·触发者 | Data.created_by | 文本一致 | 与接口相同；空显示 `-` |
| 详情·活跃密钥ID | Data.active_key_id | 数值一致 | 与接口相等；空显示 `-` |
| 详情·开始 / 结束时间 | Data.started_at / Data.finished_at | 时间戳转换一致 | 与接口一致；空显示 `-` |
| 详情·耗时 | Data.duration_ms | 数值一致 | `{duration_ms} ms`；running 显示 `-` |
| 详情·providers 统计 | Data.summary.providers.* | 数值一致 | scanned/rewritten/skipped 逐值相等 |
| 详情·api_keys 统计 | Data.summary.api_keys.* | 数值一致 | scanned/rewritten/skipped 逐值相等 |
| 详情·错误 / 预演提示 | Data.error | 文本一致 | failed 非空→红色 Alert；`dry_run`→蓝色提示；空→无提示 |

**整体预期**：

1. 打开详情调用 `GET /open-api/v1/security/reencrypt-sweeps/{task_id}`，接口返回 200。
2. 抽屉展示的所有字段值均与接口返回的 `Data` 一一对应，无遗漏、无错配。
3. 状态 / 变换方向 / 预演模式 / 扫描范围的展示遵循 i18n `security.*` 枚举映射，Tag 颜色与状态语义一致。
4. 统计区块按 `scope` 渲染，计数与进度条比例一致（分母为 0 时百分比为 0，不报错）。
5. `error` 语义分流正确：`failed` 非空→红色错误 Alert；`error="dry_run"`→蓝色预演提示；其余状态不出现提示。

#### 补充说明

- 本用例对详情**全部字段**与接口 `Data` 逐项比对，与 RS-D-02（侧重字段展示与 `summary` 双分组统计一致）互补；条件字段（运行中 / 失败 / 预演 / scope / 解密）专项见 RS-D-03 ~ RS-D-07。
- 与 RS-L-11（列表一致性）、RS-P-05（运行中横幅一致性）互为详情态 / 列表态 / 运行态的一致性子集。
- **进度条百分比展示特例**：产品用 iView `Progress`，`percent == 100` 时组件在 `created()` 把状态置为 `success`，文案位渲染**勾选图标**（`ivu-icon-ios-checkmark-circle`）而非「100%」文本。因此自动化读取百分比时，「出现勾选图标」等价于 `100`（本文档 RS-D-09 数据中 `api_keys: 2400/(2400+10)` 即 100% 场景）。
