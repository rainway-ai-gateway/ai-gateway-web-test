# 数据报表模块 - 测试场景概览

## 模块概述

数据报表（Report）模块为**只读查询**模块，面向系统管理员展示 AI 网关的请求量、错误、Token、延迟、成本，以及本期新增的**缓存、流量镜像、意图分类**三组指标。当前版本聚焦五个查询端点：

|功能区域|说明|
|---|---|
|总览指标|请求总量、错误率、Token、延迟、成本，以及缓存命中率 / 镜像命中 / 意图分类三张新指标卡|
|时序数据|QPS、Token 吞吐、延迟、TTFT / TPOT、成本，以及新增的缓存 Token（cache_read / cache_write 双序列）|
|维度排行|TopN 维度排行，新增 `ai_intent_answer` / `ai_cache_status` / `mirror_hit` 三个维度（两后端均可用）|
|占比分布|饼图占比，新增上述三个维度；空值维度归一为 `unknown`|
|日志明细|明细表分页，新增「缓存 / 镜像 / 意图答案」三列、五个新过滤项；详情抽屉覆盖接口全部 49 字段（38 个字段项 + 4 个 JSON 区块）|

模块本次变更范围为 **#5「报表缓存 / 镜像 / 意图新字段」**（见 [ui-code-changes.md](../../../ai-gateway-web/design-docs/modifications/2026-09-27-ai-cache-mirror-intent/ui-code-changes.md)）：明细表 +10 列、聚合表 +3 维度，报表消费 ai-cache / 流量镜像 / ai-intent 三组访问日志字段。

> 本批次（2026-10-03，#5「报表 · 3 新维度 Doris 对齐」，见 [ui-code-changes.md](../../../ai-gateway-web/design-docs/modifications/2026-10-03-ai-context-cache-semantic/ui-code-changes.md) §2.6 / §3.2 / §4.2 / §5）：三个新维度 `ai_intent_answer` / `ai_cache_status` / `mirror_hit` 由「仅 MySQL（Doris 返回 422）」改为**两后端均可用**，筛选栏 Doris 门控橙色提示（i18n `report.dorisNewDimHint`）与 `unneedTips` 静默逻辑一并移除；`mirror_hit` 排行 `0`/`1`、分布 `"0"`/`"1"` 桶语义不变。

> 本批次（2026-10-14，#6「报表图表维度下钻与过滤栏清理」，见 [ui-code-changes.md](../../../ai-gateway-web/design-docs/modifications/2026-10-14-report-dimension-drilldown/ui-code-changes.md) §1 / §3 / §7）：总览图表暴露维度下钻——排行图加 10 项维度下拉、两个饼图（标题改「占比 / 分布」）各加 7 项维度下拉、过滤栏行尾新增「拆分维度」（点「查询」生效，QPS / Token / 延迟拆多序列）；总览过滤栏移除「缓存状态 / 镜像命中 / 意图答案」3 个未接线死控件（明细工具栏同名过滤不受影响）。

查询后端通过 `[Report].Backend` 配置切换 **MySQL（轻量形态，log-reader `mod_log_mysql` 插件落库）** 或 **Doris（标准形态，既有 Kafka → Doris 链路）**，同一套接口两种后端结构一致。三个新维度**两后端均可用**；前置：接口层已放开两后端，但需 Doris 侧表结构先行升级（UI 仅移除前端禁用逻辑，不负责后端数据可用性）。

## 配置顺序

报表是**末端消费模块**，本身不产生数据；其数据依赖上游流量产生与日志落库链路。测试前需按以下顺序准备：

```text
业务流量（Entity 组织 → API-Key → 路由规则）
        │
        ▼
BFE 访问日志落库（明细表 bfe_ai_request_log）
        │
        ├── 明细表扩列（+10 列：ai_cache_status / mirror_hit / mirror_cluster / ai_intent_* 等）
        └── 聚合 JOB 写聚合表 bfe_ai_metrics_1m（+3 维度：ai_intent_answer / ai_cache_status / mirror_hit）
        │
        ▼
报表查询 Report（MySQL 轻量 / Doris 标准）
        │
        ▼
总览指标 → 时序 → 排行 / 占比分布 → 日志明细
```

- **总览 / 时序**：读聚合表合计（`logs_total` 走明细表 `COUNT(*)`；缓存/镜像/意图三组计数走明细表条件 `COUNT`）
- **排行 / 分布**：`dimension` 决定分组列，新维度依赖聚合表新维度列已上线并积累数据
- **日志明细**：读明细表投影，新列与新过滤项在两后端均可用（与排行 / 分布的维度查询能力无关）
- **数据可得性**：新字段自各链路上线后逐步积累，此前历史数据对应字段为空串 / 0；分钟聚合表不回填历史
