### RP-O-01：进入报表总览加载指标卡

**功能模块**: 总览指标卡  
**优先级**: P0  
**用例编号**: RP-O-01  
**设计依据**: `report.md` §2.1；`index.vue` `mounted()` / `buildFilterParams()`；`Overview.vue` `load()` / `metric-cards`

#### 前置条件

- 以系统管理员（FeatureReport ReadAll）身份登录
- 查询后端为 MySQL；默认时间窗口（近 1 小时）内有访问日志
- 浏览器 DevTools Network 面板已打开

#### 测试步骤

1. 从侧边栏进入「数据报表」页面
2. 观察默认激活的页签
3. 观察页面加载时发起的网络请求
4. 观察指标卡区域渲染结果

#### 预期结果

1. 页面标题 / 菜单展示「数据报表」，默认激活「总览」页签（`activeTab = 'overview'`）
2. `Overview` 挂载后（`mounted()` 中 `$nextTick`）并发发起 8 个请求，均携带 `start` / `end`（默认近 1 小时，秒级时间戳）：
   - `GET report/overview`
   - `GET report/timeseries?metric=qps`
   - `GET report/timeseries?metric=tokens`
   - `GET report/timeseries?metric=latency`
   - `GET report/timeseries?metric=cache_tokens`
   - `GET report/rankings?dimension=model&limit=10`
   - `GET report/distribution?dimension=status`
   - `GET report/rankings?dimension=provider&limit=10`
3. 8 张指标卡按固定顺序渲染：请求总量 / 错误总量 / Token用量 / 平均延迟 / 费用 / 缓存命中率 / 镜像命中 / 意图分类
4. `report/overview` 返回 200 时 `overviewData = Data`，卡片取值：请求总量 `fmtNum(request_total)`、错误总量 `fmtNum(error_total)`、Token用量 `fmtNum(total_tokens)`、平均延迟 `fmtMs(latency_avg_ms)`、费用 `fmtNum(cost[0].value)`
5. 页面无 JS 报错、无 echarts 报错

### RP-O-12：总览接口失败提示

**功能模块**: 总览指标卡  
**优先级**: P1  
**用例编号**: RP-O-12  
**设计依据**: `Overview.vue` `load()` 的 `.catch()` 分支与 `report.loadFailed`；`loadTs()` / `loadRanking()` / `loadDistribution()` 的图表级错误隔离

#### 前置条件

- 可拦截报表接口使其返回非 200（如 500），模拟加载失败

#### 测试步骤

**场景一：核心请求失败（`report/overview`）**

1. 使用 DevTools / 路由拦截使 `report/overview` 返回 500（或网络层中断）
2. 触发总览加载
3. 观察全局提示与页面状态

**场景二：单个图表请求失败（如 `report/timeseries?metric=qps`）**

4. 仅拦截 `report/timeseries?metric=qps`，其余请求放行
5. 触发总览加载
6. 观察全局提示、该图表状态与其余卡片

#### 预期结果

**场景一（核心请求失败）**

1. `Promise.all` 进入 `.catch()`，控制台输出 `Failed to load overview data:`
2. 页面顶部弹出错误提示「加载失败」（`report.loadFailed`）
3. `loading` 置为 `false`，加载状态结束
4. `overviewData` 保持 `null`，页面展示空态（`.report-overview .report-empty` 文案「暂无数据」），不渲染指标卡

**场景二（单图表请求失败）**

5. 失败请求由 `loadTs()` / `loadRanking()` / `loadDistribution()` 独立加载，各自内部 `.catch(() => {})` 兜底 → **不进入** `load()` 的全局 `.catch()`：控制台**不输出** `Failed to load overview data:`，页面**不弹出**全局「加载失败」提示
6. `overviewData` 仍来自成功的 overview 请求，指标卡正常展示；失败的那张图表降级展示「暂无数据」空态
7. `loading` 置为 `false`

> **2026-10-15 校准说明（RP-O-12 场景二）**：2026-10-14「图表维度下钻与过滤栏清理」重构把原先塞在同一个 `Promise.all` 中的 8 个请求拆为「核心请求（`overview` / `cache_tokens`）+ 图表请求（`loadTs` / `loadRanking` / `loadDistribution`）」，后者为支持维度下拉独立重载而各自带 `.catch(() => {})` 兜底。**因此任一图表请求失败不再触发全局提示**——这是该重构的固有语义（否则切换某个图表维度失败会误弹整页「加载失败」，而其余 6 张图正常渲染）。本用例原「预期 1 / 2」把单图表失败也归入全局 `.catch()`，属**用例滞后**（断言前提被 2026-10-14 变更推翻），已按新语义拆分场景一/场景二并改写；用例编号与优先级不变。回归证据：[report/test-report-20261015-002536.md](../../../report/test-report-20261015-002536.md)（回归中该条失败）→ 校准后复跑见 [report 00-索引](./00-索引与映射.md)。

4. 平均延迟卡主值 = `fmtMs(latency_avg_ms)`
5. 费用卡主值 = `fmtNum(cost[0].value)` + 小字币种 `cost[0].currency`；副行遍历 `cost.slice(1)`，每项形如 `{currency}: {fmtNum(value)}`，**不重复**主币种；`cost` 为空数组 / 缺失时主值展示 `-`、副行不渲染
6. 缓存命中率卡主值 = `fmtPercent(cache.hit_rate)`，两行副文案分别对应命中 / 未命中 / 豁免与读 / 写 Token
7. 镜像命中卡主值 = `fmtNum(mirror.hit_count)`
8. 意图分类卡主值 = `fmtNum(intent.classified_count)`，副文案 = `未知: {fmtNum(unknown_count)}（{fmtPercent(unknown_rate)}）`
9. 格式化规则：`fmtNum` 对 `>= 1000000` 输出 `X.XM`、`>= 1000` 输出 `X.XK`、其余原样，`null` → `-`；`fmtPercent` = `(ratio × 100).toFixed(1) + '%'`，`null` → `-`；`fmtMs` = `toFixed(1) + ' ms'`，`null` → `-`
