## 3. 排行与分布新维度

### RP-R-01：意图答案维度排行

**功能模块**: 排行与分布新维度  
**优先级**: P0  
**用例编号**: RP-R-01  
**设计依据**: `report.md` §2.3（`dimension` 枚举含 `ai_intent_answer`，排序指标 `request_count`，可用后端「全部」，两后端均可用）；§1.3 `RankingItem`

#### 前置条件

- 两后端均适用（MySQL / Doris，`[Report].Backend = mysql` 或 `doris`）
- 聚合表 `ai_intent_answer` 维度列已上线并积累分钟数据

#### 测试步骤

1. 直接调用 `GET report/rankings`，参数 `dimension=ai_intent_answer`、`limit=10`、`start` / `end`（近 1 小时）
2. 查看响应体 `Data.items`
3. 核对同一窗口下 `dimension=model` 的返回结构

#### 预期结果

1. 返回 200，`Data.items` 为数组，元素为 `RankingItem`：`{name, request_count, error_count, input_tokens, output_tokens}`
2. `name` 为该意图答案值（如 `coding` / `unknown`），按 `request_count` 分组统计
3. `dimension=ai_intent_answer` 的返回结构与既有维度（`model`）一致
4. 该维度在两后端（MySQL / Doris）均可用，返回结构一致（见 RP-R-10 / RP-V-12）

### RP-R-04：字符串新维度空值不进排行

**功能模块**: 排行与分布新维度  
**优先级**: P0  
**用例编号**: RP-R-04  
**设计依据**: `report.md` §2.3 注（字符串新维度 `ai_intent_answer` / `ai_cache_status` 的空值 `''` 不进排行）

#### 前置条件

- 两后端均适用（MySQL / Doris）；窗口内存在 `ai_intent_answer = ''`（意图未求值）与 `ai_cache_status = ''`（未启用缓存）的记录

#### 测试步骤

1. 调用 `GET report/rankings`，参数 `dimension=ai_intent_answer`、`limit=50`、`start` / `end`
2. 查看 `items` 中是否存在空字符串 `name`
3. 将 `dimension` 换成 `ai_cache_status`，重复步骤 1~2
4. 与对应维度分布（RP-R-07）的空值处理对比

#### 预期结果

1. `items` 中不出现 `name = ""` 的空值桶（空值 `''` 不进排行）
2. 各条目的 `name` 均为非空字符串
3. 空值记录不计入排行统计（与分布侧「空值归一 unknown」的语义不同）
4. `mirror_hit` 为数值桶维度，不受此规则约束（返回 `0` / `1`）

**用例编号**: RP-R-10  
**设计依据**: `report.md` §2.2 / §2.3 / §2.4（三个新维度可用后端「全部」）与 §3（错误码表已无 Doris 门控行）

- 聚合表新维度列已上线并积累分钟数据

#### 测试步骤

1. 在 Doris 后端调用 `GET report/timeseries`，参数 `dimension=ai_intent_answer`、`metric=qps`、合法 `start` / `end`
2. 在 Doris 后端调用 `GET report/rankings`，参数 `dimension=ai_cache_status`
3. 在 Doris 后端调用 `GET report/distribution`，参数 `dimension=mirror_hit`
4. 将步骤 1~3 分别在 MySQL 后端重复执行

### RP-R-12：排行数量默认与上限

**功能模块**: 排行与分布新维度  
**优先级**: P2  
**用例编号**: RP-R-12  
**设计依据**: `report.md` §2.3（`limit` 默认 10，上限 50）；`Overview.vue` `load()`（`limit: 10`）；`index.vue` `loadFilterOptions()`（`limit: 50`）

#### 前置条件

- 两后端均适用（MySQL / Doris）；调用 `GET report/rankings`

#### 测试步骤

1. 调用 `dimension=model`，不传 `limit`
2. 调用 `dimension=model`，传 `limit=50`
3. 调用 `dimension=model`，传 `limit=100`
4. 观察总览图表与筛选栏下拉实际使用的 `limit`

#### 预期结果

1. 不传 `limit` 时按默认返回不超过 10 条
2. 传 `limit=50` 时正常返回不超过 50 条
3. 传 `limit=100`（超过上限）时**不报错**，静默截断为 50 返回 200（与通用 `page_size` 超上限截断约定一致）；非数字值（如 `limit=abc`）返回参数校验错误：HTTP 422（ErrNum 422）
4. 总览模型 / 服务商排行请求固定 `limit=10`；筛选栏下拉选项请求固定 `limit=50`
