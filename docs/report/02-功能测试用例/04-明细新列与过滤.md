### RP-L-01：明细新增缓存列

**功能模块**: 明细新列与过滤  
**优先级**: P0  
**用例编号**: RP-L-01  
**设计依据**: `Logs.vue` `columns` 中 `title: report.colCache`、`key: 'ai_cache_status'`、`width: 80`、`render: params.row.ai_cache_status || '-'`

- 窗口内存在含缓存状态（`hit` / `miss` / `skip` / `''`）的明细记录

2. 单元格直接展示缓存状态原值（`hit` / `miss` / `skip`）
3. 该列位于「费用」列之后、「镜像」列之前
4. 空串 / null 时展示占位符 `-`

### RP-L-12：详情空值显示占位符

**功能模块**: 明细新列与过滤  
**优先级**: P1  
**用例编号**: RP-L-12  
**设计依据**: `Logs.vue` 详情各字段空值处理（`|| '-'` / `!= null ? v : '-'` / `fmtLevel` / `fmtUsDetail` / `fmtCacheStatus`）

#### 前置条件

- 构造字段为 null / 空串的明细记录（`logid`、`level1Name`~`level5`、`client_ip`、`err_msg`、`ai_stream`、`mirror_hit`、意图置信度、意图缓存命中等为 `null`，意图问题 / 意图答案为空串）

#### 测试步骤

1. 打开该记录的详情抽屉
2. 观察各空值字段的展示（日志 ID / 错误 / 流式 / 缓存状态 / 镜像命中 / 意图问题 / 意图答案 / 意图置信度 / 意图来源 / 意图问题版本等）
3. 观察布尔类字段的展示（流式 / 镜像命中 / 意图缓存命中）
4. 观察 API Key 五级归类字段的展示

#### 预期结果

1. 字符串类空值字段（日志 ID / 主机 ID / 产品线 / API Key / 协议 / 模式 / 错误码 / 错误 / 客户端IP / Header Host / 原始URI / 意图问题 / 意图答案 / 意图来源 / 意图问题版本 / `mirror_cluster`）为 null 或空串时展示 `-`
2. 流式 `ai_stream` 为 `1` 展示「是」、为 `0` 展示「否」、为 `null` 展示 `-`（不误按「否」展示）
3. 镜像命中 `mirror_hit` 为 `true` 展示「是」（`mirror_cluster` 非空时追加 `（集群名）`）、为 `false` 展示「否」、为 `null` 展示 `-`
4. 意图置信度使用 `!= null ? v : '-'`，为 `0` 时展示 `0`（不误判为 `-`），仅 null 时展示 `-`
5. 意图缓存命中为 null 时展示 `-`；为 `true` / `false` 时展示「是」/「否」
6. 一级~五级归类经 `fmtLevel(name, value)`：`name` 与 `value` 均为 null 时展示 `-`；否则展示 `name = value`（任一侧为 null 用 `-` 占位）
7. **例外**：`ai_cache_status` 为空串时展示「未启用」（非 `-`），`null` 才展示 `-`，见 RP-L-15
8. 展示值与接口返回保持一致，无 `undefined` / `null` 明文外露

### RP-L-13：意图延迟格式化

**功能模块**: 明细新列与过滤  
**优先级**: P1  
**用例编号**: RP-L-13  
**设计依据**: `Logs.vue` 详情「意图延迟」`fmtUs(ai_intent_latency_us)`；详情 TTFT / TPOT 经 `fmtUsDetail(us)`（`us == null || us === 0` → `'-'`）；`index.vue` `fmtUs(us)`（`us == null` → `'-'`，否则 `(us / 1000).toFixed(1) + ' ms'`）

#### 前置条件

- 构造意图延迟分别为非空（如 `1200`）、为 `0`、为 `null`（cache / 显式源）的明细记录
- 同批记录覆盖 TTFT / TPOT 为 `0`（非流式，接口写入 `0`）与为 `null` 的组合

#### 测试步骤

1. 打开意图延迟为 `1200` 的记录详情，查看「意图延迟」
2. 打开意图延迟为 `0` 与为 `null` 的记录详情，查看「意图延迟」
3. 打开 TTFT / TPOT 为 `0` 与为 `null` 的记录详情，并对照列表 TTFT 列
4. 核对换算结果与两处口径差异

#### 预期结果

1. 意图延迟 `1200`（μs）展示为 `1.2 ms`（`1200 / 1000 = 1.2`，保留 1 位小数）
2. 意图延迟为 `null`（cache / 显式源，见 `report.md` §1.2）展示为 `-`；该字段沿用 `fmtUs`，出现 `0` 时展示 `0.0 ms`（接口不写 `0`，无「未设置」口径）
3. 详情 TTFT / TPOT 经 `fmtUsDetail`：`null` **或 `0`** 均展示 `-`（接口对非流式请求写入 `0`，见 `report.md` §1.2）
4. 单位由 μs 换算为 ms，与字段语义一致；**列表侧 TTFT 列仍用 `fmtUs`**（`0` 展示 `0.0 ms`），本批次未改动列表口径
