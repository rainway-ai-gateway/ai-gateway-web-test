## 6. 过滤栏与页签

### RP-F-01：时间范围筛选

**功能模块**: 过滤栏  
**优先级**: P0  
**用例编号**: RP-F-01  
**设计依据**: `index.vue` `DatePicker`（`type="datetime"`、`format="yyyy-MM-dd HH:mm:ss"`、`width 190px`、`@on-change="onTimeChange"`、`@on-ok="applyFilters"`）、`validateTimeRange()`、`buildFilterParams()`（`start` / `end` 恒带）

#### 前置条件

- 以系统管理员登录，进入「数据报表」页面
- 窗口内存在跨多条请求日志

#### 测试步骤

1. 在过滤栏设置「起始时间」为昨天 00:00:00
2. 设置「结束时间」为今天 23:59:59
3. 点击「查询」按钮
4. 观察当前页签（总览 / 明细）的数据刷新

#### 预期结果

1. 时间选择器为 DatePicker（`type = datetime`），支持日期 + 时间选择，展示格式 `yyyy-MM-dd HH:mm:ss`，宽度 190px
2. 点击「查询」触发 `applyFilters()`：先 `validateTimeRange()` 校验通过，再按当前页签调用 `overview.load()` 或 `logs.load()`
3. 请求恒携带 `start` / `end`（Unix 秒级时间戳，由 `toUnixTimestamp()` 计算）
4. 总览页签的指标卡与图表更新至该时间窗口；明细页签列表仅展示窗口内记录
5. 起止无效、顺序错误（`end <= start`）或跨度 > 7 天时，`validateTimeRange()` 弹错并中断，不发起请求

### RP-F-02：维度多选筛选

**功能模块**: 过滤栏  
**优先级**: P1  
**用例编号**: RP-F-02  
**设计依据**: `index.vue` 维度区 `models` / `apikey_ids` / `providers` / `hosts`（`Select` `multiple` + `filterable`）、`buildFilterParams()` 中 `join(',')`

#### 前置条件

- 窗口内存在不同模型、API Key、提供商、主机的日志
- 各维度下拉选项已由 `loadFilterOptions()` 加载

#### 测试步骤

1. 在「模型」多选筛选选择一个或多个模型
2. 在「提供商」多选筛选选择若干值
3. 点击「查询」并查看请求 Query

#### 预期结果

1. 四个维度均以多选（`multiple`）+ 可搜索（`filterable`）下拉呈现
2. 选中值非空时，`buildFilterParams()` 将其以逗号拼接：`models` / `apikey_ids` / `providers` / `hosts`
3. 未选中任何值时，对应参数不并入 Query
4. 多选可取消单个选项、全选或全清，清空后该参数不再携带

### RP-F-03：流式下拉筛选

**功能模块**: 过滤栏  
**优先级**: P1  
**用例编号**: RP-F-03  
**设计依据**: `index.vue` 维度区 `filters.stream`（`Select` + `clearable`，`Option value="1"` = 是 / `Option value="0"` = 否）、`buildFilterParams()` 中 `if (this.filters.stream !== '' && this.filters.stream != null) params.stream = this.filters.stream`

#### 前置条件

- 窗口内存在流式与非流式请求日志

#### 测试步骤

1. 在「流式」下拉选择「是」
2. 再选择「否」
3. 点击 clearable 清空（全部）

#### 预期结果

1. 「流式」下拉为单选且可清除（`clearable`），取值为字符串 `'1'`（是）/ `'0'`（否），**非布尔 `true` / `false`**
2. 选择「是」时请求携带 `stream=1`；选择「否」时携带 `stream=0`
3. 清空后 `filters.stream` 为空串，条件不成立，请求不携带 `stream`
4. 数据按所选流式状态正确过滤

**优先级**: P1  
**用例编号**: RP-F-04

1. 在「状态码」输入框输入 `200,500`
2. 点击「查询」并查看请求 Query 与结果
3. 清空输入后再次查询

3. 输入为空时条件不成立，请求不携带 `status_codes`，恢复全量

### RP-F-05：组合筛选

**功能模块**: 过滤栏  
**优先级**: P1  
**用例编号**: RP-F-05  
**设计依据**: `index.vue` `buildFilterParams()` 参数合并逻辑与源码注释；`applyFilters()`

#### 前置条件

- 窗口内存在满足多维度条件的日志

#### 测试步骤

1. 设置时间范围（起始 / 结束时间）
2. 选择一个或多个模型与提供商
3. 选择流式状态并填写状态码
4. 点击「查询」
5. 观察总览与明细页签的数据

#### 预期结果

1. 请求 Query 同时携带 `start` / `end` 与所有已选过滤参数（`models` / `providers` / `stream` / `status_codes` 等），各维度叠加无冲突
2. 明细列表结果同时满足所有条件；总览指标卡与图表按相同过滤条件刷新
3. **`cache_status` / `mirror_hit` / `intent_answer` 三个新维度控件不并入通用查询参数**（源码注释明确）：后端未将其定义为 overview / timeseries / logs 的通用过滤参数，明细侧同名过滤由 Logs 工具栏独立提供（见 RP-L-04 ~ RP-L-08），避免参数重复（该限制与查询后端无关，两后端均可用，不再触发 Doris 422）
4. 修改任一过滤项后需重新「查询」才生效

### RP-F-06：重置按钮

**功能模块**: 过滤栏  
**优先级**: P1  
**用例编号**: RP-F-06  
**设计依据**: `index.vue` `resetFilters()`（`end = now`、`start = now - 3600`、`shortcut = '1h'`、重置 9 项 `filters`、`applyFilters()`）

#### 前置条件

- 已设置若干过滤条件（时间范围、模型、提供商、流式、状态码等）

#### 测试步骤

1. 设置时间范围、选择模型、选择提供商、选择流式、填写状态码
2. 点击「重置」按钮
3. 观察过滤栏控件与数据刷新

#### 预期结果

1. 时间范围恢复为最近 1 小时（`end = now`、`start = now - 3600`），快捷按钮「1 小时」恢复高亮（`shortcut = '1h'`）
2. `filters` 整体重置为初始值：`models` / `apikey_ids` / `providers` / `hosts` 清空为 `[]`，`stream` / `status_codes` / `cache_status` / `mirror_hit` / `intent_answer` 清空为 `''`（共 9 项）
3. 重置后立即 `applyFilters()`，当前页签数据自动刷新为默认条件下的结果
4. 重置不改变当前所在页签

### RP-F-07：页签切换保持过滤参数

**功能模块**: 过滤栏  
**优先级**: P1  
**用例编号**: RP-F-07  
**设计依据**: `index.vue` `onTabChange(name)`（`buildFilterParams()` 后按 tab 加载）、`Tabs @on-click="onTabChange"`

#### 前置条件

- 已设置过滤条件（时间范围、模型等）

#### 测试步骤

1. 在过滤栏设置时间范围并选择一个模型
2. 当前处于「总览」页签，观察数据按过滤条件展示
3. 切换到「明细」页签
4. 再切回「总览」页签

#### 预期结果

1. 切换到「明细」后触发 `onTabChange('logs')`，用当前 `buildFilterParams()` 的结果加载明细，过滤栏参数保持不变
2. 明细数据按相同过滤参数查询
3. 切回「总览」触发 `onTabChange('overview')`，过滤参数仍保持，总览数据按同一条件刷新
4. 过滤条件在页签间共享，不因切换而丢失或重置

### RP-F-08：快捷时间与 DatePicker 同步

**功能模块**: 过滤栏  
**优先级**: P2  
**用例编号**: RP-F-08  
**设计依据**: `index.vue` `TIME_SHORTCUTS`（`1h` / `6h` / `24h` / `7d` → 1 / 6 / 24 / 168 小时）、`setShortcut(val)`、`onTimeChange()`、`shortcut` 高亮绑定

#### 前置条件

- 过滤栏展示快捷时间按钮（1 小时 / 6 小时 / 24 小时 / 7 天）与 DatePicker

#### 测试步骤

1. 依次点击「1 小时」「6 小时」「24 小时」「7 天」快捷按钮
2. 观察 DatePicker 中的起止时间
3. 手动修改 DatePicker 中的起止时间为一个非标准窗口
4. 观察快捷按钮的高亮状态

#### 预期结果

1. 点击快捷按钮触发 `setShortcut(val)`：`shortcut` 置为对应值，`end = now`、`start = end - hours * 3600`，并立即 `applyFilters()`
2. DatePicker 起止时间随所选窗口自动更新（`1h` = 最近 1 小时，`7d` = 168 小时 / 7 天边界）
3. 当前选中项快捷按钮高亮（`:type="shortcut === opt.value ? 'primary' : 'default'"`）
4. 手动修改 DatePicker 触发 `onTimeChange()` 将 `shortcut` 置空，所有快捷按钮取消高亮，避免误导
