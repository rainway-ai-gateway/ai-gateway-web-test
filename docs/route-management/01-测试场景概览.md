# 路由管理模块 - 测试场景概览

## 模块概述

路由管理模块负责 AI 网关流量转发规则的配置，当前版本聚焦**路由表**能力：

|功能区域|说明|
|---|---|
|路由表列表|展示 Global、Entity、API-Key 三类路由表，支持按类型/属主/状态搜索、分页、启用/停用、查看详情|
|路由规则详情|展示当前路由表的启用状态与规则列表，支持查看/编辑模式、规则增删改、提交并生效|

路由表中的规则按顺序匹配，命中后按目标集群与权重转发；备用集群在目标集群异常时接管。

---

## 配置顺序

完整配置链路需按模块依赖顺序进行；路由表列表中的 Entity / API-Key 类型记录由后端在创建 Entity / API-Key 时**自动关联生成**，无需在路由表模块单独创建。

```text
Entity 类型 → Entity 组织 → API-Key → 路由表列表 → 路由规则详情
                │              │
                └──── 自动产生 Entity 路由表 ────┘
                               └── 自动产生 API-Key 路由表
```

- **Global 路由表**：不依赖 Entity / API-Key，可单独查看与配置
- **Entity / API-Key 路由表**：需先在对应模块创建属主数据；删除属主时路由表记录同步消失
- **规则编辑**：依赖已存在的集群（目标集群下拉框）

跨模块联动与全链路场景详见 [场景五](#场景五entityapi-key-与路由表联动)、[场景六](#场景六全链路配置journey) 及 [04-跨模块联动](./02-功能测试用例/04-跨模块联动.md)。

## 测试用例与 API 接口差异说明

复查接口定义后，以下能力与当前 UI 实现存在差异，已在用例中按实际 UI 行为描述，并标注 API 侧能力：

|能力|API 定义|当前 UI 行为|用例处理|说明|
|---|---|---|---|---|
|路由表列表分页/筛选|`route-tables` 支持 `page/page_size/type/owner/enabled` 查询参数|pageTable 组件在 `GET route-tables` 返回的首页数据上做客户端筛选与分页|RT-L-02~RT-L-07 按客户端行为验证；不校验 API 查询参数|若数据超过默认 page_size，需接入后端分页参数|
|路由表列表排序|`route-tables` 支持 `sort_by/sort_order`|当前列表列未开启 `sortable`|未覆盖|原型未体现排序，暂不测|
|规则列表分页/筛选|pageTable 组件支持客户端分页/筛选|规则详情页使用 pageTable 做客户端处理|RT-D-21 覆盖规则搜索|规则数量大时同需关注后端分页|
|列表刷新保留搜索条件|—|pageTable 在 `tableData` 刷新时会清空搜索值|已删除原 RT-D-19，该行为由 PageTable 通用组件测试覆盖|见项目通用组件测试|
