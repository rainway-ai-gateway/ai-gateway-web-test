# 路由管理模块 - 测试场景概览

## 模块概述

路由管理模块负责 AI 网关流量转发规则的配置，当前版本聚焦**路由表**能力：

|功能区域|说明|
|---|---|
|路由表列表|展示 Global、Entity、API-Key 三类路由表，支持按类型/属主/状态搜索、分页、启用/停用、查看详情|
|路由规则详情|展示当前路由表的启用状态与规则列表，支持查看/编辑模式、规则增删改、提交并生效|

路由表中的规则按顺序匹配，命中后按目标集群与权重转发；备用集群在目标集群异常时接管。

**核心变更依据**：

- 2026-10-12（变更记录 `modifications/2026-10-12-readonly-admin/ui-code-changes.md`）：引入「系统管理员（只读）」角色（后端以 `role` 枚举取代 `is_admin`，新增 `system_admin_readonly`）。只读视角（`role === 'system_admin_readonly'`）**全站隐藏所有写操作按钮**（实现为全局指令 `v-has`），仅保留只读入口（查看 / 详情 / 查询）。本模块 `pages/route-tables.html` 只读视角仅保留「查看」；`pages/route.html` 只读视角保留「查看」，隐藏「添加规则 / 进入(退出)编辑 / 提交并生效」。新增只读视角用例 RT-RO-01~03。

## 配置顺序

完整配置链路需按模块依赖顺序进行；路由表列表中的 Entity / API-Key 类型记录由后端在创建 Entity / API-Key 时**自动关联生成**，无需在路由表模块单独创建。

```text
Entity 类型 → Entity 组织 → API-Key → 路由表列表 → 路由规则详情
                │              │
                └──── 自动产生 Entity 路由表 ────┘
                               └── 自动产生 API-Key 路由表
```

- **Global 路由表**：不依赖 Entity / API-Key，可单独查看与配置
- **Entity / API-Key 路由表**：需先在对应模块创建属主数据；删除属主时路由表记录同步消失
- **规则编辑**：依赖已存在的集群（目标集群下拉框）

跨模块联动与全链路场景详见 [场景五](#场景五entityapi-key-与路由表联动)、[场景六](#场景六全链路配置journey) 及 [04-跨模块联动](./02-功能测试用例/04-跨模块联动.md)。

### v0.6 (2026-10-15)

**变更主题**：回归修复轮 —— 状态筛选默认值把既有用例整批打挂的集中修复、破坏性造数治理

**变更内容**：

- **集中修复（不再逐条补丁）**：列表「状态」列默认「启用」后，凡按行定位/开详情/切换启停的用例都取不到目标行。修复落在共享助手 `pages/route/RoutePage.js`：
  - 新增 `utils.clearRouteTableStatusFilter(page)`（幂等：已清空则不动作）与 `utils.ensureRouteTableRowReachable(page, row)`（行不在列表时先清空状态筛选）；
  - `openGlobalRouteTableDetail` / `openRouteTableDetail` / `expect*RouteTableRowVisible` / `expect*RouteTableStatus` / `expect*RouteTableToggleButtons` / `enable|disable*RouteTableAndWait` / `ensureGlobalRouteTable*ViaUI` / `ensureRouteTable*ViaUI` / `navigateToRouteTableByOwner` / `deleteRuleByNameAndSubmit` 全部接入，80+ 条失败由这一处修复消解；
  - 清空动作只发生在「需要操作某一行」的路径上，**不发生在页面加载时**，RT-L-17 仍能断言首屏默认值。
- **状态筛选控件定位**：状态列有默认值时 placeholder「请选择状态」不渲染，`selectRouteTableStatusFilter` 改为按列下标定位（与 RT-L-17 同一套写法）。
- **破坏性造数治理**：`resourceApi.initRouteTestData()` 由「整体替换为单条 `global-default-rule`」改为**「快照 + 追加」**——首次调用快照环境现有 Global 规则、仅在缺少目标规则时补齐、已满足则不写入，并新增 `restoreRouteTestData()` 供 `afterEach` 还原；读接口失败时直接放弃播种（绝不写），彻底消除删掉用户规则的风险。
- **API-Key 类型词汇归一**：新增 `utils.routeTableTypeMatches()`（`api_key` ↔ `apikey`），修掉「复用已有 API-Key 路由表」永远匹配不到、`waitForRouteTableOwner` 白等 60s 的问题；详情面包屑断言放宽为 `/路由规则 - (API-Key|api_key|apikey)/`（前端 `TYPE_MAP` 尚未登记 `api_key`）。
- **脏检查适配**：`提交并生效` 自 v0.5 起带脏检查（无本地净变更置灰，RT-D-29）。RT-D-11 改为「删一条 + 留一条本地新增」以保证有净变更；RT-D-15 / RT-V-13 / RT-V-13a 的清理步骤与 `deleteRuleByNameAndSubmit` 在无净变更时跳过提交（`{ skipWhenNoLocalChange: true }`）。
- **清理助手健壮化**：`deleteRuleByNameAndSubmit` 改为硬跳转列表页（不再调用会在 afterEach 里抛 skip 信号的 `ensureRouteTableModuleAvailable`，并顺带丢弃未提交的本地变更），修掉 RT-D-09 / RT-D-10 / RT-V-03-3 / RT-V-12-1 四条「用例体通过、afterEach 记失败」。
- 用例正文同步：§1（模块约定、RT-L-01/02/04/05/06/07/16）、§2.3、§2.9、§2.11、§2.15、§3.7d、§3.16
