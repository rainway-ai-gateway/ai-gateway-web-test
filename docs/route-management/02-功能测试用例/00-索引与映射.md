> 1. **前端查重没触发？否。** `submitRules`（`ai-gateway-web/src/modules/RouteTable/components/RouteRules.vue:532-539`）对本地 `rules` 的 `name` 去重，命中即 `$Message.error(route.ruleNameDuplicate)` 并 `return`（不发请求、不改模式、不动脏标记）。两条规则同名（同一 `duplicateName`）且都渲染在表内 → 必然命中；i18n 键存在（`src/i18n/zh.js:408` = 「规则名称不能重复」）。而「无 PUT、仍在编辑模式、按钮**未置灰**（= 仍有本地净变更）」**正是该分支的现场形态**（若真提交成功，会转查看模式并置灰；若走后端校验失败，会亮「提交失败」提示且仍置灰）。
> 2. **上一批文件把 Global 路由表留在启用 / 脏 / 多规则状态？否。** 逐 spec 核对收尾：`test_02` `afterEach → resourceApi.restoreRouteTestData`（本批日志多次打印「Global 路由规则与播种前快照一致，无需还原」）、`test_04` 同款 `afterEach` + 各 describe 的 `ensureGlobalRouteTableDisabledViaUI`、`test_05` 前置走「快照 + 追加」的 `initRouteTestData`、`test_07` 同款 + 各 describe `afterEach`、`test_09` 只读零写入、`test_10` / `test_12` 用 `createGlobalRouteRulesGuard` capture/restore。且 `RT-D-15` 自身前置先 `ensureGlobalRouteTableDisabledViaUI` 再重读规则；**更关键：判重只看本地 `rules` 数组**，与上一批留下的服务端状态无关。最强对照——`test_05` 的 RT-V-13 / RT-V-13a 是**同一断言模式**，在本批次里排在 `test_04` **之后**执行且**都通过**（24/24）；`-g "RT-D-1[1-5]"` 里 RT-D-14（真实 PUT Global 规则）紧邻 RT-D-15 也通过。
