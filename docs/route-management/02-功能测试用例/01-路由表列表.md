## 1. 路由表列表

> 归属场景：场景一（管理员查看并管理路由表列表）  
> 导航路径：路由管理 → 路由表
>
> **状态筛选默认「启用」（2026-10-15 生效，见 §1.17）**：列表首屏即按 `enabled=true` 过滤，停用行默认不可见。
> 因此凡**按行定位 / 打开详情 / 切换启停**的用例，前置都要先清空状态筛选
> （`utils.clearRouteTableStatusFilter(page)`，幂等——筛选已清空时不动作），
> 只有断言首屏默认态的 RT-L-17 例外。列表条数类断言（RT-L-06/07）同样必须先清空，
> 否则断言的是「启用子集」的条数。
>
> **API-Key 类型取值（2026-10-15 修正，2026-10-16 收紧）**：类型词汇有**两层**，别混用——
> - **接口层**：后端 `route-tables` 的 `type` 返回 `api_key`；UI 下拉的查询 value 是 `apikey`。
>   助手内比较**接口取值 / URL 参数**一律走 `utils.routeTableTypeMatches()`（去下划线 + 转小写后比较），
>   否则「复用已有 API-Key 路由表」永远匹配不到而退回造数、`waitForRouteTableOwner` 也会白等 60s。
> - **显示层**：列表「路由表类型」列与详情面包屑渲染的是 `TYPE_MAP[row.type]` 映射后的文案。
>   产品 `792bb73` 已补 `api_key → API-Key`（`RouteTable/index.vue:53-58`），故显示层断言
>   **精确为 `API-Key`**（不再并列 `api_key` / `apikey` 三种写法）：类型列见 `utils.expectRouteTableTypeCell()`，
>   面包屑见 `DOC_ROUTE_TABLE.apiKeyDetailBreadcrumb`。
>   ⚠️ **例外（2026-10-16 记录，2026-10-17 已解除）**：详情页属主栏「当前路由表：<type>」由 `RouteRules.vue` 自带的
>   `TYPE_LABELS` 渲染，当时该表**无 `api_key` 键**，故仍显示接口原值 `api_key` —— 属产品侧遗留，见 `02-功能测试用例/00-索引与映射.md`。
>   **2026-10-17 结论：例外已解除** —— 产品给 `TYPE_LABELS` 补上了 `api_key: 'API-Key'` 键，属主栏现渲染 `API-Key`，
>   断言已翻回 `API-Key`（临时常量 `DOC_ROUTE_TABLE.apiKeyOwnerLabelRenderedType` 已删除，`expectRouteTableDetailOpen`
>   的属主栏 `<strong>` 直接按 `typeLabel` 做 `toHaveText` 精确断言）——
>   即**显示层三层（类型列 / 面包屑 / 属主栏）现均为精确 `API-Key`**。上一段的例外描述按原文保留为历史记录。
> 因此 RT-L-14/15 复用环境中**首张已有 API-Key 路由表**（`api_key`，如 `api-key-6`），
> 不再新建 Entity 类型/Entity/API-Key 造数；启用→停用成对执行，跑完该行状态回到原值。

### 1.1 进入路由表列表页

**功能模块**：路由表列表  
**优先级**：P1  
**用例编号**：RT-L-01  
**设计依据**：`ai-gateway-web/design-docs/prototype-design/pages/route-tables.html`

- 在左侧导航栏点击「路由管理」→「路由表」
- 观察页面标题、搜索区、表格与分页区域

预期结果：

- 页面标题为「路由表」
- 表格包含列：路由表类型、路由表属主、状态、操作

### 1.17 状态筛选默认「启用」

**功能模块**：路由表列表  
**优先级**：P1  
**用例编号**：RT-L-17  
**设计依据**：`ai-gateway-web/src/modules/RouteTable/index.vue`（`searchParams: { enabled: 'true' }`、状态列 `searchValue: 'true'`）、`src/components/table/pageTable.vue`（服务端分页时把列上预置的 `searchValue` 同步进 `searchMessage`）

前置条件：

- 已使用管理员账号登录系统
- 环境内已知 Global 路由表的启用状态（本环境：停用）

测试步骤：

- 进入路由表列表页，观察状态筛选下拉的默认值与首个列表请求
- 保持状态筛选为默认值，把「类型」筛选切换为 Global
- 点击状态筛选下拉清空图标，清空状态筛选
- 清空后再把「类型」筛选切换为 Entity

预期结果：

- 状态筛选下拉默认选中「启用」（状态列 `searchValue: 'true'`），用户未做任何操作时列表即按启用状态过滤
- 首屏列表请求为 `GET /open-api/v1/route-tables?page=1&page_size=20&enabled=true`（`enabled=true` 是默认筛选，不是用户输入）
- 默认筛选下表格只展示启用状态的路由表，不出现「停用」行
- 切换「类型」后请求同时携带 `type` 与 `enabled=true`（例如 `type=global&enabled=true`），默认值不会因为修改其他筛选条件而丢失
- 清空状态筛选后请求不再携带 `enabled` 参数，请求只按剩余条件过滤；原本被默认筛选隐去的停用行（如 Global 行）重新出现
- 清空后 `enabled` 默认值不粘回：再次切换「类型」时请求只携带 `type`，不重新附带 `enabled=true`

> 备注（2026-10-15 实测）：本环境 19 张路由表当前均为停用，因此默认「状态=启用」的列表为空并显示空态，停用的 Global 行不可见；清空状态筛选后 Global 行出现。用例断言以「请求参数 + Global 行出现/消失」为准，不依赖列表条数。
