## 5. 表达式变更：请求体大小条件（2026-08-24 / 08-25）

> 变更背景：路由规则详情「表达式」片段新增 **请求体大小（bytes）条件** `req_body_larger_than` / `req_body_less_than`，默认片段 `8192` / `2048`；条件基于 HTTP `Content-Length` 头判断请求体字节数，**无 `Content-Length` 时该条件不匹配**。校验通过 `PATCH /expression/verify`；错误提示在 FormItem 内**单行显示**。
>
> 接口依据：`expression-verify.md`（示例 `req_body_larger_than(8192)`、`req_body_less_than(2048)`、`req_host_in("api.example.com") && req_body_larger_than(8192)`）。

### RT-E-07：请求体大小条件-全链路行为（无 Content-Length 不匹配）

**功能模块**: 表达式校验  
**优先级**: P1  
**用例编号**: RT-E-07

#### 前置条件

- 已配置包含 `req_body_larger_than(8192)` 的规则并提交生效

#### 测试步骤

1. 构造无 `Content-Length` 头（如 chunked 编码）且请求体 >8192 字节的请求
2. 构造带 `Content-Length: 9000` 的请求

#### 预期结果

1. 无 `Content-Length` 的请求**不匹配**该条件（按语义该条件不命中，规则不生效）
2. 带 `Content-Length: 9000`（>8192）的请求匹配该条件，规则生效
3. 与 `expression-verify.md` 语义一致（基于 Content-Length 判断）
