## 5. 表达式变更：请求体大小条件（2026-08-24 / 08-25）

> 变更背景：路由规则详情「表达式」片段新增 **请求体大小（bytes）条件** `req_body_larger_than` / `req_body_less_than`，默认片段 `8192` / `2048`；条件基于 HTTP `Content-Length` 头判断请求体字节数，**无 `Content-Length` 时该条件不匹配**。校验通过 `PATCH /expression/verify`；错误提示在 FormItem 内**单行显示**。
>
> 接口依据：`expression-verify.md`（示例 `req_body_larger_than(8192)`、`req_body_less_than(2048)`、`req_host_in("api.example.com") && req_body_larger_than(8192)`）。

### RT-E-01：表达式片段新增请求体大小条件

**功能模块**: 表达式校验  
**优先级**: P0  
**用例编号**: RT-E-01

#### 前置条件

- 进入路由规则详情页，处于编辑模式

#### 测试步骤

1. 在「表达式」输入框旁查找片段 / 快捷插入入口
2. 展开可插入的函数列表

#### 预期结果

1. 函数列表包含请求体大小条件：`req_body_larger_than`（请求体大于）、`req_body_less_than`（请求体小于）
2. 点击片段后按模板插入表达式（如 `req_body_larger_than(8192)`），光标定位到括号内便于输入字节数
3. 其余原有片段（`req_header`、`req_body_contains`、`req_host_in` 等）保持可用

### RT-E-05：请求体大小条件-非法输入校验

**功能模块**: 表达式校验  
**优先级**: P0  
**用例编号**: RT-E-05

#### 前置条件

- 进入路由规则详情编辑模式

#### 测试步骤

依次输入以下表达式并触发校验：

1. `req_body_larger_than(0)` → 预期拦截（字节数须 ≥1）
2. `req_body_larger_than(-1)` → 预期拦截（负数）
3. `req_body_larger_than(abc)` → 预期拦截（非数字）
4. `req_body_less_than()` → 预期拦截（缺少参数）
5. `req_body_larger_than(8192` → 预期拦截（括号不闭合）

#### 预期结果

1. 校验返回 `VerifyResult`（`code: 500` + `message`），输入框下方展示错误信息
2. 错误信息**单行显示**（不换行、不溢出），展示于对应 FormItem 内
3. 非法表达式无法提交

### RT-E-07：请求体大小条件-全链路行为（无 Content-Length 不匹配）

**功能模块**: 表达式校验  
**优先级**: P1  
**用例编号**: RT-E-07

#### 前置条件

- 已配置包含 `req_body_larger_than(8192)` 的规则并提交生效

#### 测试步骤

1. 构造无 `Content-Length` 头（如 chunked 编码）且请求体 >8192 字节的请求
2. 构造带 `Content-Length: 9000` 的请求

#### 预期结果

1. 无 `Content-Length` 的请求**不匹配**该条件（按语义该条件不命中，规则不生效）
2. 带 `Content-Length: 9000`（>8192）的请求匹配该条件，规则生效
3. 与 `expression-verify.md` 语义一致（基于 Content-Length 判断）
