### RT-E-08：条件原语面板清单基线

**功能模块**: 表达式/条件原语面板
**优先级**: P0
**用例编号**: RT-E-08
**源码依据**: `ai-gateway-web/src/components/Expression/ExpressionConfig.js:17-603`

#### 前置条件

1. 管理员视角，路由表列表存在 Global 路由表（环境既有），列表「状态=启用」默认筛选需先清空才能进入明细。
2. 进入路由规则详情页并**进入编辑模式**，打开「添加规则」抽屉（面板常驻抽屉第 2 个 FormItem）。

#### 测试步骤

1. 读取面板基线常量，核对分组数、原语数、连接符数与唯一性。
2. 打开「添加规则」抽屉，读取抽屉内面板的分组条目、组标题、原语按钮与 tooltip 签名。
3. 逐项比对组标题集合与顺序。
4. 检查 `vars`（条件变量）分组。
5. 检索已删除原语 `bfe_cluster_in`。
6. 检查 `time_weekday_in`（system 组）与 `intent` 组。
7. 检查 `default_t`（手输表达式原语）。

#### 预期结果

1. 基线常量：**20 个分组 / 61 个条件原语 / 5 个逻辑连接符**；分组 id、分组标题唯一；每个分组内按钮显示名唯一；61 个原语**每个都有签名条目**（签名条目数 = 原语数）。
2. 抽屉内（`hideGroups=['response']` 生效）面板规模：**19 个 `.expression-item` / 18 个 `.expression-item-box`（`.title`）/ 63 个 `.vars-expression-show` / 58 条非空 tooltip 签名**；分组标题序列与各分组按钮文本序列**与基线剔除 `response` 组后逐一相同**。
3. 组标题集合与顺序（18 个有按钮的组）：`逻辑连接符: / host: / port: / method: / path: / query: / cookie: / header: / clientIP: / vip: / proto: / context: / tag: / url: / intent: / body: / session: / system:`；`response` 组标题不出现。
4. `vars`（条件变量）分组**渲染为空条目**：无 `.expression-item-box`、无按钮（`conditionVars` 由 `vars` 入参驱动，四个请求阶段表单均未传 `vars` → 恒空，是该实现的固有特征，**不与 `.title` 数做相等断言**）。
5. 已删除原语 `bfe_cluster_in` **不存在**：面板按钮文本中无该名，且整页 DOM（含 `transfer` 到 body 的 tooltip 弹层）与可见文本均不含 `bfe_cluster_in`；同一扫描能命中 `time_weekday_in`（正对照，证明扫描有效、非空跑）。
6. `time_weekday_in` **存在**于 system 组，签名为 `time_weekday_in(weekday_list, zone)`；`intent` 组**存在**（标题 `intent:`），组内 `in` 原语签名为 `req_ai_intent_in(question_name, value_list, min_confidence)`（BFE v1.8.9-dev 新增索引）。
7. `default_t` **不在面板**：它属 `connController`（`ExpressionConfig.js:604-641`，`default_t` + 逻辑连接符），是手输表达式而非面板按钮，面板按钮序列比对与基线常量自检均不含它。

#### 测试数据

- 复用环境既有 Global 路由表与其规则，**不造数**。

**数据策略（复用环境，零写入）**：只「进入编辑模式 + 打开添加规则抽屉」，不提交任何规则；`beforeAll` 不造数，用例内对 Global 路由规则做快照并在收尾断言未改动。列表默认「状态=启用」筛选会挡住全为停用态的路由表，故进入明细前先清空该筛选（`clearRouteTableSearchFilter(page, ROUTE_TABLE_SEARCH_COLUMN.status)`，与 RT-D-28/29 同写法）。

#### 补充说明

- **基线化落点**：`EXPRESSION_PANEL_GROUPS`（组顺序 / 组标题 i18n 取值 / 组内按钮顺序）与 `PRIMITIVE_SIGNATURES`（61 条签名文本）逐条抄录自 `ExpressionConfig.js`，是「面板变更须刷新 UI 自动化基线」的检查项载体。校验方式：新增脚本比对基线常量与源码（缺失 0、多余 0），已确认逐条一致。
- 分组标题取值：`route.exprGroup.*`（中英语言包取值一致，均为英文原文），唯 `cip → clientIP`、`vars → condition vars`；`logical` 组用 `route.logicalConnector`（`逻辑连接符`）。`.title` 文本形如 `host:`（标题 + 冒号）。
- **定位纪律**：`.expression` 既是面板根 div 也是 iView `Input` wrapper 的 class（会 strict violation）→ 面板内元素一律用 `.rule-form .expression-item` / `.rule-form .expression-item-box .title` / `.rule-form .vars-expression-show`；textarea 用 `.rule-form .expression textarea` + `first()`。
- **tooltip 纪律**：tooltip 为 `:transfer="true"`，iView 只用 `v-show` 控制可见性、内容**始终渲染并常驻 body**（`node_modules/iview/src/components/tooltip/tooltip.vue:6-24`）→ 签名可一次性扫 body（58 条即来自此），但**可见性断言必须用 `.ivu-tooltip-inner:visible` 过滤**，否则会命中全部 63 个隐藏弹层。
- 自动化：`tests/route/test_14_route_expression_primitive_panel.spec.js`（RT-E-08）。

### RT-E-09：hideGroups —— 四个请求阶段表单抽屉内隐藏响应原语

**功能模块**: 表达式/条件原语面板
**优先级**: P0
**用例编号**: RT-E-09
**源码依据**: `ai-gateway-web/src/components/Expression/index.vue:85-90,104-111`

#### 前置条件

1. 管理员视角，四个请求阶段模块均可达：路由表规则详情、流量镜像规则、AI 缓存规则、AI 上下文压缩规则。
2. 四个模块均能进入编辑模式并打开「添加规则」抽屉。

#### 测试步骤

对**路由表规则（RouteTable）/ AI 缓存规则（AICache）/ AI 上下文压缩规则（AIContext）/ 流量镜像规则（TrafficMirror）** 四个模块依次执行：

1. 进入编辑模式，打开「添加规则」抽屉。
2. 读取抽屉内面板的分组条目、组标题、原语按钮与 tooltip 签名。
3. 检索 `response` 组的标题、按钮与签名。
4. 关闭抽屉并退出编辑模式（不提交）。

#### 预期结果

1. 四个抽屉内面板规模**一致**：19 个 `.expression-item` / 18 个 `.expression-item-box`（`.title`）/ 63 个 `.vars-expression-show` / 58 条非空签名，且分组标题序列、各分组按钮文本序列、签名集合与基线剔除 `response` 组后逐一相同。
2. `response` 组**整体不渲染**：无 `response:` 标题；按钮文本中无 `code`、`header_key_in`、`header_value_in`；签名中无 `res_code_in(codes)`、`res_header_key_in(key_list)`、`res_header_value_in(key, value_list, case_insensitive)`。
3. 关闭抽屉、退出编辑模式后无任何后端写入（不出现未提交变更记录）。

#### 测试数据

- 四个模块各自的规则抽屉（无规则也能打开「添加规则」抽屉）；复用环境既有数据，**不造数**。

**数据策略（复用环境，零写入）**：四个模块都只做「进入编辑模式 + 打开抽屉 + 关闭」，不填表、不提交；路由表一侧另对 Global 路由规则做快照并在收尾断言未改动。

#### 补充说明

- 产品依据：`Expression/index.vue:104-111` 的 `expressionConfig` 在 `type === 'controller'` 时按 `hideGroups`（分组 id 数组）过滤，`connController` 不参与过滤；四个请求阶段 `RuleForm.vue` 均传 `:hide-groups="['response']"`（`RouteTable/components/RuleForm.vue:36`、`TrafficMirror:34`、`AICache:34`、`AIContext:27`）。
- 业务语义（见变更记录 §1 问题 8）：`response` 原语（`res_code_in` 等）依赖响应阶段才有值，请求阶段规则（路由 / 镜像 / 缓存 / AI 上下文）中 `HttpResponse` 为 nil、恒为 false，属**死条件**，故整体隐藏。
- 四个模块的规则抽屉根 class 统一为 `.rule-form`，面板定位函数（`pages/route/ExpressionPanelPage.js`）对四个模块通用。
- 自动化：`tests/route/test_14_route_expression_primitive_panel.spec.js`（RT-E-09）。

### RT-E-10：原语签名与示例 tooltip 抽查

**功能模块**: 表达式/条件原语面板
**优先级**: P1
**用例编号**: RT-E-10
**源码依据**: `ai-gateway-web/src/components/Expression/ExpressionConfig.js`（`description` / `example` 字段）

#### 前置条件

1. 进入路由规则详情页编辑模式，打开「添加规则」抽屉。

#### 测试步骤

1. 悬停 clientIP 组 `range` 原语。
2. 悬停 body 组 `req_body_larger_than` 原语。
3. 悬停 system 组 `time_weekday_in` 原语。
4. 悬停 intent 组 `in` 原语。

#### 预期结果

1. `clientIP → range`：tooltip 签名行 = `req_cip_range(start_ip, end_ip)`（**不是** 旧版文档简写 `patterns`），示例含 `req_cip_range("1.1.1.1", "2.2.2.2")`。
2. `body → req_body_larger_than`：签名行 = `req_body_larger_than(size)`（参数名按文档修正），示例含 `req_body_larger_than(8192)` 与 Content-Length 语义说明「**无 Content-Length 时不匹配**」。
3. `system → time_weekday_in`：签名行 = `time_weekday_in(weekday_list, zone)`，示例含 `time_weekday_in("0|6", "H")` 与 `time_weekday_in("1|2|3|4|5", "H")`（国内规则显式写 `"H"` 时区）。
4. `intent → in`：签名行 = `req_ai_intent_in(question_name, value_list, min_confidence)`，示例含 `req_ai_intent_in("task_type", "test_writing|doc_writing", 0.9)`。
5. 四次悬停均**只有可见的 tooltip 弹层**参与断言（弹层常驻 body，须按可见性过滤）。

#### 测试数据

- 复用环境既有 Global 路由表（零写入）。

#### 补充说明

- 抽查项对应变更记录 §1 的问题 4/5/6（签名与参数名按文档逐字修正、示例按文档修正）与 `2026-10-16-bfe-condition-doc-sync` 新增的 `time_weekday_in`、`req_ai_intent_in`。
- 断言取 `tooltip 内签名行（`.vars-expression-title`）+ 示例片段（含 `.vars-expression-name` 的 `v-html` 内容）`：示例是 `v-html` 注入的 `<p>` 段落，按**片段级**断言以免绑定 `<p>`/`<br/>` 结构。含 `route.tipExpression`（`示例：`）前缀的原语不单独断言前缀文案。
- 自动化：`tests/route/test_14_route_expression_primitive_panel.spec.js`（RT-E-10）。

### RT-E-11：点击插入语义与查看模式只读面板

**功能模块**: 表达式/条件原语面板
**优先级**: P0
**用例编号**: RT-E-11
**源码依据**: `ai-gateway-web/src/components/Expression/index.vue:137-166`

#### 前置条件

1. 管理员视角，进入路由规则详情页编辑模式，打开「添加规则」抽屉。
2. 表达式输入框初值置为合法表达式 `req_host_in("a")`。

#### 测试步骤

1. 点击「逻辑连接符」组的 `&&`。
2. 点击 port 组的 `in`。
3. **再次**点击 port 组的 `in`（连点）。
4. 点击 clientIP 组的 `range`。
5. 观察每次点击后的表达式文本与 `PATCH /open-api/v1/expression/verify` 请求次数。
6. 对照组：编辑模式下观察原语按钮 class 与表达式输入框可编辑性。
7. 查看模式下观察原语按钮 class、表达式输入框可编辑性，并点击 `clientIP → range`、`&&`。

#### 预期结果

1. 点击原语按钮是**向表达式末尾追加模板**（非光标插入）：`req_host_in("a")` + `&&` → `req_host_in("a")&&`。
2. 追加模板为该原语的 `expression` 模板：port `in` → `req_port_in("")`，clientIP `range` → `req_cip_range("", "")`（含双引号空参）。
3. **连点会粘接**、不补分隔符：两次点击 port `in` → `req_host_in("a")&&req_port_in("")req_port_in("")`。
4. 每次点击触发**一次** `PATCH /open-api/v1/expression/verify`（方法为 `PATCH`，见 `src/utils/request.js:57` 的 `/open-api/v1/` 前缀）。
5. 查看模式（`readonly` 为真）下：**全部 63 个原语按钮带 `.readonly` class**、表达式 textarea 置灰不可编辑；点击原语**无任何效果**——表达式文本不变、**不发** `expression/verify` 请求。
6. 编辑模式为对照组：原语按钮**不带** `.readonly`、textarea 可编辑。

#### 测试数据

- 复用环境既有 Global 路由表，表达式初值 `req_host_in("a")`（合法表达式，点击后仍在本地抽屉内，不提交）。

**数据策略（复用环境，零写入）**：全部操作只改抽屉内本地表单状态，**不提交规则**；收尾关闭抽屉并放弃本地变更，断言后端 Global 路由规则未改动。

#### 补充说明

- **查看模式在当前产品无 UI 入口**（组件置位说明，也是本用例的已知产品缺口）：`RouteRules.vue:118` 把 `:readonly="mode === 'view'"` 传给 RuleForm，但
  ① 视图模式规则行操作列只渲染「查看」（`RouteRules.vue:296-302`），打开的是 `RuleView`（只读信息面板，**不含**原语面板）；
  ② 含面板的规则抽屉只由 `onAddRule` / `onEditRule` 打开（`RouteRules.vue:458-475`），二者都要求 `mode === 'edit'`；
  → `mode === 'view'` 且抽屉打开的组合在 UI 上不可达，只读分支属「防御性实现」。
  自动化按仓库既有 `__vue__` 手法（先例：`pages/resource/BusinessClusterPage.js` 的 `openCreateBusinessClusterDrawerByModel`）把 `RouteRules.mode` 置位为 `'view'`（抽屉保持打开），**只改 UI 状态、不发写请求**，对照组为同一抽屉的编辑模式——两组唯一差异是 `readonly` 取值。该产品缺口建议由产品侧补「行内查看抽屉入口」或在规则抽屉复用只读面板后再回归本用例。
- 只读判定的两个层面：按钮 class `.readonly`（`Expression/index.vue:41-45` 的 `:class` 绑定）与点击被拦截（`onBtnClick` 首行 `if (this.readonly) return;`，`Expression/index.vue:160-166`），本用例两者都断言。
- textarea 置灰来自 `:disabled="readonly"`（`Expression/index.vue:50-57`）。
- 自动化：`tests/route/test_14_route_expression_primitive_panel.spec.js`（RT-E-11，两条 test：追加语义 / 只读面板）。
