## 1. 列表与双模式

### TM-L-01：进入流量镜像规则列表页

**功能模块**: 列表与双模式
**优先级**: P1
**用例编号**: TM-L-01
**设计依据**: `src/modules/TrafficMirror/index.vue`（mounted 并发 fetchClusters/fetchRules）、`trafficMirror.pageTitle`

#### 前置条件

- 已登录且具备 `FeatureTrafficMirror + ActionRead` 权限
- 镜像目标集群数据可用

#### 测试步骤

1. 通过导航「路由管理 → 功能增强 → 流量镜像规则」进入页面
2. 观察页面头部标题与右上角按钮区
3. 观察表格区域

#### 预期结果

1. 页面路由名 `TrafficMirrorRule.list`；进入时并发发起 `GET /traffic-mirror-rules` 与 `GET clusters`（均 openapi）
2. 头部标题为「流量镜像规则（集合级，按优先级顺序匹配，首条命中生效）」；右上角视图模式仅显示「进入编辑模式」
3. 表格加载期间显示 loading，加载完成后按接口数组顺序展示规则行

### TM-L-02：列表展示七列且与接口数据一致

**功能模块**: 列表与双模式
**优先级**: P0
**用例编号**: TM-L-02
**设计依据**: `index.vue buildRuleColumns()`（7 列）、`$t('com.operation')`

#### 前置条件

- `GET /traffic-mirror-rules` 返回非空集合（含规则示例一/二/三）

#### 测试步骤

1. 进入页面，核对表头列
2. 逐列核对行数据与接口返回字段

#### 预期结果

1. 表头 7 列依次为：规则名、生效条件、镜像集群、采样比例、头部剔除、路径改写、操作
2. 各列渲染对应字段：规则名 / 生效条件 / 镜像集群 / 采样比例（百分比文案）/ 头部剔除文案 / 路径改写 / 操作按钮
3. 规则名、生效条件、镜像集群、路径改写列为空时显示 `-`；采样比例列为空时显示 `-`
4. 列标题文案与 i18n 一致，无多余列

> 说明（2026-10-15 校准）：第 1 列列头文案原写作「规则名称」，与产品实际不符。`index.vue buildRuleColumns()` 第 1 列取 `$t('route.ruleName')`，i18n `zh.js` 中该键的值为**「规则名」**（`trafficMirror` 命名空间没有独立的名称列标题键）；本用例第 1 列标题据此校准为「规则名」。「规则名称」仍是该业务字段的名称（输入框占位、校验提示、查重提示均沿用「规则名称」）。

### TM-L-16：提交并生效成功

**功能模块**: 列表与双模式
**优先级**: P0
**用例编号**: TM-L-16
**设计依据**: `index.vue submitRules()`、`trafficMirror.submitSuccess`

#### 前置条件

- 已进入编辑模式且集合有改动；集合内规则名称/生效条件均唯一

#### 测试步骤

1. 点击「提交并生效」
2. 观察按钮状态与请求
3. 等待响应完成

#### 预期结果

1. 提交前先执行集合内规则名称/生效条件去重校验（通过）
2. 按钮进入 loading（`submitting=true`）
3. 发起 `PUT /traffic-mirror-rules`，请求体为 `{rules:[...]}`
4. 返回 200 时提示「提交并生效成功！」，`originalRows` 置空，`mode` 回 `view`，执行 `fetchRules` 重新 GET 回填只读字段；loading 结束
