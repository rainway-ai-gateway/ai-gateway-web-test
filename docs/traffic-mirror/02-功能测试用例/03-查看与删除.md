### TM-D-08：查看抽屉与列表展示数据同接口响应一致性-全字段核对

**功能模块**: 查看与删除
**优先级**: P1
**用例编号**: TM-D-08
**设计依据**: `traffic-mirror-rules.md` §2.2（GET 响应数据模型与只读字段）；`index.vue` `fetchRules()` / `buildRuleColumns()` / `removeHeadersText()`；`RuleView.vue` `percentageText` / `headerViewText` / `setHeadersView` / `bodyRewritesView`

#### 前置条件

- `GET /traffic-mirror-rules` 返回 200，`Data.rules` 至少含 2 条规则，覆盖：含设置请求头与请求体改写的规则、含自定义头部剔除的规则、路径改写有值与留空的规则
- 已保存本次 GET 的完整响应 JSON，供逐字段核对；当前处于视图模式

#### 测试步骤

1. 记录列表「规则名 / 生效条件 / 镜像集群 / 采样比例 / 头部剔除 / 路径改写」各列取值
2. 依次打开每条规则的「查看」抽屉，记录 8 个只读信息行取值
3. 将列表与抽屉展示值同保存的响应 JSON 逐字段核对
4. 刷新页面（重新 `GET /traffic-mirror-rules`），再次核对

#### 预期结果

1. 列表行数与响应 `Data.rules` 数组长度一致，行顺序与数组顺序一致（顺序即优先级 / first-match-wins）
2. 列表「规则名」「生效条件」「镜像集群」「路径改写」分别等于响应中的规则名称、生效条件、镜像集群、路径改写（空值展示占位 `-`）
3. 列表与抽屉「采样比例」均按响应中的采样比例展示 `{value}%`（如 `10%`、`0%`、`100%`；若某规则响应中采样比例缺省，列表展示占位 `-`、抽屉按默认值展示 `100%`，属两处展示口径差异而非数据不一致）
4. 列表与抽屉「头部剔除」一致：响应头部剔除为非空数组 → 以「, 」连接（如 `Authorization, Cookie, X-Api-Key`）；为 `[]` → 「不剔除任何头部」；缺省 → 「默认黑名单（Authorization / Cookie / X-Api-Key）」
5. 抽屉「规则名」「生效条件」「镜像集群」「路径改写」与列表及响应逐字段一致（「生效条件」以等宽字体展示）
6. 抽屉「设置请求头」按设置请求头键值对逐行展示 `key：value`（全角冒号），行顺序与 `Object.keys` 顺序一致；为空对象 / 缺省 → 展示「无」
7. 抽屉「请求体改写」按请求体改写数组顺序逐行展示 `path → value`；为空数组 / 缺省 → 展示「无」
8. 界面（列表与抽屉）**不展示**响应只读字段创建时间 / 更新时间
9. 刷新后重复步骤 1~2，各展示值仍与最新 GET 响应逐字段一致

> 说明（2026-10-15 校准）：文中「规则名」为产品实际列头与抽屉标签文案（原文写作「规则名称」，同 TM-D-02 校准）；其余列头 / 标签（生效条件、镜像集群、采样比例、头部剔除、路径改写）与产品一致。

**优先级**: P0

- 集合内存在 ≥2 条规则

2. 删除其中一条规则并确认
