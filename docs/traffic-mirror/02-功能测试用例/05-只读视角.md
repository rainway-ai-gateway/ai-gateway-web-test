## 5. 只读管理员视角（写操作隐藏）

> 变更依据：`design-docs/modifications/2026-10-12-readonly-admin/ui-code-changes.md`（已 Review 通过）。
> 后端以 `role` 枚举取代 `is_admin`（`system_admin` / `system_admin_readonly`）；只读视角（`role === 'system_admin_readonly'`）**全站隐藏所有写操作按钮**，仅保留只读入口（查看 / 详情 / 查询）。前端实现为全局指令 `v-has`：只读登录态下给挂载元素加 `.v-has-hidden { display:none !important; }`。
> 依据 §3.4：`pages/traffic-mirror.html` 只读视角**保留「查看」**，**隐藏「添加规则 / 进入(退出)编辑 / 提交并生效」**；§4：render 操作列用 `directives: [{ name: 'has' }]`，显示分支由 `isReadonly || mode === 'view'` 收敛为 `mode === 'view'`（只读恒停留 view 模式，保留只读「查看」入口）。

### TM-RO-01：只读视角页头工具栏写按钮隐藏

**功能模块**: 流量镜像规则
**优先级**: P0
**用例编号**: TM-RO-01
**OpenAPI**: `GET /traffic-mirror-rules`

#### 前置条件

1. 以**只读系统管理员**登录（`role=system_admin_readonly`，原型 `viewer` 账号语义）。
2. 「流量镜像规则」菜单可达并进入页面，处于视图模式。

#### 测试步骤

1. 进入「流量镜像规则」页面。
2. 观察页头右上角按钮区。
3. 逐项核对页头写操作入口的可见性。

#### 预期结果

1. 页头**不显示**「进入编辑模式」按钮（对应场景二中管理员可见的模式切换入口）。
2. 只读视角下页头不含「提交并生效」等任何写入口，页面恒停留视图模式。
3. 切换为系统管理员（`role=system_admin`）登录时，页头「进入编辑模式」按钮正常显示（对照组）。

#### 测试数据

- 只读账号：`role=system_admin_readonly`
- 管理员账号：`role=system_admin`
- **数据策略**：**复用环境既有账号**（`conf.json` 的 admin + 只读账号 `viewer`），本用例**不造数、不清理**；只做可见性断言，不发起任何写请求。自动化见 `tests/traffic-mirror/test_06_traffic_mirror_rule_readonly.spec.js` 的 TM-RO-01。

#### 补充说明

- 隐藏实现：写按钮挂全局指令 `v-has`，只读视角加 `.v-has-hidden`（`display:none !important`）；前端隐藏外，后端对写端点 `PUT /traffic-mirror-rules` 做 403 兜底。

### TM-RO-02：只读视角列表操作列写按钮隐藏仅保留查看

**功能模块**: 流量镜像规则
**优先级**: P0
**用例编号**: TM-RO-02
**OpenAPI**: `GET /traffic-mirror-rules`

#### 前置条件

1. 以**只读系统管理员**登录，集合内已存在至少 1 条镜像规则。

#### 测试步骤

1. 进入「流量镜像规则」页面，观察列表「操作」列。
2. 点击某规则行的「查看」。

#### 预期结果

1. 操作列**保留**「查看」只读入口（不隐藏）。
2. 操作列**不显示**「编辑」「删除」等写操作按钮（对应编辑模式下管理员可见的行操作）。
3. 点击「查看」仍可打开只读抽屉，纯文案展示规则字段（查看能力保留）。
4. 管理员视角下（进入编辑模式后）操作列的「编辑」「删除」正常显示（对照组）。

#### 测试数据

- 只读账号：`role=system_admin_readonly`
- 存在 1 条以上镜像规则；建议含头部剔除三态样本
- **数据策略**：镜像规则为**集合级**配置（`PUT /traffic-mirror-rules` 整体替换），故自动化在 `beforeAll` 用独立 admin context 对集合做**快照**，并**优先复用集合内既有规则**（取 `GET /traffic-mirror-rules` 首条为目标行，满足本段「存在 1 条以上」的前置）；仅当集合为空时才经 API **补入 1 条测试规则**兜底（`mirror_cluster` 取 `GET /clusters` 首项，避免引用校验 422）。`afterAll` 用快照**整体 PUT 还原**（复用时为幂等写回）。只读断言只读不写。

#### 补充说明

- 依据变更记录 §3.4 / §4：只读视角操作列显示分支收敛为 `mode === 'view'`，仅渲染只读「查看」按钮。

### TM-RO-03：只读视角添加规则与提交并生效写入口不可达

**功能模块**: 流量镜像规则
**优先级**: P0
**用例编号**: TM-RO-03

#### 前置条件

1. 以**只读系统管理员**登录，处于视图模式。

#### 测试步骤

1. 进入「流量镜像规则」页面。
2. 尝试触发「添加规则」（如列表工具栏 / 抽屉入口）。
3. 尝试触发「提交并生效」（页头按钮区）。

#### 预期结果

1. 由于「进入编辑模式」在只读视角隐藏，页面恒停留视图模式，编辑模式专有的「添加规则」入口不可达（不渲染）。
2. 「提交并生效」写按钮不可达（不渲染），无任何写提交路径。
3. 视图模式下仅保留「查看」与只读检索/排序能力。
4. 管理员视角下可正常进入编辑模式、打开「添加规则」抽屉并「提交并生效」（对照组）。

#### 测试数据

- 只读账号：`role=system_admin_readonly`
- 管理员账号：`role=system_admin`
- **数据策略**：账号复用环境既有；规则集合沿用 TM-RO-02 的「快照 → 复用（集合为空则补 1 条）→ `afterAll` 还原」策略，本用例自身**不额外造数**。只读步骤只做可见性/不渲染断言，并用请求监听断言**未发出任何 `PUT /traffic-mirror-rules`**（无写提交路径）。

#### 补充说明

- 依据变更记录 §3.4：`pages/traffic-mirror.html` 只读视角隐藏「添加规则 / 进入(退出)编辑 / 提交并生效」，编辑态入口整体不可达；前端隐藏外，后端对 `PUT /traffic-mirror-rules` 做 403 兜底。
