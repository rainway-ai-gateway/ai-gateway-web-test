# 用户管理模块 - 测试场景概览

## 模块概述

用户管理模块是AI网关系统的核心功能模块,负责系统用户的创建、维护、权限管理以及登录认证等操作。该模块包含用户管理、Token管理、登录认证和注销功能四大功能区域。

## 用户角色

| 角色 | 说明 | 权限范围 |
| ------ | ------ | --------- |
| 系统管理员 | 拥有系统全部管理权限 | 用户管理、Token管理、系统配置等全部功能 |
| 系统管理员（只读） | 拥有全站页面的只读视角（`role=system_admin_readonly`） | 可查看全部管理页面；全站写操作按钮隐藏，写能力由后端 403 强制 |
| 普通用户 | 仅能访问被授权的业务功能 | 仅能使用分配的业务功能,无法管理系统用户 |

## 核心变更依据

- 2026-10-12（变更记录 `modifications/2026-10-12-readonly-admin/ui-code-changes.md`）：引入「系统管理员（只读）」角色，后端以 `role`（string，`system_admin` / `system_admin_readonly`）取代 `is_admin`（bool）；新增 `PATCH /auth/users/{user_name}/role` 端点；Token `scope` 增 `SystemReadonly`；只读视角全站隐藏写操作按钮、密钥 / Token 读端点返回掩码值。

本轮语义要点：

- **role 取代 is_admin**：用户对象 / 列表 / 详情字段由 `is_admin`（bool）改为 `role`（string），枚举 `system_admin`（系统管理员）/ `system_admin_readonly`（系统管理员（只读））。
- **创建用户**：`POST /auth/users` Body 由 `is_admin`（固定 true）改为 `role`（string，**必填**，枚举两值）。
- **变更角色端点**：`PATCH /auth/users/{user_name}/is_admin` 改为 `PATCH /auth/users/{user_name}/role`，Body `role`（枚举）；内置账号 `admin`（大小写不敏感）role 固定 `system_admin`，降级请求返回 **422**；旧 `is_admin` 端点废弃（404）。
- **登录态**：`POST /auth/session-keys` 由 `is_admin`（bool）改 `role`（string）；前端登录态存 `role`，`store.isReadonly()` 判只读。
- **Token scope 三档**：`System`（系统管理）/ `SystemReadonly`（系统管理（只读））/ `Support`（内部支持）。
- **只读视角**：菜单与 admin 一致（nav key `admin_readonly`），页面可读、写能力由后端 403 强制；全站只读视角隐藏所有写操作按钮（全局指令 `v-has` 加 `.v-has-hidden`，`display:none !important`），仅保留只读入口（详情 / 查看 / 查询）；Token 详情 / 列表 `token` 字段只读视角返回掩码值。

## 场景测试设计

本模块采用**场景测试**方法,从真实用户的使用流程出发,模拟用户在特定情境下完整操作系统,验证系统是否能正常工作。

### 场景一: 管理员入职新员工

**场景描述**: 系统管理员为新入职的同事创建账号并分配权限,新员工首次登录系统。

**涉及测试场景**:

| 步骤 | 操作 | 对应场景编号 | 优先级 |

| 1 | 管理员登录系统 | UM-32 | P0 |
| 2 | 进入用户管理页面,查看现有用户列表 | UM-01 | P1 |
| 3 | 点击"添加用户",填写用户名、密码，验证角色为默认系统管理员 | UM-04 | P0 |
| 4 | 验证密码不匹配时的校验 | UM-05 | P1 |
| 5 | 验证必填项校验(空提交) | UM-06 | P1 |
| 6 | 验证重复用户名的处理 | UM-07 | P1 |
| 7 | 验证用户名格式与密码规则 | UM-36、UM-37、UM-08 | P0 |
| 8 | 验证重置表单功能 | UM-09 | P2 |
| 9 | 验证关闭弹窗不添加用户 | UM-10 | P2 |
| 10 | 搜索新添加的用户,验证列表和分页 | UM-02, UM-03 | P1 |
| 11 | 新员工使用新账号首次登录系统 | UM-32（二次执行） | P0 |

**测试目标**: 验证管理员能否顺利完成新员工的账号创建和权限分配,系统各项校验机制是否正常工作,新员工能否正常登录。

## 测试环境要求

- 浏览器: Chrome / Firefox / Safari 最新版本
- 分辨率: 1920×1080
- 网络: 可访问AI网关管理控制台
- 前置条件: 系统已部署并正常运行
- 会话前提: 后端每个用户只保留 1 个 Session Key，任意一次登录都会作废之前的 Key。测试框架已在导航入口内置**框架级会话自愈（2026-10-15）**——检测到「Session Key 错误」模态框或 Key 探测 401 时自动重新登录并回写 `auth.json`，无需人工干预；但**仍应避免两个会话/两轮跑测并发**（互踩只能靠自愈兜住）。

## 测试数据准备

| 数据类型 | 格式/示例 | 说明 |
| --------- | ---------- | ------ |
