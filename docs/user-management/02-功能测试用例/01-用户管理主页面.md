## 1. 用户管理主页面

> **归属场景**: 场景一(管理员入职新员工)、场景二(管理员日常用户维护)

### 1.1 用户列表展示

**功能模块**: 用户管理主页面  
**优先级**: P1  
**用例编号**: UM-01

#### 前置条件

- 系统已正常运行
- 已使用管理员账号登录系统
- 系统中已存在至少一个用户

#### 测试步骤

1. 打开浏览器，访问AI网关管理控制台
2. 在左侧导航栏中，找到并点击"用户管理"菜单项
3. 观察页面加载情况
4. 查看页面中间区域的用户列表表格

#### 预期结果

- 页面成功加载，显示"用户管理"标题
- 页面顶部显示两个Tab页签："用户"和"Token"，默认选中"用户"Tab
- 左侧显示蓝色"添加用户"按钮
- 下方显示搜索框，占位文字为"请输入用户查询"
- 用户列表表格正确显示，包含以下列：
  - 用户列：显示用户名（如admin）
  - 角色列：显示用户角色（"系统管理员" / "系统管理员（只读）"）
  - 操作列：包含"变更角色"、"修改密码"（蓝色按钮）和"删除"（红色按钮）
- 页面底部显示分页控件，包含：
  - 每页显示条数下拉框（默认"20条/页"）
  - 页码导航按钮（上一页、页码、下一页）
- 列表中的用户信息与数据库中存储的数据一致
- **长文本布局**：表格列长文本截断或折行，不撑破列宽

#### 测试数据

- 用户名：admin
- 角色：系统管理员

#### 备注

- 需要验证列表是否支持排序功能（如有排序图标）
- 验证空数据状态下的页面展示（如系统中无任何用户）

### 1.2 用户搜索功能

**功能模块**: 用户管理主页面  
**优先级**: P1  
**用例编号**: UM-02

#### 前置条件

- 已登录系统并进入用户管理页面
- 系统中存在多个用户（至少2个不同用户名）

#### 测试步骤

1. 在用户管理页面的搜索框中，输入已存在用户的部分用户名（如"adm"）
2. 观察列表变化
3. 清空搜索框内容，再次观察列表变化
4. 输入不存在的用户名（如"testuser999"）
5. 观察列表变化

#### 预期结果

- 步骤2：列表实时过滤，仅显示用户名包含"adm"的用户记录
- 步骤3：列表恢复显示所有用户
- 步骤5：列表显示为空，或提示"未找到匹配的用户"
- 搜索过程中页面不刷新，实现实时过滤或回车后过滤

#### 测试数据

- 搜索关键字1：adm（部分匹配）
- 搜索关键字2：admin（完全匹配）
- 搜索关键字3：testuser999（不存在的用户）

#### 备注

- 验证搜索是否支持模糊匹配
- 验证搜索是否区分大小写
- 验证搜索结果数量较大时的分页显示

### UM-44：用户列表接口数据与页面展示一致性

**功能模块**: 用户管理主页面  
**优先级**: P1  
**用例编号**: UM-44  
**OpenAPI**: GET /auth/users

#### 前置条件

- 已使用管理员账号登录系统
- 系统中已存在至少 2 个用户（用户名可区分，如 `admin`、`user_demo`）
- 用户管理页面默认「用户」Tab 已加载用户列表

#### 测试数据参考（接口 GET /auth/users 返回体示例）

```json
{
    "ErrNum": 200,
    "ErrMsg": "success",
    "Data": [
        {
            "user_name": "admin",
            "role": "system_admin"
        },
        {
            "user_name": "user_demo",
            "role": "system_admin_readonly"
        }
    ]
}
```

#### 测试步骤

1. 打开浏览器开发者工具 Network 面板，进入「用户管理」页面并确保「用户」Tab 处于选中状态
2. 触发/捕获 `GET /auth/users` 请求，记录其返回体中 `Data` 数组的元素（依次记为 `Data[0]`、`Data[1]`…）
3. 逐行比对表格每行「用户」「角色」列展示值，与 `Data[]` 对应元素的 `user_name`、`role` 字段
4. 查看分页控件显示的总条数，与 `Data` 数组长度比对

#### 预期结果

字段比对（校验方式 = 文本一致/数值一致/数组逐项比对，与接口返回 JSON 一致）：

- **user_name**（文本一致）：表格「用户」列（列标题 `user.name` = 「用户」）逐行展示的用户名，与接口 `Data[i].user_name` 完全相同
- **role**（文本一致，含角色映射）：表格「角色」列（列标题 `user.role` = 「角色」）展示值由 `role` 映射渲染——`system_admin` 渲染为「系统管理员」（`com.sysAdmin`），`system_admin_readonly` 渲染为「系统管理员（只读）」（`com.sysAdminReadonly`）；任一行的角色文案与接口 `role` 映射一一对应，无错配
- **Data 数组**（数组逐项比对，顺序一致）：表格默认无排序时，第 i 行对应 `Data[i]`，行数与顺序与接口数组一致，不多不少
- **操作列**（无对应接口字段）：操作列（列标题 `com.operation` = 「操作」，含「变更角色」「修改密码」「删除」按钮）为页面静态渲染列，不对应接口字段，不参与数据比对
- **分页 total**（数值一致）：接口 `Data` 为完整数组、无服务端分页与 `total` 字段，页面采用客户端分页；分页控件显示的总条数应等于 `Data.length`（即表格数据行数总和）

**一致性比对矩阵**：

| UI 展示项 | 接口字段 | 校验方式 | 通过标准 |
| --------- | --------- | --------- | --------- |
| 用户列（逐行） | `Data[i].user_name` | 文本一致 | 与接口值逐字符相同 |
| 角色列（逐行） | `Data[i].role` | 文本一致（角色映射） | `system_admin` → 「系统管理员」，`system_admin_readonly` → 「系统管理员（只读）」 |
| 表格行集合 | `Data[]` | 数组逐项比对（顺序一致） | 行数与顺序与接口数组完全一致 |
| 分页控件总条数 | `Data`.length | 数值一致 | 等于接口返回数组长度 |
| 操作列 | —（无对应字段） | 不适用 | 静态操作列，不参与数据比对 |

**整体预期**：

1. 进入/刷新用户列表时调用 `GET /auth/users`，接口返回 200
2. 表格每一行的「用户」「角色」展示值与接口 `Data[]` 逐项对应，无遗漏、无错配
3. 分页控件总条数与接口返回数组长度一致
4. 列顺序为「用户 / 角色 / 操作」，与页面既有列定义一致
