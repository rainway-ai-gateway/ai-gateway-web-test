## 4. 删除用户

> **归属场景**: 场景二(管理员日常用户维护)
>
> **自动化造数校准（2026-10-15）**：`test_04_user_delete.spec.js` 用 `POST /auth/users` 造「待删除用户」，请求体必填 `role`（`system_admin` / `system_admin_readonly`，旧 `is_admin` 字段已被产品废弃并返回 422）；点行操作「删除」前先按「用户」列筛选目标用户名，使定位与分页（默认 20 条/页）解耦。

### 4.1 删除用户-成功场景

**功能模块**: 删除用户  
**优先级**: P0  
**用例编号**: UM-18

#### 前置条件

- 已登录系统并进入用户管理页面
- 用户列表中存在需要删除的用户（非当前登录用户）

#### 测试步骤

1. 在用户列表中找到目标用户
2. 点击该用户操作列中的"删除"红色按钮
3. 页面中间弹出"信息提示"确认对话框
4. 确认对话框内容显示："是否删除用户{用户名}？"
5. 点击对话框中的"确定"蓝色按钮
6. 观察对话框是否关闭
7. 在搜索框中输入刚删除的用户名进行搜索
8. 验证用户是否从列表中消失

#### 预期结果

- 步骤3：弹出模态确认对话框，背景变灰
- 步骤4：对话框标题为"信息提示"，带有黄色问号图标
- 步骤5：点击"确定"后
- 步骤6：对话框关闭
- 步骤7-8：搜索结果显示为空，用户已从列表中删除
- 页面可能显示成功提示信息
- 该用户无法再登录系统
- **确认弹窗**：弹窗包含超长用户名时文案正常展示，按钮可点击

#### 测试数据

- 目标用户：之前创建用于测试的用户

#### 备注

- 验证删除操作是否可撤销
- 验证删除后相关数据（如Token）的处理

**优先级**: P1  
**用例编号**: UM-19

#### 备注

### UM-55：删除当前登录用户（提示并强制退出）

**功能模块**: 删除用户  
**优先级**: P1  
**用例编号**: UM-55  
**自动化**: `tests/user/test_12_user_password_effect_and_self_delete.spec.js`  
**设计依据**: `User.vue` `onDelAdminUser`：删除成功且 `user.name === name` 时弹 `$Modal.error`（`user.tipUserDel`），确定后跳 `/login`；否则仅刷新列表

#### 前置条件

- 管理员创建测试用户 U 后，**以 U 身份登录**（角色 system_admin）

#### 测试步骤

1. 进入用户管理，搜索到 U 自己的行
2. 点「删除」→ 确认
3. 观察弹窗与页面跳转
4. 管理员登录复核 U 是否已被删除

#### 预期结果

1. 删除成功（后端 200）
2. 弹出「**当前用户已被删除请重新登录**」（已核实：弹窗确实出现）
3. ⚠️ **实际行为（2026-11-01 实测）**：DELETE 返回 200（用户确实被删），但页面**没有任何弹窗、也不跳转**，停留在已失效的列表页
   —— `onDelAdminUser` 中「当前用户已被删除请重新登录」分支未触发。用例以 `test.fail` 固化文档预期（弹窗 + 强制退出），登记为缺口 #86
4. 管理员复核：列表中已无 U（删除本身生效）

> 审计背景（2026-11-01）：该分支（自删 → 强制退出）是 `User.vue` 的独立逻辑，此前无用例。
