## 10. 角色与只读视角

> **归属场景**: 场景五(只读管理员视角)

### UM-45：用户列表角色列展示

**功能模块**: 角色与只读视角  
**优先级**: P0  
**用例编号**: UM-45  
**OpenAPI**: `GET /auth/users`

#### 前置条件

1. 已使用系统管理员账号登录系统。
2. 用户列表中存在 `role=system_admin` 与 `role=system_admin_readonly` 的用户各至少一个（如 `admin`、`viewer`）。

#### 测试步骤

1. 进入「用户管理」页面，确保「用户」Tab 选中。
2. 观察列表「角色」列每行的展示值。
3. 与接口 `GET /auth/users` 各元素的 `role` 字段比对。

#### 预期结果

1. 「角色」列由 `role`（string）渲染，不再有 `is_admin` 布尔列。
2. `role=system_admin` → 展示「系统管理员」。
3. `role=system_admin_readonly` → 展示「系统管理员（只读）」。
4. 任一行的角色文案与接口 `role` 映射一一对应，无错配。

#### 测试数据

1. `system_admin` → 「系统管理员」
2. `system_admin_readonly` → 「系统管理员（只读）」

#### 补充说明

- 角色文案 key：`com.sysAdmin`、`com.sysAdminReadonly`（以 i18n 为准）。

### UM-46：用户角色筛选

**功能模块**: 角色与只读视角  
**优先级**: P0  
**用例编号**: UM-46

#### 前置条件

1. 已登录系统并进入「用户管理」页面。
2. 用户列表中同时存在系统管理员与系统管理员（只读）用户。

#### 测试步骤

1. 打开「角色」筛选控件，核对可选项。
2. 选择「系统管理员」，观察列表。
3. 选择「系统管理员（只读）」，观察列表。
4. 清空筛选，观察列表。

#### 预期结果

1. 筛选项枚举为 `system_admin`（系统管理员）、`system_admin_readonly`（系统管理员（只读）），不再有 `is_admin` 布尔项。
2. 选中「系统管理员」后仅命中 `role=system_admin` 的行。
3. 选中「系统管理员（只读）」后仅命中 `role=system_admin_readonly` 的行。
4. 清空后恢复显示全部用户。

#### 测试数据

1. `system_admin` → 仅系统管理员行
2. `system_admin_readonly` → 仅只读系统管理员行

### UM-47：变更角色成功（普通用户）

**功能模块**: 角色与只读视角  
**优先级**: P0  
**用例编号**: UM-47  
**OpenAPI**: `PATCH /auth/users/{user_name}/role`

#### 前置条件

1. 以系统管理员登录并进入「用户管理」页面。
2. 列表中有一个非内置账号的用户（如 `user_demo`，当前 `role=system_admin`）。

#### 测试步骤

1. 在该用户操作列点击「变更角色」。
2. 观察抽屉内角色单选控件与默认值。
3. 选择「系统管理员（只读）」，点击提交。
4. 观察抽屉关闭与列表「角色」列刷新。

#### 预期结果

1. 操作列存在「变更角色」入口，点击后打开角色变更抽屉。
2. 抽屉内为角色单选：「系统管理员」/「系统管理员（只读）」，默认选中该用户当前角色。
3. 提交发起 `PATCH /auth/users/{user_name}/role`，Body 为 `{ "role": "system_admin_readonly" }`。
4. 提交成功后抽屉关闭，列表该用户「角色」列刷新为「系统管理员（只读）」。

#### 测试数据

1. `role`：`system_admin` → `system_admin_readonly`
2. 请求体：`{ "role": "system_admin_readonly" }`

### UM-48：内置 admin 账号角色不可变更

**功能模块**: 角色与只读视角  
**优先级**: P0  
**用例编号**: UM-48  
**OpenAPI**: `PATCH /auth/users/{user_name}/role`

#### 前置条件

1. 以系统管理员登录并进入「用户管理」页面。
2. 用户列表中存在内置账号 `admin`。

#### 测试步骤

1. 对 `admin` 点击「变更角色」。
2. 观察抽屉内容。
3. 尝试选择「系统管理员（只读）」并提交（如可触发）。
4. 观察接口响应与页面提示。

#### 预期结果

1. 抽屉提示角色固定不可变更（如「管理员角色固定为系统管理员，不可变更」）。
2. 内置账号名 `admin` 判定大小写不敏感（如 `Admin` 同样受保护）。
3. 若强行提交降级请求，`PATCH /auth/users/admin/role` 返回 **422**，页面提示变更失败。
4. `admin` 的 `role` 保持 `system_admin` 不变。

#### 测试数据

1. 目标账号：`admin`（大小写不敏感）
2. 期望响应：422

### UM-49：创建用户角色单选

**功能模块**: 角色与只读视角  
**优先级**: P0  
**用例编号**: UM-49  
**OpenAPI**: `POST /auth/users`

#### 前置条件

1. 以系统管理员登录并进入「用户管理」页面。
2. 准备一个未被占用的用户名。

#### 测试步骤

1. 点击「添加用户」，打开创建用户抽屉。
2. 观察「角色」控件形态与默认值。
3. 分别选择「系统管理员」「系统管理员（只读）」并提交，抓取请求体。
4. 不选择角色（清空）后直接提交。
5. 观察响应与列表。

#### 预期结果

1. 「角色」由原来的「固定勾选系统管理员」改为**单选项**：「系统管理员」/「系统管理员（只读）」，默认选中「系统管理员」。
2. 角色为**必填**。
3. 提交体只含 `role`（string 枚举），**不再含 `is_admin`**。
4. 不选角色提交时提示角色必填，不发起请求。
5. 提交成功后列表新用户「角色」列展示所选角色文案。

#### 测试数据

1. `role`：`system_admin`（默认）/ `system_admin_readonly`
2. 请求体：仅含 `role`，不含 `is_admin`

### UM-52：只读视角用户管理页写按钮隐藏

**功能模块**: 角色与只读视角  
**优先级**: P0  
**用例编号**: UM-52

#### 前置条件

1. 以只读账号（`role=system_admin_readonly`，如 `viewer`）登录系统。
2. 已进入「用户管理」页面。

#### 测试步骤

1. 观察页面工具栏按钮。
2. 观察「用户」Tab 列表操作列。
3. 切换到「Token」Tab，观察操作列。
4. 打开某条 Token 的「详情」，查看 Token 值。

#### 预期结果

1. 工具栏「添加用户」「令牌创建」按钮隐藏（经全局指令 `v-has` 加 `.v-has-hidden`，`display:none !important`）。
2. 用户列表操作列仅保留只读入口，隐藏「变更角色」「修改密码」「删除」。
3. Token 操作列仅保留「详情」，隐藏「删除」。
4. Token 详情内 `token` 字段展示后端返回的**掩码值**（前端原样展示，不额外脱敏）。

#### 测试数据

1. 只读登录账号：`viewer`（`role=system_admin_readonly`）
2. Token `token` 字段：掩码值

#### 补充说明

- 写能力由后端 403 强制；前端隐藏仅为视角收敛。
