# 模块深度检查清单（覆盖率审计方法）

> **适用**：对任一模块做「用例设计质量 + 覆盖完整性」审计，产出可执行的修复项。
> **来源**：2026-10-30 cluster 模块深度审计的实战方法固化（该模块 5 轮审计发现并修复 20+ 问题，清单见 [覆盖缺口清单](./覆盖缺口清单.md)）。
> **配套**：`.trae/skills/module-coverage-audit/SKILL.md`（给 agent 的执行入口）、`npm run check:mapping`（映射核对脚本）。

## 1. 阶段一：文档↔索引↔spec 三方对账（先跑机器能查的）

```bash
# 1.1 模块规模与文档量
wc -l docs/<模块>/01-*.md docs/<模块>/02-功能测试用例/*.md tests/<模块目录>/*.spec.js

# 1.2 统计表 vs 索引行数逐组对齐（把 01 概览的「总计」与索引实际行数/优先级分布算清）
node -e "const fs=require('fs');const t=fs.readFileSync('docs/<模块>/02-功能测试用例/00-索引与映射.md','utf8');
const rows=t.split('\n').filter(l=>/^\| ?\[?[A-Z]/.test(l));const g={};for(const l of rows){
const m=l.match(/\|\[?([A-Z]+-[A-Z0-9]+)-/);const p=l.match(/\|(P[012])\|/);
if(m&&p){g[m[1]]=g[m[1]]||{P0:0,P1:0,P2:0};g[m[1]][p[1]]++;}}console.log(g,'total',rows.length)"

# 1.3 映射声明 ↔ spec 实际引用（权威脚本，0 失真才继续）
npm run check:mapping
```

**1.4 文档工程评级**（cluster 审计实际评过、必须落到结论表）：看四项——① 是否有版本化变更说明（每次 UI 变更能否追到依据链接）；② 是否有「测试问题复盘」并记录处置决策（不是只记现象）；③ 统计口径是否自洽（曾主动作废旧口径？）；④ 章节号/编号规则是否被遵守（`§N = 用例号N`、一用例一归属）。四项缺任一，文档工程记「中」以下并在发现表列出。

**必查失真类型**（cluster / route / api-key 均命中过）：
- 统计表滞后（新增用例只改索引不改统计）——route 85→91、cluster 多次
- 映射行过宽（`24~31` 但 spec 只含 24~29、31）或指错 spec（EM-K-30 声称 test_01、实际在 entity journey）
- 章节号错位（`§N = 用例号N` 规则被新增用例破坏）
- 「已评审（spec 待实现）」长期挂账（route RT-E-01~07 至今无 spec）

## 2. 阶段二：元素级对账（本方法的**核心增量**，其余模块大多没做过）

目标：回答「页面上每个控件，是否有断言覆盖它以哪种方式存在」。

```bash
# 2.1 从 Vue 源码提元素清单（label / 控件类型 / 条件渲染）
grep -n "FormItem\|i-switch\|<Select\|InputNumber\|v-if=\|v-show=" src/modules/<Module>/components/<X>.vue

# 2.2 从 spec 提断言指纹（helper 名即语义）
grep -rhoE "utils\.[a-zA-Z]+\(page" tests/<模块>/*.spec.js | sort | uniq -c | sort -rn
```

**2.2b 源码四读法（cluster 审计的真正杀招，逐条都要读，不能只靠 grep 模板）**

| 读什么 | 目的 | cluster 实证产出 |
|---|---|---|
| **模板**（FormItem/label/控件/`v-if`） | 元素清单 + 条件渲染边界 | `cancelOnClientClose` 只出现在 API payload（UI 零交互）、删行按钮零断言、`mask-closable=false` |
| **computed / 默认值函数**（如 Review.vue 的 `displayXxx`、`defaultXxx()`） | 渲染口径与「缺省展示什么」 | 复查页展示默认值补齐逻辑 → 设计「缺省/关闭态」断言 |
| **buildData / submit 构造** | 请求体契约的**唯一真相** | `buildData` 恒下发 `normalize_upstream_error` → 改正文档「缺省不提交」的错误预期 |
| **watch / applyXxx（回填）** | 存量/编辑态数据路径 | `applyLlmConfig` 对 `key_affinity.enabled` 的兜底默认是 `true`（**与新建默认 false 相悖，疑似缺陷**） |

> 附加判据：**同一表单在创建态与编辑态是两套代码路径**（`fillXxxStep` vs `applyXxx`/`syncFormWithProvider`）。只测创建态即视为编辑态未覆盖，必须在矩阵里单列一行。

**2.3 声明覆盖类型核对（`check:mapping` 查不到的一类失真）**

映射行声称的**覆盖类型**必须在 spec 中核对对应断言，而不只是「用例号出现过」：

| 声称 | 核对什么 | cluster 实证 |
|---|---|---|
| 复查/回显 | spec 中是否有读复查页/编辑回显的 helper 调用 | 索引称 key_affinity「复查归入 test_03」，`grep -c review test_06/07/08` = **0** → 声明失真 |
| 提交体 | 是否有 `postDataJSON()` 断言 | — |
| 边界值 | 是否覆盖上下界两端 | RM-BC-39 字节口径 |
| 只读 | 是否含后端拒绝探针 | RM-BC-RO 有探针才算达标 |

**矩阵模板**（每模块一张，逐字段填）：

| 字段/控件 | 默认值 | 条件显隐 | 必填/格式校验 | 边界值 | 提交体 | 复查/详情回显 | 编辑回显 | 元素特殊行为（删行/嵌套/disabled） |
|---|---|---|---|---|---|---|---|---|
| … | ✅/— | ✅/— | ✅/— | ✅/— | ✅/— | ✅/— | ✅/— | … |

> 空列即缺口。cluster 实战命中：`cancelOnClientClose` 仅出现在 API payload（UI 零交互）、模型映射「删行」零断言、会话保持关闭态显隐未测、列表搜索框封装零调用。

## 3. 阶段三：用例设计质量评价（六维度 + 标杆）

| 维度 | 合格线 | 标杆（cluster 实证） |
|---|---|---|
| 主路径 | 创建/编辑/详情/删除 + 约束 | 删除约束走「API 造引用 → 删 → 弹窗含引用名 → 前往处理」全链 |
| 字段校验 | 必填/格式/边界成体系 | 字段矩阵驱动；字节/字符口径区分（256 字节 vs 200 汉字） |
| 一致性 | UI ↔ OpenAPI | 提交体 `postDataJSON` 契约断言 + 详情/复查/编辑回显三处对账 |
| **状态语义** | 条件渲染的「休眠保留」有专例 | WRR↔EPP、off↔medium 往复切换值不丢 + 提交体不丢值 |
| 权限 | 只读按钮隐藏 | 附**后端拒绝探针**（402/403），不停留在「看不见」 |
| 跨模块 | 至少 1 条 journey | 主链全 UI 闭环 + 审计逐步核对 + 反序清理 |

**质量红线**：断言按 02 文档预期写、**不迁就实现**；实现与文档冲突时走「测试问题复盘」登记 → 用户决策 → 改文档或改实现，禁止静默弱化断言。

**每轮审计的最小交付**：至少 1 条新增/修复用例或 1 处文档失真修复——**只出报告不动手的审计不算完成**（cluster 首轮即修了 3 处文档脱节 + 补 test_12）。

## 4. 阶段四：场景与跨模块补强（journey 模板）

1. **主链闭环**：Provider →（API key/Entity）→ Cluster → Route → 部署可见；每步 UI 操作 + 审计核对 + 按依赖**反序清理**
2. **换依赖**：编辑态切换上游依赖（如换 Provider），断言旧数据处置（过滤/清空/保留）+ 提交体无旧残留 + GET 读回
3. **引用约束生命周期**：被引用删除拦截 → 前往处理 → 解引用 → 删除成功
4. **增强层叠加**：主链 + 缓存/镜像/意图等增强规则同会话配置面，验证互不阻塞、可反序拆除
5. **生命周期释放**：资源删除后关联分配/快照释放（如 EPP 集群 ↔ 实例组分配）
6. **审计反向核对**：写操作后按「资源名 + 动作」同格检索日志（见坑位 4.1）

## 5. 阶段五：系统性盲区扫描（逐项打勾）

| # | 盲区 | 最小落地 |
|---|---|---|
| 1 | 异常容错 | `page.route` 注入 500/延迟 → 不白屏 + 错误提示 + 恢复可用（注意 3s 竞态，坑位 4.1） |
| 2 | 幂等/防重 | 连点两次提交 → 同名仅一条 + 请求数 ≤2 |
| 3 | 并发/竞态 | 「API 侧变更 + UI 旧状态提交」构造，不用双窗口抖动型 |

| 5 | 大数据量 | 批量造数 → 末页可达 + 筛选精确 |
| 6 | 安全 | 密钥不落明文（响应/表格/请求体三处）；XSS 载荷按文本渲染无注入节点；URL 直访越权 |
| 7 | 角色矩阵 | admin / readonly / 普通用户 / Token 操作者 四视角 × 各模块入口 |
| 8 | 组合优先级 | **需产品先定义语义**，未定义不臆造 |

## 6. 阶段六：修复与验证闭环

**新增用例硬约束**（与 `.trae/skills/ai-gateway-test-generation` 一致）：
- spec 只调 `pages/`/`utils/`，零裸 selector；等待用 `waitForResponse`/轮询，禁 `waitForTimeout` 兜底
- 造数走 API + `track*` 登记，`afterEach` 按依赖反序清理（集群→路由→Provider 顺序错误会 409）
- 快照型资源（全局路由规则、缓存/镜像集合、意图配置单例）必须 `saveOriginalState` + `afterEach` 还原
- 用例编号 + spec 头注释写清映射；完成后同步「02 正文 / 00 索引 / 映射行」三件套

**验证顺序**：定向单测 → 受影响 spec 全量 → （必要时）模块全量 → `npm run check:mapping`。长批次（>10min）出现「会话自愈失败/sessionKey」类失败，先定向复跑，多为批次抖动（坑位 4.2）。

## 8. 实战坑位库（本次踩过，务必先读）

1. **iView Message 3s 竞态**：错误提示约 3s 自动消失。断言前必须**先挂 `waitForSelector` 再触发请求**（并发等待），否则必然假失败（ai-cache #33 首跑即此坑）。
2. **长批次会话抖动**：>10min 批次出现「重新登录后仍未取得 session key」属会话竞争假失败；定向复跑确认，勿据此判产品缺陷（#34/#35 回归 6 条失败复跑全绿）。
3. **审计写入异步 + 表格不自动刷新**：日志断言须「重试搜索」轮询；且**同一资源多条记录**（create/delete）时 `rowByText` 会命中首行 → 必须「资源名 + 动作」同一行过滤（entity #39 假失败过）。
4. **about:blank 会话读取**：API 工具在未导航页读 localStorage 抛 SecurityError；route-api 已加 auth.json 兜底，新工具照抄 `getUserData` 兜底模式。
5. **分页控件两套实现**：`PageTable.pagination()`/`pageNumberCount` 是 Element 选择器，iView 表格需 `lastPageNumber`（2026-10-30 新增）与 `li.number`；断言页码前先 `expect.poll` 等分页渲染。
6. **数字输入框千分位**：`2,097,152` → 数值断言先 `replace(/,/g,'')`（EM-K-66/EM-E-61 均踩）。
7. **PATCH 禁带 name**：`PATCH /clusters/{name}` 请求体含 `name` 直接 422；模拟他人修改时须剔除（BC-C-01 首跑 422）。
8. **抽屉退出路径**：cluster 向导无「取消」按钮、遮罩不可点（`mask-closable=false`）、**Esc 不可关**；断言按实际行为写并记偏差，勿按 iView 默认假设。
9. **列表筛选会被数据刷新清空**：`pageTable` 在 `tableData` watcher 重置筛选，导航后需等首屏响应再筛选（api-key EM-K-RO-02 历史坑）。
10. **route 规则是整集合 PUT**：并发/幂等断言须比对提交体而非只数请求；集合级 last-write-wins 无版本校验。

## 9. 一页版执行顺序

```
采集统计 → check:mapping → 元素矩阵 → 六维评价 → 场景清单 → 盲区打勾
   → 输出发现表（证据+优先级） → 逐项修复（三件套同步） → 定向验证 → 受影响 spec 回归
   → 清单回写（闭环/阻塞/不做） → 提交
```
