# 自动化测试用例评审标准

> **定位**：本标准从本项目（ai-gateway-web-test，17 个模块、数百条 Playwright 用例）的多轮深度审计实践中固化，用于评审**任何 UI 自动化项目**的用例设计质量。评审对象是「用例 + 断言 + 数据策略 + 文档」整体，不是 spec 代码本身。
>
> **用法**：新项目评估时按 §1~§7 逐项打分/打勾；§8 是执行流程。凡标注〔实例〕的条目均来自本项目真实事故，附编号可回查 `docs/模块深度检查清单.md` 坑位与 `docs/覆盖缺口清单.md`。
>
> **版本说明（2026-11-02）**：v1.0 初版，随 `utils/layout.js` 布局断言层与缺陷修复批次沉淀。

---

## 1. 覆盖性评审（用例设计层面）

### 1.1 需求-用例映射完整性

- 每个接口契约字段、每条校验规则（必填/格式/长度/唯一性/范围）都有对应用例，以**字段校验矩阵**核对，禁止「只测 happy path」。
- 边界值必须成对出现：长度上界/上界+1、0/负数、int64 溢出值、空串/纯空白、前导尾随空格、多字节（**UTF-8 字节 vs 字符口径**〔实例〕Entity 描述 255 字节口径变更）、控制字符。
- **页面元素 100% 审计**：把页面所有输入项、按钮、开关、下拉、Tab 列成清单逐一对照用例。〔实例〕由此发现「允许模型/禁止模型」整组元素 0 用例（缺口 #57）。
- 状态机覆盖：启用/停用、编辑/只读、视图/编辑双模式、空集合/单条/大数据量、加载失败（接口 500 不白屏）。
- 交互链路：新增→列表→搜索→详情→编辑→删除闭环；拖拽/排序/筛选**组合态**；未保存离开拦截；并发/重复提交/快速双击。

### 1.2 跨模块与场景用例

- 单模块 CRUD 之外，必须有跨模块联动（A 创建→B 引用→删 A 的保护）与端到端旅程用例。
- 共享组件改动必须评估**全项目影响面**并据此圈定回归范围。〔实例〕`pageTable` 一处改动波及 4 个拖拽模块，靠「谁传了 draggable 参数」圈定。

### 1.3 缺陷驱动覆盖

- 线上/历史 bug 必须回归用例化，断言精确到 bug 现象本身，不是「能跑通」。

## 2. 断言质量评审（最核心重灾区）

### 2.1 硬性要求

- **只写硬断言，禁止「只打日志不断言」**：每条用例至少一个会失败的 `expect`。评审时搜裸 `console.log`、无断言的 try-catch。〔实例〕EP-POOL-05 由「打印响应」改造为 3 条硬断言（决策 #96）。
- **断言验证效果而非过程**：不只断言「请求发出」，要断言「后端状态改变 + 前端反馈 + 副作用不存在」。
- **断言不弱化**：产品缺陷导致的失败，保留正确预期、以 `test.fail` 固化，禁止为转绿放宽断言、加无限轮询、降级断言对象；修复后转真实通过。〔实例〕表格长文本行高缺陷 5 条用例固化，当日修复、全部转真实通过（§二十七）。
- **预期值必须来自契约**：错误文案、长度上限以接口文档/源码/i18n 为准。〔实例〕路由规则名文档口径曾误写 128，源码与 RT-V-14 实为 1–64。
- **关键负向断言**：「不发生」的事也要断言——未写后端（请求跟踪器）、不弹框、URL 不变、按钮保持置灰。

### 2.2 布局/视觉断言（无视觉回归工具时的兜底层）

- 用 DOM 指标断言替代像素比对：`scrollWidth <= clientWidth + 1`（横向溢出）、矩形重叠（`getBoundingClientRect`）、行数封顶（`scrollHeight / lineHeight`）、ellipsis 实效（`text-overflow` + 内容确实被裁切）、字数计数器与输入框同行、footer 在视口内。参考实现：`utils/layout.js`。
- **阈值必须实测后固化**：先写一次性探针 spec 打印真实指标，再定断言值，禁止拍脑袋；实测数据回写文档。
- 组件能力以**依赖源码**为准，不以模板 props 为准。〔实例〕iView 3.5.4 的 Input 无 `showWordLimit`（dist 全文检索 0 命中），`show-word-limit` 为无效属性，计数器从未渲染——`grep node_modules/<lib>/dist` 确认版本能力后再断言 props 效果。

## 3. 数据与前置评审

- **数据即场景**：每条用例说清造数方式（UI / API / mock）及理由。〔实例〕「类型经 UI 创建避免下拉同步延迟」「规则 mock 避免写后端」「只读视角复用环境数据不造数」。
- **清理必须可靠**：afterEach 清理 + API 兜底双保险；造的数据命名带时间戳可追溯、删得掉。
- **数据隔离**：不用共享环境数据做断言基准；定位目标行用搜索/文本过滤，不依赖分页位置与下标。
- **前提显式化**：依赖其他模块资源（集群、类型）时前置校验存在性，失败信息明确（「无可用 X」），不 letting it 随机超时。

## 4. 稳定性与工程评审

### 4.1 选择器策略（按优先级）

1. 页面对象封装，spec 内禁止裸选择器；选择器收敛在 pages/ 层，spec 无裸 selector。
2. 禁用脆弱选择器：`nth-child` 取行、长 CSS 路径、文本全等匹配动态值；行定位用「文本过滤 + 限定表格作用域」（注意搜索行与数据行同 tbody 的串位问题）。
3. `filter({ has })` 嵌套定位器有兼容性隐患时改 `hasText`；动态属性注意框架 patch 特性（〔实例〕Vue 对枚举型属性不做 `removeAttribute`，`draggable` 残留需 watch 清理）。

### 4.2 异步与等待

- 禁止裸 `waitForTimeout` 当同步手段；用 `expect.poll` 等「条件收敛」式等待；明确失败信息。
- 区分纯前端操作与发请求操作：纯前端过滤不发请求，不要包请求等待（必然超时重放，白白浪费 15s/次）。

### 4.3 执行环境

- 明确并发约束并在 config 真实生效。〔实例〕后端单 Session Key → 强制 `workers: 1`；曾发现脚本 `PW_WORKERS=2` 被 config 硬编码 1 静默吞掉（坑位 #24 前置）。
- 长批次预期会话抖动假失败：失败先**定向复跑**甄别，再定性；config 加会话健康退避重试。

## 5. 已知缺陷与预期失败纪律（评审必查）

1. `test.fail` 必须带完整理由：现象 + 根因（源码级）+ 实测数据 + 恢复条件。
2. **防掩盖验证**：预期失败用例若在前置/中间步骤失败，结果仍显示「通过」——评审必须用**去掉 `test.fail` 的临时副本复跑**，确认失败点恰好是目标断言（坑位 #18，有实际教训）。
3. `test.skip` 必须写恢复条件，禁止裸 skip。
4. 缺陷修复后：`test.fail` 转真实通过，同步回写文档「阻塞记录 → 修复记录」。

## 6. 文档同步评审（三件套）

代码与文档一体交付，改动必须三处同步：

1. **02 正文**：用例步骤/预期/阻塞记录与实际断言一致；
2. **00 索引与映射**：索引行 + 自动化映射行（spec 文件 ↔ 用例号 ↔ 生命周期 ↔ 最近通过日期 ↔ 现状说明）；
3. **统计口径**：README/统计的 spec 数、用例数、优先级分布。

- **机器校验防漂移**：映射表声明的用例号必须出现在 spec 文件（`check-coverage-mapping.js`）；声明了 spec 但文件缺失要告警而非静默跳过（决策 #76）。
- **取数留证**：每轮全量回归归档报告（通过/失败/耗时），「最近通过」据此回写，禁止凭记忆填。

## 7. Review 速查清单

**设计**
- [ ] 每条校验规则有正向 + 负向 + 边界对
- [ ] 页面元素 100% 有对应用例（元素审计清单）
- [ ] 空态 / 加载失败 / 大数据量有覆盖
- [ ] 跨模块场景 ≥1 条；历史 bug 已回归用例化

**断言**
- [ ] 每条用例 ≥1 个硬断言；无裸日志
- [ ] 断言验证效果（后端状态/提示/副作用），非请求发出
- [ ] 预期值有据可查（接口文档/源码/i18n）
- [ ] 关键负向断言存在；无弱化断言、无掩盖性轮询

**数据**
- [ ] 造数方式与理由写明；清理可靠（含 API 兜底）
- [ ] 不依赖共享数据/分页位置

**工程**
- [ ] 选择器全在页面对象层；无 nth 取行
- [ ] 等待用条件收敛而非固定 sleep
- [ ] 并发约束在 config 真实生效
- [ ] `test.fail`/`test.skip` 有理由 + 恢复条件，且已用临时副本核实失败点

**文档**
- [ ] 02 正文 / 00 索引映射 / 统计三件套同步
- [ ] 映射校验脚本通过（0 失真、0 静默缺失）
- [ ] 本轮执行结果已回写（日期 + 证据）

## 8. 评审方法论（本项目验证有效的流程）

1. **九步深度检查**：元素审计 → 契约对照 → 用例映射 → 数据策略 → 断言审查 → 执行验证 → 缺口登记 → 补齐落地 → 文档回写。逐模块进行，每模块产出缺口清单。
2. **缺口清单驱动**：所有发现进统一清单（编号/优先级/状态/责任边界），按批次消化，完成一项勾一项，避免「发现了但忘了修」。
3. **先探针后固化**：对不确定行为（布局指标、缺陷是否真实）一律先写探针拿实测数据，再定断言写法。
4. **行业方案先摆后选**：设计争议（如拖拽与排序冲突）列出业界方案 + 本项目约束给用户决策，决策落文档，测试按决策改（实例：#79 决策①「排序/筛选激活时禁用拖拽」）。
5. **小步提交**：审计批、修复批分开 commit，消息注明验证数据（X/Y 通过、耗时），保证任意提交点可回溯。
